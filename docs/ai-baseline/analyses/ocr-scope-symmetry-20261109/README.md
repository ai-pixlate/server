## 대칭 범위 발견 사항

### 제외 대상이 삽입 오류로 남을 위험

`GS-03_018/sec_1_08 reg_0044`의 `VMDDI2COrOKEDaKIM`은 원본 하단에서 용기 인쇄가 바닥에 비친 부분이다. 기존 자동 분류는 큰 제외 영역 밖이라는 이유로 include로 남겼다. 상세페이지의 별도 설명이 아니므로 용기 인쇄 반사 범위로 제외하는 것을 권고한다. 반사 문구를 GT에 추가하면 안 된다. 이번에는 기존 주석·OCR을 바꾸지 않고 [추가 보류 기록](hold-overlay.json)으로 해당 영역과 섹션을 차단했다. 제외 영역 보정 시 GT/OCR 모두 동일 원본 범위를 사용해야 한다.

### 문자열 교차 경보 2개는 실제 대칭 오류가 아님

- `GS-03_002/sec_1_04 reg_0023 BODY`: 수상 배지 내부이며 제외. GT L007 BODY와 OCR reg_0012는 별도 BODY BRIGHTENING 설명이라 포함이다. 동일 문자열이라는 이유로 배지 OCR을 포함하면 안 된다.
- `GS-03_018/sec_1_08 reg_0007 b3`: 별도 제목 `b3 바디 브라이트닝 루틴`의 일부라 포함. 같은 문자열의 GT L020·L042는 용기 인쇄라 제외다. GT L004의 일부와 연결해야 하며 전체 줄 일치만 요구하면 오경보가 난다.

현재 대조에서 일반 설명을 잘못 제외한 추가 확정 사례는 발견하지 못했다. 이를 자동 1,063영역의 의미 무오류 보증으로 확대하지 않는다. 포함/제외 양쪽에 같은 문자가 있거나 분리·병합 출력이 있는 경우 문자열 매칭은 경보 도구일 뿐 범위 결정 근거가 아니다. [경보 목록](lexical-alerts.json).

`GS-01_002/sec_1_06 reg_0002 F`는 얼굴 위치에서 발생한 출력이다. GT에 없다는 이유로 제외하지 않는다. `GS-03_002/sec_1_01 reg_0026 √`도 일반 효능 안내의 그림 위치에서 검출됐다. 인증 로고가 아니므로 자동 제외하면 오검출을 숨길 수 있다. 이러한 출력은 확정된 범위 안에서 삽입 후보로 보존하며 이번에 오류 문자 수를 계산하지 않는다.

## 빈 출력 36개

기하상 제외 32개, 포함 2개, 경계 2개다. [전수 목록](empty-output-audit.json).

- 경계 2개는 GS-01_002/sec_1_11 reg_0026·0027. 원본 crop는 용기 입구·반사 사진이며 대응하는 번역 문구를 확인하지 못했다.
- 포함 2개는 GS-03_002/sec_1_01 reg_0011·0025. 원본 crop는 얼굴·일반 효능 그림으로, 해당 빈 반환에 일대일로 연결되는 GT 문자 근거가 없다.
- 따라서 이 네 빈 영역을 각각 삭제 오류로 계산할 수 없다. 포함 GT가 실제로 존재하고 다른 출력에도 대응하지 않는 경우에만 후속 문자 대응에서 누락(D)을 계산한다. 영역 수를 D로 환산하거나 다른 영역에서 이미 인식한 GT를 중복 삭제 처리하지 않는다.
- 정상 빈 반환과 실행 실패 `no_output`은 구별한다. 정상 빈 반환 때문에 포함 GT를 분모에서 제거하지 않는다. 실행 실패·GT 불완전·범위 미정의 예외 규칙은 기존 v6 초안대로 유지한다.

### 전사보다 범위/앵커 확인이 먼저인 대상

GS-01_001/sec_1_01 L054와 GS-01_002/sec_1_01 L005는 위 표대로 사용자 위치 확인이 필요하다. 미결만으로 새 전사를 지시하지 않는다. reg_0044 반사 인쇄와 Good all 혼합 출력은 GT 추가 문제가 아니라 범위 연결 문제다.

### 추가 전사 후보에서 제외

- GS-02_008/sec_1_04: 논문 전체는 확정 제외 정책. 별도 효능 설명 18줄은 기존 GT에 있어 논문 재전사 불필요.
- GS-01_002/sec_1_06 L024–028: 원본 각주와 기존 전사를 대조했고 이번 점검에서 보완 근거를 찾지 못함. OCR `o` 범위 문제는 별도 유지.
- GS-02_008/sec_1_01 L001–002: 원본의 수치·단위가 기존 GT에 있음. 치수라는 이유로 재전사하지 않음.
- GS-02_014/sec_1_11: 별도 개발 메모 the vita A/retinal/tightening은 기존 GT에 있고, 용기 표기는 제외 범위. 이번에는 포함 메모 누락 근거 없음.
- GS-03_013/sec_1_01 L014: 원본에도 **25~29세**로 보임. 다른 이미지의 25~59세에 맞춰 고치지 않음.
- GS-03_018/sec_1_08 L079–081: 별도 각주가 기존 GT에 있음. 새 발견은 인쇄 반사 범위이므로 GT 추가 없이 범위 보정 필요.

후보 제외는 GT 새 승인·무오류 보증이 아니라 이번에 추가 전사를 요청할 근거가 없다는 뜻이다. 기존 18개 재전사 초안과 v1/v2 동결본을 그대로 보존했다.

## v6 채점기 구현 전 조건

일반적인 입력 해시·상태 차단·대칭 필터 검증의 구현 준비는 가능하다. **현재 초안만으로 공식 채점 가능한 v6 완성 구현/운영은 아직 불가**하다.

1. 위 미결 6항목 및 반사 인쇄의 처리 승인. 혼합 단일 OCR 반환값을 분리하지 못하는 경우의 공통 규칙을 정의한다.
2. revision 3은 포함 설명 창을 제외 사진에서 차감하는 후보 로직을 사용하지만 v6 초안은 우선순위를 미확정으로 둔다. 이 차감 규칙과 출력별 시각 확인 예외를 명세화·승인해야 한다. 현재 출력별 예외를 다음 버전 region ID에 그대로 적용하면 안 된다.
3. 범위·GT 연결을 원본 이미지 좌표/의미 기준으로 고정하고, 제품마다 달라지는 region_key와 분리한다. 제품별 새 출력의 경계 교차를 다시 검증한다.
4. GT 보완 3개와 앵커 확인을 거쳐 새 범위의 GT를 사용자 승인 후 동결한다. v1/v2는 보존한다.
5. 정상 빈 출력·중복·누락, 이름이 같은 다른 위치, 로고+일반 문구 결합, 반사 인쇄, 이미지/출력 해시 불일치를 합성 사례로 검증한다. v5 대응 방식의 분리·병합 한계도 별도 검증한다.

## 수동 화면 확인과 보존

이전 Computer Use 안전 중단을 재시도하거나 우회하지 않았다. **브라우저 시각 검증 미완료**다. 사용자가 [기존 읽기 전용 화면](../ocr-scope-refinement-20261109/review.html)을 Chrome에서 직접 열어 섹션 선택 → OCR 영역 탭 → 해당 번호 선택 → 확대 순으로 확인할 수 있다. 화면은 기존 revision 3 데이터이므로 reg_0044는 아직 include로 보인다. 이 보고서의 추가 보류 기록을 함께 적용해 읽어야 한다. GT 탭은 기존 텍스트를 보여 주며 승인/수정 기능은 없다. 원본 링크는 로컬 전용이다.

검증 재현: 저장소 worktree에서 `python docs/ai-baseline/analyses/ocr-scope-symmetry-20261109/audit.py`. 외부 연결·OCR·CER 함수 호출 없음. 기존 보호 파일 232개 및 revision 3 파일 13개 불변을 확인했다. 검증 스크립트와 보고서·별도 분석 색인만 추가했다. 커밋·push·PR은 하지 않았다.
