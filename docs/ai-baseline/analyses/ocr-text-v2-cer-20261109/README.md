# OCR Text v2 CER 이상 수치 원인 분석

2026-11-09. 기존 동결본·보존 OCR 반환·측정 결과만 읽어 분석했다. 공식 CER 및 입력 파일은 수정하지 않았다. 아래 순서 재배열·문자 빈도·단일 섹션 제외 계산은 모두 원인 분석용 보조 진단이며 공식 측정값을 대체하지 않는다.

## 결론

전체 42.79%, GS-02 63.52%는 현행 CER v4·동결 정답에 대해 정확하게 계산됐다. 그러나 이를 순수 문자 인식 오류율로 해석하기에는 한계가 크다.

가장 큰 원인은 GS-02_008/sec_1_04의 논문 본문·참고문헌을 빈 정답으로 수용하면서 그 영역의 OCR 반환은 그대로 채점하는 비대칭이다. 이 섹션 하나가 GS-02 오류의 79.44%, 전체 오류의 49.60%를 차지한다. 읽기 순서 차이 역시 실제로 CER을 키우며, 회전 라벨의 실제 인식 오류도 함께 존재한다.

권장 우선순위는 평가 범위·채점 방식 개선안을 별도 버전으로 설계하는 것이다. 현재 CER은 재현 가능한 기존 기준 결과로 유지한다. 순수 인식 성능을 비교하려면 정답과 출력이 같은 텍스트 범위를 다루도록 먼저 맞춰야 한다. OCR 자체 개선은 회전·미세 라벨 등 확인된 실제 오류에 집중하는 편이 적절하다.

## 1. 공식 계산 재검증

- 독립적으로 작성한 2행 동적계획 Levenshtein 거리로 112개 입력 문자열을 확인했다. measured 110개의 거리 합은 기존 S+D+I와 모두 일치했다.
- 별도로 기존 채점기의 동률 규칙을 적용한 S/D/I/N을 메모리에서 다시 확인했고 110개 모두 기존 값과 일치했다.
- NFC·명세 지정 공백 제거를 별도 구현해 기존 정규화 결과와 112개 모두 일치함을 확인했다. 대소문자·문장부호·상표 기호는 명세대로 유지된다.
- measured 섹션마다 출력 문자 수 - 정답 문자 수 = I-D가 성립한다.
- 정답·출력 연결과 출력 SHA-256을 검증했다. 배열을 잘못 연결하거나 다른 섹션을 읽었다는 증거는 발견하지 못했다.
- 기존 12개는 S/D/I/N·상태와 출력 해시가 모두 일치한다. 기존 730/5,333 = 13.69% 결과가 그대로 재현된다.
- 기존 동결·결과 파일 185개의 분석 전후 해시가 일치한다. 추가 OCR·모델 호출·GT 수정은 수행하지 않았다.

| 범위 | S | D | I | 정답 문자 N | 출력 문자 | 공식 CER |
|---|---:|---:|---:|---:|---:|---:|
| GS-01 | 759 | 716 | 219 | 6,100 | 5,603 | 27.77% |
| GS-02 | 471 | 680 | 5,139 | 9,903 | 14,362 | 63.52% |
| GS-03 | 756 | 640 | 694 | 7,540 | 7,594 | 27.72% |
| all | 1,986 | 2,036 | 6,052 | 23,543 | 27,559 | 42.79% |

전체 112개 중 텍스트 없는 사진 2개는 not_applicable이다. N=0인 두 섹션은 공식 전체 CER의 분자·분모에 포함되지 않으며 기존 결과에 출력 문자 수가 보존돼 있다.

## 2. GS-02 오류 집중 구간

GS-02 48개 중 CER 10% 미만은 32개, 10% 이상은 16개다. 20% 이상 12개, 50% 이상 6개, 100% 이상 1개다. 아래 5개는 오류 문자 수 기여도가 큰 순서로 선정했다. 5개 합계 5,618자는 GS-02 오류 6,290자의 89.32%다.

| 섹션 | S / D / I | 정답 / 출력 문자 | 공식 CER |
|---|---:|---:|---:|
| GS-02_008__sec_1_04 | 7 / 24 / 4966 | 456 / 5398 | 1095.83% |
| GS-02_002__sec_1_01 | 88 / 124 / 6 | 386 / 268 | 56.48% |
| GS-02_008__sec_1_01 | 89 / 39 / 26 | 275 / 262 | 56.00% |
| GS-02_001__sec_1_03 | 31 / 62 / 53 | 839 / 830 | 17.40% |
| GS-02_014__sec_1_04 | 18 / 43 / 42 | 272 / 271 | 37.87% |

### GS-02_008/sec_1_04 — 빈 정답 수용 범위의 영향이 지배적

정답 456자, 출력 5,398자로 길이 차이가 4,942자다. 문자열 내용·순서를 아무리 맞춰도 이 길이 차이만큼 편집이 필요하다. 공식 오류 4,997자의 98.90%에 해당한다. 문자 빈도까지 고려한 순서 무시 하한도 4,946자여서 순서 변경으로 줄일 수 있는 최대치는 51자다.

이미지에는 축소 논문 페이지, 여러 줄의 회색 참고문헌, 겹친 논문 본문이 실제로 있다. GT에는 큰 한국어 설명과 일부 영문 제목만 들어 있고 본문·참고문헌은 동결 시 빈 정답으로 수용했다. OCR 반환에는 논문 제목·저자·학술지 목록 및 본문이 대량 포함돼 있다. 그 중 오인식된 영문도 보여 전부 정확한 인식이라고 주장할 수 없지만, GT가 없는 영역이므로 정인식과 오인식 모두 추가 문자열로 작용한다.

비어 있지 않은 완전히 같은 OCR 줄의 중복은 이 섹션에서 0건이다. 대량 삽입을 동일 줄 반복이나 로그 중복 연결로 설명할 증거는 없다. 서로 다르게 인식된 중복·겹친 논문은 정확한 중복량을 확정하지 못했다.

민감도 확인용으로 이 섹션 하나를 분자·분모에서 빼면 GS-02는 1,293/9,447 = 13.69%, 전체는 5,077/23,087 = 21.99%다. 이는 이 섹션의 영향도를 보여 주는 계산이며 정식 제외·수정 성능으로 사용하지 않는다. 여기의 13.69%는 기존 12개 결과와 숫자만 우연히 같고 평가 범위가 다르다.

### GS-02_002/sec_1_01 — 회전 라벨 오인식·누락과 GT 의심 문자열

제품이 크게 기울어져 있고 작은 튜브 라벨이 반복된다. OCR은 RETINAL SHOT/TIGHTENING BOOSTER의 순서를 바꾸거나 파편으로 인식했고, MATRIXYL을 AEATRIXYL로 반환하는 등 문자 차이가 있다. GT 386자 대비 출력 268자로 118자 부족하며, 순서를 무시해도 문자 빈도상 최소 149자 차이가 남는다. 순서만으로 해소할 수 없는 내용 차이다.

추가로 동결 GT L005·L006에는 `313, 638, 404, 807`, `304, 595, 396, 780`라는 문자열이 있다. 이미지에는 해당 숫자열이 확인되지 않으며 좌표 형태의 데이터가 전사 칸에 들어갔을 가능성이 있다. 두 줄은 공백 제거 후 합계 30자다. v1 원본 JSON부터 같은 값이며 v2 동결 과정에서 생긴 내용은 아니다. 원본 이력 확인 전에는 유입 원인을 확정할 수 없다. 이 부분은 후속 GT 품질 검토 대상이고 이번 분석에서는 수정하지 않았다.

### GS-02_008/sec_1_01 — 회전 인식 문제와 다열 순서 차이 혼재

기울어지거나 뒤집힌 라벨에서 `Panthenol`·`MATRIXYL` 등의 문구가 뒤집힌 형태 또는 다른 문자로 출력된다. GT와 OCR에 각각 여러 제품의 반복 라벨이 있어 동일 문구 반복 자체를 중복 검출 오류로 볼 수 없다.

하단 3열의 GT는 왼쪽 열 전체 → 가운데 열 전체 → 오른쪽 열 전체 순서다. OCR은 `4중 / 3단깊이 / 각질층` 다음 `모공 / 속탄력 / 착색개선`처럼 가로 방향의 행 순서다. 원본에서 두 배열의 차이를 확인했다. 문자 빈도 하한은 41자, 공식 오류는 154자로 순서 영향과 실제 문자 차이가 섞여 있다. 그 차이 113자를 모두 순서 오류로 단정하지 않는다.

### GS-02_001/sec_1_03 — 두 열 영수증과 기호·미세 문자

스마트폰·영수증 화면의 두 열 내용을 GT와 OCR이 다른 순서로 연결한다. 예를 들어 GT는 할인 안내 다음 사업자 번호를 놓지만 OCR은 사업자 번호를 먼저 놓는다. 고객센터·웹주소, 세금 표 행에서도 순서가 다르다.

`www.oliveyoung.co.kr` → `www.o1fveyoung.co.kr`, `환불` → `환물`과 같은 실제 인식 차이 및 화살표·STEP 원형 숫자 누락도 있다. 문자 빈도 하한은 18자, 공식 오류는 146자다. 순서의 영향 가능성이 크지만 줄 분할과 기호 차이까지 있어 128자 전부를 순서 효과라고 확정할 수 없다.

### GS-02_014/sec_1_04 — 정확한 문구도 연결 순서 때문에 오류 증가

사용법 표에서 GT는 각 사용자 등급의 왼쪽 설명 → 용량 → 사용 주기 순서이고, OCR은 비슷한 높이의 줄을 가로로 읽어 서로 섞는다.

출력 35개 영역의 문자와 개수를 그대로 보존하고, 원본 표에서 확인한 열 순서에 따라 재배열하면 **103/272 = 37.87% → 7/272 = 2.57%**가 된다. 순서만 바꾼 진단에서 오류 96자, 35.29%p가 줄었다. 최적 성능을 주장하는 값이 아니며 수동 순서 변경 목록을 diagnostics.json에 보존했다.

더 작은 예에서는 초급자 부분의 6줄·36자가 정규화 후 모두 정확히 인식됐으나 순서만 달랐다.

- GT — 초급자 → 레티놀/레티날 → 제품 첫 사용자 → 쌀알 크기로 소량 → · 초반 한 달 간 → 주 1~2회 사용
- OCR — 초급자 → 쌀알 크기로 소량 → · 초반 한 달 간 → 주 1~2회 사용 → 레티놀/레티날 → 제품 첫 사용자

같은 문구·같은 횟수인데 원래 순서에서는 26/36 = 72.22%, 대응 순서에서는 0/36 = 0%다. 사용자가 질문한 “문자는 정확한데 연결 순서 때문에 오류로 계산되는 사례”를 직접 확인한 예다.

재배열 후 남은 7자는 bullet 기호 차이, 빠진 점·bullet, 손 그림에서 나온 것으로 보이는 `YL`, 가이드 문구의 한 글자 차이 등이다. `YL`의 원인 부위는 추정이며, 글자별 차이는 기존 결과 쌍으로 확인했다.

## 3. 전체 읽기 순서 영향의 범위

보조 진단으로 섹션별 문자 빈도를 비교했다. 정답에만 남는 문자 수 A와 출력에만 남는 문자 수 B에 대해 max(A,B)를 계산했다. 위치와 순서를 모두 무시해 문자를 자유롭게 짝짓는 하한이다. 단어 내부 문자 순서까지 무시하므로 이 값을 실제 인식 CER로 사용할 수 없다.

| 범위 | 공식 오류 | 문자 빈도 하한 | 하한/N | 공식 오류와 하한의 차이 |
|---|---:|---:|---:|---:|
| GS-01 | 1,694 | 591 | 9.69% | 1,103자 |
| GS-02 | 6,290 | 5,657 | 57.12% | 633자 |
| GS-03 | 2,090 | 972 | 12.89% | 1,118자 |
| 전체 | 10,074 | 7,220 | 30.67% | 2,854자 |

GS-02는 모든 문자 순서를 자유롭게 재배열해도 최소 5,657자 차이가 남는다. 따라서 순서 변경만으로 제거할 수 있는 최대치는 633자(6.39%p)이며, 63.52% 전체를 읽기 순서로 설명할 수 없다. 전체에서의 최대 감소 여지도 2,854자(12.12%p)다. 정확한 행 순서 원인 비율은 미확정이며, 위 하한과 공식 오류의 차이를 순서 오류의 확정량으로 합산하지 않는다.

수동으로 입증한 96자 감소는 문자 추가·삭제 없이 OCR 영역 순서만 변경한 한 섹션의 결과다. 나머지 섹션을 GT에 유리하게 재정렬하여 공식 점수를 대체하지 않았다.

## 4. 정규화·출력 경계·원시 엔진 자료

독립 정규화 결과는 112개 모두 일치했다. 단순 띄어쓰기·줄바꿈 차이는 명세에 따라 이미 제거돼 있다. `·`와 `•`, TM과 ™, 대소문자 등은 명세상 차이를 유지하므로 실제 문구가 유사해도 오류가 된다. 이는 계산 구현 문제로 확인되지 않았다.

이번 112개는 모두 고정 짧은 섹션 경로다. v1.0.1의 ocr.run → to_result는 엔진 rec_texts 배열을 순서대로 OcrResult.regions[].text에 담는다. 이 버전 경로에는 이후 버전의 추가 보정·재정렬이 없다. 최초 계측은 run 반환을 model_dump로 보존하고 같은 결과를 서비스에 반환한다. 보완 스크립트도 같은 반환을 저장했다.

원시 엔진 rec_texts 딕셔너리는 이번 증거에 별도 파일로 저장되지 않았다. 따라서 raw 엔진 후보와 반환값의 별도 실측 비교에는 한계가 있다. 서비스 반환 원본과 제품 코드의 전달 관계는 확인했으며, 다른 제품 버전의 과거 OCR을 raw 대체 근거로 사용하지 않았다.

## 5. 권장 후속 조치

1. **현행 CER 유지** — 계산은 정확하고 기존 12개와도 일치하므로 42.79%를 현행 정답·순서 기준의 전체 문자열 차이로 보존한다. 순수 OCR 문자 오인식률이라고 해석하거나 사용자 체감 오류율로 직접 제시하기에는 범위·순서 영향이 크다.
2. **평가 범위·채점 방식 개선을 우선 설계** — 판독 불가 영역을 평가에서 제외하려면 해당 GT와 대응 OCR 출력 모두에서 동일 범위를 제외하는 규칙이 필요하다. bbox 검수를 생략하려면 재현 가능한 평가용 crop/마스크 등 입력 범위를 고정하는 별도 방안을 검토해야 한다. 순서가 모호한 표·다열은 인식 내용과 읽기 순서를 분리해 진단하는 기준을 사전에 정한다. 기존 버전은 보존하고 새 정답·명세 버전으로 동일 제품과 이후 통합을 재평가해야 한다.
3. **OCR 자체 개선은 실제 오류에 집중** — 회전·작은 라벨, 미세 영문, 기호 누락·오검출을 우선한다. 빈 정답 영역에서 인식한 문구를 단순히 삭제해 점수를 낮추는 방향은 근거가 부족하다.
4. **GT 의심 항목 후속 검토** — v1에서 승계된 좌표 형태 숫자 두 줄, 빈 정답 수용 16개, AI만 검수한 53개를 후속 품질 관리 범위로 검토한다. 이번 분석에서는 재검수·수정·동결을 진행하지 않았다.
