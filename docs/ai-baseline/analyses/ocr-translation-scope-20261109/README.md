# OCR 번역 대상 범위 조사·결정안

2026-11-09 · 사용자 결정 대기 · 실행/명세 변경 아님. 18개 GT 재전사 작업은 중단했고 기존 v3 초안을 보존한다. 이 문서는 신규 GT가 아니며 OCR01·CER v5의 현재 정의를 대체하지 않는다. OCR 실행·CER 계산·API 호출·승인·동결·커밋을 하지 않았다.

## 1. 목적과 먼저 구분할 사항

추천 목적: **고정된 서비스 번역 대상 텍스트의 보정 후 OCR 문자 인식 정확도**. 실제 서비스가 오인식·누락·라벨 오판정 때문에 번역에 보내지 못한 글자도, 정답 범위상 대상이면 평가에서 빠지면 안 된다. 실행마다 실제 번역 성공 블록만 분모로 삼으면 성능이 나쁜 버전이 유리해진다.

두 가지 범위를 혼동하지 않는다.

1. **독립 OCR 기술 평가(추천):** 112개 고정 입력에서 N3 포함을 가정하고 라벨/브랜드 로고를 뺀 대상 문구를 사람이 원본으로 사전 지정한다. 섹션 판정·라벨 분류의 성능과 분리한다. 실제 첫 회차 번역된 문구의 성능이라고 부르지 않는다.
2. **실제 서비스 번역 범위 평가:** PM 정답의 N3 포함/제외까지 고정해야 한다. [GS-01 승인 기준](../../references/gs-v1/gs01-v1-20261103/README.md)상 GS-01_001은 전체 제외이므로 여기서는 비대상이다. GS-02·03의 섹션별 승인 범위는 이번 조사에서 확정하지 않았다. 첫 회차 AI가 전체 제외/실패한 결과를 정답 범위로 쓰지 않는다.

아래 112개 표는 1번을 전제로 한 **내용 분류 후보**다. 2번의 최종 개수는 아직 산출할 수 없다. 1번에서는 GS-01_001의 디자인 안내도 OCR 대상 문구가 있으므로 혼합, 2번에서는 비대상이 된다. 목적 선택이 필요하다.

## 2. 조사 근거와 한계

- [파이프라인 5절·7.4·7.5절](../../../ai/pipeline.md), [계약 2.2~2.4절](../../../ai/contract.md): 용기·패키지 인쇄와 브랜드명 전체 일치 블록은 하류 제외. 일반 설명·제품명은 이름이라는 이유로 제외하지 않는다. 문서/화면 캡처는 문서라는 이유로 라벨이 아니다.
- v1.0.1 SHA `bfa3b700144467f4adf7d6802b7b2e93791fe6de`의 `docs/ai/pipeline.md`, `pipeline/stages/label.py`, `pipeline/stages/translate.py`, `pipeline/handoff/translation.py`도 Git에서 읽었다. 공백 원문은 번역 대상으로 받지 않지만, 작은 글씨/논문/영문을 일괄 제외하는 근거는 확인하지 못했다. 저신뢰 인페인팅 제한을 번역 제외 규칙으로 일반화하지 않는다.
- [OCR Text v2](../../references/ocr-text/ocr-text-v2-20261109/README.md) 112개 이미지의 바이트 SHA-256 일치 확인. 원본 개요 10매로 전부 확인하고 논문·기프트카드·사용법 이미지 등 경계 사례는 개별 원본으로 확인했다. 작은 글씨 전수 전사/완전성 검수는 하지 않았다.
- [v5 기존 완전성 조사](../ocr-v5-candidate-20261109/README.md)의 문제 대상 ID/검수 이력을 참고했다. OCR 출력·오류율로 분류하거나 제외 범위를 정하지 않았다. 과거에 결과를 본 이력이 있으므로 새로운 블라인드 조사라고 주장하지 않는다. 사용자 범위 검수에서는 CER를 가리고 원본·정책을 먼저 승인하는 것을 추천한다.

## 5. 혼합 섹션의 공정한 처리

**추천 검토안 A: 원본 전체 입력 유지 + 사전 고정한 의미 영역으로 GT/출력을 대칭 제한.** 원본에서 번역할 영역과 보호할 라벨/로고 영역을 사용자가 승인한다. 줄별 bbox 정밀 채점은 하지 않고 범위를 구분하는 큰 영역만 둔다. 이는 bbox 정확성 지표가 아니라 평가 범위 주석이다. 기존 GT의 line ID에도 동일 범위를 연결한다.

- 출력은 서비스 보정 후 반환값 전체를 보존하고, 그 출력의 원본 좌표와 고정 영역을 연결한다. 문자열 유사도·CER·confidence로 출력 문구를 제거하지 않는다.
- 포함 영역의 누락 GT 문자는 D, 포함 영역의 추가/중복 출력은 I로 남는다. 제외 영역에는 GT와 출력 모두 같은 규칙을 적용한다.
- OCR 영역이 포함/제외 경계를 가로지르거나, GT 좌표가 검증되지 않아 줄의 범위를 확인할 수 없으면 자동 문자열 절단/삭제하지 않는다. 범위 대응 미확정으로 기록하고 그 섹션을 완결 집계로 내보내지 않는다. 좋은 결과만 부분 선택하지 않는다.
- **오인식된 bbox가 밖으로 나가며 출력이 제외되는 편향**과 과병합 텍스트의 분리 불가가 남는다. 포함/제외/경계/미연결 출력 개수와 근거를 모두 남기고, 여러 버전에 동일 규칙을 적용하는 합성 검증이 필요하다. 겹침 임계값·경계 처리 알고리즘은 이번에 정하거나 구현하지 않았다.
- 기존 GT는 텍스트 전용으로 동결됐으므로 예전 bbox를 검증된 범위 정답으로 재사용할 수 없다. 검수 도구의 범위 표시·출력 연결 기능은 후속 구현 사항이다.

**대안 B: 대상만 있는 고정 crop을 별도 입력 버전으로 승인.** GT와 OCR가 동일 crop을 보게 해 범위 대칭성을 명확히 할 수 있다. 그러나 문맥·줄 분할·OCR 검출 결과가 바뀌므로 기존 전체 섹션 OCR 출력에서 텍스트만 잘라 새 crop 실행으로 간주할 수 없다. 모든 버전 재실행, crop 해시·부모 위치·버전 관리가 필요하며 현재의 동일 112개 입력 비교와는 별도 벤치마크가 된다. 이번에는 crop/GT 생성이나 추론을 하지 않는다.

**좌표를 범위 구분에도 전혀 쓰지 않으려면**, 혼합 섹션의 문자열만으로 동명 제품명·브랜드·반복 문구의 출처를 공정하게 구별하기 어렵다. 이 경우 A를 보장할 수 없으며 B 또는 혼합 섹션 미측정이 필요하다. GT만 삭제하고 전체 OCR와 비교하는 방법, 출력의 정답 유사도가 높은 문구만 고르는 방법은 채택하지 않는다.

## 6. 추가 GT 검수 범위·작업량

- 범위 검수: 112개 전부의 분류 승인. 특히 혼합 31개는 포함/제외 연결, 보류 1개는 정책 결정, 비대상 4개는 제외 근거 확인이 필요하다.
- 기존 GT 줄 수 참고: 대상 76개 **888줄**, 혼합 31개 **956줄**, 보류 1개 **8줄**, 비대상 4개 **9줄**. 합계 1,861줄은 기존 데이터량이지 신규 전사량/누락량/확정 분모가 아니다.
- 기존 18개 경고의 재분류: 혼합 15개, 비대상 1개(GS-01_002/sec_1_24), 대상 2개(GS-02_008/sec_1_05, GS-03_014/sec_1_01). 15개 혼합의 문제가 전부 라벨에만 있다고 단정하지 않는다. GS-02_008/sec_1_04 논문, GS-02_014/sec_1_11 손글씨 등 대상 문제는 남는다. 기존 18개 보완 초안은 중단/보존했으며 새 범위 정답으로 자동 승계하지 않는다.
- 우선 완전성 검토 후보: GS-02_008/sec_1_04 논문/참고문헌, sec_1_05 특허, GS-03_014/sec_1_01 성적서. 추가로 GS-02_013/sec_1_02 인증서 등 기존 경고가 없던 문서도 원본 전체 누락 여부 확인이 필요하다. 작은 글씨가 읽히지 않으면 미확정으로 남긴다.
- 53개 AI 단독 검수의 사람 미검수 이력은 유지한다. 과거 47개 사용자 검수는 새 범위 승인/완전성 확인으로 자동 변환하지 않는다.
- 추가 전사 줄 수와 시간은 미확정이다. 범위 승인 전에는 라벨 쪽 미전사가 사라지는 양과 논문 쪽 남는 양을 계산할 수 없다. 시간 근거도 없어 임의 시간치를 제시하지 않는다. 후속 승인 후 3종(일반/혼합/문서)의 작업 시간을 먼저 관측해 산정하는 것을 권한다.

## 7. OCR01·v5에 필요한 후속 변경 (이번 미적용)

1. OCR01의 전체 문자 인식 목적과 신규 서비스 번역 대상 인식 목적을 버전으로 구분. S/D/I 및 문자 가중 CER 계산은 유지하되 범위/분모 변경으로 과거 v4/v5와 직접 성능 개선 비교 금지.
2. v5의 “번역에 쓰이지 않아도 전체 문자 포함” 조항은 사용자 결정 후 새 범위 명세로 대체/추가하고 현재 후보 결과의 적용 명세는 보존.
3. 고정 범위 버전·원본 112개 해시·정책 버전·GT line ID 대응·범위 승인 이력·출력 연결 판정 근거를 보존. 2·3차에서 제품의 라벨/로고/번역 선택에 따라 기준을 변경하지 않음.
4. 범위 비대상과 GT 불완전/판단 보류, 출력 없음/연결 실패를 구별. 미측정을 0오류로 계산하지 않고 대상/측정 가능/보류 개수와 문자 분모를 공개.
5. v5 A2의 순서·분리/병합 한계는 범위를 줄여도 해결되지 않는다. 별도 검증 필요. H01~H05·OP01~OP07과 공통 결함 분석은 변경하지 않음.
