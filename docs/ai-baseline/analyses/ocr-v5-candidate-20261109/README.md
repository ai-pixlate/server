# OCR CER v5 후보 및 GT 완전성 점검

2026-11-09 · 후보/진단 결과 · 공식 기준 전환 전. 기존 v4, OCR Text v1/v2, 공식 실측 증거를 변경하지 않았다. 새 GT 작성·동결·OCR 추론·외부 API 호출·커밋·push·PR은 수행하지 않았다.

## 1. 점검 범위와 완전성

112개 전부의 ID·이미지 SHA-256·정답 줄·빈 문자열·기존 검수 근거·출력 해시를 대조했다. 전체 이미지 개요 7매를 열람하고 GS-02_008/sec_1_04와 GS-02_002/sec_1_01은 개별 원본으로 확인했다. **1,861줄의 독립 재전사/재검수를 완료했다는 뜻은 아니다.** 특히 작은 인쇄의 완전성은 개요 이미지로 검증할 수 없다. 이번에는 원본 전사를 새로 작성하지 않았으며 OCR 출력으로 정답을 채우지 않았다.

전체 목록·이미지 경로·해시·빈 줄·기존 문제 근거는 [112개 점검 색인](candidate-a2/completeness-audit.json), 읽기 쉬운 목록은 [섹션별 표](section-review.md)다.

| 구분 | 섹션 | 처리 |
|---|---:|---|
| GT 범위/내용 재검수 우선 | 18 | 기존 미완전 수용 16개 + L008 빈 정답 1개 + 좌표형 GT 의심 1개. v5 범위 보류 |
| AI 검수만 수행 | 53 | 사용자 미검수 그대로 표시. 무오류/완전성 확인으로 간주하지 않음 |
| 기존 사람 검수 근거 있고 알려진 범위 경고 없음 | 39 | 별도 후보 집계. v5 완전성·공식 승인 완료 아님 |
| 전체 GT 빈 무문자 이미지 후보 | 2 | GS-03_003/sec_1_01, GS-03_007/sec_1_01. CER 분모 0; 후자는 출력 문자 1개도 별도 보존 |

줄을 가진 GT 중 빈 줄은 GS-01_002/sec_1_01 L005와 GS-02_014/sec_1_09 L008 두 개뿐이다. **빈 줄이 적다고 GT가 완전한 것은 아니다.** 16개 대부분의 미전사 부분은 줄 자체가 없어서 빈 문자열 검색만으로 찾을 수 없다. 검수 기록의 omission/illegible 근거와 함께 대조했다.

### 우선 사용자 재검수

- **GS-02_008/sec_1_04**: 이미지에 논문 본문·표·참고문헌이 있으나 GT는 주로 제목·홍보 문구 456자다. 독립 전사가 필요한 영역과 원본 해상도로 판독 불가능한 영역을 먼저 나눠야 한다. GT 456자/출력 5,398자의 범위 차이를 OCR 오류로 확정하면 안 된다. 제목·참고문헌 일부는 보이지만 논문 미세 본문 전체를 판독 가능하다고 단정하지 않는다.
- **GS-02_002/sec_1_01 L005·L006**: `313, 638, 404, 807` / `304, 595, 396, 780`의 정규화 30자가 GT에 있으나 개별 원본에 해당 인쇄 근거를 찾지 못했다. 좌표 유입 의심이다. 삭제·대체를 자동 반영하지 않았으며 사용자 확인 후 새 GT 버전에 반영해야 한다.
- **16개 기존 예외 전체**: 튜브 미세 인쇄·실링 로트·가려진 라벨·패키지 뒷면·논문/특허·손글씨·시험성적서. 정확한 ID와 원래 검토 근거는 색인에 보존했다. “번역하지 않음”은 문자 인식 평가의 제외 근거가 아니다.
- **GS-02_014/sec_1_09 L008**: v4의 빈 정답 승인은 보존하되 v5에서는 실제 무문자인지 판독 불가 문자인지 확인해야 한다. 위치를 확인하지 않고 OCR 출력에서 대응 문구만 지우는 것은 금지한다.

현재 영구적으로 평가 불가능하다고 확정한 섹션은 없다. 18개는 원본 독립 전사/범위 판정 전까지 공식 평가 불가(보류)다. 읽을 수 있는 부분은 OCR Text v3에서 보완하고, 읽을 수 없는 문자가 남으면 전체 섹션 보류 또는 OCR 출력을 보지 않고 사전 고정한 공통 입력 crop을 별도 버전으로 승인받는다. 높은 CER 자체는 보류 기준이 아니다.

## 2. 구현과 검증

[v5 후보 명세](../../protocols/v1/ocr-v5.md), [구현](../../../../tools/baseline/ocr_v5.py), [합성 테스트](../../../../tests/test_ocr_v5.py).

줄 내부 문자 순서를 유지한 Levenshtein 일대일 최적 대응, 연속 1~3줄 그룹 대응, 기존 전체 연결 경로를 비교한다. 미대응 문자는 모두 삭제·삽입에 남고 문자 중복 소비는 없다. 문자 정렬/빈도 비교·confidence 필터·bbox 사용은 하지 않는다. S/D/I 역추적과 정규화는 v4를 재사용했다.

최초 A 후보는 4개 이상 분리·병합을 처리하지 못해 v4보다 나빠진 섹션 13개가 발견됐다. “동일 연결 문자열의 줄 경계 변경은 오류를 만들지 않는다”는 독립 합성 조건을 추가하고 A2에 전체 연결 경로를 추가했다. 최초 출력은 [폐기 후보 A 기록](results/comparison.json)으로 보존하며 34.00%를 최종 후보값으로 사용하지 않는다. 실출력에 맞춰 섹션별 임계값이나 매칭 규칙을 다르게 적용하지 않았다.

검증: v5 21개 + 기존 OCR 채점/동결 회귀 30개 = **51개 통과**. 순서 변경, 실제 오인식, 분리·병합, 누락·중복·추가, NFC/공백, 빈 GT/출력, 미전사 부분의 삽입 비용, 입력 불변성을 검증했다. 거리 구현은 무작위 300쌍을 기존 DP와 대조했고 Hungarian은 작은 행렬의 모든 순열 최소값과 대조했다. 최초 회귀 실행은 sandbox TEMP 생성 오류였으며 저장소 `.cache`의 새 임시 경로를 지정해 통과했다.

그룹 대응은 휴리스틱이며 전역 최적화를 보장하지 않는다. 4줄 이상 분리 조각이 재정렬까지 된 경우, 배열에서 떨어진 조각, 반복되는 비슷한 줄의 잘못된 의미 대응은 남는 한계다. 전체 읽기 순서의 모든 순열에 대한 완전한 불변성을 보장하지 않는다. 공식 전환 전에 이 경계를 추가 합성/사람 대응 검증으로 해결하거나 명시적으로 승인해야 한다.

## 3. 동일 112개 GT·출력의 비교

아래는 N>0인 110개 섹션의 동일 분모 비교다. 2개 N=0 섹션도 색인/원시 후보 결과에는 유지한다. **GT가 불완전한 영역을 포함하므로 순수 인식 품질이나 공식 성능 수치가 아니다.**

| 범위 | v4 오류/N | v4 CER | v5 A2 오류/N | v5 후보 CER |
|---|---:|---:|---:|---:|
| GS-01 | 1,694/6,100 | 27.77% | 739/6,100 | 12.11% |
| GS-02 | 6,290/9,903 | 63.52% | 5,843/9,903 | 59.00% |
| GS-03 | 2,090/7,540 | 27.72% | 1,131/7,540 | 15.00% |
| 전체 | 10,074/23,543 | 42.79% | 7,713/23,543 | **32.76%** |

전체 S/D/I: v4 1,986/2,036/6,052 → v5 647/1,525/5,541. 줄 대응 변경으로 총 2,361자(10.03%p)가 줄었다. 이를 전부 실제 읽기 순서 오류로 확정하지 않는다. 그룹 분리·병합 처리와 모호한 대응의 영향도 포함한다.

- GS-02_014/sec_1_04: 103/272(37.87%) → 7/272(2.57%). 원본 표의 열/행 순서 차이 사례에서 이전 수동 순서 진단 7자와 일치한다. 실제 기호·문자 차이는 남았다.
- GS-02_008/sec_1_04: 4,997 → 4,959자. v5에도 I=4,946자, S=9, D=4가 남는다. 순서 방식만으로 GT 범위 불일치를 해결할 수 없다는 증거다. v5 전체 오류의 약 64.29%가 이 섹션에 집중된다.
- GS-02_002/sec_1_01: 218 → 187자. 실제 회전 라벨 인식 오류와 GT 좌표형 텍스트 의심이 함께 있어 187자를 전부 OCR 오인식으로 분류하지 않는다.

### 검수 근거별 별도 비교

| 범위 | 섹션 수 | v4 | v5 후보 | 해석 |
|---|---:|---:|---:|---|
| 기존 사람 검수·알려진 범위 경고 없음 | 39 | 1,701/9,559 = 17.79% | 796/9,559 = 8.33% | 비교적 근거가 강한 부분 범위; v5 승인/완전성 재검증 전 |

39개 부분의 GS별 후보는 GS-01 279/2,508=11.12%, GS-02 270/4,114=6.56%, GS-03 247/2,937=8.41%다. 어려운 범위를 보류한 선택 편향이 있으므로 8.33%를 전체 112개의 성능으로 발표하지 않는다. v5 공식 범위 승인 완료 섹션은 아직 0개다.

## 4. 보존·재현과 후속 작업

[최종 A2 결과](candidate-a2/comparison.json)에 섹션별 S/D/I/N, 대응 줄 인덱스, 채택 경로, GT/출력/이미지/구현/명세 해시를 저장했다. 기존 동결·결과 **185개 파일**의 분석 전후 SHA-256 일치를 검증했다. 112개 이미지/출력 해시도 모두 일치한다. 원시 증거를 새로 생성하거나 수정하지 않았다. 과거 12개 v4 결과는 그대로다.

저장소 루트에서 사용한 Python 환경으로 실행한다. `--out`은 존재하지 않는 새 디렉터리여야 한다.

```powershell
python -m pytest tests/test_ocr_v5.py tests/test_baseline_ocr.py -q --basetemp .cache/pytest-v5-new
python docs/ai-baseline/analyses/ocr-v5-candidate-20261109/analyze.py --image-root C:/Users/Yeram/Documents/pixlate-server --out .cache/ocr-v5-reproduce-new
```

공식 전환 순서:

1. 18개 우선 대상의 원본 독립 전사·판독 가능성 재검수. 오류율을 참고해 제외하지 않는다.
2. OCR Text v3 초안에 보완·범위 결정·부모 GT 해시를 기록하고 사용자 승인 후 동결. AI만 검수한 53개의 승인/검수 범위도 명시한다.
3. 반복/유사 문구 대응과 비연속·다수 조각 병합의 합성 반례, 사람이 정한 대응쌍으로 v5 한계를 검증하고 알고리즘·범위를 승인한다.
4. 동일 입력·출력 경계·동결 GT·v5 버전으로 기존 출력 재평가. 공식 수치와 후보 수치를 분리하고 2·3차에도 동일 기준을 고정한다.

현재 v5를 공식 기준선으로 전환하지 않는다. 우선순위는 GT 완전성·평가 범위 정합성 복구이며 OCR 모델 개선은 그 후 분리된 실제 오인식 근거로 결정한다.
