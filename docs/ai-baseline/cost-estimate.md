# Baseline 비용 산정과 비과금 실행 준비

> 2026-10-27 정적 조사 / 2026-10-28 별도 승인 소규모 연결 점검 추가 · 공식 실측 승인 보류

2026-10-28 [측정 범위 변경](plan.md#이번-회차-측정-범위--pm-승인-완료)은 PM 승인이 완료됐다(2026-10-28 사용자 확인). 아래 산정 수치·권장 상한·테스트 기록은 변경 전 근거로 보존하며 무수정 조건으로 재산정하거나 새 실행 상한을 승인한 것이 아니다. N3 최초 선택에 따른 처리량과 사용자 수정 재렌더 제외의 비용 영향은 후속 점검하고 근거 없이 비용을 차감하지 않는다.

이 문서는 2단계 산정안과 3단계 정적 검증 결과다. 최신 확인 결과는 아래 **승인된 연결 점검 비용** 절을 우선한다. 비용·실행 승인은 계속 보류다. 평가 명세 1~5단계와 계산식은 변경하지 않는다. PM의 비용 승인·부담은 합의 완료이며, 아래 실제 실행 범위·상한은 사용자가 최종 승인한다. [예산 승인 원칙](protocols/v1/execution.md#ai-실행자의-사전-예산-승인)을 따른다.

측정 대상은 사용자 결정에 따라 **v1.0.1**로 변경했다. 전체 SHA·원격 태그·운영 이미지 기록의 대조와 현재 배포 확인의 한계는 [측정 계획](plan.md#측정-대상과-목적)을 따른다. 아래 v1.0.0 링크는 최초 산정 근거 이력이다. v1.0.1과의 전체 diff에서 AI 처리·모델 설정·분할 및 하류 호출 경로가 동일함을 확인했으므로 이를 유지하되, 브로커 안정화가 실패·대기 시간에 미칠 영향까지 동일하다고 가정하지 않는다.

## 근거와 확정 수준

2026-10-27 최초 조사 이력이다. 배포 SHA·SDK와 연결 점검의 후속 확인은 측정 계획 및 이 문서의 최신 절을 따른다.

- **확인값:** 로컬 `v1.0.0` 커밋은 `8b1536ffa6d784b31fe6ee2f4935f175922d7568`, 로컬 원격 추적 `origin/release/1.0.0`은 `a46b73d6455a7b5ead5bb21f90c0c9483ce85efa`다. 두 트리의 diff는 없다. 원격 갱신이나 실제 배포 SHA 확인을 수행한 것은 아니다. 배포 SHA가 다르면 실행 전 다시 대조한다.
- **확인값:** [고정 평가셋](protocols/v1/dataset.md)의 로컬 manifest와 원본 34개 SHA-256 모두 일치. 합계 높이 151,351px. 과거 하류 개발 입력본은 32원본·100섹션이며, 34장 공식 평가셋의 분할 결과나 최종 포함 목록이 아니다.
- **코드 근거:** 아래 제품 코드 설명은 작업 브랜치가 아닌 위 릴리즈 트리 기준이다. [설정](https://github.com/ai-pixlate/server/blob/8b1536ffa6d784b31fe6ee2f4935f175922d7568/pipeline/config/default.toml), [호출자](https://github.com/ai-pixlate/server/blob/8b1536ffa6d784b31fe6ee2f4935f175922d7568/pipeline/vlm.py), [N2 재시도](https://github.com/ai-pixlate/server/blob/8b1536ffa6d784b31fe6ee2f4935f175922d7568/app/flows/analysis.py), [하류 재시도](https://github.com/ai-pixlate/server/blob/8b1536ffa6d784b31fe6ee2f4935f175922d7568/app/flows/downstream.py)를 사용했다.
- **단가 확인:** Gemini Developer API Standard 유료 단가, USD, 2026-10-27 조회. `gemini-3.8-flash` 입력 $0.75/100만 토큰, 출력(사고 포함) $3.75/100만 토큰, 2026-12-31까지 적용. 무료 할당·캐시 할인·Batch 할인은 가정하지 않는다. 세금·환전·다른 계약 요율은 미산정. [공식 가격](https://ai.google.dev/gemini-api/docs/pricing)
- **미확인:** 실제 배포 SHA, 공식 실행 환경의 SDK 고정 버전, 현재 34장의 분할·OCR·최종 포함 수, 분할·번역의 대표 토큰 실측과 실패 요청 청구액. 조사한 실험 문서와 로컬 출력 목록에는 전체 제품 실행 비용을 완성할 번역 실측 근거가 없다. 이를 0으로 채우거나 다른 단계 평균으로 대체하지 않는다.

## 모델별 호출량과 토큰 산정

릴리즈의 유료 생성 모델은 다섯 단계 모두 `gemini-3.8-flash`다. 단계별 호출 수는 원본 34에 단순히 5를 곱하지 않는다. 한 섹션 안 여러 블록은 같은 요청에 포함될 수 있다.

| 단계 | 최초 실행 호출 수의 정의 | 과거 관찰값 및 토큰(입력 / 응답 / 사고) | 현재 34장에 대한 판단 |
|---|---|---|---|
| ① 섹션 분할 | `V`: 색 분할 후 1,500px 초과 구간의 창 수. 높이 h≤4,000이면 1, 그 이상이면 ceil((h−300)/3,700) | 이번 산정에 사용할 대표 토큰 합계 미확보 | V와 토큰 미확정 |
| ③ 병합·역할 | `M`: OCR 후 보낼 블록이 있는 섹션 수 | 최초 99요청, 성공 98의 139,594 / 18,528 / 97,414 | 평균은 성공 요청 기준. 실패 1회·별도 재실행 토큰은 합계 밖 |
| ③-1 판정 | `J`: 판정에 도달한 섹션 수(`call_scope=all`, 검사 항목 구성 유지) | 100요청, 383,474 / 61,159 / 91,207 | 동일 구성의 섹션 평균을 조건부 참고 가능 |
| ④ 라벨 | `L`: N3 포함 섹션 중 보낼 비공백 블록이 있는 섹션 수 | 99요청, 265,725 / 23,122 / 28,618 | 과거 개발 입력은 N3 공식 선택과 다름 |
| ⑧ 번역 | `T`: 번역 대상이 있는 섹션 수. 최초 섹션당 1요청 | 대표 실측 토큰 미확보 | 번역 대상·용어집·대체 지시·사고 사용량 미확정 |

근거: [병합 실측](../ai-experiments/2026-09-28_03-merge_llm-assist-check.md), [판정 실측](../ai-experiments/2026-09-29_03-1-judge_run-v1.md), [라벨 실측](../ai-experiments/2026-09-29_04-label_run-v1.md). 과거 결과의 품질 판정을 새 회차 정답으로 사용하지 않는다.

재시도 전 `N = V + M + J + L + T`다. 입력·출력·사고를 따로 합산해 `C = (0.75 × 입력 + 3.75 × (응답 + 사고)) / 1,000,000`으로 추정한다. 총토큰에 단일 단가를 곱하거나 사고 토큰을 누락하지 않는다.

| 과거 사용량의 현재 단가 환산 | 추정 USD | 성공 요청당 평균 USD |
|---|---:|---:|
| 병합 98성공 | 0.539478 | 0.00550488 |
| 판정 100성공 | 0.858978 | 0.00858978 |
| 라벨 99성공 | 0.39331875 | 0.00397292 |
| 합계 | **1.79177475** | 서로 다른 단계이므로 통합 평균 미사용 |

이 합계는 **과거 세 단계의 부분 비용**이며, 새 34장 전체 예상 비용·최저 비용·청구액이 아니다. 조건부 부분 견적은 `0.00550488M + 0.00858978J + 0.00397292L`이다. 예를 들어 세 단계가 각각 100회 성공하고 과거 평균을 따른다는 비교 시나리오라면 약 $1.807이지만, 분할·번역·실패·재시도가 빠져 있다. 100섹션을 34/32배 해 전체 호출량을 확정하지 않는다.

**전체 예상 비용은 현재 숫자로 확정할 수 없다:** `C전체 = C분할 + C병합 + C판정 + C라벨 + C번역 + C추가시도`. 분할·번역과 현재 처리량이 없는 상태에서 $5 또는 $10 등의 전체 예상액을 만들지 않는다.

## 재시도와 기술적 상한

N2 analyze·judge는 각각 자동 재시도 최대 2회(최대 3시도)다. analyze 재시도는 원본의 앞선 분할·OCR·병합도 다시 수행할 수 있다. 하류 label·translate 자동 재시도는 각 1회(최대 2시도)다. 번역 누적 `max_retry=2`를 자동 2회로 오독하지 않는다. 사용자 추가 재시도는 이번 기본 범위 밖이다. 과거 병합 실패 1/99를 전체 단계의 미래 실패율로 일반화하지 않는다.

분할 결과가 재시도 사이 변할 수 있으므로 최초 관찰 섹션 수에 배수만 곱한 값을 안전 상한으로 쓰지 않는다. 릴리즈 `section_split.enforce_min_section`의 최소 높이 200px에서, 이번 원본별 `max(1, floor(height/200))` 합계는 **739섹션**이다. 길이 1,501px 이상인 초기 구간의 창 수는 `floor(구간 높이/1501)` 이하이므로 원본별 합으로 **V≤85**다. 이는 실제 예상 분할량이 아닌 매우 느슨한 구조적 최대치다. 실패 시 원본 전체 한 섹션 fallback도 이 범위 안이다.

| 단계 | SDK 요청 수의 구조적 최대치(내부 BE 재시도 포함) |
|---|---:|
| 분할 | 3 × 85 = 255 |
| 병합 | 3 × 739 = 2,217 |
| 판정 | 3 × 739 = 2,217 |
| 라벨 | 2 × 739 = 1,478 |
| 번역 | 2 × 739 = 1,478 |
| 합계 | **7,645** |

근거가 된 릴리즈에는 번역문 LLM 규제 판정·임베딩 API 호출 경로를 포함하지 않는다. 작업 브랜치의 추가 모델 설정을 릴리즈 비용에 섞지 않는다. 배포 SHA·호출 경로·설정·사용자 재실행 범위가 바뀌면 위 상한은 재계산한다.

## 2단계 당시 균일 예약 방식의 계산 이력 — 승인안 아님

2단계 당시 [실행기](../../tools/baseline/be.py)의 `Meter`는 요청 전에 `(calls+1) × reserve_per_call ≤ max_amount`와 `calls+1 ≤ max_calls`를 검사한다. 실제 비용만큼 잔액을 돌려주는 방식이 아니다. 실패도 호출 수를 소비한다. SDK 내부 요청 재시도는 이 래퍼 아래에서 일어나므로 SDK 1회가 HTTP 여러 회면 호출 수와 예약 비용이 부족해진다.

로컬 `.venv`의 google-genai 2.24.0 소스에서는 `retry_options=None`이면 `stop_after_attempt(1)`이고 릴리즈 호출자는 해당 옵션을 설정하지 않는다. 다만 릴리즈 요구사항은 `google-genai>=1`이므로 측정 전용 환경에서도 같은 동작인지 고정·검증해야 한다. SDK 상수의 기본 5회만 보고 항상 5배라고 계산하지 않는다.

[공식 모델 한도](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash/)는 입력 1,048,576·출력 65,536토큰이다. **출력 한도에 과금 사고 토큰이 포함되고 SDK 요청당 HTTP 시도가 1회라는 조건을 실행 전에 검증할 경우**, 요청당 모델 최대치 환산은 `$1.032192`이며 올림 예약액은 `$1.04`다. 당시 균일 예약 방식의 계산은 다음과 같다. 현재 승인 후보로 사용하지 않는다.

| 설정 | 조건부 후보 | 의미 |
|---|---:|---|
| `max_calls` | 7645 | 34장·공식 1회·릴리즈 내부 자동 재시도만 포함한 구조적 상한 |
| `reserve_per_call` | 1.04 USD | 평균 비용이 아닌 모델 최대 토큰량 기반 예약액 |
| `max_amount` | 7950.80 USD | 7645 × 1.04. 실제 지출 예측이 아님 |
| `currency` | USD | 세금·환전 별도 |
| `basis` | 본 문서·릴리즈 SHA·가격 확인일·SDK/과금 한도 검증 기록 | 검증 전 실행 설정에 적용하지 않음 |

**권장:** 위 $7,950.80을 곧바로 승인받아 실행하지 않는다. 이는 기존 균일 예약 방식으로 확보 가능한 느슨한 상한을 드러내는 계산이다. 3단계에서 입력·출력·SDK 시도 상한을 더 좁게 검증하고 예산 중단을 시험한 뒤, 사용자가 수용할 실용적 상한을 다시 제시한다. 평균 요청비를 `reserve_per_call`로 쓰면 상한을 보장하지 못한다. 지금은 낮고 근거 있는 전체 실행 상한을 제안할 정보가 부족하다. 총 예상 비용과 권장 승인 상한의 산정은 **일부 완료**다.

사용자가 최종 승인할 묶음은 **배포 SHA 고정, GS-01~03 34장·미국·영어·원본별 공식 생성 1회, 릴리즈 내부 자동 재시도, 포함할 사전 점검의 정확한 입력·횟수, N3·N5 개입 범위, API 호출 상한·USD 금액 상한**이다. 사전 점검·사용자 추가 재생성은 위 7,645회에 포함하지 않았다. Codex 검수는 평가 API 없이 진행한다. 범위 또는 상한 초과 예상 시 추가 호출을 중단하고 기존 결과·미완료 목록을 보존해 사용자에게 재승인받는다. PM에게 재승인을 요청하지 않는다.

## 별도 비용과 실행시간

| 항목 | 비용·시간 해석 |
|---|---|
| 로컬 PaddleOCR·LaMa | 제품 LLM API 청구와 별도. 전기·감가·설치·보관 비용은 미산정이며 0원으로 확정하지 않음 |

[CPU OCR 초기 기록](../ai-experiments/2026-09-23_02-ocr_1a-probe.md)은 섹션당 9~28초로, 동일 속도의 100섹션이라는 조건에서 OCR만 15~46.7분이다. [LaMa 100섹션 기록](../ai-experiments/2026-09-30_06-inpaint_run100-v1.md)은 초기화 포함 85.4초이나 과거 Linux GPU 조건이다.

따라서 **판정+라벨+OCR만의 100섹션 조건부 참고시간은 약 41~73분**이다. 병합·분할·번역·초기화·수집·재시도·사람 검수를 제외했으며 34장 완료 예상시간이 아니다. 긴 원본 타일 OCR의 CPU 비용, Windows LaMa, 분할 SDK 기본 timeout, 429/네트워크 대기와 사람 검수 시간이 미확인이라 전체 종료시각은 확정할 수 없다.

완료 목표 **2026-11-12**까지 16일이다. 일정 제안은 10/28~11/2에 아래 3단계와 기준 자료 준비, 11/3까지 범위·상한 확정 및 사용자 승인, 11/4~8 승인된 실행·Codex 검수, 11/9~11 사람 검수·집계·백업, 11/12 완료 확인이다. 이는 작업 배치 제안이며 소요시간 실측이나 담당자 일정 확정이 아니다. 승인·환경·사람 검수 준비가 지연되면 목표일을 보장할 수 없다.

## 3단계 코드 구현·환경 준비에 넘길 항목

1. 배포 SHA·설정·참조 자료·SDK 버전 고정. 분할·번역의 기존 원시 사용량 기록을 추가 확보하고, 없으면 미확인 상태 유지. 모델 호출 없는 준비와 유료 사전 점검을 분리한다.
2. 전용 Windows 환경의 CPU OCR·GPU LaMa·로컬 PostgreSQL·폰트·사전·용어집·해시 확인. 설치·import만으로 실제 처리 가능성을 확정하지 않는다.
3. 가짜 요청으로 예산 직전/초과/실패·SDK 재시도·기록 실패의 중단 보장 검증. 제품 동작을 바꾸지 않는 입력/출력 비용 상한 검증과 필요 시 측정 도구의 예약·기록 보완 범위를 먼저 정한다. 2단계에서는 도구를 수정하지 않았으며, 3단계 변경은 아래에 기록한다.
4. 기존 도구의 지표 1~7·238행·자동 기본 선택 및 구형 출력 구조를 최신 H01~H05·체크포인트·사람 검수·회차 파일 구조와 대조해 보완한다. 기존 도구를 공식 최신 프로토콜 구현 완료로 간주하지 않는다. 중단 시 `started.json` 때문에 자동 재실행할 수 없으므로 증거 보존·미완료 관리도 준비한다.
5. 사전 점검 범위와 낮춘 실용적 예산 상한을 사용자에게 제시한다. 승인 전 모델 로딩·추론·API·실측을 하지 않는다. [확정된 PM 검수 조건과 표본 추천안](protocols/v1/evaluation.md#7단계-사람-검수-프로토콜)을 구분하고 미채택 표본 안·기준 자료 동결 여부를 별도 확인한다.


## 3단계 추가 검증 — 비용·실행 승인 보류

### 호출량을 좁힌 근거

`pipeline/samples/local/merge-input-v1`의 32개 `split_debug.json`과 `split.json`을 읽은 결과 **분할 API 48회·110섹션**이었다. 앞의 100섹션은 하류 개발 선택본이며 분할 전체가 아니다. [정적 산정 도구](../../tools/baseline/estimate.py)는 파일 해시와 계산을 반환하며 API를 사용하지 않는다.

누락된 GS-02_002(높이 2,117), GS-03_016(403)의 구조적 추가 한도는 12섹션·분할 1회다. **과거 32장의 분할이 유지되고 각 섹션이 하류 네 단계를 모두 통과한다는 비교 시나리오**에서는 다음과 같다. 실제 현재 출력의 하한·완료 보장은 아니다.

| 항목 | 조건부 호출량 | 비용 근거 |
|---|---:|---|
| 분할 | 48~49 | 사용량 원시 기록이 없어 금액 미확정 |
| 병합·판정·라벨 각각 | 110~122 | 과거 성공 평균을 적용한 세 단계 합계 약 $1.99~$2.20 |
| 번역 | 110~122 | 실제 용어집·대체 지시·응답·사고 토큰 미확정 |
| 최초 합계 | **488~537** | 위 부분 비용 + 분할·번역·실패 비용 |
| 모든 내부 재시도 포함 | **최대 1,367** | 3×49 + (3+3+2+2)×122. 분할 변화 시 이 범위를 넘을 수 있음 |

번역 100섹션의 저장 블록으로 모든 블록을 대상으로 조립한 기본 요청은 프롬프트 포함 합계 306,039 UTF-8바이트(용어집·대체 지시 제외)였다. 원문 문자 수는 26,310이다. **바이트·문자는 토큰이 아니며**, 이를 토큰 또는 전체 비용으로 환산하지 않는다. 사고 토큰은 응답 문자열만으로 복원할 수 없다. 따라서 전체 예상액의 근거 있는 점 추정은 여전히 불가능하다.

### 권장 중단 상한 제안

완료 비용 예측 대신 **최초 승인 묶음의 중단 상한 $50**을 제안한다. 근거는 조건부 최대 최초 분할+번역 171회의 출력 한도 환산 `$42.02496`(171×65,536×$3.75/100만)과 관찰 평균 기반 세 단계 약 $2.20, 나머지 약 $5.77의 여유다. 이 조합은 입력·실패·재시도 전체의 보장 상한이 아니며 여유액은 실행 정책 제안이다. 실패·사용량 미확인은 호출당 예약액을 소비하므로 완료 전 중단될 수 있다. **$50이면 34장 완료된다는 의미가 아니다.** 사용자가 이를 승인하지 않은 현재는 적용하지 않는다.

| 설정 | 새 제안 | 적용 조건 |
|---|---:|---|
| max_calls | 1367 | 위 조건부 재시도 범위에서 중단. 실제 분할 증가 시 추가 실행 중지 |
| max_amount | 50 USD | 단가 추정 소비액+다음 예약액 기준 중단, 세금·환전 별도 |
| reserve_per_call | 1.04 USD | 요청당 모델 한도 $1.032192의 올림값. 평균 비용 아님 |
| settle_usage | true | 확인된 입력·응답·사고 토큰만 정산, 실패·누락은 예약 유지 |
| input_per_million / output_per_million | 0.75 / 3.75 USD | gemini-3.8-flash, 가격 확인일 기록 |
| sdk_attempts | 1 | 전용 환경 google-genai 2.31.0의 retry_options=None→stop_after_attempt(1) 소스 확인 |

[공식 사고 토큰 안내](https://ai.google.dev/gemini-api/docs/thinking/)와 모델 한도에서 출력 한도에 사고가 포함됨을 확인했다. 실행 직전 배포 모델·SDK·실제 요율이 동일한지 다시 고정해야 한다. $7,950.80과 7,645회는 이전 구조적 계산 이력이며 승인 상한으로 사용하지 않는다.

[예산 모듈](../../tools/baseline/be.py)은 사용량 확인 후 예약 잔액을 돌려주고, 요청 전 금액/횟수 초과·기록 실패 시 추가 호출을 막는다. 이미 진행된 요청을 사후 취소할 수는 없으므로 예약 한도 검증이 전제다. 재개 시 예산 초기화를 허용하지 않으며 실제 실행 연결은 아직 보류다.

### 남은 차단 사항과 시간

1. 운영 버전은 운영자 확인, 격리 checkout은 직접 확인 완료. 서버·GPU 워커별 직접 검증 여부는 구분하며 로컬 환경 차이와 재현 조건을 실행 기록에 고정한다.
2. [34장 기준 자료 초안](runs/reference-preparation-20261027/README.md)의 PM 확인·동결, 상품 메타데이터·N3/N5 필수 확인 담당자·A표본 안 채택 확인. 실제 청구·fallback 추가 증거는 실측 후 확보하며 확인 전 미측정으로 유지한다.
3. 사용자 최종 승인: 고정 34장·미국/영어·원본별 공식 1회, 내부 재시도만, N3/N5 개입 범위, 제안 1,367회/$50 상한과 중단 정책. 추가 유료 사전 점검·사용자 재생성은 포함하지 않는다. PM 재승인 요청 없음.

110~122섹션에 과거 판정·라벨·CPU OCR 속도를 적용한 **부분 시간은 약 45~89분**이다. 분할·번역·병합·초기화·재시도·사람 검수가 빠져 있어 전체 예상시간으로 쓰지 않는다. 11월 12일 목표는 유지하되 환경 조건 동결·기준 자료와 검수 준비·사용자 최종 실행 승인이 차단 사항이다. 실제 모델 호출·유료 테스트·공식 실측은 하지 않았다.


### 남은 작업 후속 검증 — 2026-10-27

사용자 결정으로 **상품별 1작업, GS-01~03 총 3작업**에 2·14·18장씩 연결한다. H01~H05의 원본/기준 단위와 계산식은 변경하지 않는다. OP01은 실제 생성된 상품 작업을 분모로 한다. N2 재시도는 해당 상품의 여러 원본을 다시 처리할 수 있으므로 원본별 독립 재시도처럼 해석하지 않는다.

- 위 488~537회와 1,367회는 과거 분할 유지·모든 섹션 하류 처리의 조건부 시나리오로 유지한다. 작업 수가 3개가 됐다고 이를 3/34배로 줄이지 않는다. 실제 분할·번역 토큰의 새 실측은 하지 않았으므로 전체 비용의 점 추정을 추가하지 않는다.
- 권장 검토 후보는 여전히 **$50·1,367회·호출당 $1.04 예약 후 사용량 정산**이다. 승인값이 아니다. 세 작업은 Meter 하나를 공유하고, 실패·토큰 미확인은 예약액을 유지한다. 추가 모델 호출 없이 한도를 초과하면 중단한다.
- 원본 34장·자산 31개 해시 재확인 통과. v1.0.1 격리 사본은 깨끗한 상태다.
- 전용 환경 `pip check` 통과. 운영 API constraints 72개 중 59개 동일, 13개 차이: boto3/botocore, certifi, FastAPI/Starlette, google-auth/google-genai, NumPy, Pillow, pluggy, PyYAML, SQLAlchemy, Windows 미설치 uvloop. 운영 API 목록은 학교 GPU 환경의 고정 목록이 아니다. 의존성을 일괄 변경하지 않았으며 로컬 버전 목록과 비교 결과를 `.cache/baseline-stage3-followup/environment.json`에 보존했다.
- Pillow 13.0.0과 운영 기록 12.3.0은 렌더러 버전도 다르므로 동일 운영 렌더 환경이라고 표현하지 않는다. 동일 Windows 조건의 후속 비교를 위해 버전·폰트·설정을 동결해야 한다. google-genai 2.31.0과 운영 기록 2.29.0의 차이도 기록한다.
- Baseline 합성 테스트 **98개 통과**. v1.0.1 사본의 렌더·폰트·브로커 테스트 **24개 통과, DB 필요 1개 건너뜀**. 추가로 실제 로컬 PostgreSQL과 가짜 AI·S3 URL·Redis 대역을 사용한 제품 하류 통합 시험 **6개 통과**. 각 시험은 별도 임시 DB를 생성·제거했고 기존 평가 DB는 변경하지 않았다. 최초 시험의 S3 서명 자격 증명 누락은 시험 대역을 연결해 해소했다. 모델을 로딩하거나 호출하지 않았다. 이 결과만으로 실제 OCR·LaMa·외부 API 성공이나 새 수집 연결의 전체 실측 성공을 보장하지 않는다.

다음은 범위 변경 전 구현의 확인 흐름 기록이다. 이번 회차에는 편집하지 않고 필수 확인만 수행하도록 후속 도구 보완이 필요하다. 사람 검수는 N3 전체 섹션 선택, 최초 미리보기 보존 후 N5 문구·경고 확인 순서로 수행한다. 사람이 응답 파일을 제출하기 전 자동 진행하지 않으며 수정 0건도 명시적인 확인이 필요하다. 사용자 최종 비용·실행 승인은 계속 보류다.


## 2026-10-28 최종 비과금 점검

소규모 연결 점검 전 이력이다. 이후 환경 정비·실제 연결·비용 기록은 [승인된 연결 점검 비용](#승인된-연결-점검-비용)과 연결된 실행 점검표를 우선한다.

비용·실행 승인은 계속 보류다. 무수정 회차는 H01~H04를 측정하고 H05는 별도 서비스 평가로 남긴다. 기존 공식 원본별 1회 원칙과 내부 자동 재시도 기록을 유지한다. 앞의 개발·시험 이력은 보존하며 현재 환경과 검증 결과는 [최종 점검표](protocols/v1/execution.md#baseline-실행-전-최종-점검표)를 따른다.

### 추가 비용 근거와 제안

- 로컬 `pipeline/samples/local`의 분할 관련 JSON 512개를 추가 검색했으나 `prompt_token_count`, `thoughts_token_count`, `usage_metadata`가 있는 파일은 없었다. 번역 실측 파일도 해당 로컬 트리에서 발견하지 못했다. handoff 예시·합성 자료를 실측으로 사용하지 않는다. 범위 밖 기록의 존재까지 부정하는 것은 아니다.
- 기존 32장 split_debug에서 **48회·110섹션**을 재확인했다. 누락 2장의 구조적 추가 한도는 1회·12섹션이다. 과거 분할 유지·모든 섹션 하류 통과라는 조건의 최초 호출 **488~537회**, 내부 재시도 포함 **1,367회**는 그대로다. 이번 무수정 조건에서는 임의 재선택·번역 편집·사용자 재렌더를 추가하지 않는다. AI의 실제 제외량/새 분할 결과가 없으므로 임의로 호출량을 할인하지 않는다.
- 병합·판정·라벨의 관찰 평균으로 설명 가능한 부분은 **$1.99~$2.20**뿐이다. 분할·번역 및 실패의 토큰이 없어 전체 비용의 점 추정/통계적 예상 범위는 여전히 미확정이다. 문자·바이트를 토큰으로 환산하지 않았다.
- **권장 중단 후보는 max_amount=$50, max_calls=1,367, reserve_per_call=$1.04, settle_usage=true를 유지한다. 승인된 값이 아니다.** $50은 완료 예상액이 아니라 최초 승인 묶음의 정책적 중단 한도다. 기존 근거(조건부 분할·번역 171회의 출력 한도 비용 $42.02496 + 세 단계 관찰 평균 약 $2.20 + 약 $5.77 여유)를 보존한다. 입력·실패·재시도까지 모두 보장하지 않으므로 34장 완료 전 중단될 수 있다.
- 사용 단가는 **기존 2026-10-27 문서에 기록된** 입력 $0.75/M·출력/사고 $3.75/M이다. 이번에는 외부 조회/API 없이 로컬 증거만 확인했으므로 현재 요율·모델 한도의 재확인으로 표시하지 않는다. 설치 SDK 2.31.0의 retry_options 미지정→1회 시도 소스를 재확인했다. 정산은 입력·응답·사고 토큰이 모두 확인된 경우만 하며 누락/실패는 예약액을 유지한다. 실제 청구액과 추정 소비액은 구분한다.

기존 **$7,950.80은 승인 후보로 사용하지 않는다.** Codex 채팅 평가에 별도 LLM 평가 API 비용을 더하지 않는다. 로컬 OCR·LaMa 자원 비용과 PM의 비교 이미지 4장 제작 비용도 제품 API 비용에 합산하지 않는다.

### 시간·실행 전 조건

기존 판정·라벨·OCR의 부분 시간 **45~89분**은 전체 소요시간이 아니다. 분할·번역·병합·초기 로딩·재시도·필수 사람 확인이 미확정이므로 총 실행시간을 확정하지 않는다. 11월 12일 완료 목표에서 기준 자료 동결, 확인 담당자 확보, 환경 차이 수용, 승인 후 실제 연결/장치 문제 발견이 일정 위험이다.

사용자가 최종 승인할 항목은 (1) v1.0.1/미국·영어/3상품·34장/상품별 1작업/공식 생성 1회/H01~H04·N3/N5 무수정 확인 범위, (2) Windows 고정 환경과 운영 차이 수용, (3) 비용·호출·예약 상한과 사용 단가·모델 한도 근거, (4) 필요한 연결/추론 확인을 포함한 실행 범위다. N3/N5 확인 담당자는 PM의 평가 검수 역할과 구분해 지정해야 한다. 한도/범위 초과 시 중단하고 별도 승인을 받는다. PM 기준 자료 PR #93 검수·동결, 승인 증거와 환경 lock을 연결한 실제 회차 구성 전에는 공식 실측하지 않는다.


## 승인된 연결 점검 비용

2026-10-28 사용자 승인 범위는 별도 테스트 입력의 OCR·LaMa·Gemini 연결 점검, 외부 유료 API 총 $2 이내다. 공식 34장 실행 승인은 포함하지 않는다. [연결 점검 기록](../ai-experiments/2026-10-28_baseline-connection-check.md)에 전체 조건·원시 증거 위치를 보존했다.

실제 Gemini 전송은 **1회**(SDK/전송 재시도 없음), 릴리즈 번역 설정 gemini-3.8-flash·temperature=0·timeout=60초다. 입력 608·응답 27·사고 250 = **885토큰**, `(608×0.75 + (27+250)×3.75)/1,000,000` = **추정 $0.00149475**다. 실제 청구 금액은 미확인이다. 로컬 OCR·LaMa 점검에는 외부 모델 API 비용이 없으며 전력/장비 비용은 별도다.

[공식 요율](https://ai.google.dev/gemini-api/docs/pricing)과 [모델 한도](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash)를 2026-10-28 재확인했다. 단일 요청의 토큰 한도 기준 비용은 $1.032192로 $2보다 작다. 요청 전 $1.04 예약→실제 응답 토큰으로 정산했고 두 번째 요청은 호출 전에 차단했다. 입력 오류로 API 진입 전에 끝난 테스트 스크립트의 첫 시도는 유료 전송 0회로 별도 기록했다. 실제 사용량 원장은 `gemini-corrected-usage.jsonl`이며 초기 오류 후 로컬 금지 콜백을 검사한 `gemini-usage.jsonl`은 API 지출로 합산하지 않는다.

공식 34장은 **최초 488~537회 / 중단 후보 1,367회·$50 / 호출당 예약 $1.04** 제안을 유지하며 아직 승인되지 않았다. 이번 1블록 번역비를 34장에 곱하지 않는다. 대표성 있는 분할·번역 토큰 자료가 없으므로 전체 기대 비용을 확정하지 않는다. 실제 호출 SDK를 운영과 같은 2.29.0으로 정비하고 재시도 없음도 확인했지만, 작은 텍스트 입력 성공은 전체 이미지 단계의 성공/비용 보장이 아니다. $7,950.80은 승인 후보로 사용하지 않는다.
