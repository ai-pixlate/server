# Baseline 2단계 — 예상 비용과 실행 승인 준비

> 2026-10-27 정적 조사 · 실제 모델 호출·실측 없음 · 사용자 실행 승인 전

이 문서는 실행 준비의 2단계 산정안이다. 평가 명세 1~5단계와 계산식은 변경하지 않는다. PM의 비용 승인·부담은 합의 완료이며, 아래 실제 실행 범위·상한은 사용자가 최종 승인한다. [예산 승인 원칙](protocols/v1/execution.md#ai-실행자의-사전-예산-승인)을 따른다.

## 근거와 확정 수준

- **확인값:** 로컬 `v1.0.0` 커밋은 `8b1536ffa6d784b31fe6ee2f4935f175922d7568`, 로컬 원격 추적 `origin/release/1.0.0`은 `a46b73d6455a7b5ead5bb21f90c0c9483ce85efa`다. 두 트리의 diff는 없다. 원격 갱신이나 실제 배포 SHA 확인을 수행한 것은 아니다. 배포 SHA가 다르면 실행 전 다시 대조한다.
- **확인값:** [고정 평가셋](protocols/v1/dataset.md)의 로컬 manifest와 원본 34개 SHA-256 모두 일치. 합계 높이 151,351px. 과거 하류 개발 입력본은 32원본·100섹션이며, 34장 공식 평가셋의 분할 결과나 최종 포함 목록이 아니다.
- **코드 근거:** 아래 제품 코드 설명은 작업 브랜치가 아닌 위 릴리즈 트리 기준이다. ## 모델별 호출량과 토큰 산정

릴리즈의 유료 생성 모델은 다섯 단계 모두 `gemini-3.8-flash`다. 단계별 호출 수는 원본 34에 단순히 5를 곱하지 않는다. 한 섹션 안 여러 블록은 같은 요청에 포함될 수 있다.

| 단계 | 최초 실행 호출 수의 정의 | 과거 관찰값 및 토큰(입력 / 응답 / 사고) | 현재 34장에 대한 판단 |
|---|---|---|---|
| ① 섹션 분할 | `V`: 색 분할 후 1,500px 초과 구간의 창 수. 높이 h≤4,000이면 1, 그 이상이면 ceil((h−300)/3,700) | 이번 산정에 사용할 대표 토큰 합계 미확보 | V와 토큰 미확정 |
| ③ 병합·역할 | `M`: OCR 후 보낼 블록이 있는 섹션 수 | 최초 99요청, 성공 98의 139,594 / 18,528 / 97,414 | 평균은 성공 요청 기준. 실패 1회·별도 재실행 토큰은 합계 밖 |
| ③-1 판정 | `J`: 판정에 도달한 섹션 수(`call_scope=all`, 검사 항목 구성 유지) | 100요청, 383,474 / 61,159 / 91,207 | 동일 구성의 섹션 평균을 조건부 참고 가능 |
| ④ 라벨 | `L`: N3 포함 섹션 중 보낼 비공백 블록이 있는 섹션 수 | 99요청, 265,725 / 23,122 / 28,618 | 과거 개발 입력은 N3 공식 선택과 다름 |
| ⑧ 번역 | `T`: 번역 대상이 있는 섹션 수. 최초 섹션당 1요청 | 대표 실측 토큰 미확보 | 번역 대상·용어집·대체 지시·사고 사용량 미확정 |

근거: [병합 실측](../ai-experiments/2026-09-28_03-merge_llm-assist-check.md), [판정 실측](../ai-experiments/2026-09-29_03-1-judge_run-v1.md), [라벨 실측](../ai-experiments/2026-09-29_04-label_run-v1.md). 과거 결과의 품질 판정을 새 회차 정답으로 사용하지 않는다.

재시도 전 `N = V + M + J + L + T`다. 입력·출력·사고를 따로 합산해 `C = (0.75 × 입력 + 3.75 × (응답 + 사고)) / 1,000,000`으로 추정한다. 총토큰에 단일 단가를 곱하거나 사고 토큰을 누락하지 않는다.

| 과거 사용량의 현재 단가 환산 | 추정 USD | 성공 요청당 평균 USD |
|---|---:|---:|
| 병합 98성공 | 0.539478 | 0.00550488 |
| 판정 100성공 | 0.858978 | 0.00858978 |
| 라벨 99성공 | 0.39331875 | 0.00397292 |
| 합계 | **1.79177475** | 서로 다른 단계이므로 통합 평균 미사용 |

이 합계는 **과거 세 단계의 부분 비용**이며, 새 34장 전체 예상 비용·최저 비용·청구액이 아니다. 조건부 부분 견적은 `0.00550488M + 0.00858978J + 0.00397292L`이다. 예를 들어 세 단계가 각각 100회 성공하고 과거 평균을 따른다는 비교 시나리오라면 약 $1.807이지만, 분할·번역·실패·재시도가 빠져 있다. 100섹션을 34/32배 해 전체 호출량을 확정하지 않는다.

**전체 예상 비용은 현재 숫자로 확정할 수 없다:** `C전체 = C분할 + C병합 + C판정 + C라벨 + C번역 + C추가시도`. 분할·번역과 현재 처리량이 없는 상태에서 $5 또는 $10 등의 전체 예상액을 만들지 않는다.

## 재시도와 기술적 상한

N2 analyze·judge는 각각 자동 재시도 최대 2회(최대 3시도)다. analyze 재시도는 원본의 앞선 분할·OCR·병합도 다시 수행할 수 있다. 하류 label·translate 자동 재시도는 각 1회(최대 2시도)다. 번역 누적 `max_retry=2`를 자동 2회로 오독하지 않는다. 사용자 추가 재시도는 이번 기본 범위 밖이다. 과거 병합 실패 1/99를 전체 단계의 미래 실패율로 일반화하지 않는다.

분할 결과가 재시도 사이 변할 수 있으므로 최초 관찰 섹션 수에 배수만 곱한 값을 안전 상한으로 쓰지 않는다. 릴리즈 `section_split.enforce_min_section`의 최소 높이 200px에서, 이번 원본별 `max(1, floor(height/200))` 합계는 **739섹션**이다. 길이 1,501px 이상인 초기 구간의 창 수는 `floor(구간 높이/1501)` 이하이므로 원본별 합으로 **V≤85**다. 이는 실제 예상 분할량이 아닌 매우 느슨한 구조적 최대치다. 실패 시 원본 전체 한 섹션 fallback도 이 범위 안이다.

| 단계 | SDK 요청 수의 구조적 최대치(내부 BE 재시도 포함) |
|---|---:|
| 분할 | 3 × 85 = 255 |
| 병합 | 3 × 739 = 2,217 |
| 판정 | 3 × 739 = 2,217 |
| 라벨 | 2 × 739 = 1,478 |
| 번역 | 2 × 739 = 1,478 |
| 합계 | **7,645** |

근거가 된 릴리즈에는 번역문 LLM 규제 판정·임베딩 API 호출 경로를 포함하지 않는다. 작업 브랜치의 추가 모델 설정을 릴리즈 비용에 섞지 않는다. 배포 SHA·호출 경로·설정·사용자 재실행 범위가 바뀌면 위 상한은 재계산한다.

## 예산 제한 설정 제안과 승인 대상

[기존 실행기](../../tools/baseline/be.py)의 `Meter`는 요청 전에 `(calls+1) × reserve_per_call ≤ max_amount`와 `calls+1 ≤ max_calls`를 검사한다. 실제 비용만큼 잔액을 돌려주는 방식이 아니다. 실패도 호출 수를 소비한다. SDK 내부 요청 재시도는 이 래퍼 아래에서 일어나므로 SDK 1회가 HTTP 여러 회면 호출 수와 예약 비용이 부족해진다.

로컬 `.venv`의 google-genai 2.24.0 소스에서는 `retry_options=None`이면 `stop_after_attempt(1)`이고 릴리즈 호출자는 해당 옵션을 설정하지 않는다. 다만 릴리즈 요구사항은 `google-genai>=1`이므로 측정 전용 환경에서도 같은 동작인지 고정·검증해야 한다. SDK 상수의 기본 5회만 보고 항상 5배라고 계산하지 않는다.

[공식 모델 한도](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash/)는 입력 1,048,576·출력 65,536토큰이다. **출력 한도에 과금 사고 토큰이 포함되고 SDK 요청당 HTTP 시도가 1회라는 조건을 실행 전에 검증할 경우**, 요청당 모델 최대치 환산은 `$1.032192`이며 올림 예약액은 `$1.04`다. 이를 적용한 기존 도구의 보수적 설정 후보는 다음과 같다.

| 설정 | 조건부 후보 | 의미 |
|---|---:|---|
| `max_calls` | 7645 | 34장·공식 1회·릴리즈 내부 자동 재시도만 포함한 구조적 상한 |
| `reserve_per_call` | 1.04 USD | 평균 비용이 아닌 모델 최대 토큰량 기반 예약액 |
| `max_amount` | 7950.80 USD | 7645 × 1.04. 실제 지출 예측이 아님 |
| `currency` | USD | 세금·환전 별도 |
| `basis` | 본 문서·릴리즈 SHA·가격 확인일·SDK/과금 한도 검증 기록 | 검증 전 실행 설정에 적용하지 않음 |

**권장:** 위 $7,950.80을 곧바로 승인받아 실행하지 않는다. 이는 기존 균일 예약 방식으로 확보 가능한 느슨한 상한을 드러내는 계산이다. 3단계에서 입력·출력·SDK 시도 상한을 더 좁게 검증하고 예산 중단을 시험한 뒤, 사용자가 수용할 실용적 상한을 다시 제시한다. 평균 요청비를 `reserve_per_call`로 쓰면 상한을 보장하지 못한다. 지금은 낮고 근거 있는 전체 실행 상한을 제안할 정보가 부족하다. 총 예상 비용과 권장 승인 상한의 산정은 **일부 완료**다.

사용자가 최종 승인할 묶음은 **배포 SHA 고정, GS-01~03 34장·미국·영어·원본별 공식 생성 1회, 릴리즈 내부 자동 재시도, 포함할 사전 점검의 정확한 입력·횟수, N3·N5 개입 범위, API 호출 상한·USD 금액 상한**이다. 사전 점검·사용자 추가 재생성은 위 7,645회에 포함하지 않았다. Codex 검수는 평가 API 없이 진행한다. 범위 또는 상한 초과 예상 시 추가 호출을 중단하고 기존 결과·미완료 목록을 보존해 사용자에게 재승인받는다. PM에게 재승인을 요청하지 않는다.

## 별도 비용과 실행시간

| 항목 | 비용·시간 해석 |
|---|---|
| 로컬 PaddleOCR·LaMa | 제품 LLM API 청구와 별도. 전기·감가·설치·보관 비용은 미산정이며 0원으로 확정하지 않음 |
| Codex 채팅 검수·기준 자료 | 별도 LLM 평가 API 호출·비용 없음. 기존 채팅 이용료 배분·검수 시간은 미산정 |
| PM 일반 LLM 비교 4장 | PM 생성 모델·사용량·금액 별도 확보. 제품 34장 비용에 합산하지 않음. 제공 결과만 H01·H02·H04로 비교 |
| OI-54·NFR-15 | 별도 과제. 이번 실행 범위·예산에 포함하지 않음 |

과거 판정 100호출 합계 958초, 라벨 99호출 약 10분이다. 병합 성공 98회의 중앙값 4.8초·P90 10.2초·최대 47.4초를 합계나 미래 시간 보장으로 쓰지 않는다. [CPU OCR 초기 기록](../ai-experiments/2026-09-23_02-ocr_1a-probe.md)은 섹션당 9~28초로, 동일 속도의 100섹션이라는 조건에서 OCR만 15~46.7분이다. [LaMa 100섹션 기록](../ai-experiments/2026-09-30_06-inpaint_run100-v1.md)은 초기화 포함 85.4초이나 과거 Linux GPU 조건이다.

따라서 **판정+라벨+OCR만의 100섹션 조건부 참고시간은 약 41~73분**이다. 병합·분할·번역·초기화·수집·재시도·사람 검수를 제외했으며 34장 완료 예상시간이 아니다. 긴 원본 타일 OCR의 CPU 비용, Windows LaMa, 분할 SDK 기본 timeout, 429/네트워크 대기와 사람 검수 시간이 미확인이라 전체 종료시각은 확정할 수 없다.

완료 목표 **2026-11-12**까지 16일이다. 일정 제안은 10/28~11/2에 아래 3단계와 기준 자료 준비, 11/3까지 범위·상한 확정 및 사용자 승인, 11/4~8 승인된 실행·Codex 검수, 11/9~11 사람 검수·집계·백업, 11/12 완료 확인이다. 이는 작업 배치 제안이며 소요시간 실측이나 담당자 일정 확정이 아니다. 승인·환경·사람 검수 준비가 지연되면 목표일을 보장할 수 없다.

## 3단계 코드 구현·환경 준비에 넘길 항목

1. 배포 SHA·설정·참조 자료·SDK 버전 고정. 분할·번역의 기존 원시 사용량 기록을 추가 확보하고, 없으면 미확인 상태 유지. 모델 호출 없는 준비와 유료 사전 점검을 분리한다.
2. 전용 Windows 환경의 CPU OCR·GPU LaMa·로컬 PostgreSQL·폰트·사전·용어집·해시 확인. 설치·import만으로 실제 처리 가능성을 확정하지 않는다.
3. 가짜 요청으로 예산 직전/초과/실패·SDK 재시도·기록 실패의 중단 보장 검증. 제품 동작을 바꾸지 않는 입력/출력 비용 상한 검증과 필요 시 측정 도구의 예약·기록 보완 범위를 먼저 정한다. 이번 작업에서는 도구를 수정하지 않는다.
