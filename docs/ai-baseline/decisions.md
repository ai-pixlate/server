# 측정 결정

> 상태: 기존 지표 정의 유지 · 2026-10-28 회차 범위 변경 PM 승인 완료(2026-10-28 사용자 확인) · 공식 생성 미실행 · 기준 자료 동결 후 공식 채점

이 문서는 최신 입력본과 충돌하지 않는 기존 실행 결정을 보존한다. 명세 전체의 확정이나 PM·실측 승인을 뜻하지 않는다. 지표와 집계는 [최신 집계 명세](protocols/v1/aggregation.md)를 따른다.

## 목적

- 이후 고도화의 비교 기준이 되는 단계별 품질을 확보한다.
- 최종 발표에서 품질 개선 노력과 결과를 설명할 근거를 확보한다.

## 2026-10-28 자동 파이프라인 평가 범위 변경

사용자가 이번 v1.0.1 회차에서 사용자 편집을 제외하기로 결정했다. 기존 PM 승인 명세의 H05·사용자 수정 효과 측정 범위에서 변경됐으며, 사용자가 2026-10-28 해당 범위의 PM 승인 완료를 확인했다. 지표 삭제·계산식 변경이 아닌 회차 범위 변경이다. 상세 범위는 [측정 계획](plan.md#이번-회차-측정-범위--pm-승인-완료)이 소유한다.

기존 배포 SHA·평가셋·비용 산정·테스트 이력·기준 자료 초안은 보존한다. 기존 도구의 사용자 편집 지원 및 H05 집계 테스트 통과는 새 무수정 범위 구현 완료의 증거가 아니다. 범위 PM 승인은 2026-10-28 사용자 확인으로 기록한다. 기준 자료 검수·동결과 사용자의 비용·실행 승인은 별도로 기다린다.

## 측정 대상 v1.0.1 선택

2026-10-27 사용자 결정으로 기존 v1.0.0 대신 **v1.0.1**을 측정한다. 전체 SHA와 대조 근거는 [측정 계획](plan.md#측정-대상과-목적)에서 관리한다. 운영 API 이미지 출처에 기록된 코드가 v1.0.1과 일치하므로 기존 태그보다 기록된 배포 코드를 더 충실히 평가할 수 있다. 현재 실행 중인 모든 운영 구성요소의 배포가 확인됐다는 뜻은 아니다.

두 태그 사이 [PR #83](https://github.com/ai-pixlate/server/pull/83)은 Celery의 브로커 소켓 읽기 제한을 기본 30초로 추가하고 `CELERY_BROKER_SOCKET_TIMEOUT`으로 설정할 수 있게 한다. 환경변수 예시와 브로커 설정·dispatch 실패 후 복구 테스트를 동반한다. 연결 제한·keepalive·결과 저장소·ack 처리와 AI 이미지 처리 파이프라인 코드는 변경하지 않았다.

결과 해석 시 다음을 구분한다.

- 이미지 처리 코드가 같아도 배포 설정·의존성·모델 응답·실행 환경이 같거나 품질 결과가 동일하다고 보장하지 않는다.
- 브로커 읽기 제한은 연결 장애 감지·재연결·dispatch 실패와 대기 시간에 영향을 줄 수 있다. 실행시간·실패·재시도 지표를 v1.0.0과 동일한 운영 조건의 결과로 간주하지 않는다. 30초는 전체 복구 시간 또는 작업 실행 제한이 아니다.
- PR #83이 기록한 작업 실행 중 연결 단절 후 ack 실패·소비 정지 한계는 해결됐다고 표현하지 않는다. 격리 Windows 측정으로 운영 장애 복구 성능을 입증하지 않는다.
- 기존 평가셋·평가 지표·계산식·프로토콜, 아래 OCR 표본 예외와 규제사전 경고 결정은 유지한다. 측정 대상 선택은 비용·실측 승인이 아니다.

## 실행 환경

기준 자료 확인·평가 검수는 사용자 결정에 따라 PM이 담당하고 원본당 제한 시간을 두지 않는다. 종료 조건과 역할 구분은 [사람 검수 프로토콜](protocols/v1/evaluation.md#7단계-사람-검수-프로토콜)이 소유한다. A등급 표본의 수·선정 방식은 추천안이며 아직 채택 전이다. 이 결정은 기준 자료 동결이나 비용·실행 승인이 아니다.

운영·학교 서버와 동일한 환경을 재현하는 것을 필수 조건으로 두지 않는다. 현재 Windows PC에서 CPU OCR·로컬 GPU LaMa·전용 Python 가상환경·로컬 PostgreSQL·격리 BE 실행기를 사용한다. 검증된 구성을 고정하고, 후속 비교에서는 고도화 대상 외의 실행·평가 조건을 유지한다. 세부 조건은 [실행 명세](protocols/v1/execution.md#로컬-실행-환경과-재현-조건)를 따른다.

## OCR 품질 표본의 실행 제한

1.0.1 이미지 변환 baseline에서는 GS-01~03 원본 34장 전체 평가를 우선한다. 이 평가에 포함된 기존 OCR 품질 표본 12개에 대해서는 [OCR 채점 명세 v3](../ai-experiments/2026-09-25_02-ocr_scoring-spec-v3.md)의 정답 동결 전 OCR 실행 금지 제한을 해제한다.

기존 정답 초안은 보존하되 검수된 정답으로 사용하지 않는다. 독립 OCR 정량 평가를 완료한 것으로 간주하지 않으며, 과거 실측 결과와 채점 명세 원문은 보존한다. 향후 OCR 정량 평가에서는 정답 작성·검수 이력과 평가할 OCR 출력의 노출 여부를 별도로 관리한다. 출력에 노출되지 않은 검수자가 원본을 기준으로 정답을 작성하는 방식은 사용할 수 있다.

이 결정은 1.0.1 baseline의 입력 제한에 대한 예외다. 다른 OCR 실험의 제한을 일괄 폐기하거나, 계획 승인만으로 실제 OCR 실행을 허용하는 결정은 아니다.

## 규제사전 경고의 처리

사용자가 제공한 `regulation_dict_20260930.xlsx`(SHA-256 `ce2f95e1b7f21eb90cbba551d6c976fb11efabf608392521ae0970a288ddacbc`)의 RG-021·RG-022 대체 표현 경고는 1.0.1 baseline 실행의 차단 조건으로 두지 않는다. 적재된 원본 값을 유지하며, 경고와 실제 처리 결과는 측정 기록에 남긴다. 릴리즈의 검증·실패·제외 처리를 우회하거나 해당 항목을 품질 합격으로 간주하지 않는다.
