# PR #155 — PM 검수 반영 및 재집계

상태: **PM 코멘트 반영·재집계 완료, 반영본 PM 재확인 대기**. 근거는 [PM 검수 코멘트](https://github.com/ai-pixlate/server/pull/155#issuecomment-7125560174)이며 [원문·작성자·시각](pm-comment.json)을 보존했다. 양 체크포인트에 같은 판정을 적용하라는 PM 지시를 따랐다. 이 반영 과정에서 이미지를 새로 채점하거나 모델을 호출하지 않았다.

상위 폴더는 [Codex 최초 채점](../README.md)의 보존본이다. 최초 평가·결함·빈 검수 파일·집계·모델 미확인 기록을 **수정하지 않았다**. 현재 반영 결과는 이 하위 폴더에서 관리한다. 기존 정답지·실행 증거·평가 명세도 그대로다.

## 재집계 결과

| 지표 | 최초 채점 | PM 반영 |
|---|---|---|
| H01 | 13/31 = 41.94% | **동일** |
| H02 최초 결과 | A 1·B 8·C 3 / 측정 12, 판정 불가 1 | **A 1·B 8·C 4 / 측정 13, 판정 불가 0** |
| H03 최종 결과 | A 1·B 8·C 3 / 측정 12, 판정 불가 1 | **A 1·B 8·C 4 / 측정 13, 판정 불가 0** |
| H04 최초·최종 각각 | 107/110 = 97.27% | **105/111 = 94.59%** |

PM 예상 수치와 모두 일치한다. H02/H03 각각 A 7.69%·B 61.54%·C 30.77%, 평가 가능률은 13/31 = 41.94%다. 미생성 18장·정상 전체 제외 3장은 유지한다. H04 각 체크포인트의 평가 가능률은 **111/178 = 62.36%**, 미생성 67·미적용 21·판정 불가 0·평가 실패 0개다. H04 보존율은 전체 적용 178개를 모두 평가했다는 뜻이 아니다.

H03 정상 측정 범위의 미해결 결함은 critical 8·major 20이며 중대 결함 보유 원본은 12/13장이다. [상품·원본별 집계](metrics.csv), [원본별 등급](source-results.md), [H04 항목별 표](h04-review-table.md)를 제공한다.

## 판정 변경과 추가 기록

| 대상 | 반영 내용 |
|---|---|
| GS-02_003-REF-001 | 제품명 판독 불가·critical. H04를 measured/readable=false로 전환하고 H02/H03은 C로 집계 |
| GS-01_002-REF-020 | 15.92% 판독 불가·critical, H04 실패 |
| GS-01_002-REF-025 | 6.78% 판독 불가·critical, H04 실패 |
| GS-01-IMG-002-layout | K01 표 머리글/값 칸, K02 제목/본문, K03 로고/부제·제목/설명·성분 목록/분류 제목·각주 겹침 위치와 관찰 추가. major 유지 |
| GS-01-IMG-002-irritation | 저자극을 hypoallergenic으로 바꾼 의미 오류, 신규 major |
| GS-02-IMG-014-rice-name | 쌀알 크기에 불필요한 학명을 붙인 표현, 신규 minor. 의미 정확성은 유지하고 기존 용법 표 판독 실패와 구분 |

H04는 최초 성공 107개에서 두 수치 실패를 빼 **105개**, 기존 판정 불가 제품명 1개를 실패로 정상 측정에 추가해 분모 **111개**가 된다. 기존 용량·사용 빈도/콩알 의미 실패는 유지한다. 여섯 실패 항목을 각 체크포인트에서 각각 기록하며 결함군 병합 여부와 H04 단위 집계를 혼동하지 않는다.

제품명 항목의 기존 `accurate=null`은 필수 bool 필드에 맞춰 보존 block 421의 번역값 `celimax Retinal Shot Booster`가 기준 제품명에 대응한다는 근거로 기록 변환자가 `true`로 보완했다. 이는 PM이 이미지 판독을 성공으로 봤다는 뜻이 아니다. **PM 판정은 readable=false이며 H04는 실패**다. 이 보완의 작성자·근거를 검수 행과 관찰값에 명시했다. 나머지 두 수치의 정확성 값은 유지하고 판독성만 변경했다.

## 이력과 중복 처리

- [human_review.csv](human_review.csv): PM 검수 114행. 동의한 기존 결함·심각도, 변경 판정, 신규 결함, K영역, A 표본, 명시적인 H04 판정을 구분한다. 결함 심각도 동의를 최초 원인 단계의 확정으로 확대하지 않는다.
- 신규 PM 결함은 대응하는 최초 Codex 판정이 없으므로 검수 행의 `ai_value=null`로 기록한다. 기존 기록 개정은 실제 최초 AI 값을 연결하며 PM이 추가한 관찰을 AI 최초 값으로 표시하지 않는다.
- [evaluation-additions.jsonl](evaluation-additions.jsonl): 영향 원본 3장 × 양 체크포인트, 평가 개정 6행. 최초 평가 ID를 `supersedes_evaluation_id`로 연결한다.
- [defect-additions.jsonl](defect-additions.jsonl): 기존 결함의 평가 연결·위치 개정 20행과 신규 관찰 10행. 기존 결함 ID와 root ID를 유지하고 최초 행은 삭제하지 않는다.
- [adopted-evaluations.jsonl](adopted-evaluations.jsonl)·[adopted-defects.jsonl](adopted-defects.jsonl): 기존 집계기의 최신 평가 선택·PM 검수 적용을 거친 파생본이다. 원 기록을 대신하지 않는다. `reason`의 작성 시점과 PM 검수 참조도 구분한다.

15.92%와 6.78%는 서로 다른 그래프·정보 단위이고 하나의 최초 원인에서 전파됐다는 증거가 없어 `badge-020`, `badge-025` 두 결함으로 기록했다. 각 결함의 최초/최종 관찰은 같은 root ID로 묶는다. 두 수치의 판독 실패를 기존 layout major에서 다시 가산하지 않는다. GS-02_003 역시 제품명 판독 실패는 신규 critical, 기존 layout major는 별개의 Seller 잘림 관찰로 분리해 같은 현상을 이중 가산하지 않는다.

K01~K03 추가 위치는 기존 GS-01 layout root의 개정이며 새로운 root를 만들지 않았다. PM이 동의한 기존 major 심각도는 유지한다. 따라서 채택 결함은 **양 체크포인트 관찰 62행 / 고유 결함군 31개(critical 8·major 20·minor 3)**다. [결함 목록](defect-inventory.md)에 같은 root의 양쪽 관찰을 한 행으로 표시했다. 개정 이력의 과거 행까지 모두 더해 결함 수를 늘리지 않는다.

## 검수 범위·A 표본·모델 정보

[A 표본 기록](a-sample-review.json)에 PM의 상품×체크포인트별 A 1장 추천안 채택, 원래 후보 목록/해시, 명세의 SHA-256 정렬 키와 선정 결과를 남겼다. 양 체크포인트 모두 GS-02_012를 선정·검수했고 A를 유지한다. GS-01은 A가 없고 GS-03은 결과가 없다.

K04 정상 제외, K05·K06 판정, K07~K09 미생성 예외 처리는 동의 기록으로 남겼다. **EI-01은 평가 이슈 유지, EI-02는 문제없음**이며 둘 다 품질 결함을 추가하지 않았다. [이슈 상태](issues.json) 참조.

H04에서는 변경 3개와 저대비 보존 동의 2개만 각 체크포인트의 명시적 단위 검수로 표시한다. H02/H03 전체 원본 검수 표시는 GS-02_003과 A 표본 GS-02_012에 한정한다. 다른 K영역·결함 검수를 원본 전체 검수나 모든 H04 항목의 사람 확인으로 확대하지 않았다. PM 코멘트의 검수 완료와 이번 반영본의 최종 재확인은 별개다.

[모델 확인 부록](model-confirmation.json): **GPT-6 Astra(Medium)**. 출처는 2026-11-24 사용자 확인이며 Codex가 화면을 직접 확인했다고 기록하지 않았다. 최초 세션의 미확인 상태를 고치지 않고 사용자 확인 정보를 연결했다.

## 검증·재현

기존 `protocol.aggregate`의 스키마·참조·해시 검증과 최신 평가/검수 적용 규칙을 그대로 사용했다. H02/H03 A1·B8·C4, H04 105/111을 검증했고 최초 파일·보존 입력의 해시 불변성을 확인했다. [검증 결과](validation.json), [추가 일관성 점검](verification.json) 참조. 기존 준비/프로토콜/범위 회귀 테스트 32개가 통과했다.

상위 폴더의 최초 재현 절차로 복원·검증한 입력 디렉터리를 사용한다. 출력은 입력 밖의 존재하지 않는 새 경로여야 한다.

```powershell
python -X utf8 -B docs/ai-baseline/evaluations/h01-h04-official-20261124/pm-review-20261124/reproduce.py --input .cache/h-scoring-replay --output .cache/h-scoring-pm-replay
```

입력을 복사한 `materialized/`에 최초 기록과 추가 이력을 함께 연결하며, `results/`에 PM 반영 결과를 생성한다. 기존 입력을 덮어쓰지 않는다. 정답·실행·최초 기록과 이 스크립트만으로 재집계하며 모델이나 API를 호출하지 않는다. TQ/OP 통합 집계는 포함하지 않는다.

## PM 재확인 및 별도 조사 요청

PM에게는 세 판정 변경, K01~K03 위치 추가, 두 신규 결함, 수치 배지 두 결함의 분리와 기존 layout 중복 제거가 의도대로 반영됐는지 재확인을 요청한다. 제품명 정확성 bool의 기록 보완과 검수 범위 표시도 확인할 수 있도록 근거를 공개했다. 반영본 재확인 전 `formal_complete=false`를 유지한다.

용어집의 콩·쌀 항목이 콩알·쌀알의 단어 내부에 매칭되는지, 최신 버전에서도 재현되는지, 실행 기록의 `glossary_ids`가 비어 있는 이유는 **별도 조사 요청으로만 기록**했다. 이번 작업에서 조사·수정·재생성하지 않았으며 해당 원인을 확정하지 않았다.
