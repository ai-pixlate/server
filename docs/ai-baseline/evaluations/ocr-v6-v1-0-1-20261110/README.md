## 검증과 한계

- 합성·회귀 **147개 통과**. 별도 전체 행렬 Levenshtein 구현으로 선택된 모든 매칭의 S/D/I를 재계산했고, 정규화된 GT/출력의 각 문자·줄 소비와 분모 보존을 확인했다.
- GS별 합계·전체 문자 가중 집계를 별도로 합산해 일치 확인. 독립 검산은 선택된 대응 경로의 편집거리·집계를 검증하며 v5 휴리스틱이 모든 그룹 대응의 전역 최적해라는 증명은 아니다.
- 별도 캐시 경로로 동일 입력을 재실행해 **112개 섹션 기록 및 summary 전체가 동일**함을 확인했다. 시간 로그만 비교 대상에서 제외했다.
- 사용자 검수 47개, AI만 검수 53개의 신뢰성 한계와 기존 v1 12개 이력을 유지한다. 53개를 사람 전수 검수로 표시하지 않는다.
- v4 **42.79%**, v5 후보 **32.76%**, 이번 v6 **3.49%**는 평가 범위·분모·대응 방식이 다르다. 이번에는 번역 대상만 포함하고 고정 보류 3개를 분리했으며 승인된 GT 교정도 적용했다. 차이를 OCR 제품 성능 개선으로 해석하거나 원인별 기여율을 추측하지 않는다.

## 후속 통합 비교 기준

이번 결과는 **동일한 고정 105개 부분 범위의 v1.0.1 기준선**으로 사용할 수 있다. 2·3차도 같은 원본 이미지·동결 GT·범위·정규화·대응·집계 코드 해시를 적용한다. 새 제품의 보정 후 출력에 대해서는 이미지 해시·출처·영역 대칭 연결을 다시 검증해야 한다. 새 버전에서 경계 교차·자료 누락 등이 발생하면 대상이 같다는 이유로 강제 채점하지 않는다.

run.py는 최초 v1.0.1 증거를 고정해 재현하는 어댑터다. 이후 통합은 새 출력 색인·제품 SHA를 받는 실행 연결이 필요하며 동결된 채점 함수/범위는 바꾸지 않는다. 입력·범위나 규칙을 변경하면 별도 기준선으로 관리한다.

GT/범위/명세/채점 규칙·제품 코드·기존 결과는 수정하지 않았다. 커밋·push·PR은 생성하지 않았다.
