# OCR Text v2 AI 1차 검수 도구 설계

> 아래 실행·모델·비용·초안 상태는 당시 검수 도구 개발 이력이다. 현재 동결/측정 상태는 [OCR 최종 정리](ocr-baseline-summary.md)와 v6 동결본을 따른다. 외부 API 작업은 이번 PR에서 실행하지 않는다.

상태: 사용자 승인으로 신규 100개 섹션의 Codex 채팅 전사·AI 1차 대조를 수행했다. 모두 미승인 초안이며 사람 검수·정답 동결 전이다. 외부 API 실행은 중단했다. 서비스 H01~H05/OP01~OP07 또는 OCR CER 정의를 변경하지 않는다.

## 독립 전사와 대조

1. `transcribe`: 고정 섹션 이미지 바이트와 전사 지침만 전달한다. 기존 GT, Baseline OCR, 과거 모델 출력, inventory의 OCR 경로·내용을 전달하지 않는다. 제안은 별도 AI 기록에만 보존한다.
2. 사용자가 화면에서 제안을 명시적으로 적용한다. 기존 초안이 있으면 덮어쓰지 않고 수동 대조한다. 적용은 미승인 초안 생성이며 검수 완료가 아니다.
3. `review`: 원본 이미지와 현재 초안 lines[]만 보내 대조한다. 초안은 검수 대상이지 사실 근거가 아니다. 이미지 내 지시문은 전사할 데이터이며 실행하지 않는다.
4. 5개 확인 항목: 전사 오류, 누락, 판독 불가, 중복, 읽기 순서. 각 항목을 모두 검사했다는 응답과 구체적 근거를 요구한다. bbox 정확성은 평가하지 않는다. 줄 순서는 배열 그대로, 불확실한 텍스트는 추측 복원하지 않는다.

응답 형식: `lines`(전사 제안 문자열 배열; review는 빈 배열), `checks`(5개 검사 키), `issues`(type, line_index: 0부터 또는 -1=전체/누락, reason), `reason`, `complete`(전체 이미지 대조 여부). 누락 필드·유형 오류·비정상 종료·차단·절단은 실패. 정상 응답이라도 complete=false 또는 issues가 있으면 검토 필요. review의 통과는 모든 검사 수행·완전 대조·문제 0건일 때만 가능하다. 모델의 pass 주장만 믿지 않는다.

AI 기록은 원본 해시, 색인 해시, 초안 리비전·내용 해시, 모델 요청/응답 버전, 지침·스키마 해시, 사용량, 예상 비용, 실행 방식(mock/live/chat), 원문 응답, 상태·근거를 보존한다. 이전 기록은 삭제하지 않는다. 초안 리비전 또는 해시가 달라지면 이전 결과는 무효로 표시한다. 모의 결과는 항상 모의 표기하며 실제 검수 통과로 승격하지 않는다.

## 사람 2차 검수

- 검토 필요·실패: 전수 확인. 미실행·무효 결과는 다시 AI 검수하거나 별도 결정이 필요하며 통과 표본에서 제외한다.
- 전체 신규 대상의 유효 AI 결과가 모이면 표본 계획을 별도 파일로 고정한다. GS별 통과 수 n에 대해 ceil(n×0.2)를 선택한다. 정수 올림 때문에 전체 비율은 20%보다 조금 높을 수 있다(100개 전부 통과하면 5+9+8=22개). 비어 있지 않은 GS마다 최소 1개가 포함된다.
- 고정 seed `ocr-text-v2-human-sample-v1`와 GS·섹션 ID의 SHA-256 순위로 재현 가능한 의사무작위 선택. 목록 순서·호출 완료 순서와 무관하다. AI 결과 cohort와 목록을 보존하며 이후 변경 시 계획은 무효이고 재확인이 필요하다. 유리한 seed로 재추출하지 않는다.
- 사람이 선택한 `오류 없음 / 오류 발견 / 판단 보류`와 근거를 별도 누적 저장한다. 초안 편집·기존 human status·AI status·동결 승인과 분리한다. 오류 발견 시 **해당 계획의 모든 AI 통과 항목으로 검수 확대 필요**를 표시한다. 이 보수적 경고는 오류 기록 수정이나 재표본 추출로 숨기지 않는다.
- AI만으로 자동 승인·동결하지 않는다. 표본 비대상도 승인 완료로 표시하지 않는다. v1 동결 12개는 대상에서 제외한다.

## 실행 경계와 비용 후보

기존 설치된 google-genai 2.29.0을 재사용한다. 현재 어댑터 후보는 `gemini-2.5-flash`: 이미지+JSON 응답, temperature=0, thinking_budget=0, max_output_tokens=8192, SDK attempts=1, 호출당 120초, 도구·검색·자동 함수 호출 없음. 다른 모델로 자동 대체하지 않는다. 재시도는 별도 승인 후 명시적으로 해야 한다.

공식 문서 조회 기준 2.5 Flash 표준 단가는 입력(이미지 포함) $0.30/백만 토큰, 출력 $2.50/백만 토큰이다. 입력 최대 1,048,576 토큰과 출력 한도로 호출당 최악 비용 약 $0.3351 → **$0.34 예약** 후보. 응답 사용량이 불명확하거나 실패하면 예약액을 유지한다. 사용량 비용은 청구액이 아닌 추정치다.

- 신규 100개를 각각 전사+검수하면 최대 기본 200회. 이미 사람이 작성한 초안은 전사를 생략하면 100회. 수정 후 재검수·실패 재시도는 별도 증가하므로 자동 수행하지 않는다.
- 토큰 실측 없음. 200회에 호출당 입력 2천/출력 1천을 가정하면 $0.62, 입력 8천/출력 4천이면 $2.48이다. **관측 기반 예상치가 아닌 예산 시나리오**다.
- 초기 검토 후보: 안전 중단 $6, 최대 200회, 호출당 예약 $0.34. 미정 비용이 누적되면 100개 완료 전에 중단할 수 있다. 200회 모두 최악 비용이면 $68이지만 이를 권장 지출/승인 한도로 제시하지 않는다.
- 공식 문서에 2026-12-01부터 2.5 Flash의 자동 라우팅·요금 변경 공지가 있다. 어댑터는 해당 날짜 이후 호출을 차단한다. 실제 실행 전에 모델 가용성·단가·기간을 재확인하고 사용자 승인을 받아야 한다.

근거: [가격](https://ai.google.dev/gemini-api/docs/pricing#gemini-2.5-flash), [모델 한도](https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash), [이미지 입력](https://ai.google.dev/gemini-api/docs/image-understanding), [구조화 응답](https://ai.google.dev/gemini-api/docs/structured-output). 공식 문서의 품질 보장은 없으며 실제 한국어 전사·검수 정확성은 아직 검증하지 않았다.

## 보존 및 승인

로컬 검수 작업 폴더 아래 `_ai/`에 실행별 기록, `_sampling/`에 고정 계획, `_human/`에 사용자 2차 검수 이력을 보존한다. 실제 작업 공간의 기존 초안과 모의 테스트 작업 공간은 분리한다. 웹 화면에는 유료 실행 버튼이 없다.

라이브 CLI는 `--execute-approved`와 별도 승인 JSON 모두 필요하다. 승인에는 approved=true, authority(사용자 근거), model, inventory_sha256, sections(허용 ID), actions, max_calls, max_amount, expires_at, prompt_bundle_sha256을 명시한다. 서버·CLI 시작만으로 호출하지 않는다. 승인 파일은 이 작업에서 생성하지 않는다. 실행 기록·예산 장부는 독점 잠금과 호출 전 예약으로 보호하며 중단 후 미정 예약은 유지한다. 보호 파일을 삭제해 다시 호출하지 않는다.

## 도구 실행 방법

기존 [검수 화면 실행](ocr-review.md#ocr-text-v2--112개-섹션-텍스트-검수) 명령을 그대로 사용한다. 실행 중이던 서버는 종료 후 재시작해야 새 API가 반영된다. 초안은 그대로 유지한다.

모의 검증은 실제 입력과 분리된 합성 작업 공간에서 수행한다. 아래 CLI 인자의 `<...>`는 준비된 합성/승인 파일 경로로 교체한다.

```text
python docs/ai-experiments/tools/ocr_truth/ai_review.py --inventory <색인.json> --frozen <동결본폴더> --drafts <별도.cache작업폴더> --action transcribe --section <섹션ID> --provider mock --responses <모의응답.json>
```

모의응답 JSON은 `{섹션ID: 응답객체}` 매핑이다. 이후 화면에서 제안을 적용하고 `--action review`로 대조 응답을 모의 실행한다. 실제 GT 폴더에는 이번 작업의 모의 응답을 저장하지 않는다.

승인 후의 라이브 실행은 같은 명령에서 `--provider gemini --approval <승인.json> --execute-approved`로 명시한다. `GEMINI_API_KEY`는 환경변수로만 읽고 저장하지 않는다. 이 문서의 명령은 실행 승인이 아니다. 실제 실행 전에는 승인 파일 생성, 모델/요금 확인, 소수 표본으로 품질 확인 여부를 사용자가 결정해야 한다.

`--section`은 반복 지정 가능하며 실패 시 후속 호출을 중단한다. 동일 리비전·작업의 중복 실행은 거부한다. CLI는 전사 제안을 초안에 자동 적용하거나 사람 검수 상태를 바꾸지 않는다. 승인 후에도 사용자 적용이 끝난 초안에 대해서만 review를 호출한다.

### 승인 파일 필드

| 필드 | 의미 |
|---|---|
| approved / authority | true 및 사용자 승인 근거 원문·위치 |
| model | 현재 지원 후보 `gemini-2.5-flash` |
| inventory_sha256 | 사용 중인 색인 파일 바이트 SHA-256 |
| prompt_bundle_sha256 | `ai_review.bundle_hash()`의 지침·응답 스키마 해시 |
| sections / actions | 허용 섹션 ID 배열 / transcribe·review 중 허용 작업 배열 |
| max_calls / max_amount | 승인된 총 생성 요청 수 / USD 안전 중단 상한 |
| expires_at | 시간대가 포함된 ISO 8601 승인 만료 시각 |

입력 모델은 날짜 제한 이전에도 실제 계정에서 사용할 수 있는지 미확인이다. SDK 응답의 model_version이 요청 모델 계열과 다르면 실패·추가 호출 중단으로 기록한다. 모의 결과는 라이브 결과와 같은 표본 계획에 섞지 않는다. SDK API 오류는 HTTP 코드·제공자 상태·정제한 메시지·허용한 reason 필드만 기록한다. 환경변수 비밀값·키/토큰 패턴·URL을 제거하며 헤더·요청·전체 오류 본문·메타데이터는 저장하지 않는다. 그 밖의 예외는 클래스만 기록한다. 생성 응답 본문이 있으면 JSON 문자열·해시를 남긴다. 명시적 재시도 승인은 실패 run_id에 연결하고 1회만 소비하며, 기존 실행 기록·미정 예약액을 유지한다.

동일 모델을 두 번 사용하는 흐름은 Baseline OCR 출력과 **자료 출처가 독립적**이라는 뜻이며, 모델 오류가 통계적으로 독립적임을 보장하지 않는다. 사람의 전수/표본 검수와 별도 동결 승인 절차는 계속 필요하다.


## 2026-11-05 최초 연결 실패 및 승인된 진단 재시도

- 첫 전사 실패 후 사용자가 첫 요청만 1회 재시도하도록 별도 승인했다. 신규 99개와 검수 호출은 실행하지 않았다.
- 진단 재시도: **404 / NOT_FOUND**. 제공자 응답은 `gemini-2.5-flash`가 신규 사용자에게 더 이상 제공되지 않는다고 명시했다. 해당 API 사용 조건에서는 실행할 수 없다. 이는 처음 조사한 일반 가격·종료 일정만으로 계정 가용성을 보장할 수 없음을 확인한 결과다.
- 응답에는 `gemini-3.8-flash`와 Interactions API가 안내됐으나 대체 모델 선택·호출 방식 변경·추가 실행은 수행하지 않았다. 모델 변경은 별도 조사·사용자 결정 대상이다.
- 누적 요청 2회 / 미정 예약 USD 0.68 유지 / 토큰·실제 청구액 확인 불가. 예약액을 실제 발생 비용 또는 비용 0으로 단정하지 않는다.
- 첫 실패 원본은 그대로 보존했다. 재시도 승인·정제 오류·진단 요약은 로컬 `.cache/ocr-text-v2-review/_execution/20261105-first-ai-review/`와 `_ai/`에 별도 기록했다. 당시 초안·사람 검수·동결은 모두 0건이었다. 이후 채팅 전사 결과와 구분한다.
- 비밀정보 제거와 재시도 횟수·기존 예산 보존을 포함한 합성·회귀 테스트 67개 통과.


## 2026-11-05 Codex 채팅 전사·1차 대조

사용자의 “AI 전사 및 검수는 이 채팅으로 해 / 진행해” 지시에 따라 외부 API 대신 원본 이미지 100개를 채팅에서 직접 읽고 전사·재대조했다. Baseline OCR 출력 및 과거 모델 출력을 전사 근거로 제공하지 않았다. 기존 v1 동결 12개는 수정하지 않았다.

- 신규 초안 100개, 1,492줄. 문자가 없는 사진 2개는 lines=[]로 저장했다.
- AI 1차 통과 67개 / 검토 필요 33개 / 채팅 작업 실패 0개. 검토 필요 중 16개는 미세 글씨·가림 등으로 전사가 불완전하다. 불완전 부분을 평가 제외로 확정하지 않았다.
- GS별: GS-01 통과 10·검토 필요 11, GS-02 통과 29·검토 필요 14, GS-03 통과 28·검토 필요 8.
- GS별 통과의 20% 올림 표본: 2·6·6개, 총 14개. 검토 필요 33개와 합해 사람 검수 대상은 47개다. 기존 seed와 추출 규칙을 그대로 적용했다.
- 직접 작성한 초안을 기존 저장 절차로 반영하고 이력 작성자를 codex_chat_ai_draft로 명시했다. 사용자 실행 지시에 따른 초안 저장이며 사람이 제안을 확인·승인했다는 뜻이 아니다. 모든 상태는 draft, 사람 검수·승인·동결 0건이다.
- 채팅 전사 100건과 동일 채팅의 이미지 재대조 100건을 mode=chat으로 보존했다. 두 번의 독립 모델 호출이나 독립된 사람 검수로 해석하지 않는다. 정확한 Codex 모델명·설정 증빙은 미확보다.
