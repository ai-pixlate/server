# AI 파이프라인 지표 개편·OCR 기준선 정리

## 현재 분류와 결과

서비스 성과 지표 H01~H05 / 단계별 기술 품질 지표 OCR01·OCR02(보류)·OI-54·NFR-15 / 운영 성능 지표 OP01~OP07로 구분한다. 공통 결함 분석은 별도 유지한다. H01~H05·OP01~OP07의 의미·계산식과 제품 파이프라인 계약은 변경하지 않았다.

| 평가 | 이유·범위·방식 | 결과와 성격 |
|---|---|---|
| v4 | 112개 고정 섹션 전체 텍스트, 배열 순서 연결 CER | 공식 과거 결과 42.79%. 읽기 순서·GT 미전사와 출력 범위 차이가 영향을 줌 |
| v5 | 같은 기존 증거에서 줄 순서 독립 대응·분리/병합 후보 검증 | 후보 32.76%. 휴리스틱 한계 및 GT 완전성 문제 유지 |
| v6 | 번역 대상 고정 범위·대칭 필터 + v5 A2 대응. GT 두 줄 비활성화와 사용자 확인 L045 @ 반영 | **고정 105개 부분 CER 3.49% (584/16,742자)**. 정책 제외 4개·고정 undetermined 3개 |

평가 범위·분모·대응 방식이 달라 수치 차이를 OCR 모델 성능 향상으로 해석하지 않는다. 사용자 검수 47개와 AI만 검수 53개를 구분한다. 0오류 회신은 사용자 검수 47개 범위이며 사람 전수검수·정답 무오류를 주장하지 않는다. 기존 v1 12개 검수 이력도 승계한다.

## 검증·재현 조건

최종 관련 Python 테스트 **188개 모두 통과**, v6 독립 편집거리/집계 검산 및 재실행 112개 레코드·집계 동일. 세 로컬 HTTP 테스트는 샌드박스에서 WinError 10013으로 실패했으나, 동일 코드·테스트를 소켓 접근 허용 환경에서 실행해 통과했다. 테스트 제외나 제품 코드 수정 없이 원인을 구분했다. HTTP 대상은 127.0.0.1이고 AI 검수는 모의 응답이다.

원본 이미지 112개와 일부 과거 증거 색인의 경로는 Windows 로컬 절대 경로다. 저장소 clone만으로 이미지·모델 자산·가상환경이 자동 확보되지 않는다. 같은 바이트의 이미지와 기존 출력 자료를 별도 확보하고 입력 색인 해시로 검증해야 한다. 과거 JSON에 기록된 경로를 동결 파일에서 직접 고치지 말고 로컬 경로 해석 연결을 사용한다. 현재 최초 측정 run.py는 당시 로컬 구조를 전제로 하므로 다른 PC에서는 경로 연결을 준비해야 한다.

CER 재현 자체는 저장된 보정 후 OCR 출력과 Python/Pillow 검수 의존성으로 가능하며 모델 가중치·API 키·추가 OCR 추론은 필요 없다. 모델 자산은 제품 OCR 재실행 때만 필요하다. `.cache`, 가상환경, 가중치, 원본 이미지 중복은 이번 변경에 포함하지 않는다. 날짜별 JSON은 검수/범위 변경의 근거와 해시 연결을 보존하기 위해 포함한다.

Git 줄바꿈 변환으로 동결 해시가 바뀌지 않도록 관련 근거 경로와 해시 고정 코드/명세에 `-text` 속성을 지정한다. 정규화된 문서와 바이트 고정 증거를 구분한다. Git index 바이트와 로컬 동결·결과 해시를 커밋 전에 비교한다.

2·3차 비교는 동일 105개·GT·고정 범위·명세·코드 해시로 수행한다. 새 출력의 이미지 동일성·출처·범위 경계는 별도 검증한다. 추가 미측정이면 고정 부분 CER 확정도 중단한다. 이 PR은 검토용이며 병합·추가 실행 승인을 자동 생성하지 않는다.

## 동결 당시 문서와 현행 안내

`protocols/v1/ocr.md`는 동결 당시 외부 증거 해시가 가리키는 원문으로 유지한다. v6 현행 안내를 포함한 변경본은 [ocr-current.md](protocols/v1/ocr-current.md)에 보존했다. 기존 증거 해시와 동결 패키지는 변경하지 않는다.
