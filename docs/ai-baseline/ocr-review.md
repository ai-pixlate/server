# OCR 정답 검수 환경

현재 상태: 사용자 전사·누락 전수 검수 완료(369줄, 오류 0건). bbox·겹침 38건 검수는 생략한다. 아래 화면 안내는 기존 v3 도구 사용법이며 현재 v4의 동결 요건이 아니다. 텍스트 전용 동결은 [v4 설계](protocols/v1/ocr-v4.md)를 따른다. 기존 완료 체크·freeze 기능을 텍스트 전용 승인으로 사용하지 않는다. [자료 점검](ocr-preflight.md), [채점 세부 결정안](protocols/v1/ocr-scoring-details.md).

## 실행

현재 `feature/ai-pipeline-evaluation-metrics` worktree 루트에서 실행한다. Python에는 기존 환경의 Pillow와 pipeline 의존성이 필요하다. 다음은 이 PC의 이미지 저장소를 연결한 읽기 전용 실행이다.

```powershell
& 'C:/Users/Yeram/Documents/pixlate-server/.cache/bl-venv-locked-20261028/Scripts/python.exe' docs/ai-experiments/tools/ocr_truth/truth.py serve --read-only --image-root 'C:/Users/Yeram/Documents/pixlate-server'
```

브라우저에서 `http://127.0.0.1:8765/`를 연다. 종료는 터미널 Ctrl+C. 다른 PC에서는 이미지 상대 경로가 들어 있는 저장소를 `--image-root`로 지정한다. 서버 시작 시 12장 SHA-256이 모두 일치해야 한다. 이미지를 복사하거나 정답 JSON의 경로를 바꿀 필요는 없다.

**다음 단계에서 사람이 실제 검수를 시작할 때만** `--read-only`를 제거한다. 수정 대상은 도구가 있는 worktree의 정답 JSON이며 이미지 저장소는 수정하지 않는다. 이번 작업에서는 저장·검수 완료·동결 명령을 실행하지 않는다.

## 화면 사용

- 왼쪽: 12개 섹션과 저장된 전체 검수 진행률. 가운데: 이미지·bbox·배율. 오른쪽: 선택 영역 확대, 전사·bbox·태그·메모.
- 겹침 목록에서 두 줄 ID를 누르면 이미지의 두 bbox가 빨간색으로 강조되고 첫 줄로 이동한다. 두 번째 줄 ID를 선택해 각각 대조한다.
- `rotated=true`는 둘 중 하나 이상 회전 태그, `양쪽 ink_overlap=true`는 양쪽 모두 해당 태그라는 뜻이다. 자동 검사 예외이지 사람 검수 완료가 아니다. 겹침을 없애기 위해 태그를 임의로 붙이지 않는다.
- 기존 38쌍은 4섹션에 있다: GS-01_002/sec_1_17 3쌍, GS-02_001/sec_1_03 1쌍, GS-02_002/sec_1_01 13쌍, GS-03_002/sec_1_04 21쌍.
- '미검수 줄만 표시'와 현재 섹션 진행률로 남은 줄을 찾는다. 전체 진행률은 저장된 값, 현재 섹션은 저장 전 편집값을 포함한다.
- 전사와 누락 줄을 전수 확인하고, bbox는 해당 줄을 가리키는지 확인한다. 적절한 bbox를 픽셀 단위로 다시 다듬지 않는다. 좌표 상세는 기본 접힘이며, 이미지 드래그 수정은 ‘상자 수정 모드’를 켰을 때만 가능하다. 기존 잉크 기준·여백 규칙은 유지한다.
- ‘집중 확인만’은 겹침에 참여한 줄·상자 없는 줄·메모에 ‘확인 필요’가 있는 줄을 표시한다. 모호한 항목은 기존 메모에 사유를 기록하고 완료 체크를 보류한다. 누락 여부는 필터를 끄고 전체 이미지와 대조한다.
- 편집 모드에서 사람이 이미지와 대조한 줄만 체크하고 저장한다. 전사·좌표·태그 변경 시 기존 확인을 해제하며 변경 이력은 기존 history에 보존한다. 읽기 전용 모드는 서버도 저장을 거부한다.

## 완료 조건과 범위

기존 JSON의 v3 검수 상태는 그대로 보존한다. 전사 검수 완료는 사용자 회신 근거로 별도 기록하며 좌표·태그 승인으로 확대하지 않는다. 현재 평가에 겹침 38쌍 해결이나 bbox 검수는 필요하지 않다. 텍스트 연결은 사용자가 채택한 기존 `lines[]` 배열 순서를 유지한다. L008은 사용자 결정으로 빈 정답을 유지하고 섹션 평가에 포함한다. 사용자 승인에 따라 [별도 텍스트 정답](references/ocr-text/ocr-text-v1-20261104/README.md)을 동결했다. 기존 도구의 freeze는 실행하지 않았다.

## OCR Text v2 — 112개 섹션 텍스트 검수

112개 입력은 [확대 사전 점검 색인](preparations/ocr-text-v2-preflight-20261105/inventory.json)을 사용한다. 기존 v3 화면과 분리된 `serve-text` 모드이며, `truth.py`의 로컬 서버·응답 처리와 ID·시간 형식을 재사용한다. 기존 12개 동결 정답은 직접 조회만 하고 신규 100개만 별도 작업 공간에 저장한다. OCR 결과를 자동으로 전사 초안에 넣지 않는다.

현재 worktree 루트에서 실행:

```powershell
& 'C:/Users/Yeram/Documents/pixlate-server/.cache/bl-venv-locked-20261028/Scripts/python.exe' docs/ai-experiments/tools/ocr_truth/truth.py serve-text --inventory docs/ai-baseline/preparations/ocr-text-v2-preflight-20261105/inventory.json --frozen docs/ai-baseline/references/ocr-text/ocr-text-v1-20261104 --drafts .cache/ocr-text-v2-review
```

`http://127.0.0.1:8766/`에서 사용한다. `--check-only`를 붙이면 서버 없이 이미지·동결본·기존 초안 연결만 확인한다. 다른 PC에서는 `--image-root <이미지가 있는 저장소>`로 경로를 연결한다. 서버는 이 PC에서만 접속 가능하며 외부 공유용이 아니다.

- GS-01 25개 / GS-02 48개 / GS-03 39개를 GS·상태별로 필터링하고 원본/섹션 ID로 선택한다.
- 왼쪽 목록, 가운데 확대·스크롤 가능한 섹션 이미지, 오른쪽 텍스트를 대조한다. 줄 추가·수정·삭제와 명시적 위/아래 이동을 지원하며 자동 정렬·정규화는 하지 않는다. 빈 문자열도 그대로 저장한다.
- v1 동결 12개·369줄은 화면과 서버에서 수정 금지. 나머지는 빈 줄 목록으로 시작하며 사람이 직접 작성한다. 초기 접속만으로 신규 정답 파일을 생성하지 않는다.
- `임시 저장` 시에만 `.cache/ocr-text-v2-review/<섹션 ID>.json`에 저장한다. 상태는 미작성/초안/검수 중/확인 필요/사람 확인 기록을 구분한다. '사람 확인 기록'은 사용자가 전사·누락을 직접 확인했다는 체크를 해야 저장된다. **이 기록은 승인·동결이 아니다.** 수정하면 다시 확인해야 한다.
- 전체·GS별 진행률은 **신규 사람 확인 수 / 신규 대상 수**이며 기존 v1 동결 수는 별도로 표시한다. 초기값은 신규 0/100, v1 12개다. bbox 체크·태그·겹침 검수는 요구하지 않는다.
- 줄 ID와 `lines[]` 순서, 원문 텍스트, 이미지/색인 해시, 메모, 변경 전후 이력과 저장 시각을 보존한다. 여러 창의 오래된 저장은 revision 검사로 차단한다. 저장하지 않은 상태에서 이동/종료 시 확인한다.
- `.cache` 초안은 Git 제외·로컬 전용이다. 별도 백업이 필요하며 공유·동결 완료로 취급하지 않는다. v1 동결·CER 결과·공식 회차 파일을 저장 대상으로 사용하지 않는다.

### AI 1차 검수와 사용자 2차 검수

[AI 검수 설계·비용·실행 안내](ocr-ai-review.md)를 따른다. 현재 구현·모의 검증 상태이며 실제 실행 승인 전이다.

- AI 전사 제안은 초안과 분리해서 표시한다. `빈 초안에 제안 적용`을 사람이 눌러야 저장된다. 기존 내용이 있는 초안은 자동으로 덮어쓰지 않는다.
- 원본 이미지와 저장된 초안의 AI 대조 결과를 통과/검토 필요/실패로 표시하며 모의 응답은 별도로 표시한다. 전사 제안만 받은 상태는 검수 통과가 아니다.
- 전체 신규 대상의 유효 AI 검수 결과가 모인 뒤 `사용자 검수 표본 고정`을 누른다. GS별 통과의 20%(올림) 표본과 검토 필요·실패 전수 대상을 분리한다. 선정 당시 결과·초안 해시와 seed를 보존한다.
- 사용자 2차 검수에서 직접 대조 확인과 근거를 기록한다. 표본 오류 발견 시 전체 검수 확대 경고를 유지한다. 이 기록은 전사 작성 상태·AI 판단·정답 승인과 별개다.
- 초안을 변경하면 이전 AI 결과와 표본 계획은 무효다. 화면은 이전 근거를 보존해서 보여 주지만 현재 통과로 집계하지 않는다. 화면에는 유료 실행 버튼이 없다.

### 이번 검증

- 실제 입력 112개와 동결 12개 연결 검증 통과. 신규 실제 GT 작성·검수 이력은 생성하지 않았다.
- 기존 화면의 이미지·목록·동결본 수정 차단을 브라우저에서 확인했다. 긴 해시의 줄바꿈과 동결 상태 표시를 정리했다.
- 실제 GT와 분리한 합성 화면에서 전사 제안 표시·적용, 텍스트 편집·임시 저장, 표본 고정, 오류 발견·검수 확대 경고, 초안 변경 후 무효화와 사용자 기록 차단을 확인했다.
- 합성·회귀 테스트 65개 통과. 실제 모델 정확성·가용성·청구액·라이브 연결은 미검증이다. 모델 API 호출·실제 CER 측정·정답 동결은 하지 않았다.
