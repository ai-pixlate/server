# 1.0.1 baseline 측정 계획

> 상태: 기존 지표 정의 유지 · 2026-10-28 회차 범위 변경 PM 검토 대기 · 공식 실측 미실행 · 비용·실행 승인 보류

Baseline 실측 완료 목표는 **2026-11-12**다. 목표일이 미정 항목의 자동 확정이나 실행 승인을 뜻하지 않는다.

## 측정 대상과 목적

2026-10-27 사용자 결정에 따라 측정 대상은 **v1.0.1**, 전체 커밋 SHA는 **`bfa3b700144467f4adf7d6802b7b2e93791fe6de`**로 고정한다. 기존 v1.0.0 계획에서 변경한 이유는 [측정 대상 선택 결정](decisions.md#측정-대상-v101-선택)에 기록한다. 제품 버전 변경이며 평가 명세 v1과 기존 지표·프로토콜은 유지한다.

2026-10-27 GitHub 원격 기록과 로컬 커밋 내용을 대조한 결과:

**운영 버전 확인 출처:** 2026-10-27 운영자인 사용자가 현재 운영 서버에서 v1.0.1을 실행 중임을 확인했다. 이는 운영자 확인이며 에이전트가 서버에 접속해 검증한 결과가 아니다. EC2 `/etc/pixlate/release.conf`의 RELEASE_SHA·API_DIGEST, 실제 실행 중인 API 컨테이너의 이미지·릴리즈 표식, 학교 OCR/GPU 워커 배포 SHA는 직접 확인하지 못했다. [배포 절차](../../deploy/README.md)에 따라 실행 전 이를 대조하고 확인 시각·근거를 회차 기록에 남긴다. 불일치하면 측정 SHA를 임의로 바꾸거나 배포 일치를 주장하지 않고 보고한다. 태그·main HEAD·릴리즈 게시만으로 현재 운영 배포를 단정하지 않는다. 비용·실행 승인은 계속 보류다.

현재 품질과 결함·실패를 재확인 가능한 기록으로 남기고, 같은 평가셋·평가 방법으로 후속 버전의 개선과 퇴행을 비교한다. 최종 발표에서는 측정 결과와 실제 전후 이미지를 함께 제시한다.

측정 대상은 모델 추론과 전후처리·판정·번역·렌더를 포함한 이미지 변환 처리 품질이다. 기존 릴리즈의 BE 처리 흐름을 격리 환경에서 재사용한다. 운영 인프라 성능이나 모델 단독 효과를 검증한 것으로 해석하지 않는다.

고정 입력은 [평가셋](protocols/v1/dataset.md), 로컬 환경 결정은 [decisions.md](decisions.md#실행-환경), 공식 생성 횟수·재시도·예산 승인은 [execution.md](protocols/v1/execution.md)를 따른다.

## 이번 회차 측정 범위 — PM 검토 대기

2026-10-28 사용자 결정으로 이번 v1.0.1 Baseline은 **사용자 수정을 제외한 AI 자동 파이프라인 품질 평가**로 진행하도록 범위를 변경한다. 기존 PM 승인 명세에서 사용자 수정 부담·수정 효과까지 다루던 범위와 달라진 사항이며 **PM 검토 대기**다. H01~H05의 정의·계산식·평가 단위·A/B/C 기준은 변경하지 않는다.

| 항목 | 이번 회차 적용 |
|---|---|
| H01~H04 | 기존 정의·분모·예외 규칙대로 측정. H02는 machine_snapshot, H03은 N6 service_final을 각각 평가 |
| H05 사용자 수정 부담 | **미측정(별도 서비스 평가 예정)**. 정의를 삭제하거나 수정 0건으로 보고하지 않음 |
| 사용자 수정 효과·회복 분석 | 후속 서비스 평가로 이관. 두 체크포인트의 차이를 사용자 수정 효과로 해석하지 않음 |
| N3·N5·N6 | AI 최초 섹션 선택과 자동 번역문을 유지. 필요한 서비스 확인 절차를 정상 수행하고 변경 없이 확인한 증거를 보존한 뒤 N6 최종 이미지 생성 |
| OP06 | 기존 정의·내부 기록 유지. 무수정을 강제한 실험이므로 실제 사용자 승인 성과로 해석하거나 발표하지 않음 |
| PM 평가 검수 | 기준 자료 확인·동결과 AI 평가 결과 검수 역할 유지. 제품 결과를 고치는 행위와 평가 판단을 정정하는 행위를 구분 |

필수 확인은 사용자 편집과 구분하며 임의의 자동 승인·상태 우회로 생략하지 않는다. 실행 조건은 [회차 실행 조건](protocols/v1/execution.md#이번-회차의-무수정-실행-조건), 미측정 표시는 [기록 방식](runs/README.md#이번-회차의-범위-기록)을 따른다. PM 검토 완료나 사용자 최종 비용·실행 승인이 이루어진 것으로 간주하지 않는다.

## 비목표

- 운영자 화면이나 별도 평가 기능 신규 개발
- 제품 파이프라인·DB/API 계약 변경
- 좋은 결과를 선택하기 위한 반복 생성
- 고정 평가셋 결과를 전체 상품·국가·언어 성능으로 일반화

보조 운영지표는 기존 기록에서 확인 가능한 값을 품질과 함께 표시하기 위한 것이다. 서비스 장기 운영지표와 격리 실행 결과를 동일하게 해석하지 않는다.

## 별도 평가와 후속 과제

[OI-54](protocols/v1/aggregation.md#oi-54-규제-위험-표현-검출-재현율)는 baseline 이미지 진단과 별도 평가셋으로 검출 재현율과 정상·허용 표현 오탐을 함께 보고한다. [NFR-15](protocols/v1/aggregation.md#nfr-15-인페인팅-텍스트-잔존)는 별도 후속 과제이며 진행 순서와 미정 항목은 집계 문서에서 관리한다.

일반 LLM 비교에서는 PM이 이미지 4장을 생성하고, 우리는 제공된 결과를 H01·H02·H04로 평가해 동일 원본의 Pixlate `machine_snapshot`과 비교한다. 비교 대상 4장의 원본 키·생성 모델·설정·지침·산출물·실패 기록을 확보하고, 누락된 정보는 확인 불가로 남긴다. 선택된 4장과 동일한 기준 자료로 비교하며 baseline 34장 전체 결과와 합산하거나 일반화하지 않는다. 결과 구조와 연결은 [일반 LLM 비교 기록](runs/README.md#일반-llm-비교-기록)을 따른다.
