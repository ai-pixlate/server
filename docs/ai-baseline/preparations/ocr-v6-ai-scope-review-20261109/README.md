# OCR v6 미검증 65개 AI 1차 범위 검수

상태: 원본 기반 AI 1차 판단·필터 연결 검증. **사용자 승인·GT 동결·CER 채점 아님.** 이전 검증 완료 46개와 Good all goodal 차단 1개는 그대로 유지했다.

## 대상 정합성

[이전 상태](../ocr-v6-type-validation-20261109/section-status.json)의 `사용자 확인 필요` ID 65개와 [검수 대상](target-ids.json)이 정확히 일치한다. 중복·누락 0개. GS-01~03 전체 112개는 모두 상태표에 남는다.

이전 75개 전체 포함 후보 / 4개 제외 / 33개 혼합은 문서 제외 정책 전 분류다. 특허증 GS-02_008/sec_1_05와 시험성적서 GS-03_014/sec_1_01이 혼합으로 이동해 73 / 4 / 35가 됐다. `제외 요소 후보 33 + 혼합 연결 32`는 정책 분류가 아니라 미완료 작업 구분이다.

- 전체 포함 후보 73 = 기존 검증 40 + 제외 요소 추가 확인 33
- 혼합 35 = 기존 검증 2 + 연결 추가 확인 32 + 별도 차단 1
- 전체 제외 4는 기존 검증 완료

이번 AI 검수는 위 33+32만 대상으로 한다. 새 원본 판정은 `source-decisions.json`에 별도로 보존하며 이전 분류 파일을 덮어쓰지 않는다. 원형 배치만으로 일반 시험 안내를 인증 로고로 제외하지 않는다.

## 결과

| 상태 | 전 | 후 |
|---|---:|---:|
| 검증 완료 | 46 | 78 |
| 사용자 확인 필요 | 65 | 33 |
| 채점 차단 | 1 | 1 |

65개 원본 모두 Codex 채팅에서 이미지를 직접 확인했다. **32개가 새로 필터 조건을 통과한 검증 완료 후보**다. 실제 사용자 승인 여부는 모두 별도 `human_approved: false`이며 공식 채점 허용으로 바꾸지 않았다. 원본에서 먼저 의미 영역과 GT 줄 연결 후보를 정하고, 그 후 OCR bbox를 동일 필터로 검사했다. OCR/CER에 맞춘 텍스트 변경이나 문자열 분할은 하지 않았다. 통과한 32개의 포함 영역을 원본 위에 그린 이미지도 다시 대조했다.

대표적인 통과 근거:

- GS-01_002/sec_1_06: 얼굴·용기 사진과 하단 설명 분리; GT L001~007은 용기 인쇄, L008~028은 별도 설명.
- GS-01_002/sec_1_07: VEGAN 심볼과 오른쪽 일반 인증 설명 분리.
- GS-01_002/sec_1_19·20: 용기 인쇄와 하단 제품 설명·해시태그 분리.
- GS-02_001/sec_1_02: 기프트카드 인쇄 제외, 별도 참여고객 안내·금액 포함.
- GS-02_009/sec_1_03: 원형 7개는 일반 시험 안내이므로 포함. 원형이라는 이유로 제외하지 않음.
- GS-02_013/sec_1_02: 피부자극 시험 증서 내부 제외, 확대 결론과 하단 설명 포함. 모든 종류의 인증서 제외 정책을 만든 것이 아님.
- GS-03_018/sec_1_10: 두 용기 인쇄를 제외하되 표 제목·제품 특징 레이블·추천/미백/톤업 표는 보존.

전수 근거와 남은 대상은 [섹션별 목록](review-list.md), 기계 판정은 [상태](section-status.json)·[감사 기록](filter-audit.json)를 참조한다. 이 결과로 분류 정확도 100%, GT 완전성, 공식 전환을 주장하지 않는다.

## 사용자가 확인할 것

[검수 화면](review.html)을 로컬 브라우저에서 연다. 별도 서버는 필요 없다. 원본 이미지가 있는 현재 PC의 파일 경로를 참조하므로 팀 공유 완료 자료는 아니다.

- **경계 교차 17개 섹션 / 45개 OCR 영역:** 강조한 OCR bbox가 원본의 포함 문구만 가리키는지, 실제 제외 문구까지 결합했는지 확인한다. 단지 경계가 어긋난 경우 원본 기준 범위 보완 의견을 기록한다. 문자열 임의 분할·OCR 수정은 하지 않는다.
- **의미·연결 확인 16개 섹션 / 16개 묶음:** 표시한 기존 영역과 원문을 보고 별도 설명이 제외 영역에 덮이지 않는지 확인한다. 예: Reef Safe 타원 심볼, 제형 숫자 3, 배경 b3+, 제품 콜라주의 손글씨, 문서 위 인용문. 기존 사용자 결정(D01~D05·D07, 특허/시험문서 제외)은 다시 뒤집거나 재승인 요청하지 않는다.
- 총 **33개 섹션·61개 확인 항목**. 전사 전체 재검수나 픽셀 단위 bbox 정확도 검수가 아니다. 녹색 포함/빨강 제외 후보, 점선 미검증 영역과 주황 OCR 위치를 확인한다.
- 선택값은 자동 설정하지 않는다. 포함/제외/보류 의견과 GT/OCR ID를 메모한 뒤 JSON으로 내보낸다. 의견 기록은 GT 적용 승인·동결과 분리된다.
- Good all goodal은 이번 65개 밖의 기존 차단 1개다. 분리 근거가 새로 확보되지 않았으므로 유지한다. 현재 단일 반환값을 로고 포함 예외로 처리하지 않는다.

## 위치 연결의 한계

새 GT sidecar의 `source_semantic_scope_witness`는 원본에서 확인한 의미 영역의 포함/제외를 필터로 검사하기 위한 대표 사각형이다. **실제 GT 줄 위치·bbox가 아니다.** GT 줄을 특정 포함 영역에 연결한 근거는 원본 시각 판단과 줄 ID 목록이며, 문자열 유사도로 OCR에 대응시키지 않는다. UI에서도 이것을 GT 실제 bbox로 표시하지 않는다. 같은 의미 영역의 GT는 연결 후보 목록일 뿐 일대일 대응이 아니다. 실제 OCR bbox가 경계를 넘으면 이 GT 연결과 무관하게 차단한다.

## 검증과 재현

- 공통 필터 합성 테스트 30개 통과: 빈 OCR·누락·중복·삽입 유지, 제외 영역 처리, 문서 위 인용문 보존, 혼합/경계 차단, 해시 방어.
- 112개 감사 기록의 GT/OCR 원문·횟수·순서와 입력의 동일성 확인. 필터 포함 목록은 감사 기록의 include 항목과 동일하다.
- 원본·출력·GT의 고유 파일 159개 해시 확인, 기존 보호 파일 232개 불변 확인.
- 검수 상태/해시 방어 및 61개 화면 DOM 모의 렌더 통과. JS 구문 검증 통과.
- 브라우저 실제 시각 검증은 **미완료**. 이전 Computer Use 안전 중단을 우회·재시도하지 않았다. 위 화면을 수동으로 열어 이미지와 확대/의견 내보내기를 확인해야 한다.
- 재현: 저장소 루트에서 `python docs/ai-baseline/preparations/ocr-v6-ai-scope-review-20261109/build.py`
- 화면 모의 검증: `node docs/ai-baseline/preparations/ocr-v6-ai-scope-review-20261109/test-review.cjs`

공통 필터 코드는 변경하지 않고 기존 구현을 호출했다. [원본 판단](source-decisions.json), [영역](fixed-regions.json), [GT 연결](gt-region-links.json), [해시](source-hashes.json), [검증 요약](validation.json), [화면 입력](review-data.json)은 이번 별도 패키지에 보존한다.

## v6 채점까지 남은 조건

현재 78개는 필터 조건 충족(포함 74·전체 제외 4)이다. 33개 사용자 확인과 Good all goodal 1개의 차단을 해소하기 전 전체 112개를 채점 가능으로 표시하지 않는다. 그 후 범위/GT 완전성 확인·승인과 버전 고정, v5 대응 방식의 한계 검토 및 v6 공식 전환 승인이 필요하다. 이번 작업에서는 GT 수정·동결, OCR 추론, CER 계산, 외부 API, 제품 코드 변경, 커밋·push·PR을 수행하지 않았다.
