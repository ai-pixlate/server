# OCR v6 UI 재검증 및 기술적 연결 보완

상태: 범위 후보 · GT 미수정/미동결 · CER 미실행. 이전 결과는 덮어쓰지 않고 이 폴더에 후속 범위·연결·감사 기록을 보존한다.

## UI와 초기화 확인

[검수 화면](../ocr-v6-review-ui-20261109/review.html)을 로컬 브라우저에서 연다. 특정 문구 강조, 대상 맞춤/원본 전체, 확대·이동, GT/OCR 및 연결 불확실성, AI 추천 근거, 포함/제외/보류와 이유, 저장/재조회/내보내기/미검수 필터/이전·다음을 구현했다.

- 모의 DOM·저장소 검증 통과: 초기 선택 없음, 추천 자동 승인 없음, 항목 간 저장 격리, 새 기록 복원, 구형 형식·다른 해시·없는 ID 거부.
- b3+ 오른쪽 강조 상자가 검정 제목 끝부분까지 덮던 부분을 표시 전용 overlay로 보정했다. 원본 해시가 일치할 때만 적용하며 승인 근거 데이터와 채팅 판정 해시는 바꾸지 않는다. 원본 확인과 DOM 좌표 검증은 수행했지만 실제 브라우저 렌더 확인은 별도다.
- 이전 61개 화면의 정확한 localStorage 키만 삭제하고 새 저장소로 이관하지 않는 것을 확인했다. 삭제 후 키가 실제 사라졌는지 재조회하는 검사도 추가했다. 삭제 실패·저장소 접근 불가는 완료로 표시하지 않는다.
- **실제 브라우저 저장소 삭제 및 시각·포인터 동작은 미확인**이다. 이전 Computer Use 안전 중단을 재시도하지 않았다. 파일 URL별 저장소 격리가 있는 경우 [이전 진입점](../ocr-v6-ai-scope-review-20261109/review.html)을 열어 초기화 후 새 화면으로 이동해야 한다. 새 화면만 열었다는 이유로 다른 파일 URL의 기록까지 삭제됐다고 주장하지 않는다.
- 과거 9개 항목 공식 검수 증거와 OCR Text v1/v2는 유지한다. UI 초기화 후 새로 받은 두 제외 판정은 [채팅 기록](../ocr-v6-review-ui-20261109/user-review-chat.json)으로 유지한다. 이를 이전 입력의 이관으로 취급하지 않는다.
- 두 정책 판단은 이미 완료됐다. 화면에 추가 선택 불필요 안내를 넣었으며 사용자 선택값을 자동 입력하지 않았다.

수동 확인은 초기화 안내, 주황색 대상과 실제 문구 일치, 드래그/확대, 임시 저장 후 새로고침 정도면 된다. 두 정책을 다시 판정할 필요는 없다.

## 보완 전 30개의 주원인

| 주원인(중복 없는 분류) | 섹션 수 |
|---|---:|
| GT 위치·의미 영역 연결 부족 | 14 |
| OCR 사각형과 고정 범위 경계 교차 | 13 |
| 혼합 OCR 문자열 및 GT 연결 | 1 |
| 과대한 OCR 사각형이 각주까지 교차 | 1 |
| 배경·전경 겹침 | 1 |

여러 원인이 겹친 섹션은 주원인 하나로 분류했다. 원래 전체 차단 사유는 [cause-classification.json](cause-classification.json)에 보존했다.

## 보완 결과

| 상태 | 보완 전 | 보완 후 |
|---|---:|---:|
| 필터 검증 완료 | 82 | **104** |
| 기술적 연결 차단 | 30 | **8** |

22개를 추가 해결했다. 완료 104개 중 적용 대상 100개, 전체 제외 4개이며 공식 채점 완료를 뜻하지 않는다. 추가 해결 ID는 [validation.json](validation.json)에 있다.

- 13개 경계 교차 섹션: 원본에서 설명 문구·캡션·후기·효능 수치 영역을 확인하고 경계를 보정했다. 포장 인쇄를 포함하거나 얼굴 전체를 포함하지 않았다.
- 9개 GT 연결 부족 섹션: 원문을 수정하지 않고 기존 GT 줄을 원본의 의미 영역에 연결했다. 실제 GT 줄 bbox가 아닌 의미 영역은 그렇게 명시했다.
- Q&A의 일반 설명은 포함하고 뒤로 비치는 포장 `3000`은 제외한다. 연구 사진 위 별도로 쓴 `the vita A`·`retinal`·`tightening`은 포함하고 제품 라벨/용기 인쇄는 제외한다.
- 24H 시계 심볼 내부 문구와 아래 별도 `24시간 지속` 설명을 구분한다. 포장·수상 배지는 제외하되 아래 별도 수상 결과·효능 설명은 포함한다.
- 빈 GT는 빈 원문으로 보존해 좌표를 발명하지 않는다. 승인된 빈 GT 제외 이외에는 빈 줄을 유지하며 출력은 별도로 원본 범위를 적용한다. 비어 있지 않은 GT의 연결 조건은 그대로다.

이번 작업에서 원본 28개 섹션을 직접 열어 확인했다. 숫자 3과 b3+는 직전 원본 검토·승인·해시 연결을 재사용했다. 일부 부분은 원본 크롭으로 재확인했으며 크롭은 개발 캐시에만 저장했다. 원본 파일과 GT 전사를 수정하지 않았다.

변경 영역·원본 이미지 해시는 [source-repairs.json](source-repairs.json), GT와 OCR의 모든 전후 판정은 [decision-transitions.json](decision-transitions.json), 전체 감사 기록은 [filter-audit.json](filter-audit.json)을 참조한다. OCR 원문에 맞춰 문자열을 나누거나 치환하지 않았다.

## 남은 8개와 대안

| 섹션 | 남은 기술적 문제 | 필요한 다음 작업 |
|---|---|---|
| GS-01_002/sec_1_04 | 설문 문구·수치와 POWDER ROOM 로고가 작은 원형 배지에 함께 배치됨. 아래 별도 설문 설명은 포함 대상 | 배지 내부 로고/설문 문구/곡선 제품명 연결을 세분화하고 GT·OCR 양쪽의 경계 검증. 배지 전체를 일괄 제외하지 않음 |
| GS-02_001/sec_1_03 | 앱·영수증 예시·제품 썸네일·QR과 별도 이벤트 안내가 혼재 | 안내/영수증 텍스트와 제품 인쇄·비텍스트 QR 영역 연결. QR 캡션·메뉴명까지 제외하지 않음 |
| GS-02_002/sec_1_01 | 원본에 없는 좌표형 GT L005·L006, 로고/포장/랭킹 배지·별도 설명의 연결 부족 | 기존 좌표형 GT 제외 결정을 근거로 비시각적 초안 오류의 제외 연결 방식을 검증하거나 후속 GT 버전에서 정정. 현재 동결본에 가짜 위치를 부여하지 않음 |
| GS-02_008/sec_1_04 | 논문 본문과 위에 겹친 3개 별도 인용문의 경계, 일부 GT 범위 연결 부족 | 문서 제외에서 인용문 포함 영역을 정확히 차감하고 교차 OCR를 검증. GT가 없다는 이유로 문서 밖 설명을 제외하지 않음 |
| GS-03_018/sec_1_08 | 여러 제품 인쇄/반사상과 BODY 콜아웃·레벨·효능표가 가까이 배치됨 | 제품별 GT 묶음과 별도 콜아웃의 의미 영역 연결. 반사상 reg_0044 제외를 유지하며 인접 설명을 제거하지 않음 |
| GS-01_002/sec_1_23 | `Good all goodal`이 일반 설명+로고를 단일 OCR 문자열로 반환 | 현재 region 항목에는 bbox/poly/region_key/score/text만 있고 문자별 위치가 없음. 기존 추가 증거에 문자/단어 위치가 있는지 검토하거나 이후 별도 승인된 출력 수집 방식 필요. 추측 분할·전체 제외 금지 |
| GS-03_005/sec_1_01 | 제외된 제형 숫자 `3`의 OCR bbox가 포함할 하단 각주까지 덮음 | 원본 요소와 OCR의 안전한 의미 연결 또는 세부 위치 증거 필요. 숫자 문자열만 보고 큰 사각형 전체를 제외하지 않음 |
| GS-03_014/sec_1_03 | 제외 배경 b3+가 포함 전경 제목과 겹침 | GT 요소의 배경/전경 연결 및 공통 필터 표현 방식 보완. 지금 대응 OCR이 없다고 GT만 먼저 제거하지 않음 |

앞의 5개는 연결 주석과 세부 검증이 아직 끝나지 않은 항목이며 기술적으로 불가능하다고 단정하지 않는다. 뒤의 3개는 현 사각형·단일 문자열만으로는 안전한 자동 처리를 입증하지 못했다. 모두 차단을 유지한다. 새로운 사용자 정책 선택은 요청하지 않는다.

## 검증과 v6 채점 전 조건

```powershell
python docs/ai-baseline/preparations/ocr-v6-connection-repair-20261109/build.py
python -m pytest tests/test_ocr_scope.py tests/test_ocr_scope_followup.py tests/test_ocr_scope_repair.py -q
node docs/ai-baseline/preparations/ocr-v6-review-ui-20261109/test-review.cjs
```

- 합성·회귀 테스트 **53개 통과**, UI 모의 검증 통과. 동일 원본 좌표에 서로 다른 문자열·중복·추가 문자열을 넣어도 GT/OCR 공통 범위 판정이 달라지지 않음을 검사했다.
- 112개 전부 재검증, 기존 완료 82개 회귀 없음. 원문 레코드 개수·순서·텍스트 보존 확인. 준비된 배열만 검사하고 CER 함수는 호출하지 않음.
- 보호 파일 **232개**, 원본·출력·GT 증거 색인 **159개** 해시 일치. 중복 포함 가능하므로 합산하지 않는다. 이전 결과 패키지는 보존했다.
- 자동 필터 통과가 독립적인 영역 정확도 100%를 뜻하지 않는다. 기존 의미 영역 연결 근거와 사용자 승인 범위를 함께 확인해야 한다.
- 남은 8개 연결 해결, 실제 번역 대상 GT 완전성 검증, v5 문자 대응 한계 검증, v6 범위/명세 버전 고정과 채점 승인까지 필요하다. 이번 작업에서는 GT 수정·동결·CER·OCR·API·커밋·push를 하지 않았다.
