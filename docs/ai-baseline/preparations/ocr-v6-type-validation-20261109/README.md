# OCR v6 유형별 범위 검증

상태: 필터 적용 가능성 검증. GT 승인·동결 및 CER 채점 아님.

| 상태 | 개선 전 | 개선 후 |
| --- | ---: | ---: |
| 검증 완료 | 2 | 46 |
| 사용자 확인 필요 | 109 | 65 |
| 채점 차단 | 1 | 1 |

검증 완료 46개는 전체 포함 40개, 전체 제외 4개, 기존 검증된 문서 혼합 2개다. 기존 확인 필요 109개 중 44개를 자동 검증 경로로 전환했다. 남은 65개는 전체 포함 후보 중 제외 요소 확인 33개와 기존 혼합 영역 연결 확인 32개다. 별도의 혼합 문자열 차단 1개까지 포함하면 미해결은 66개다.

## 조건과 근거

- 기존 75/4/33 분류에서 특허증·시험성적서 정책 반영 후 73/4/35가 된다. 기존 분류 원본은 보존한다. 이번에는 GS-02_013/sec_1_02의 인증서도 확인 대상으로 식별했으며, 별도 인용문을 제거하지 않는다.
- 전체 포함은 원본 개요 재확인으로 별도 제외 요소가 없는 설명·표·각주 패널만 등록했다. GT 줄 좌표 없이 모든 GT/OCR 문자열을 원순서로 보존한다. 누락·중복·추가 문구·빈 출력은 제거하지 않는다. 흰 여백 등 설명 패널 내부 오검출도 남는다.
- 전체 제외는 원본의 패키지/로고 또는 비텍스트 이미지라는 정책 근거와 이미지 해시를 기록한다. not_applicable이며 0% CER로 반환하지 않는다.
- 혼합은 기존 공통 영역 분할을 유지한다. 미검증 경계, GT 앵커, 혼합 문자열은 통과시키지 않는다. 이전 의미 연결과 OCR 기하 판정은 검토 보조자료로 재사용하며, 단순히 자동 판정됐다는 이유로 승인하지 않는다.
- Good all goodal은 일반 설명과 로고가 결합되어 안전한 분리가 검증되지 않았으므로 차단한다.
- 독립 정답에 대한 분류 정확도 측정은 하지 않았다. 검증 완료는 입력/범위 필터 조건 충족이며 전사 완전성·사람 승인·정확도 100%를 뜻하지 않는다.

## 산출물과 재현

- [원본 검토 근거](source-review.json): 이미지 해시·분류 판단·검토 근거. contact sheet 번호는 로컬 시각 점검 참고이며 재현 입력은 원본 이미지 경로/해시다.
- [섹션별 상태](section-status.json), [확인 목록](review-queue.json): 기존 영역 및 GT/OCR 연결을 함께 보존한다.
- [고정 영역](fixed-regions.json), [GT 연결](gt-region-links.json), [필터 추적](filter-audit.json), [검증 요약](validation.json)
- 재현: 저장소 루트에서 `python docs/ai-baseline/preparations/ocr-v6-type-validation-20261109/validate_inputs.py`
- 테스트: `python -m pytest tests/test_ocr_scope.py -q` — 30개 통과. 포함/제외/혼합, 해시 불일치, 제외 영역 삽입 방지, 포함 인용문 보존, 빈 OCR·누락·중복, 혼합 문자열 차단 및 입력 불변성 검증.
- 112개 이미지/출력 파일 해시와 보호 파일 232개 불변 확인. 기존 보고서·동결본·결과를 덮어쓰지 않았다.
