# OCR v6 사용자 검수 준비

> 검수 후 사용자 정책이 갱신됐다. D06 전체 포함은 채택하지 않으며 특허증·시험성적서 내부는 제외한다. 이 화면·후보는 당시 자료로 보존한다. [최신 정책·남은 미결](../../analyses/ocr-v6-policy-followup-20261109/README.md)을 우선한다.

미승인·미동결 검토 자료. [검수 화면](review.html)을 Chrome에서 직접 열면 된다. 서버·설치·모델 호출은 필요 없다. 기존 영역 비교 화면의 원본 SVG·GT/OCR 표시 방식을 재사용했다. 기존 GT 편집 서버는 GT 저장 기능이 있어 이번 판정 메모 화면에는 연결하지 않았다.

## 검토할 9개 카드

| ID | 확인 사항 | 추천(자동 적용 안 됨) |
|---|---|---|
| D01 | GS-01_001/sec_1_01 L054 + 위치 | 패키지 인쇄 제외, 위치 확인 먼저 |
| D02 | GS-01_002/sec_1_01 L005 빈 정답 의도/위치 | 보류. 위치 정보가 없어 영역을 임의 표시하지 않음 |
| D03·D04 | GS-02_002/sec_1_01 좌표형 GT 두 줄 | 보류 및 새 GT 교정 검토 |
| D05 | GS-01_002/sec_1_06 OCR o | 삽입 후보 포함 권고, 범위 귀속 결정 필요 |
| D06 | GS-01_002/sec_1_23 Good all goodal | 혼합 문자열 보류, 분리하지 않음 |
| D07 | GS-03_018/sec_1_08 reg_0044 반사상 | 인쇄 반사 범위 제외 권고 |
| G01 | GS-02_008/sec_1_05 특허증 내부 | 필드 누락·판독 불가 확인, 선명한 원본 필요 여부 |
| G02 | GS-03_014/sec_1_01 시험성적서 | 오른쪽 표·하단 반복 문구 및 왼쪽 L018 교정 후보 확인 |

범위 판정은 7개 항목·6개 섹션이다. D01–D06은 기존 사용자 판단 필요 5개 섹션과 정확히 일치하고 D07은 추가 반사상이다. GT 보완 3개 섹션 중 좌표형 숫자 항목은 D03·D04를 재사용하므로 중복 카드가 없다. 전체는 9개 카드·8개 원본 섹션이다.

## 기록 방법

1. 항목을 선택하고 확대/해당 위치 보기로 원본과 기존값을 비교한다. 주황색은 검토 위치이며 정밀 bbox 정답이 아니다. D01은 후보 위치, D02는 위치 없음, D03·04는 검수되지 않은 원본 GT bbox임을 구분한다.
2. 포함 / 제외 / 보류 중 하나를 고르고 메모에 위치·이유·GT 보완 후보에 대한 의견을 적는다. 기본값은 미선택이며 추천을 자동 입력하지 않는다.
3. **이 항목 의견 기록**을 누른다. 브라우저 localStorage에 임시 저장하며 GT 파일에 쓰지 않는다. 저장 실패 시 화면 경고를 확인하고 JSON을 내보낸다.
4. 마지막에 **검수 기록 JSON 내보내기**로 파일을 저장한다. 브라우저 임시 저장은 백업이 아니며 파일 위치/브라우저가 바뀌면 보이지 않을 수 있다. 내보낸 파일은 자료 SHA-256·항목 ID·판정·메모·시각에 연결된다. 동일 해시의 기록만 다시 불러올 수 있다.

의견 기록은 GT 승인·수정·동결이 아니다. GT 보완은 원본 이미지로만 판단한다. 기존 OCR 표는 연결 비교용으로 접어 두었으며 GT 전사 근거로 사용하면 안 된다. 이미지와 파일 경로는 로컬 전용이다.

## 보완 후보의 범위와 한계

- 특허증: 기존 제목·별도 설명은 유지하고 내부 필드의 누락을 검토한다. 원본 자체가 작아 번호·날짜·인명 전체 전사를 확정할 수 없다. 별도 설명의 숫자나 OCR 출력으로 빈칸을 채우지 않았다. 완성된 전사 초안이 아니라 보완 범위 후보다.
- 시험성적서: 왼쪽 본문은 기존 L011–024에 이미 있다. 두 보고서 전체가 미전사라는 이전 요약을 이번 자료에서는 정정했다. 오른쪽 표의 필드명 후보, L018 `최석배수 → 희석배수` 교정 후보, 하단 중복 인용 범위를 구분했다. 표 값·가려진 행은 미확정이다.
- 좌표형 GT: 실제 원본 문자 근거가 없는 메타데이터 혼입 의심이다. 새 버전 삭제/교정 검토만 제시하며 기존 두 줄은 그대로 유지했다.

후속 순서: 사용자 의견 회수 → 정책/앵커 미결 정리 → 승인된 범위의 별도 GT 보완 초안 → 사용자 검수·새 범위 동결 → 대칭 필터·v6 채점기 검증. **현재 혼합 섹션 채점 차단은 해소되지 않았다.** D06 혼합 반환값과 포함 설명 창 우선 규칙 등 공통 명세 합의도 남아 있다.

## 검증

생성: `python docs/ai-baseline/preparations/ocr-v6-user-review-20261109/build.py`

테스트: `node docs/ai-baseline/preparations/ocr-v6-user-review-20261109/test-review.cjs`

데이터는 [review-data.json](review-data.json), 출처 해시는 [source-hashes.json](source-hashes.json), 생성 검증은 [validation.json](validation.json)에 있다. 이전 Computer Use 안전 중단을 재시도하거나 우회하지 않았다. **브라우저 시각·클릭·다운로드 동작 검증은 미완료**이며 데이터/상태 로직·JS 구문 검사와 구분한다. 사용자가 화면을 열어 이미지 표시·확대·의견 저장·JSON 내보내기를 확인해야 한다.

공식 GT·OCR·CER·제품 코드 변경, 승인·동결, 모델 호출, 커밋·push·PR 없음.
