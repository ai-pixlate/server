# 지표 집계 방식

> 상태: 기존 지표 정의 유지 · 2026-10-28 회차 범위 변경 PM 검토 대기 · 공식 실측 미실행 · 비용·실행 승인 보류

지표별 단위·분자·분모·계산식·예외의 소유 문서다. 기준 단위는 [평가셋](dataset.md#평가-대상과-단위), 체크포인트와 결함·판정 기준은 [평가 기준](evaluation.md)을 따른다.

## 공통 집계 규칙

### 평가 상태

- `measured`: 정상 평가 완료
- `not_applicable`: 해당 지표의 평가 대상이 아님
- `undetermined`: 산출물은 있지만 판단하기 어려움
- `no_output`: [해당 지표·단계·처리 대상의 필수 산출물 부재](evaluation.md#실행-결과-상태)
- `evaluation_failed`: 평가 수행 또는 출력·기록 처리 실패(상태값은 유지하며 Codex 채팅 평가에도 적용)

### 품질 비율과 평가 가능률

품질 적합률과 A/B/C 분포 등 품질 판단 지표는, 개별 지표에서 별도 규칙을 명시하지 않은 한 `measured` 상태인 정상 측정 단위만 분모로 사용한다.

```txt
품질 적합률 = 적합 판정 단위 수 ÷ 정상 측정 단위 수 × 100
평가 가능률 = 정상 측정 단위 수 ÷ 전체 적용 대상 수 × 100
```

H01과 보조 운영지표처럼 개별 분모를 명시한 경우 해당 정의를 우선한다. H05의 수정 건수·분포·평균은 각 표시 단위를 따르며 임의로 품질 적합률로 바꾸지 않는다.

예를 들어 적용 대상 10개 중 2개가 `undetermined`이고 나머지 8개가 모두 적합하면, 품질 적합률은 `8/8=100%`, 평가 가능률은 `8/10=80%`, 판단 불가 2건으로 기록한다.

예외 상태를 조용히 제외하지 않고 각각의 건수를 함께 표시한다.

### 계산 가능한 분모가 0인 경우

- 전체 적용 대상 수가 0이면 `— / 해당 대상 없음`으로 표시한다.
- 전체 적용 대상은 있지만 정상 측정 수가 0이면 `— / 정상 측정 0건`으로 표시하고 `undetermined`, `no_output`, `evaluation_failed` 등의 원인을 함께 기록한다.
- 평가 실패나 산출물 없음으로 정상 측정이 0건인 경우를 “해당 대상 없음”으로 표시하지 않는다.

백분율 계산식은 `분자 ÷ 분모 × 100`이다. 건수·평균·분포를 요구하는 지표를 임의의 단일 비율로 바꾸지 않는다. 개별 정의에 따른 계산 분모가 양수인 지표에 정상 측정 0건 표시를 일괄 적용하지 않는다.

## 이번 회차 적용 범위

[회차 범위 변경](../../plan.md#이번-회차-측정-범위--pm-검토-대기)은 PM 검토 대기다. 아래 H01~H05·OP06의 기존 정의·계산식은 유지한다. 이번 회차는 H01~H04만 측정하며 H05와 사용자 수정 회복 분석은 `미측정(별도 서비스 평가 예정)`이다. 무수정 조건에서 관찰한 변경 없음으로 H05를 0건·무개입 성공률 등으로 산출하지 않는다. 범위 제외는 평가 실패나 not_applicable과 다르며 [회차 기록 규칙](../../runs/README.md#이번-회차의-범위-기록)을 따른다.

## 핵심 지표 5개

기존 핵심 지표 체계는 아래 5개를 유지한다. 이번 회차 발표·요약에는 H01~H04 측정 결과와 H05 미측정 사유를 구분해 표시한다. A/B/C의 결함 수 기준은 [평가 문서](evaluation.md#사용-가능성-abc)가 소유한다.

### H01. 기대 산출물 생성률

- 단위: 원본 이미지
- 분모: **정답 기준으로** 최종 산출물이 생성돼야 하는 원본 수
- 분자: 정상 최종 deliverable이 생성된 원본 수
- 계산: `분자 ÷ 분모 × 100`
- `blocked`와 `no_output`은 실패로 분모에 포함한다.
- `not_applicable`만 분모에서 제외하며, 정답 기준에서도 해당 원본의 모든 섹션 제외가 맞을 때만 사용한다.
- 잘못된 시스템 판정으로 전부 제외됐다면 `not_applicable`이 아니라 `decision_wrong` 결함과 산출물 실패로 기록한다.

### H02. 최초 결과 사용 가능 등급

- 단위: 원본 이미지
- 대상: `machine_snapshot`
- 결과: A/B/C 건수와 비율
- 계산: `각 등급 원본 수 ÷ measured 상태의 정상 평가 원본 수 × 100`
- 함께 표시: `no_output`, `undetermined`, `evaluation_failed` 건수, 평가 가능률, N3 개입 구분

### H03. 최종 결과 사용 가능

- 단위: 원본 이미지
- 대상: `service_final`
- 대표 수치: `A등급 원본 수 ÷ 정상 평가된 최종 결과 원본 수 × 100`
- 함께 표시: A/B/C 건수·비율, 미해결 `critical`·`major` 결함 수, 중대 결함 보유 원본 수, 예외 상태와 평가 가능률
- H02와 H03을 함께 제시해 최초 결과와 최종 결과를 구분한다.

기존 최종 미해결 중대 결함률은 별도 핵심 지표가 아닌 상세 결과다. `미해결 critical 또는 major 결함이 1건 이상 있는 원본 수 ÷ 정상 평가된 최종 결과 원본 수 × 100`으로 표시할 수 있다. 최종 이미지 없음은 A/B/C나 중대 결함률에 강제로 넣지 않고 H01의 산출물 실패와 별도 `no_output` 건수에 반영한다.

### H04. 핵심 정보 보존율

- 단위: 해당 결과에 표시돼야 하는 `critical_fact`
- 체크포인트: `machine_snapshot`, `service_final` 각각 측정
- 분자: 값이 정확하고 실제 이미지에서 판독 가능한 핵심 사실 수
- 기본 분모: `measured` 상태인 적용 핵심 사실 수
- 계산: `정확하고 판독 가능한 핵심 사실 수 ÷ 정상 측정 핵심 사실 수 × 100`
- 평가 가능률: `measured 수 ÷ 전체 적용 대상 수 × 100`

핵심 정보 후보는 상품명·브랜드명, 용량·수량·비율, SPF·PA·시험 수치, 주요 또는 강조 성분, 사용법·사용 횟수·사용 조건, 경고·주의사항, 제품 대상·효능 조건, 규제 판단에 직접 영향을 주는 표현이다. 기준 자료의 사람 확인·동결은 [평가셋](dataset.md#평가-기준-자료)을 따른다. 번역 데이터가 정확해도 실제 이미지에서 읽을 수 없으면 보존 성공으로 세지 않는다.

### H05. 사용자 수정 부담

하나의 합성 점수로 만들지 않고 다음 분포·건수를 함께 표시한다. 수정 1건의 기준은 [사용자 수정 규칙 초안](evaluation.md#사용자-수정-규칙-초안)을 따른다.

- 원본별 수정 0건 / 1건 / 2~3건 / 4건 이상 분포
- N3에서 변경한 섹션 수
- N5에서 수정한 번역 블록 수
- 수정 발생 이미지당 평균 변경 섹션 수·수정 블록 수: 각 건수를 수정 발생 이미지 수로 나누어 별도 표시
- 사용자 재시도는 수정 건수와 분리
- `수정 0건이면서 최종 A등급`인 원본 수는 내부 교차 분석으로 표시 가능

기존 완전 무개입 완료율은 별도 핵심 지표로 두지 않는다. N5 텍스트 박스 크기·위치 수정은 [v1.0.1 기능 확인](evaluation.md#n5-박스-수정-기능-확인)에 따라 `기능 미지원`으로 별도 표시하며 H05에 포함하거나 0건으로 채우지 않는다.

## 단계 진단 방식

단계별 독립 적합률 8개를 공식 필수 지표로 채점하지 않는다. 핵심 지표 평가 중 찾은 각 결함에 처음 발생한 단계 하나를 연결한다. 지정·전파·중복 처리 규칙은 [원인 단계와 발견 단계](evaluation.md#원인-단계와-발견-단계)를 따른다.

원인 단계:

1. 섹션 분해
2. OCR
3. 블록 병합·역할 분류
4. 규제·현지 판정·정책 적용
5. 제품 라벨·브랜드 로고 판정
6. 인페인팅
7. 번역·현지화
8. 렌더·배치

원인 증거가 부족하면 `origin_stage=undetermined`로 기록한다. 이는 결함 자체의 평가 상태와 별개다. 결함과 심각도가 확인돼도 원인 단계만 불명일 수 있다.

진단 결과는 다음과 같이 표시한다.

```txt
최초 발생 단계 × critical / major / minor 결함 건수
+ 영향을 받은 원본 수
+ origin_stage=undetermined 건수
```

영향 원본은 고정 `source_key`로 중복을 제거해 센다. 같은 원본이 여러 원인 단계의 영향을 받을 수 있으므로 단계별 영향 원본 수의 합을 전체 고유 원본 수로 사용하지 않는다. 원인 불명 건수가 많으면 단계 진단의 신뢰도가 낮다는 뜻이므로 숨기지 않는다.

### 자동 계산 보조 신호

실제 구조화 결과에서 직접 계산 가능한 경우에만 번역문 누락, 강제 용어 미적용, placeholder 노출, 렌더 overflow, 산출물 누락, 실행 실패·재시도·fallback, 규격 검증 결과를 별도 표시한다. 신호만으로 결함 심각도나 원인 단계를 자동 확정하지 않는다.

### 사용자 수정 회복 분석

기존 사용자 수정 회복률은 핵심 지표에서 제외하고 다음 두 내부 파생 결과로 유지한다. 이번 회차에는 두 분석 모두 미측정이며 후속 서비스 평가에서 사용한다. N6 렌더에 따른 차이를 사용자 수정 회복으로 세지 않는다.

- AI `original_verdict` → N3 사용자 최종 선택: 사용자 변경으로 해결된 섹션 판정 결함 수
- `machine_snapshot` → `service_final`: 사용자 수정으로 해결된 번역 결함 수

`corrected_by_user`로 기존 결함과 연결하며 자동 결과의 결함을 삭제하거나 심각도를 낮추지 않는다. 두 시점의 결과를 하나의 통합 회복률로 합산하지 않는다.

## Baseline 보조 운영지표 7개


보조 운영지표는 운영자 화면을 새로 구현하기 위한 범위가 아니다. 고정 평가셋 실행에서 기존 실행 기록과 사용량으로 확인 가능한 값을 품질 결과와 함께 기록한다. 요구사항정의서 v3.5.9의 `02_기능명세`와 `11_용어집` 정의를 참고하되, 실제 서비스 장기 운영지표와 baseline 격리 실행 결과를 동일하게 해석하지 않는다.


### OP01. 작업 완료·단계 도달 현황

- 작업 완료율: `완료 작업 수 ÷ baseline 기간에 생성된 작업 수 × 100`
- 완료는 저장과 첫 다운로드 중 먼저 발생한 시점
- N2·N4·N6 단계별 도달·완료·중단 건수와 도달률 기록
- baseline은 통제 실험이므로 72시간 이탈률보다 실제 건수를 우선 표시

### OP02. 단계별 실행 안정성

논리 실행 단위:

```txt
평가 회차 + 단계 + 처리 대상 ID
```

같은 대상의 재시도는 하나의 논리 실행 단위로 묶는다.

상태 정의는 [실행 결과 상태](evaluation.md#실행-결과-상태)를 따른다.

상태별 건수·비율, 작업 오류, 부분 실패, 오류 코드별 영향 작업 수를 기록한다. 같은 작업의 같은 오류 코드는 반복돼도 1건, 다른 오류 코드는 각각 센다.

### OP03. 자동 재시도·대체 처리

자동 재시도 발생률:

```txt
자동 재시도가 1회 이상 발생한 논리 실행 단위 수
÷ 전체 실행 논리 단위 수 × 100
```

총·단계별 재시도, 회복 수, 한도 소진 수를 기록한다.

fallback은 종류별로 별도 계산한다.

- 원본 전체 섹션 fallback ÷ 분할 대상 원본
- 원본 배경 fallback ÷ 인페인팅 필요 섹션
- 기본 스타일 사용 ÷ 스타일 적용 대상 섹션
- 부분 번역 진행 ÷ 번역 대상 섹션

### OP04. 처리시간

사람의 N3·N5 검수 대기시간과 시스템 처리시간을 분리한다.

- N2: 분석 실행 시작 → N3 진입
- N4: N4 진행 시작 → N5 진입
- N6: 최종 확정 → 최종 렌더 완료
- 전체 시스템 처리시간: N2 + N4 + N6

작업별 값, 평균, 중앙값과 원본 수로 나눈 참고값을 표시한다. 현재 기록으로 분리할 수 없는 ①·②·③ 개별 시간은 `미측정`으로 둔다.

### OP05. 모델·자원 사용량과 비용

- 제품 생성의 단계·용도별 모델 호출, 토큰, GPU 시간, 추론 횟수, 렌더 시간
- 자동 재시도·재렌더 사용량 포함

작업 원가:

```txt
Σ(용도별 사용량 × 단가)
```

- 건당 원가: `완료 작업 원가 합 ÷ 완료 작업 수`
- 섹션당 원가: `작업 원가 ÷ N2 전체 섹션 수`
- 원본당 비용도 확인 가능한 배분 근거와 함께 기록하며, 근거가 없으면 임의로 나누지 않고 미산정으로 표시
- 작업별 원가와 P50·P90 기록. 표본이 적으면 `참고값 / 표본 적음(n건)` 표시
- 단가가 없으면 금액을 추정하지 않고 원래 단위로 기록
- 제품 생성 비용과 Codex 평가 관련 사용량·비용을 분리. 평가용 LLM API는 호출하지 않으며 확인할 수 없는 채팅 사용량·비용을 0으로 채우지 않음

### OP06. 무수정 승인률·사용자 수정 신호

`무수정 승인률`은 내부 기록에 유지하되 발표 지표에서 제외한다. 기존 계산식과 H05 사용자 수정 부담의 정의는 유지한다. 이번 회차 OP06은 무수정 실험 조건에 따른 내부 관찰값일 뿐 실제 사용자의 승인 성과·수정 불필요성·만족도로 해석하거나 발표하지 않는다.

운영지표 무수정 승인률:

```txt
N5 번역문을 한 글자도 수정하지 않고 처음 확정한 완료 작업 수
÷ 최초 N5 확정을 거친 완료 작업 수 × 100
```

- N3 섹션 변경은 번역문 수정으로 세지 않음
- 번역 실패의 빈 칸을 직접 입력하면 수정
- 저장 후 수정은 제외
- 첫 N5 확정 시점 기준

함께 기록할 신호:

- N3 변경 섹션 수
- N5 수정 블록 수와 수정 전·후 문장
- 규제 제안 해제 수
- 검증 통과 후 직접 수정한 수
- 빈 번역 직접 입력 수

PRD O1의 `무수정 승인률`은 H05의 수정 부담·내부 교차 분석과 구분한다.

### OP07. 규제·규격 결과 분포

규제 판정 통과율:

```txt
N2 판정을 정상 완료한 섹션 중 규제 판정이 0건인 섹션 수
÷ N2 규제 판정을 정상 완료한 섹션 수 × 100
```

- 허용 행은 규제 판정 건수에서 제외
- 번역문 재대조 결과는 포함하지 않음
- 판정 실패 섹션은 분모에서 제외하고 실패 건수로 별도 표시

규격 검증 통과율:

```txt
N6 규격 검증 통과 파일 수
÷ N6 규격 검증을 받은 전체 파일 수 × 100
```

자동 제외 섹션, 현지 기준 미검사 섹션, 규제 판정 실패 섹션도 별도 집계한다. 이 값은 운영 결과 분포이며, 판정 결함은 [단계 진단](#단계-진단-방식)에서 다루며 OI-54와 구분한다.

## 비슷한 지표의 구분

- H01은 원본 이미지의 기대 산출물 생성, OP01은 상품 작업의 완료를 측정한다.
- H05는 N3·N5의 사용자 수정 부담, OP06은 PRD O1의 N5 무수정 승인을 다룬다.
- 규제·현지 판정 결함 진단은 기대값과 실제 처리의 차이를 기록한다. OP07은 판정·규격 결과 분포이며 OI-54는 별도 평가셋의 검출 재현율이다.
- H04는 결과 이미지의 핵심 정보 보존을 측정하고, 원인 단계 진단은 그 정보가 어디서 손상됐는지 근거로 설명한다.

## 별도 평가 트랙

### OI-54. 규제 위험 표현 검출 재현율

Baseline 이미지 전체 평가와 분리된 독립 평가셋을 사용한다. 공식 명칭은 **규제 위험 표현 검출 재현율**이다.

```txt
검출한 실제 위험 표현 수 ÷ 실제 위험 표현 전체 수 × 100
```

같은 평가셋에서 정상 또는 허용 표현을 위험으로 잘못 검출한 **정상·허용 표현 오탐 건수**도 함께 표시한다. Baseline의 규제·현지 판정 결함은 내부 진단으로 사용하며 이 재현율에 섞지 않는다. 현지 판정 정확도는 발표 수치로 사용하지 않는다.

### NFR-15. 인페인팅 텍스트 잔존

후속 과제의 순서는 잔존 정의 → 분모 결정 → 자동 측정 방식 검증 → V1 결과 실측 → PM 검토 후 기준값 확정이다. 현재 자동 측정법·분모·기준값은 미확정이다.

분모 검토 후보는 `잔존 텍스트가 발견된 삭제 대상 영역 수 ÷ 전체 삭제 대상 텍스트 영역 수`이며 공식 계산식으로 확정한 것이 아니다. 삭제 마스크 픽셀 수를 잔존율로 직접 사용하지 않는다.

## 최종 결과 표시 원칙

비율 지표는 분자·분모와 비율을, 등급 지표는 A/B/C 건수·분포를 표시한다. 건수·분포 중심인 수정 부담과 단계 진단에 비율을 강제하지 않는다. 각 결과에는 적용 가능한 다음 정보를 함께 표시한다.

```txt
분자 / 분모
비율 또는 A/B/C 분포
not_applicable 수
undetermined 수
no_output 수
evaluation_failed 수
AI만 판정한 수
사람이 확인한 수
```

핵심 지표, 원인 단계별 결함 진단, 보조 운영지표를 하나의 종합점수로 합치지 않는다.

GS-01·02·03별 결과와 전체 결과를 함께 표시한다. 상품별 원본 수가 다르므로 전체 비율만으로 판단하지 않는다. 사람이 일부 영역을 확인한 것을 원본의 모든 지표에 대한 사람 검수 완료로 확대하지 않는다.

## 판정·제외의 세부 집계

규제·현지 판정 결함 진단은 사람이 확인한 고정 `policy_expectation`과 실제 처리를 대조한다. 제외된 영역도 평가하며, 같은 기준 단위를 현재 섹션 수만큼 중복 집계하지 않는다. 정상 제외로 대상이 없는 하류 지표는 `not_applicable`, 잘못된 제외로 필요한 산출물이 없으면 `no_output`과 원인을 기록하고 해당 판정 결함에 연결한다. 최종 이미지에서 관찰되는 누락은 직접 평가하되 전파 결함의 중복은 [원인 단계와 발견 단계](evaluation.md#원인-단계와-발견-단계) 규칙을 따른다.

이 진단은 고정셋 기대 처리 대조이며 OI-54의 규제 위험 표현 검출 재현율이나 NFR-14 충족 근거가 아니다. 사람이 확인한 기대값이 없는 항목은 참고용 진단으로만 사용한다. 판정과 증거의 파일 연결은 [8단계 결과 구조](../../runs/README.md)를 따른다.

정당한 전체 섹션 제외와 함께 사라진 유용한 정보는 정책 준수와 구분해 기록한다. 부분 보존을 요구하는 새 제품 정책을 평가 문서에서 만들지 않는다.

## 공식 버전 비교

동일한 고정 기준 단위와 평가 조건으로 비교한다. H02·H03의 사용 가능성에는 원본별 A/B/C 전이와 예외 상태 전이를 표시하고, 다른 지표에는 해당 단위와 계산식을 사용한다. 원본 A/B/C를 모든 지표에 강제하지 않는다.

기존 결함 ID와 위치·근거를 보존하고, 후속 버전의 개선·퇴행과 신규 결함을 추적한다. 한 결함을 여러 박스로 표시하거나 분할·병합됐다는 이유로 중복 집계하지 않는다. 같은 원본·내용 또는 대상·결함 유형으로 대응시키며 좌표 겹침만으로 확정하지 않는다. 뒤늦게 찾은 baseline 결함과 신규 퇴행을 구분한다.

### 후속 비교 출력 제안

8단계 파일 구조와 연결은 [회차 결과 구조](../../runs/README.md)를 따른다. 버전 간 변화와 [회차 내 결함 해결 상태](evaluation.md#결함-해결-상태)를 구분한다. P90 산출 방식과 애매한 결함 대응의 추가 검수 방식은 미정으로 유지한다.
