# 지표 집계 방식

> 상태: `v1-draft` · `pm_review_pending` · 1~5단계 사용자 확정 · PM 승인 전 · 공식 실측 승인 전

지표별 단위·분자·분모·계산식·예외의 소유 문서다. 기준 단위는 [평가셋](dataset.md#평가-대상과-단위), 체크포인트와 결함·판정 기준은 [평가 기준](evaluation.md)을 따른다.

## 공통 집계 규칙

### 평가 상태

- `measured`: 정상 평가 완료
- `not_applicable`: 해당 지표의 평가 대상이 아님
- `undetermined`: 산출물은 있지만 판단하기 어려움
- `no_output`: [해당 지표·단계·처리 대상의 필수 산출물 부재](evaluation.md#실행-결과-상태)
- `evaluation_failed`: 평가 AI 호출 또는 출력 처리 실패

### 품질 비율과 평가 가능률

품질 적합률과 A/B/C 분포 등 품질 판단 지표는, 개별 지표에서 별도 규칙을 명시하지 않은 한 `measured` 상태인 정상 측정 단위만 분모로 사용한다.

```txt
품질 적합률 = 적합 판정 단위 수 ÷ 정상 측정 단위 수 × 100
평가 가능률 = 정상 측정 단위 수 ÷ 전체 적용 대상 수 × 100
```

개별 지표에서 “기준 단위 수”라고 쓴 경우에도 품질 적합률의 분모는 정상 측정된 기준 단위 수를 뜻한다. H01·H05·H06·보조 운영지표처럼 전체 적용 대상을 명시적으로 분모로 정의한 지표는 해당 개별 정의를 우선한다.

예를 들어 적용 대상 10개 중 2개가 `undetermined`이고 나머지 8개가 모두 적합하면, 품질 적합률은 `8/8=100%`, 평가 가능률은 `8/10=80%`, 판단 불가 2건으로 기록한다.

예외 상태를 조용히 제외하지 않고 각각의 건수를 함께 표시한다.

### 계산 가능한 분모가 0인 경우

- 전체 적용 대상 수가 0이면 `— / 해당 대상 없음`으로 표시한다.
- 전체 적용 대상은 있지만 정상 측정 수가 0이면 `— / 정상 측정 0건`으로 표시하고 `undetermined`, `no_output`, `evaluation_failed` 등의 원인을 함께 기록한다.
- 평가 실패나 산출물 없음으로 정상 측정이 0건인 경우를 “해당 대상 없음”으로 표시하지 않는다.

백분율 계산식은 `분자 ÷ 분모 × 100`이다. 건수·평균·분포를 요구하는 지표를 임의의 단일 비율로 바꾸지 않는다. H06-A~C와 D05-A·B를 백분율로 표시할 때도 해당 비에 100을 곱한다. 개별 정의에 따른 계산 분모가 양수인 지표에 정상 측정 0건 표시를 일괄 적용하지 않는다.

## 핵심 품질 지표 8개

### H01. 기대 산출물 생성률

- 단위: 원본 이미지
- 분모: 최종 산출물이 생성돼야 하는 원본 수
- 분자: 정상 최종 deliverable이 생성된 원본 수
- 계산: `분자 ÷ 분모 × 100`
- 의도적으로 모든 섹션이 제외된 원본은 `not_applicable`, 기술적 누락은 `no_output`

### H02. 최초 생성 결과 사용 가능성

- 단위: 원본 이미지
- 대상: `machine_snapshot`
- 결과: A·B·C 건수와 비율
- 계산: `각 등급 원본 수 ÷ 정상 측정 원본 수 × 100`
- N3 단순 확인·선택 변경·불명을 나눠 표시

### H03. 최종 서비스 결과 사용 가능성

- 단위: 원본 이미지
- 대상: `service_final`
- H02와 같은 A/B/C 기준과 계산식 사용
- H02와 H03을 함께 제시해 자동 품질과 최종 서비스 품질을 구분

### H04. 핵심 정보 보존율

- 단위: `critical_fact`
- `machine_snapshot`, `service_final` 각각 측정
- 분모: 해당 결과에 표시돼야 하는 `critical`·`important` 핵심 사실 수
- 분자: 값이 정확하고 이미지에서 판독 가능한 핵심 사실 수
- 번역 데이터가 정확해도 렌더 이미지에서 읽을 수 없으면 실패

### H05. 완전 무개입 완료율

- 단위: 원본 이미지
- 분모: 최종 산출물이 생성돼야 하는 원본 수
- 분자: 아래 네 조건을 모두 만족한 원본 수
  1. N3 섹션 포함·제외 변경 없음
  2. N5 번역문 수정 없음
  3. 사용자 재시도 없음
  4. `service_final` 등급 A
- 자동 재시도는 사용자 개입으로 세지 않음

### H06. 사용자 수정 부담

- H06-A 사용자 수정 발생 원본 비율: `실제 변경이 발생한 원본 수 ÷ N3·N5 검수 원본 수`
- H06-B N3 섹션 변경률: `AI 최초 판단과 다르게 변경한 섹션 수 ÷ 검토된 전체 섹션 수`
- H06-C N5 번역문 수정률: `최초 확정 전 수정한 블록 수 ÷ N5 자동 번역 대상 블록 수`
- H06-D 수정 발생 이미지당 평균 수정량: 변경 섹션과 수정 블록을 서로 합치지 않고 각각 계산
- 단순 확인은 수정으로 세지 않으며, 빈 번역을 직접 입력한 경우는 수정으로 셈

### H07. 사용자 수정 회복률

N3와 N5는 비교 시점과 수정 대상이 다르므로 하나의 대표 비율로 합산하지 않고 두 하위 결과를 함께 표시한다.

#### H07-A. N3 섹션 판정 회복률

- 단위: N3에서 직접 수정 가능한 섹션 판정 결함
- 비교 시점: AI `original_verdict` → N3 사용자 최종 선택
- 분모: AI 최초 판정에 존재하며 N3에서 직접 수정 가능한 결함 수
- 분자: 사용자의 섹션 포함·제외 변경으로 해소된 결함 수
- 계산: `N3에서 corrected_by_user인 결함 ÷ N3 직접 수정 가능 결함 × 100`

#### H07-B. N5 번역 수정 회복률

- 단위: N5에서 직접 수정 가능한 번역 결함
- 비교 시점: `machine_snapshot` → `service_final`
- 분모: `machine_snapshot`에 존재하며 N5에서 직접 수정 가능한 결함 수
- 분자: 사용자의 번역문 수정 후 `service_final`에서 해소된 결함 수
- 계산: `N5에서 corrected_by_user인 결함 ÷ N5 직접 수정 가능 결함 × 100`

각 하위 지표에서 직접 수정 가능한 결함이 0건이면 `— / 해당 대상 없음`으로 표시한다. 적용 대상이 있으나 정상 측정이 0건인 경우와의 구분은 [분모 0 처리](#계산-가능한-분모가-0인-경우)를 따른다.

### H08. 최종 미해결 중대 결함률

- 단위: 원본 이미지
- 분모: 최종 이미지가 생성되고 정상 평가된 원본 수
- 분자: 미해결 `critical` 또는 `major` 결함이 1건 이상 있는 원본 수
- 함께 표시: 중대 결함 보유 원본 비율, `critical` 건수, `major` 건수, 결함 유형별 건수
- 최종 이미지 없음은 H08이 아니라 H01의 `no_output`

## 단계 진단 지표 8개

단계 진단의 적합 여부는 [판정 기준](evaluation.md#단계-진단-적합-기준)을 따른다.

### D01. 분할 보존 적합률

- 단위: `layout_region`
- 분모: 원본에서 보존돼야 하는 기준 영역 수
- 분자: 한 섹션에 누락·중복·절단 없이 포함되고 순서·문맥이 유지된 영역 수
- 섹션 수·높이·원본 전체 fallback은 근거 정보일 뿐 점수로 사용하지 않음

### D02. OCR 정보 보존율

- 단위: `text_span`
- 분모: OCR해야 하는 기준 텍스트 범위 수
- 분자: 의미에 영향을 주는 누락·대치·중복 없이 추출된 범위 수
- 하나의 기준 텍스트가 여러 OCR 영역으로 나뉘어도 전체 텍스트가 정확하면 허용
- 원본에 없는 OCR은 `spurious 영역 수`와 영향 원본 수로 별도 기록

### D03. 블록 구조·역할 적합률

- 단위: `semantic_block`
- 분모: 기준 의미 블록 수
- 분자: 병합·읽기 순서·역할이 모두 적합한 의미 블록 수
- 병합·분리 적합률, 읽기 순서 적합률, 역할 분류 적합률도 하위 결과로 표시
- 의미·후속 처리를 바꾸지 않는 경미한 과분리는 `minor`로 기록하고 적합 가능

### D04. 규제·현지 판정 적합률

- 단위: `policy_expectation`
- 분모: 기준 판정이 정의된 기대 단위 수
- 분자: finding, 근거, include/exclude, 대체·완충 지시 중 해당 단위에 적용되는 항목이 모두 맞은 수
- finding 검출, include/exclude 결정, 대체·완충 지시 적합률을 하위 결과로 표시
- 명시적 `not_inspected`는 `undetermined`로 기록하고 정상 판정으로 간주하지 않음

### D05. 보호 대상 판정 적합률

두 하위 지표를 별도로 표시한다.

- D05-A 보호 대상 정상 판정률: `올바르게 보호한 기준 대상 수 ÷ 보호해야 할 기준 대상 수`
- D05-B 일반 번역 대상 정상 판정률: `정상적으로 번역 대상으로 둔 일반 텍스트 수 ÷ 일반 번역 대상 기준 수`
- 제품 라벨·브랜드 로고의 false positive·false negative를 별도 집계

### D06. 인페인팅 품질 적합률

- 단위: 인페인팅 대상 섹션
- 분모: 삭제 대상 텍스트가 하나 이상 있는 섹션 수
- 분자: 텍스트 삭제, 보호 대상 보존, 배경 자연스러움 세 조건을 모두 만족한 섹션 수
- 하위 결과: 삭제 대상 `text_span` 제거 적합률, `protected_visual` 보존율, 섹션 배경 자연스러움 적합률
- 삭제 대상이 없는 섹션의 `unchanged`는 `not_applicable`

### D07. 번역·현지화 적합률

- 단위: 번역 대상 `text_span`
- 분모: 실제 번역돼야 하는 기준 텍스트 수
- 분자: 의미·사실과 자연스러움·용어가 모두 허용 수준인 번역 수
- D07-A 의미·사실 보존율과 D07-B 자연스러움·용어 적합률을 분리해 표시
- 수치·단위·조건·고유명사·주의사항, 정보 추가·누락, 강제 용어, placeholder를 확인
- 번역문이 비어 있으면 전체 부적합

### D08. 렌더 가독성·배치 적합률

- 단위: 렌더 대상 번역 블록
- 분모: 비어 있지 않은 유효 번역문을 가진 렌더 대상 블록 수
- 분자: 실제 렌더, 잘림·overflow, 겹침, 크기·대비, 상품 침범, 배치·정렬이 모두 허용 수준인 블록 수
- 번역 입력 자체가 비어 있으면 D08 분모에서 제외하고 D07에서 처리
- `overflow=false`만으로 자동 적합 처리하지 않음

## Baseline 보조 운영지표 7개


보조 운영지표는 운영자 화면을 새로 구현하기 위한 범위가 아니다. 고정 평가셋 실행에서 기존 실행 기록과 사용량으로 확인 가능한 값을 품질 결과와 함께 기록한다. 요구사항정의서 v3.5.9의 `02_기능명세`와 `11_용어집` 정의를 참고하되, 실제 서비스 장기 운영지표와 baseline 격리 실행 결과를 동일하게 해석하지 않는다.


### OP01. 작업 완료·단계 도달 현황

- 작업 완료율: `완료 작업 수 ÷ baseline 기간에 생성된 작업 수 × 100`
- 완료는 저장과 첫 다운로드 중 먼저 발생한 시점
- N2·N4·N6 단계별 도달·완료·중단 건수와 도달률 기록
- baseline은 통제 실험이므로 72시간 이탈률보다 실제 건수를 우선 표시

### OP02. 단계별 실행 안정성

논리 실행 단위:

```txt
평가 회차 + 단계 + 처리 대상 ID
```

같은 대상의 재시도는 하나의 논리 실행 단위로 묶는다.

상태 정의는 [실행 결과 상태](evaluation.md#실행-결과-상태)를 따른다.

상태별 건수·비율, 작업 오류, 부분 실패, 오류 코드별 영향 작업 수를 기록한다. 같은 작업의 같은 오류 코드는 반복돼도 1건, 다른 오류 코드는 각각 센다.

### OP03. 자동 재시도·대체 처리

자동 재시도 발생률:

```txt
자동 재시도가 1회 이상 발생한 논리 실행 단위 수
÷ 전체 실행 논리 단위 수 × 100
```

총·단계별 재시도, 회복 수, 한도 소진 수를 기록한다.

fallback은 종류별로 별도 계산한다.

- 원본 전체 섹션 fallback ÷ 분할 대상 원본
- 원본 배경 fallback ÷ 인페인팅 필요 섹션
- 기본 스타일 사용 ÷ 스타일 적용 대상 섹션
- 부분 번역 진행 ÷ 번역 대상 섹션

### OP04. 처리시간

사람의 N3·N5 검수 대기시간과 시스템 처리시간을 분리한다.

- N2: 분석 실행 시작 → N3 진입
- N4: N4 진행 시작 → N5 진입
- N6: 최종 확정 → 최종 렌더 완료
- 전체 시스템 처리시간: N2 + N4 + N6

작업별 값, 평균, 중앙값과 원본 수로 나눈 참고값을 표시한다. 현재 기록으로 분리할 수 없는 ①·②·③ 개별 시간은 `미측정`으로 둔다.

### OP05. 모델·자원 사용량과 비용

- 제품 생성의 단계·용도별 모델 호출, 토큰, GPU 시간, 추론 횟수, 렌더 시간
- 자동 재시도·재렌더 사용량 포함

작업 원가:

```txt
Σ(용도별 사용량 × 단가)
```

- 건당 원가: `완료 작업 원가 합 ÷ 완료 작업 수`
- 섹션당 원가: `작업 원가 ÷ N2 전체 섹션 수`
- 작업별 원가와 P50·P90 기록. 표본이 적으면 `참고값 / 표본 적음(n건)` 표시
- 단가가 없으면 금액을 추정하지 않고 원래 단위로 기록
- 제품 생성 비용과 GPT-6 Astra 평가 비용을 분리

### OP06. 무수정 승인률·사용자 수정 신호

운영지표 무수정 승인률:

```txt
N5 번역문을 한 글자도 수정하지 않고 처음 확정한 완료 작업 수
÷ 최초 N5 확정을 거친 완료 작업 수 × 100
```

- N3 섹션 변경은 번역문 수정으로 세지 않음
- 번역 실패의 빈 칸을 직접 입력하면 수정
- 저장 후 수정은 제외
- 첫 N5 확정 시점 기준

함께 기록할 신호:

- N3 변경 섹션 수
- N5 수정 블록 수와 수정 전·후 문장
- 규제 제안 해제 수
- 검증 통과 후 직접 수정한 수
- 빈 번역 직접 입력 수

운영지표 `무수정 승인률`과 H05 `완전 무개입 완료율`은 별도 지표다.

### OP07. 규제·규격 결과 분포

규제 판정 통과율:

```txt
N2 판정을 정상 완료한 섹션 중 규제 판정이 0건인 섹션 수
÷ N2 규제 판정을 정상 완료한 섹션 수 × 100
```

- 허용 행은 규제 판정 건수에서 제외
- 번역문 재대조 결과는 포함하지 않음
- 판정 실패 섹션은 분모에서 제외하고 실패 건수로 별도 표시

규격 검증 통과율:

```txt
N6 규격 검증 통과 파일 수
÷ N6 규격 검증을 받은 전체 파일 수 × 100
```

자동 제외 섹션, 현지 기준 미검사 섹션, 규제 판정 실패 섹션도 별도 집계한다. 이 값은 운영 결과 분포이며, 판정의 정확성은 D04에서 평가한다.

## 비슷한 지표의 구분

- H01 기대 산출물 생성률: **원본 이미지**에 최종 파일이 생성됐는가
- OP01 작업 완료율: **상품 작업**이 저장 또는 첫 다운로드까지 완료됐는가
- H05 완전 무개입 완료율: N3 변경·N5 수정·사용자 재시도 없이 A등급 결과를 얻었는가
- OP06 무수정 승인률: N5 번역문을 수정하지 않고 처음 확정했는가
- D04 규제·현지 판정 적합률: 판정이 기대값과 맞는가
- OP07 규제 판정 통과율: 이번 평가셋에서 규제 판정이 걸리지 않은 섹션 비율
- H04 핵심 정보 보존율: 결과 이미지에서 핵심 정보가 정확하고 읽히는가
- D02·D07: 핵심 정보가 OCR 또는 번역 중 어디서 손상됐는가

## 최종 결과 표시 원칙

각 지표는 최소한 다음 값을 함께 표시한다.

```txt
분자 / 분모
비율 또는 A/B/C 분포
not_applicable 수
undetermined 수
no_output 수
evaluation_failed 수
AI만 판정한 수
사람이 확인한 수
```

핵심 품질지표, 단계 진단지표, 보조 운영지표를 하나의 종합점수로 합치지 않는다.

GS-01·02·03별 결과와 전체 결과를 함께 표시한다. 상품별 원본 수가 다르므로 전체 비율만으로 판단하지 않는다. 사람이 일부 영역을 확인한 것을 원본의 모든 지표에 대한 사람 검수 완료로 확대하지 않는다.

## 판정·제외의 세부 집계

D04는 고정된 `policy_expectation`과 실제 처리를 대조한다. 제외된 영역도 평가하며, 같은 기준 단위를 현재 섹션 수만큼 중복 집계하지 않는다. 정상 제외로 대상이 없는 하류 지표는 `not_applicable`, 잘못된 제외로 필요한 산출물이 없으면 `no_output`과 원인을 기록하고 D04 결함에 연결한다. 최종 이미지에서 관찰되는 누락은 직접 평가하되 전파 결함의 중복은 [원인 단계와 발견 단계](evaluation.md#원인-단계와-발견-단계) 규칙을 따른다.

기존의 제외·대체 지시별 TP/FN/FP/TN 표는 D04의 보조 분석 제안으로 보존한다. 제외 필요와 대체·완충 지시 필요를 각각 양성으로 두고, 정상 평가된 기준 단위만 비교하며 예외 상태는 별도 표시한다. 이는 고정셋 기대 처리 대조이며 규제 검출 재현율이나 NFR-14 충족 근거가 아니다. 추가 결과 파일 구성은 8단계에서 검토한다.

정당한 전체 섹션 제외와 함께 사라진 유용한 정보는 정책 준수와 구분해 기록한다. 부분 보존을 요구하는 새 제품 정책을 평가 문서에서 만들지 않는다.

## 공식 버전 비교

동일한 고정 기준 단위와 평가 조건으로 비교한다. H02·H03의 사용 가능성에는 원본별 A/B/C 전이와 예외 상태 전이를 표시하고, 다른 지표에는 해당 단위와 계산식을 사용한다. 원본 A/B/C를 모든 지표에 강제하지 않는다.

기존 결함 ID와 위치·근거를 보존하고, 후속 버전의 개선·퇴행과 신규 결함을 추적한다. 한 결함을 여러 박스로 표시하거나 분할·병합됐다는 이유로 중복 집계하지 않는다. 같은 원본·내용 또는 대상·결함 유형으로 대응시키며 좌표 겹침만으로 확정하지 않는다. 뒤늦게 찾은 baseline 결함과 신규 퇴행을 구분한다.

### 후속 비교 출력 제안

8단계 결과 구조 검토용이며 최종 출력 스키마가 아니다. 기존 제안은 H02·H03의 3×3 등급 전이표, 결함별 해결·완화·유지·악화·평가 불가, 재발 이력, 신규 결함 표다. 완화는 결함이 남지만 영향이 줄어든 경우다. 재발은 이전 후속 회차에서 해결된 결함이 다시 나타난 경우이며 중복 합산하지 않는다. 최초 baseline과 첫 후속 회차만으로 재발을 판정하지 않는다.

이 버전 간 변화 표시는 [회차 내 결함 해결 상태](evaluation.md#결함-해결-상태)와 별도다. 애매한 결함 대응의 사람 검수 방식은 7단계에서 정한다. P90 산출 방식의 기존 제안인 정렬값의 `ceil(0.9×건수)`번째 값 선택은 8단계 집계 출력 설계에서 검토하며 아직 확정하지 않는다.
