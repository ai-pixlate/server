# 고정 평가셋

## 평가 대상

1.0.0 baseline과 후속 버전 측정에는 GS-01~03의 원본 34장 전체를 동일하게 사용한다.

GS-01~03 원본 34장은 baseline과 후속 고도화 실측에서 공통으로 사용하는 고정 평가셋 `gs-v1`이다. 저장 위치는 `pipeline/samples/evaluation/gs-v1/`이며, 상품별 하위 폴더에 원본을 보관한다. 아래 표의 파일 경로는 이 폴더를 기준으로 한다.

평가셋 버전은 제품 릴리즈 버전과 독립적으로 관리한다. 업로드 후 확인한 파일 목록·크기·해상도·SHA-256을 같은 폴더의 `manifest.json`에 보존한다. 각 측정 회차는 이 목록과 원본 해시를 대조한다.

고정한 원본은 덮어쓰거나 재인코딩·축소하지 않는다. 평가셋을 변경해야 하면 새 버전으로 보관하고 기존 `gs-v1`을 유지한다. 서로 다른 평가셋의 결과를 동일 입력에 대한 품질 개선으로 비교하지 않는다.

| 상품 묶음 | 상품 | 포함 파일 | 파일 수 |
|---|---|---|---:|
| GS-01 | 구달 어성초 선크림 | `GS-01/GS-01_001.jpg` ~ `GS-01/GS-01_002.jpg` | 2 |
| GS-02 | 셀리맥스 레티날 부스터 | `GS-02/GS-02_001.jpg` ~ `GS-02/GS-02_014.jpg` | 14 |
| GS-03 | 비클리닉스 톤업 바디로션 | `GS-03/GS-03_001.jpg` ~ `GS-03/GS-03_018.jpg` | 18 |
| 합계 | 상품 3종 | 각 범위의 모든 파일 | 34 |

기존 개발용 입력본에서 제외했던 원본과 영역도 공식 평가셋에 포함한다. 기존 모델 출력과 과거 오류를 정답으로 사용하지 않는다.

기존 OCR 품질 표본 12개의 1.0.0 baseline 실행 제한은 [확정 결정](../../decisions.md#ocr-품질-표본의-실행-제한)에 따라 해제한다. 정답 초안은 보존하며 검수된 정답으로 취급하지 않는다.

## 평가 구성

| 구성 | 범위 | 용도 |
|---|---|---|
| 공식 고정 평가셋 | 원본 34장 전체 | 전체 처리와 최종 품질의 버전 간 비교 |
| 중점 확인 영역 | 고정 평가셋 안의 주요 정보·취약 영역 | 수치 보존·로고 보호·배경 복원 등의 개선과 퇴행 추적 |
| 기존 단계별 입력본 | 기존 32장·100섹션 묶음 | 특정 단계의 원인 분석과 개발 중 회귀 확인 |

중점 확인 영역은 별도의 추가 표본이 아니다. 상품 → 원본 파일 → 원본 내 영역의 관계를 유지하고, 원본 파일과 좌표·내용으로 영역을 연결한다. 과거 섹션 번호는 참고값으로 사용한다. 분할 방식이 바뀌어도 같은 원본 영역을 비교하며, 과거 섹션 수를 고정하지 않는다.

## 중점 확인 영역

중점 확인 영역은 사전 핵심 영역 9곳과 1.0.0 baseline에서 확인된 B/C 문제 영역 전체로 구성한다. 원본 34장 전체 평가를 보완하며, 중점 영역만으로 전체 품질을 판단하지 않는다.

| 구분 | 선정 시점 | 선정 기준 | 목적 |
|---|---|---|---|
| 사전 핵심 영역 | baseline 측정 전 | 상품별 3곳, 총 9곳. 중요한 수치·문구, 상품·로고, 복잡한 배경과 배치를 포함 | 반드시 유지해야 할 정보와 시각적 요소 확인 |
| baseline 문제 영역 | baseline 평가 후 | 1.0.0 baseline에서 B/C로 판정된 결함의 위치 전체 | 고도화에 따른 해결 여부와 재발 추적 |

하나의 영역에 여러 확인 항목을 포함할 수 있다. 사전 핵심 영역은 정보의 중요성과 시각적 특성을 기준으로 선정하며, 과거 개발 중 오류가 있었다는 이유만으로 선정하지 않는다.

영역은 판단에 필요한 주변 문맥과 배경까지 포함한다. 표는 제목·단위·각주를 함께 확인하고, 상품 보호는 상품 윤곽과 인접 편집 영역을 함께 확인한다.

### 영역별 기록

| 항목 | 내용 |
|---|---|
| 영역 ID | 버전이 바뀌어도 유지할 식별자 |
| 원본 식별자·좌표 | 원본 파일 식별자와 확인할 사각형 영역 |
| 구분 | 사전 핵심 영역 / baseline 문제 영역 |
| 관련 품질 지표 | 정보 보존·보호 및 복원·번역·배치 등 |
| 기대 조건 | 해당 영역에서 유지하거나 충족해야 할 구체적인 조건 |
| baseline 판정·근거 | 1.0.0 baseline 측정 후의 판정과 근거 |
| 후속 판정·변화 | 후속 버전의 판정, 개선·동일·퇴행 및 근거 |

baseline 문제 영역은 같은 원인·유형끼리 묶어 검토하되 개별 위치를 모두 보존한다. AI 에이전트가 위치와 근거를 정리하고, 사람은 C 판정·애매한 사례·반복 유형의 대표 사례를 우선 확인한다.

해결된 baseline 문제 영역도 삭제하지 않고 재발 여부를 확인한다. 후속 버전에서 새로 발생한 문제는 전체 평가에서 찾아 기록한다.

## 비교 결과

- GS-01·GS-02·GS-03 각각의 품질 분포와 개선·퇴행을 표시한다.
- 전체 결과에는 판정 대상 건수와 A/B/C 건수를 함께 표시한다.
- 중점 확인 영역은 원본 이미지 내 동일한 좌표 영역을 기준으로 버전 간 변화를 비교한다.

- 지표별 원본 등급 전이표, baseline 결함의 해결·완화·유지·악화·평가 불가, 재발 이력과 신규 결함을 공식 비교 결과로 기록한다. 상태 정의와 결함 대응·중복 집계 규칙은 [지표 집계 방식](aggregation.md#공식-버전-비교)을 따른다.
- 영역 ID와 결함 ID를 구분한다. 한 영역에 서로 다른 결함이 있을 수 있으며, 한 결함의 표시 박스가 여러 개라고 결함 수를 늘리지 않는다.

상품마다 원본 파일 수가 다르므로 파일 수에 따른 전체 집계만으로 품질을 판단하지 않는다. 이 평가셋은 개발에 사용한 상품 3종의 고정 비교셋이며, 결과는 동일 상품에서의 고도화 전후 개선을 설명하는 데 사용한다. 새로운 상품 전반에 대한 성능으로 확대 해석하지 않는다.

## 평가 기준 자료

AI 에이전트가 다음 항목을 정리하고 사람이 핵심 내용을 확인한다. 확인한 기준 자료는 후속 측정에서도 재사용한다.

- 반드시 보존할 상품명·수치·단위·주의문구
- 보존해야 할 상품·로고·패키지 영역
- 번역·제거·유지할 내용과 사용자 선택 조건
- 1.0.0 baseline 측정에서 문제가 확인된 영역 — baseline 측정 결과를 바탕으로 정리하고 후속 버전 비교에 사용한다.

사용자 선택 조건을 고정해 의도적인 제외와 잘못된 누락을 구분한다.

| 항목 | 기준 |
|---|---|
| 기준 자료의 내용 | 원본별 핵심 정보와 보호 대상, 유지·제거·번역 또는 대체할 내용을 기록한다. |
| 번역의 허용 범위 | 의미가 같은 자연스러운 표현 변경은 허용한다. 핵심 정보·조건·부정 표현의 누락이나 근거 없는 내용 추가는 허용하지 않는다. |
| 숫자·단위 | 원문의 값과 단위를 기본으로 유지한다. 변환이 필요한 경우 적용 규칙을 기준 자료에 명시한다. |
| 처리 기대값 | 서비스 정책과 고정된 사용자 선택을 기준으로 유지·제거·변경의 기대값을 정한다. 평가 대상 모델의 출력을 정답으로 사용하지 않는다. |
| 원본 자체의 결함 | 원본의 잘림·판독 불가 등은 모델이 새로 만든 오류와 구분한다. 근거 없는 복원을 정답으로 요구하지 않는다. |
| 기준의 재사용 | 확인된 기준 자료는 후속 버전 평가에도 동일하게 사용한다. 기준 오류를 수정하면 비교 대상에도 같은 기준을 적용한다. |

## 규제·현지 판정의 기대 처리

기대 처리는 원본 좌표·해당 문구에 연결하고, 섹션 포함·제외 판단과 포함한 텍스트의 대체·완충 지시를 분리한다. 새로 생성된 섹션 번호에만 정답을 묶지 않는다.

규제사전·현지부적합사전, 상품 규제 분류, 적용 정책·예외와 고정 사용자 선택을 함께 근거로 사용한다. 데이터 담당이 사전·분류·문맥 기대값을 확인하고 지정된 사람 검수자가 최종 평가 기준을 확인한다. 평가 대상 모델이 내린 판단으로 기대값을 채우지 않는다.

정책대로 섹션 전체를 제외하면서 유용한 내용도 사라진 경우에는 정책 준수 여부와 정보 손실을 구분한다. 섹션 전체 제외 정책을 기준으로 삼으면서 부분 보존을 정답으로 요구하지 않는다. 기대 처리 자체가 바뀌면 동일한 기준을 비교 대상에 적용한다.
