# 평가 기준과 검수

> 상태: `v1-draft` · `pm_review_pending` · 1~5단계 사용자 확정 · PM 승인 전 · 공식 실측 승인 전

지표별 계산 정의는 [집계 명세](aggregation.md)가 소유한다. 이 문서는 체크포인트·결함·심각도·판정 기준과 후속 평가·검수 제안을 소유한다.

## 평가 체크포인트와 파이프라인

```txt
원본 이미지
→ ① 섹션 분해
→ ② OCR
→ ③ 줄·문단 병합 및 역할 분류
→ ③-1 규제·현지 판정 / ③-1′ 정책 적용
→ N3 섹션 확인
→ ④ 제품 라벨 판정
→ ⑤ 브랜드 로고 판정
→ ⑥ 인페인팅 · ⑦ 스타일 · ⑧ 영어 번역
→ ⑨ 최초 미리보기
→ N5 번역 검수·수정
→ N6 최종 렌더
```

### `machine_snapshot`

제품 내부 자동 재시도가 끝나고 최초 미리보기가 생성됐지만, N5에서 사용자가 번역문을 수정하기 전의 자동 결과다.

### `service_final`

N3 섹션 확인과 N5 번역문 검수·수정을 거친 뒤 N6에서 생성된 최종 결과다.

### N3 개입 구분

- `confirmation_only`: AI의 최초 포함·제외 판단을 바꾸지 않고 확인만 함
- `selection_changed`: 사용자가 포함·제외를 실제 변경함
- `unknown`: 변경 여부를 확인할 수 없음

자동 결과에 결함이 있었지만 사용자가 수정해 최종 결과에서 해결됐다면, 자동 결함을 삭제하거나 낮게 평가하지 않고 `corrected_by_user`로 기록한다.

## 실패·결함·평가 문제의 구분

### 기록 종류

- `execution_failure`: 기술적 실행 실패, 재시도, fallback, 산출물 누락
- `quality_defect`: 실제 정보 정확성·시각 품질 오류
- `evaluation_issue`: 기준 자료 또는 평가 AI의 판단 문제

자동 재시도 후 공식 자동 결과가 정상이라면 실행 실패만 기록하고 품질 결함은 만들지 않는다. fallback 사용 자체도 결함이 아니며, 결과에 실제 품질 문제가 관찰된 경우에만 품질 결함을 만든다.

### 실행 결과 상태

- `success`: 첫 시도에서 정상 완료
- `recovered`: 자동 재시도 후 정상 완료
- `degraded`: 일부 실패 또는 승인된 fallback 결과를 사용해 다음 단계 진행
- `blocked`: 일부 결과가 있더라도 필수 단계 실패로 정상 진행 불가
- `no_output`: 해당 지표·단계·처리 대상이 기대한 사용 가능한 필수 산출물이 생성되지 않음

`no_output`의 범위는 평가 문맥에 따라 정한다. H01·H02·H03에서는 최종 또는 체크포인트 이미지가 없는 경우이고, OP02에서는 해당 단계의 논리 실행 단위가 기대한 산출물이 없는 경우다. 승인된 fallback 산출물로 다음 단계가 진행됐다면 `no_output`이 아니라 `degraded`로 기록한다.

### 품질 결함 유형

1. `content_missing`
2. `content_wrong`
3. `content_extra_or_duplicate`
4. `structure_or_order_wrong`
5. `decision_wrong`
6. `protection_wrong`
7. `text_not_removed`
8. `protected_content_damaged`
9. `background_artifact`
10. `translation_missing`
11. `translation_meaning_error`
12. `translation_fact_error`
13. `translation_naturalness`
14. `render_missing_or_clipped`
15. `readability_or_layout`
16. `final_unusable`

세부 정보는 `number`, `unit`, `usage`, `warning`, `product_name`, `brand`, `ingredient`, `regulatory`, `logo`, `product_shape`, `alignment`, `contrast`, `overflow` 등의 태그로 보완한다.

### 품질 심각도

- `critical`: 핵심 수치·단위·용법·주의사항·규제 정보 오류, 제품·브랜드 정체성의 중대한 훼손, 핵심 문구 판독 불가, 잘못된 구매·사용 판단 가능성, 최종 산출물 없음 또는 사실상 사용 불가
- `major`: 실제 사용 전 반드시 수정해야 하는 중요한 정보·주요 시각 영역의 오류
- `minor`: 핵심 의미와 사용성은 유지되지만 국소적인 문구·배치·복원 수정이 필요한 오류

사용자 수정 기능이 있어도 자동 결과의 심각도는 낮추지 않는다.

### 수정 지원 유형

- `built_in_direct`: N3 또는 N5에서 사용자가 직접 수정 가능
- `built_in_retry`: 사용자가 재시도할 수 있음
- `visible_no_direct_fix`: 결과는 보이지만 서비스 내부 직접 수정 불가
- `not_covered`: 검수 화면에서 발견·수정하기 어려움

`built_in_direct`는 오류가 검수 화면에 실제로 노출되고, 같은 화면에서 직접 수정할 수 있을 때만 사용한다.

### 결함 해결 상태

- `unresolved`
- `corrected_by_user`
- `corrected_by_retry`
- `corrected_by_system`
- `not_reproduced`
- `disputed`

### 원인 단계와 발견 단계

- `origin_stage`: 결함이 처음 만들어진 단계. 명확하지 않으면 `unknown`
- `detected_stage`: 결함이 관찰된 단계

명확한 전파 오류는 가장 이른 원인 단계의 root defect 한 건으로 기록하고, 후속 결과는 manifestation으로 연결한다. 후속 단계가 독립적으로 새로운 오류를 만들었으면 별도 결함으로 기록한다.

## 품질 등급 판정 기준

### 텍스트 비교

의미·품질 평가에서는 의미에 영향 없는 줄바꿈, 연속 공백, 앞뒤 공백, 일부 문장부호와 대소문자 차이를 허용할 수 있다. 숫자·단위·긍정/부정·조건·제품명·브랜드명·성분명·주의사항의 변경은 허용하지 않는다.

운영지표 `무수정 승인률`은 Unicode NFC와 `CRLF→LF`만 정규화하고, 나머지 문자 변경은 수정으로 센다.

### 사용 가능성 A/B/C

- **A — 수정 없이 사용 가능:** `critical`·`major` 결함이 없고 핵심 정보가 정확하며 읽을 수 있음
- **B — 부분 수정 필요:** `critical` 결함은 없고 제한된 번역·섹션·배치 수정으로 사용 가능
- **C — 사용 곤란:** `critical` 결함, 핵심 정보 판독 불가, 상품·브랜드 중대 훼손, 광범위한 오류 또는 큰 수정·재생성 필요
- 산출물 없음은 A/B/C가 아니라 `no_output`

A/B/C는 H02·H03의 사용 가능성에 적용한다. 최종 결과는 직접 평가하며 중간 단계 판정을 자동 전파하지 않는다. 관찰한 결함의 위치·기대 조건·근거를 남기고 AI 판정과 사람 확인을 구분한다.

### 단계 진단 적합 기준

- `critical`·`major` 결함 없음 → 적합
- `critical` 또는 `major` 결함 있음 → 부적합
- `minor`는 별도 건수로 기록하며 기능적으로 사용할 수 있으면 적합 가능

평가 상태와 평가 가능률은 [공통 집계 규칙](aggregation.md#공통-집계-규칙)을 따른다. 품질 결함의 심각도와 평가 상태는 별도이며, 산출물 없음에 관한 심각도 설명을 A/B/C의 C 등급으로 치환하지 않는다.

## AI 평가 방식

평가 AI는 **GPT-6 Astra (light)**다. 전체 1차 평가와 결함 위치·근거 기록을 담당하고, 사람은 기준 보정과 중요·불확실 사례를 확인한다. 이 선택은 제품 생성 모델 변경이 아니다. 실제 모델 식별자와 설정을 기록하며 `light`를 확인 없이 API 파라미터로 치환하지 않는다.

운영지표는 로그·사용량으로 계산하고 AI 추정으로 채우지 않는다. 평가 입력 묶음·출력 JSON·프롬프트·독립 재검토 방식은 아직 확정하지 않았다.

## 후속 검토 제안

**아래 전체는 6~7단계의 미확정 제안이다.** 기존 상세안을 검토 자료로 보존하며, 실행 의무·검수 완료 기준·승인으로 사용하지 않는다. 제안 안의 A/B/C는 현재 체계에서는 사용 가능성 판정에만 적용하며 단계 진단에는 적합 여부·결함 심각도에 맞춘 재설계가 필요하다. N3·N5 검수자와 수정 기준, 사용자 재시도 취급도 7단계에서 결정한다.

### 6단계 AI 평가·독립 재검토 제안

전체 1차 평가에 선택적 독립 재검토를 추가하는 기존 제안이다.

| 항목 | 기준 |
|---|---|
| AI의 역할 | 품질 지표는 이미지와 기준 자료를 비교해 판정하고 근거를 작성한다. baseline 실행 지표는 로그·사용량 기록으로 계산하며 AI의 추정값으로 채우지 않는다. |
| 1차 평가 범위 | 원본 34장에 대응하는 평가 가능한 산출물 전체를 평가한다. K01~K09와 이후 baseline 문제 영역은 명시적으로 확인한다. |
| 평가 입력 | 원본 이미지, 평가할 산출물, 확정 평가 기준과 처리 기대값을 제공한다. 작은 글씨를 확인할 세부 이미지와 전체 맥락을 함께 제공한다. |
| 평가자 구성 | 이미지 판독이 가능한 주 평가자 하나를 사용한다. 생성·개발 대화와 분리된 평가 세션에서 판정한다. 동일 모델 사용은 허용한다. |
| 독립 재검토 대상 | K01~K09 전체, 1차 B/C 판정, 판단 불가 사례를 다른 평가 세션에서 한 번 재검토한다. 최초 baseline 이후에는 baseline 문제 영역도 포함한다. |
| 독립성 확보 | 재검토자는 1차 등급·설명을 먼저 보지 않고 같은 자료로 판정한다. 독립 판정 후 두 결과를 대조한다. |
| 불일치 처리 | 등급이나 중요한 결함 유무가 다르면 양쪽 근거를 보존하고 사람 확인 대상으로 표시한다. 단순 평균·다수결이나 더 좋은 등급의 자동 채택으로 해결하지 않는다. |
| 평가 횟수 | 기본 1회, 재검토 대상은 추가 1회로 한다. 원하는 등급이 나올 때까지 반복하지 않는다. 기술적 실패로 다시 평가한 경우 사유와 이력을 남긴다. |
| 평가 기준 보정 | 공식 평가 전에 K01~K09로 기준 적용을 확인한다. 기준과 평가 프롬프트를 고정한 뒤 공식 평가를 새로 수행하며, 보정 중 판정은 공식 결과에 섞지 않는다. |
| 판정 기록 | 대상 식별자, 지표, 등급 또는 예외 상태, 결함 위치·관찰 내용·기대 조건·판정 이유, 평가자 식별 정보를 남긴다. 1차·재검토·사람 판정을 구분한다. |
| 모델·설정·프롬프트 관리 | 최초 공식 측정에서 사용한 모델 식별자·제공되는 버전 정보·설정·프롬프트를 보존하고 후속 비교에도 동일하게 적용한다. 회차별 모델 선택과 실제 사용 설정은 실행 기록에 남긴다. |
| 평가자가 변경되는 경우 | 같은 평가자를 사용할 수 없거나 평가 방식을 바꾸면, 보존한 baseline 산출물과 고도화 산출물을 새 평가자로 함께 평가한다. 평가 조건이 다른 점수를 그대로 비교하지 않는다. |

같은 모델의 독립 세션도 같은 오류를 낼 수 있으므로, 두 평가자의 동의를 사람 검수 완료로 취급하지 않는다.

독립 재검토에도 같은 모델·설정을 사용하되 세션을 분리하는 안을 검토한다.

규제·현지 판정에는 제외된 영역도 원본·판정 기록·기대 처리로 평가한다. 후속 버전에서는 baseline 결함 ID와의 대응, 해결·완화·유지·악화·평가 불가, 재발 여부와 신규 결함의 근거를 기록한다. 애매한 대응은 사람 검수로 넘긴다.

### 7단계 사람 검수 범위 제안

이 절의 인원·필수 범위·표본 수·확대 및 종료 조건은 모두 미확정 제안이다.

핵심 영역과 중요한 판단은 직접 확인하고, 나머지는 표본 검수한다.

| 항목 | 기준 |
|---|---|
| 검수 책임자 | 지정된 사람 검수자 1명이 최종 판정을 담당한다. AI는 검수 자료 정리와 근거 비교를 보조한다. |
| 측정 전 기준 확인 | AI가 작성한 핵심 정보·보호 대상·처리 기대값을 사람이 확인한다. 확인한 자료는 후속 측정에서 재사용하며, 변경된 부분만 다시 확인한다. |
| 사전 기준 보정 | 공식 평가 전 K01~K09를 사람이 확인해 AI의 기준 적용을 보정한다. 이 판정을 공식 평가 결과로 재사용하지 않는다. |
| 공식 평가의 필수 검수 | K01~K09 전체, 두 AI 중 하나라도 C로 판정한 사례, AI 간 등급·중요 결함 판단이 다른 사례, 판단 불가 사례를 모두 확인한다. |
| AI가 동의한 B 판정 | 같은 상품·품질 지표·결함 유형으로 묶고, 각 묶음에서 최소 1곳을 확인한다. 검수하지 않은 위치까지 사람이 확인한 것으로 표시하지 않는다. |
| A 판정 표본 검수 | 최종 이미지 사용 적합성이 A인 원본 중 상품별 1장씩 무작위 선정해 이미지 전체를 확인한다. 해당 상품에 A가 없으면 생략한다. 선정된 원본에 연결된 단계별 A 판정도 함께 확인한다. |
| 후속 버전의 추가 검수 | baseline의 C 문제 영역은 개선 여부와 관계없이 모두 확인한다. baseline B 문제 영역은 불일치·C·B 표본 규칙을 적용한다. |
| 표본에서 오판 발견 시 | 확인한 표본에서 AI의 잘못된 등급이나 중요한 결함 누락이 발견되면, 같은 상품의 해당 품질 지표 판정 전체로 사람 검수를 확대한다. 기준·프롬프트 자체의 오류라면 영향을 받는 전체 범위를 재평가하고 다시 검수한다. |
| 최종 판정 | 사람이 확인한 항목은 사람 판정을 최종값으로 사용한다. 기존 AI 판정과 수정 이유를 보존한다. 사람도 근거가 부족하면 판단 불가로 남긴다. |
| 중복 검수 방지 | 여러 검수 조건에 해당하는 영역은 한 번에 확인한다. 확인한 지표·결함별 결과는 각각 기록한다. |
| 검수 기록 | 검수자 식별자, 대상·범위, 최종 판정, AI 판정 변경 여부와 이유를 기록한다. AI 평가만 완료한 항목과 사람이 확인한 항목을 구분한다. |
| 검수 종료 조건 | 필수 검수·표본 검수·오판에 따른 확대 검수를 모두 마치고, 불일치를 최종 판정 또는 판단 불가로 정리하면 종료한다. 판단 불가가 남았다는 이유만으로 검수를 무한 반복하지 않는다. |

K01~K09 확인을 기본으로 하고, C·불일치·판단 불가 사례에 따라 검수량이 늘어난다. 필수 검수를 임의의 건수 상한으로 잘라내지 않는다.

규제·현지 판정 지표에도 같은 검수 규칙을 적용한다. 제거된 영역은 최종 이미지에 없다는 이유로 검수 대상에서 제외하지 않는다. 데이터 담당이 사전·분류·문맥 기대값을 확인하고 지정 검수자가 평가 기준을 확인한다.

결함의 버전 간 대응이 애매한 사례는 사람이 확인한다. 좌표 겹침이나 동일 문구만으로 연결을 확정하지 않는다. 자료 부족으로 해결 여부를 확인할 수 없으면 평가 불가로 남긴다. 뒤늦게 발견한 baseline 결함과 실제 신규 퇴행을 구분한다.
