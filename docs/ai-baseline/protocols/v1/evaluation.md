# 평가 기준과 검수

> 상태: `v1-draft` · PM 회신 반영 초안 · GitHub 문서 PR 최종 검토 전 · 공식 실측 승인 전

지표별 계산 정의는 [집계 명세](aggregation.md)가 소유한다. 이 문서는 체크포인트·결함·심각도·판정 기준과 후속 평가·검수 제안을 소유한다.

## 평가 체크포인트와 파이프라인

```txt
원본 이미지
→ ① 섹션 분해
→ ② OCR
→ ③ 줄·문단 병합 및 역할 분류
→ ③-1 규제·현지 판정 / ③-1′ 정책 적용
→ N3 섹션 확인
→ ④ 제품 라벨 판정
→ ⑤ 브랜드 로고 판정
→ ⑥ 인페인팅 · ⑦ 스타일 · ⑧ 영어 번역
→ ⑨ 최초 미리보기
→ N5 번역 검수·수정
→ N6 최종 렌더
```

### `machine_snapshot`

제품 내부 자동 재시도가 끝나고 최초 미리보기가 생성됐지만, N5에서 사용자가 번역문을 수정하기 전의 자동 결과다.

### `service_final`

N3 섹션 확인과 N5 번역문 검수·수정을 거친 뒤 N6에서 생성된 최종 결과다.

### N3 개입 구분

- `confirmation_only`: AI의 최초 포함·제외 판단을 바꾸지 않고 확인만 함
- `selection_changed`: 사용자가 포함·제외를 실제 변경함
- `unknown`: 변경 여부를 확인할 수 없음

자동 결과에 결함이 있었지만 사용자가 수정해 최종 결과에서 해결됐다면, 자동 결함을 삭제하거나 낮게 평가하지 않고 `corrected_by_user`로 기록한다.

## 실패·결함·평가 문제의 구분

### 기록 종류

- `execution_failure`: 기술적 실행 실패, 재시도, fallback, 산출물 누락
- `quality_defect`: 실제 정보 정확성·시각 품질 오류
- `evaluation_issue`: 기준 자료 또는 평가 AI의 판단 문제

자동 재시도 후 공식 자동 결과가 정상이라면 실행 실패만 기록하고 품질 결함은 만들지 않는다. fallback 사용 자체도 결함이 아니며, 결과에 실제 품질 문제가 관찰된 경우에만 품질 결함을 만든다.

### 실행 결과 상태

- `success`: 첫 시도에서 정상 완료
- `recovered`: 자동 재시도 후 정상 완료
- `degraded`: 일부 실패 또는 승인된 fallback 결과를 사용해 다음 단계 진행
- `blocked`: 일부 결과가 있더라도 필수 단계 실패로 정상 진행 불가
- `no_output`: 해당 지표·단계·처리 대상이 기대한 사용 가능한 필수 산출물이 생성되지 않음

`no_output`의 범위는 평가 문맥에 따라 정한다. H01·H02·H03에서는 최종 또는 체크포인트 이미지가 없는 경우이고, OP02에서는 해당 단계의 논리 실행 단위가 기대한 산출물이 없는 경우다. 승인된 fallback 산출물로 다음 단계가 진행됐다면 `no_output`이 아니라 `degraded`로 기록한다.

### 품질 결함 유형

1. `content_missing`
2. `content_wrong`
3. `content_extra_or_duplicate`
4. `structure_or_order_wrong`
5. `decision_wrong`
6. `protection_wrong`
7. `text_not_removed`
8. `protected_content_damaged`
9. `background_artifact`
10. `translation_missing`
11. `translation_meaning_error`
12. `translation_fact_error`
13. `translation_naturalness`
14. `render_missing_or_clipped`
15. `readability_or_layout`
16. `final_unusable`

세부 정보는 `number`, `unit`, `usage`, `warning`, `product_name`, `brand`, `ingredient`, `regulatory`, `logo`, `product_shape`, `alignment`, `contrast`, `overflow` 등의 태그로 보완한다.

### 품질 심각도

- `critical`: 핵심 수치·단위·제품명·용법·주의사항 오류, 필수 제외·대체 누락으로 중요한 위험 표현이 최종 결과에 남음, 제품·브랜드 정체성의 중대한 훼손, 핵심 문구 판독 불가, 사실상 사용 불가
- `major`: 실제 사용 전 반드시 수정해야 하는 중요한 정보·주요 시각 영역의 오류
- `minor`: 핵심 의미와 사용성은 유지되지만 국소적인 문구·배치·복원 수정이 필요한 오류

규제 표현 노출이나 상품 가림은 일괄적으로 같은 심각도를 주지 않고 실제 정보·사용 영향에 따라 판단한다. 사용자 수정 기능이 있어도 자동 결과의 심각도는 낮추지 않는다.

### 수정 지원 유형

- `built_in_direct`: N3 또는 N5에서 사용자가 직접 수정 가능
- `built_in_retry`: 사용자가 재시도할 수 있음
- `visible_no_direct_fix`: 결과는 보이지만 서비스 내부 직접 수정 불가
- `not_covered`: 검수 화면에서 발견·수정하기 어려움

`built_in_direct`는 오류가 검수 화면에 실제로 노출되고, 같은 화면에서 직접 수정할 수 있을 때만 사용한다.

### 결함 해결 상태

- `unresolved`
- `corrected_by_user`
- `corrected_by_retry`
- `corrected_by_system`
- `not_reproduced`
- `disputed`

### 원인 단계와 발견 단계

- `origin_stage`: 결함이 처음 만들어진 단계. 증거가 부족하면 `undetermined`
- `detected_stage`: 결함이 관찰된 단계

중간 산출물에서 오류가 처음 직접 확인되는 가장 이른 단계를 선택한다. 앞 단계가 정상이고 다음 단계에서 처음 오류가 생겼다면 다음 단계를 선택한다. 최종 이미지에서 발견됐다는 이유로 렌더 단계에 자동 배정하지 않는다.

명확한 전파 오류는 가장 이른 원인 단계의 root defect 한 건으로 기록하고, 후속 결과는 manifestation으로 연결해 중복 감점하지 않는다. 두 단계에서 독립적으로 오류가 생겼으면 별도 결함으로 기록한다. 원인 단계 목록과 집계는 [단계 진단 방식](aggregation.md#단계-진단-방식)을 따른다. `origin_stage=undetermined`는 원인 불명이며, 품질 평가 자체가 어려운 평가 상태 `undetermined`와 구분한다.

## 품질 등급 판정 기준

### 텍스트 비교

의미·품질 평가에서는 의미에 영향 없는 줄바꿈, 연속 공백, 앞뒤 공백, 일부 문장부호와 대소문자 차이를 허용할 수 있다. 숫자·단위·긍정/부정·조건·제품명·브랜드명·성분명·주의사항의 변경은 허용하지 않는다.

운영지표 `무수정 승인률`은 Unicode NFC와 `CRLF→LF`만 정규화하고, 나머지 문자 변경은 수정으로 센다.

### 사용 가능성 A/B/C

A/B/C는 해당 체크포인트의 결함 수만으로 결정한다.

- **A — 그대로 사용 가능:** `critical=0`, `major=0`
- **B — 수정 후 사용 가능:** `critical=0`, `major≥1`
- **C — 사용 곤란:** `critical≥1`

`minor` 결함만 있는 결과는 A다. 산출물 없음은 A/B/C로 강제하지 않고 `no_output`으로 기록한다.

H02·H03은 같은 기준을 사용한다. 최종 결과는 직접 평가하며 중간 단계 판정을 자동 전파하지 않는다. 관찰한 결함의 위치·기대 조건·근거를 남기고 AI 판정과 사람 확인을 구분한다. 최종 A등급 비율과 B·C 분포·중대 결함 표시는 [H03](aggregation.md#h03-최종-결과-사용-가능)을 따른다.

### 규제 표현 처리 기준

- 허용 표현이 남는 것은 결함이 아니다.
- 조건부 표현은 필요한 N5 경고가 표시됐으면 결함이 아니다.
- 조건부 표현에 필요한 경고가 표시되지 않았으면 결함이다.

고정 사전·정책에 따른 서비스 동작 평가이며 법적 적합성을 보증하는 표현이 아니다. 기준 자료는 [판정 기대값](dataset.md#평가-기준-자료)을 따르고, 평가 AI가 정답을 새로 만들지 않는다.

평가 상태와 평가 가능률은 [공통 집계 규칙](aggregation.md#공통-집계-규칙)을 따른다. 품질 결함의 심각도·원인 단계·평가 상태는 구분한다.

## 사용자 수정 규칙 초안

- 서비스 내장 기능만 사용하고 포토샵 등 외부 편집 도구는 사용하지 않는다.
- N3에서 섹션 하나의 include/exclude 값을 바꾸면 수정 1건으로 센다.
- N5에서 블록 하나의 최종 문구가 최초 자동 문구와 다르면 수정 1건으로 센다. 같은 블록을 여러 번 저장해도 최종 집계에서는 1건이다.
- 사용자 재시도는 번역문 수정 건수와 분리한다.
- N3 섹션 되살리기·제외는 baseline 수정 부담에 포함한다. O1 무수정 승인률에서는 기존 PRD 정의대로 섹션 변경을 번역문 수정으로 세지 않는다.

검수 담당자와 원본당 제한 시간은 PM 확정 예정이며, N5 텍스트 박스 크기·위치 변경의 수정 건수는 PRD v3.5.10 반영 후 확정한다. 현재 숫자나 처리 규칙을 임의로 채우지 않는다.

## AI 평가 방식

평가 AI는 **GPT-6 Astra (light)**다. 전체 1차 평가와 결함 위치·근거 기록을 담당하고, 사람은 기준 보정과 중요·불확실 사례를 확인한다. 이 선택은 제품 생성 모델 변경이 아니다. 실제 모델 식별자와 설정을 기록하며 `light`를 확인 없이 API 파라미터로 치환하지 않는다.

운영지표는 로그·사용량으로 계산하고 AI 추정으로 채우지 않는다. 평가 입력 묶음·출력 JSON·프롬프트·독립 재검토 방식은 아직 확정하지 않았다.

## 후속 검토 제안

6~7단계는 미정 항목의 자리만 유지한다. 앞 절의 사용자 수정 규칙 초안과 구분하며, 이전 상세 제안의 인원·표본 수·재검토 횟수·종료 조건을 실행 규칙으로 사용하지 않는다.

### 6단계 AI 평가·독립 재검토 제안

GPT-6 Astra의 실제 입력 묶음·출력 JSON·프롬프트·독립 재검토 방식은 미정이다. 현재 선택한 평가 AI의 역할을 구체적인 호출·출력 계약으로 확대하지 않는다.

### 7단계 사람 검수 범위 제안

검수 담당자·표본 범위·원본당 제한 시간·사람 검수 상세 규칙은 미정이다. K01~K09와 중요·불확실 사례를 어떻게 확인할지 후속 설계에서 정하며, 현재 인원·필수 표본 수·확대 및 종료 조건을 확정하지 않는다.
