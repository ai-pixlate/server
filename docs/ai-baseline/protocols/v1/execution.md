## 측정 실행 조건

Codex 평가·사람 검수 절차는 [평가 프로토콜](evaluation.md#ai-평가-방식)을 따른다. 제품 생성의 사전 점검·호출·도구 연결 세부 절차는 별도 준비 사항이다. 아래의 기존 실행 환경·횟수·재시도·비용 승인 결정은 보존하되 실행 준비 완료로 해석하지 않는다. 단계별 확정 상태는 [계획](../../plan.md#확정-범위와-후속-작업)을 따른다.

| 항목 | 기준 |
|---|---|
| 측정 대상 | [계획](../../plan.md#측정-대상과-목적)에서 고정한 릴리즈 v1.0.1 전체 SHA를 기준으로 하며, 현재 운영 서버의 v1.0.1 실행은 운영자 확인으로 기록하며, 직접 검증한 서버·워커 SHA와 구분한다. 실행에 영향을 주는 미커밋 코드 변경이 있는 상태에서는 공식 측정하지 않는다. |
| 실행 기록 | 제품 커밋, 평가 명세 버전, 모델·설정·프롬프트·사전·폰트·의존성 버전, 장비·운영체제를 기록한다. 제공되지 않는 외부 모델 버전 정보는 확인 불가로 표시한다. |
| 사용자 입력 | 원본과 상품 메타데이터는 [평가셋](dataset.md)을 따르며 대상은 미국·영어다. N3·N5 개입은 [체크포인트](evaluation.md#평가-체크포인트와-파이프라인)에 따라 구분해 기록한다. 수정 건수는 [사용자 수정 규칙 초안](evaluation.md#사용자-수정-규칙-초안)을 참조하며 사람 검수 조건과 박스 수정 기능 상태는 같은 평가 문서의 해당 절을 따른다. |
| 실행 횟수 | 공식 생성은 원본별 1회로 한다. 품질이 낮다는 이유로 다시 생성해 좋은 결과만 선택하지 않는다. AI 평가는 [AI 평가 방식](evaluation.md#ai-평가-방식)을 따른다. |
| 상품 작업·원본 연결 | 2026-10-27 사용자 결정: GS-01·02·03별 1작업, 총 3작업에 원본 2·14·18장을 연결한다. 원본별 공식 생성은 1회다. 실행기는 상품 작업을 순차 처리하며 실제 실행 순서는 승인 범위에 기록한다. |
| 캐시 | 이전 회차의 생성 결과를 재사용하지 않는다. 모델 파일 등 실행 준비용 캐시는 허용하고, 외부 서비스의 캐시 사용이 확인되면 기록한다. |
| 재시도·시간 제한 | 측정 대상 릴리즈의 재시도·시간 제한 설정을 사용하고 실행 기록에 고정한다. 측정 도중 성공률을 높이려고 변경하지 않는다. |
| 후속 비교 | 평가 조건은 유지한다. 고도화에 따른 모델·설정 변경은 비교 대상 변경으로 기록하며, 장비·실행 환경이 달라진 속도 결과는 같은 조건의 성능 개선으로 해석하지 않는다. |

원본별 1회는 공식 생성 횟수다. 제품 내부 자동 재시도의 모든 시도와 최종 반영 여부를 기록한다. 원본 이미지 수를 OP01의 상품 작업 수로 간주하지 않으며, OP01의 생성 작업 분모는 실제 생성된 상품 작업 수(계획 3개)이며, H01~H05의 기존 평가 단위는 유지한다. 작업 공유 비용을 원본에 균등 배분하지 않는다.

실제 릴리즈 커밋·장비명 등 회차별 값은 실행 기록에 기입한다. 평가 기록과 파일 연결은 [8단계 구조](../../runs/README.md)를 따르며 측정 도구 구현은 별도 작업이다. 현재 문서만으로 실행 가능 상태를 선언하지 않는다.

### AI 에이전트의 수행 범위

AI 에이전트는 사용자 확정 범위와 별도로 승인된 작업 범위 안에서 실행 설정 작성, 입력 검증, 결과 수집·정리와 평가 기록을 수행한다. 자료에서 확인할 수 있는 값은 먼저 확인하고, 사용자의 직접 작업이 필요하거나 측정 대상·평가 기준·실행 범위에 영향을 주는 결정만 질문한다. 확인되지 않은 상품 정보·처리 기대값·사람 검수 완료 여부를 임의로 채우지 않는다.

기준 자료 동결과 사람 검수는 [7단계 프로토콜](evaluation.md#7단계-사람-검수-프로토콜)을 따른다. 기준 자료 검토 전 초안과 동결본을 구분하며 PM 확인 전에는 공식 평가를 시작하지 않는다. 비용이 발생하는 실행은 [사전 예산 승인](#ai-실행자의-사전-예산-승인)을, 커밋·푸시는 [입력·결과 보관 방식](#입력결과-보관-방식)의 승인 규칙을 따른다.

### 격리 BE 실행 경로

격리 BE 재사용과 로컬 환경 결정은 유지한다. 아래의 CLI 진입점·순차 호출·작업 전달·DB 준비 등 구체적인 연결 절차는 후속 실행 설계 제안이며, 도구 구현이나 실행이 승인됐다는 뜻이 아니다.

통제된 환경에서 측정용 실행기가 해당 릴리즈의 BE 처리 흐름을 순차 호출하여 분석·판정·하류 처리·최종 렌더·산출물 저장을 수행한다. 실행 진입점은 CLI를 사용할 수 있다. 사전·용어집 공급, 섹션 제외, 실패 처리, 렌더 입력 조립과 원본별 이미지 조립은 기존 처리 코드를 재사용하며 별도 규칙으로 재구현하거나 생략하지 않는다.

격리 PostgreSQL과 해당 릴리즈의 마이그레이션·참조 데이터를 준비하고 실제 모델 어댑터를 사용한다. 작업 전달과 저장소는 격리 실행에 맞게 연결할 수 있으나, 시험용 가짜 모델·합성 사전·시험용 스타일 설정을 공식 생성에 사용하지 않는다. 운영 EC2·RDS·S3, 외부 API 서버와 별도 Celery 워커 배포를 필수 조건으로 두지 않는다.

같은 원본의 한 번의 실행에서 단계별 산출물과 최종 이미지를 수집한다. 기존 단계별 CLI로 생성 단계를 따로 다시 실행한 결과는 공식 회차에 섞지 않는다. 측정용 실행기 버전, DB 스키마, 사전·용어집·브랜드 메타데이터 등 참조 데이터의 스냅샷 식별자·해시, 정책 규칙·스타일 기본값, 저장소·작업 전달 방식과 장비·자원 제한을 회차 기록에 남긴다. 실행 경로나 환경이 달라진 처리 시간은 동일 조건의 성능 비교로 사용하지 않는다.

| 시점 | 고정 입력·행동 |
|---|---|
| N1 | 상품별 상품명·규제 분류·카테고리와 미국·영어를 기록한다. 같은 상품의 원본에는 같은 상품 메타데이터를 적용한다. |
| N3 | AI `original_verdict`와 사용자 최종 선택을 구분해 보존한다. 이번 회차는 최초 선택을 변경 없이 확인한다. AI 판단을 정답으로 사용하지 않으며 사용자 수정 회복 분석은 후속 서비스 평가로 이관한다. |
| N5 | 이번 회차는 자동 번역문을 수정하지 않고 확인한다. 최초 미리보기와 N6 최종 결과는 별도로 보존하며 사용자 수정 회복 분석은 후속 서비스 평가로 이관한다. 미해결 경고와 확인 이력을 남긴다. 결함 여부는 [허용·조건부 표현 기준](evaluation.md#규제-표현-처리-기준)을 따르며, 경고 확인 이력만으로 다른 품질 항목까지 합격으로 간주하지 않는다. |
| 최종 결과 | N6 최종 렌더와 저장된 이미지 확보까지 포함한다. ZIP 등 별도 내보내기는 평가하지 않는다. |
| 전체 제외 | 포함할 섹션이 없으면 N6 확정을 강제하지 않는다. 전체 제외 종료와 정답 기준의 적합성을 구분하며, 실패·분모 제외 여부는 [H01](aggregation.md#h01-기대-산출물-생성률)을 따른다. |

N1·N3·N5·N6는 기존 처리 흐름의 상태다. N3·N5 검수 참여와 수정 기준을 우회하는 자동 확인 절차는 확정하지 않는다. 격리 DB에 처리에 필요한 판매자·브랜드·작업 레코드를 준비한다. 운영 판매자 계정은 요구하지 않는다. 측정 작업을 다른 작업과 분리하고 장비의 동시 작업 여부를 기록한다.

상품의 서비스 카테고리와 실행용 호환값은 [평가셋의 상품 카테고리](dataset.md#상품-카테고리)를 따른다. 기존 체계의 용어집을 유지하고 실행용 `internal_category`를 작업에 직접 입력한다. 서비스 화면의 카테고리 선택과 표시 카테고리→내부 분류 매핑 기능은 이 측정에서 검증하지 않는다. 측정 준비 도구에서 새 카테고리 체계 지원을 위해 제품 로직을 변경하거나 용어집 코드를 임의 치환하지 않는다.

후속 측정에서 새 카테고리 체계나 용어집을 적용하면 변경 내용을 비교 조건에 기록한다. 해당 품질 차이를 모델 변경만의 효과로 해석하지 않는다. 측정 대상 릴리즈가 새 체계를 지원하게 되면 실행 전 호환값과 용어집의 일치를 다시 확인하며, 기존 확정 입력을 자동으로 바꾸지 않는다.

### 로컬 실행 환경과 재현 조건

| 항목 | 구성 |
|---|---|
| 장비·OS | 현재 Windows PC에서 BE·OCR·LaMa를 실행한다. 학교 GPU 서버와 운영 인프라는 연결하지 않는다. |
| Python | 측정 전용 가상환경을 사용하고 BE·OCR·GPU 의존성의 호환성을 검증한다. 기존 개발 환경은 유지한다. |
| OCR | 릴리즈의 OCR 모델·설정과 CPU 빌드 Paddle을 사용한다. CPU 실행 조건을 후속 측정에도 유지한다. |
| LaMa | 로컬 NVIDIA GPU와 호환되는 PyTorch CUDA 빌드를 사용한다. 학교 서버의 패키지 버전 재현은 요구하지 않는다. 릴리즈가 지정한 모델·가중치·정밀도는 유지한다. |
| DB | localhost 전용 PostgreSQL에 측정용 DB를 준비한다. Docker는 필수가 아니며 독립 실행형 설치도 허용한다. 릴리즈 마이그레이션과 확인된 참조 데이터를 사용한다. |
| 작업·저장 | 기존 격리 실행기의 순차 작업 전달과 로컬 파일 저장소를 사용한다. Redis·외부 API 서버·별도 Celery 워커·S3 배포는 요구하지 않는다. |

운영 환경과 동일한 구성보다 고도화 전후의 비교 조건 유지가 우선이다. 장비·OS·드라이버·Python·패키지·DB 버전과 설치 출처, 모델 파일 해시, 전원 연결·전원 모드·동시 작업·자원 제한을 회차에 기록한다. 설치 목록과 재설치에 필요한 파일 또는 고정된 배포 정보를 보존한다. 호환성 검증이 끝난 조합을 고정하며 준비 과정의 설치 성공만으로 실행 가능성을 확정하지 않는다.

후속 측정에서는 고도화 대상인 코드·모델·설정 변경을 명시하고 나머지 실행·평가 조건을 유지한다. 외부 모델은 제공자가 노출하는 모델 ID·버전·설정과 실행일을 기록하며 내부 버전을 완전히 고정할 수 있다고 가정하지 않는다. 장비 등 환경 변경이 불가피하면 기존 릴리즈도 새 환경에서 다시 측정해 비교 조건을 맞추되, 최초 baseline 기록은 보존한다. 조건을 맞추지 못한 속도 결과는 동일 환경 성능 비교로 해석하지 않는다.

환경 준비를 위해 입력 축소, 모델 교체, 사전·프롬프트·폰트 변경, 제외·재시도·실패·렌더 규칙 변경을 임의로 하지 않는다. 실제 입력의 메모리 수용 여부와 전체 연결은 별도 승인된 사전 실행에서 확인한다.

### 사전 실행 가능성 점검

점검 입력·순서·범위와 smoke 실행 절차는 미정이다. 준비 과정의 설치 성공을 전체 입력의 실행 보장으로 간주하지 않으며, 실제 모델을 호출하는 점검은 별도 예산·실행 승인 후 수행한다.

| 항목 | 기준 |
|---|---|
| 비용 구분 | 이미지 생성 비용, AI 평가 비용, 격리 실행 인프라 비용을 분리한다. 기준 자료 작성·보정 비용도 공식 평가 비용과 구분해 기록한다. |
| 사용량 | 모델별 호출 수, 제공되는 토큰·이미지 사용량, 재시도 사용량을 기록한다. 실패한 호출에서 발생한 비용도 포함한다. |
| 금액 산정 | 실제 청구액을 확인할 수 있으면 사용한다. 사용량과 단가로 계산한 금액은 추정 비용으로 표시하고, 단가 출처·적용일·통화를 기록한다. |
| 로컬 실행 비용 | 확인 가능한 임대·과금 비용만 금액으로 계산한다. 전기료·장비 감가상각 등을 근거 없이 추정하지 않으며, 미산정으로 표시한다. |
| 비용 계산 | [OP05](aggregation.md#op05-모델자원-사용량과-비용)의 작업·섹션 단위 계산을 따른다. 배분 근거가 없는 공통 비용은 별도 기록한다. |
| 예산 관리 | 실제 측정 요청에서 승인된 예산 한도를 회차 기록에 남긴다. 한도 안에 끝낼 수 없다고 판단되면 추가 호출을 중단하고, 기존 결과와 미완료 범위를 보존한다. 계획 승인 자체를 유료 실측 승인으로 간주하지 않는다. |

PM의 비용 승인·부담은 합의 완료다. 실제 실행 범위와 비용 상한은 사용자가 최종 승인한다. 평가용 LLM API는 사용하지 않는다. 제품 생성·Codex 채팅 평가·기준 자료 작성 및 보정·격리 실행 인프라 비용을 구분한다. 확인할 수 없는 비용을 0원으로 처리하지 않는다.

### 9단계 비용 산정 후속 검토

산정 근거와 미확인 항목은 [비용 산정안](../../cost-estimate.md)에 둔다. 이는 실행 준비 작업의 2단계이며 평가 명세의 2단계(평가 대상·단위)를 변경하지 않는다. 전체 예상 비용과 실용적인 실행 상한은 미확정이다. 기존 제안은 모델별 호출·재시도 사용량에 단가를 적용하고, 실제 청구액과 추정 비용을 분리하며 단가 출처·적용일·통화를 기록하는 것이다. 숫자를 임의로 채우지 않고 산정안을 제시한 뒤 아래 승인을 받는다.

### AI 실행자의 사전 예산 승인

AI 에이전트는 유료 작업 전 실행 범위와 예상 금액을 제시하고 사용자의 실행 범위·비용 상한 승인을 받는다. PM의 비용 승인·부담 합의는 완료됐으므로 추가 PM 승인을 요구하지 않는다. 사전 점검·공식 생성·Codex 평가·기준 보정 비용을 구분하고, 추정 근거·단가 출처·통화·재시도 포함 여부·예상 범위와 승인받을 상한을 설명한다. 금액을 신뢰성 있게 추정할 수 없다면 그 한계와 제한된 점검 범위의 상한을 먼저 제안한다. 견적을 얻기 위한 유료 시험 호출도 승인 없이 수행하지 않는다.

승인된 범위·금액 상한·승인 시점과 근거를 회차 기록에 남기고 실행기의 호출·금액 한도에 반영한다. 설정 파일의 숫자만으로 사용자의 실행 승인을 대신하지 않는다. 승인된 범위 안에서는 호출마다 재승인받지 않고 실제 사용량을 기록한다. 여러 단계를 한 번에 승인받았다면 그 범위 안에서는 재승인을 요구하지 않는다. 포괄적인 예산 허용이나 과거 회차 승인을 새 실행의 무제한 승인으로 해석하지 않는다.

승인 상한을 초과할 것으로 예상되거나 승인 범위 밖의 추가 실행이 필요하면 추가 호출을 중단하고, 기존 결과를 보존한 뒤 변경된 예상 금액과 범위에 대해 사용자에게 다시 승인받는다. 실행 후 실제 사용량·확인 가능한 비용·추정 비용을 구분해 기록한다.

파일 검사·설정 준비·모델 없는 검증은 예산 승인 전에 진행할 수 있다. 이 절은 실제 모델 호출의 별도 승인 원칙을 완화하지 않는다.

## 측정 도구 준비 범위

[평가 프로토콜](evaluation.md#ai-평가-방식)과 [결과 구조](../../runs/README.md)를 기록 기준으로 사용한다. 측정 스크립트·자동 집계·수집 도구 구현은 별도 작업이며, 이번 문서 정비는 제품 실행·모델 호출·유료 작업을 포함하지 않는다.

### 격리 실행 도구

기존 격리 BE와 로컬 저장 환경은 유지한다. 구체적인 호출·연결 절차와 도구 수정 범위는 아직 정하지 않는다. 기존 도구 출력이나 시험 파일을 최신 명세의 공식 실행 방법으로 간주하지 않는다.

## baseline 완료 기준

**후속 검토 제안:** 아래 완료 체크리스트는 기존 실행 설계안을 최신 지표에 맞춰 정리한 것이다. 남아 있는 N3·N5 필수 확인 담당자·A등급 표본 안 채택·기준 자료 동결과 예산·실행 범위를 확인하기 전에는 공식 완료 판정에 사용하지 않는다.

| 항목 | 기준 |
|---|---|
| 대상 처리 | 원본 34건 모두에 산출물 생성 완료·전체 제외 종료·실패 등의 최종 실행 상태가 기록되어 있어야 한다. 전체 제외의 적합성(정상 제외·잘못된 제외·판단 불가)은 실행 상태와 별도 기록한다. 미실행 작업이 남으면 공식 측정은 미완료로 둔다. |
| 품질 기록 | [최신 지표](aggregation.md)의 평가 결과·예외 상태·결함 근거를 연결한다. K01~K09·중대 결함·불확실 판단·A등급 일부 표본은 [7단계 프로토콜](evaluation.md#7단계-사람-검수-프로토콜)에 따라 확인한다. |
| baseline 실행 기록 | [Baseline 보조 운영지표](aggregation.md#baseline-보조-운영지표-7개)를 집계하고 수집 불가·미산정 이유를 표시한다. |
| 사람 검수 | 7단계 합의 범위를 검수하고, N3·N5 필수 확인 담당자·A등급 표본 안 채택·기준 자료 동결 등 남은 항목을 확인한 뒤 완료 여부를 판단한다. |
| 재확인 가능성 | 실행 조건·입력 목록·산출물·판정 근거가 연결되고, 결과 묶음과 백업을 확인할 수 있어야 한다. |
| 점수와 완료 구분 | 낮은 품질이나 기록된 실행 실패 자체는 측정 미완료 사유가 아니다. 높은 점수 달성이 아니라 측정과 기록의 완결성으로 완료를 판단한다. |
| 재실행 구분 | 평가 도구 오류 등으로 재측정하면 기존 회차를 보존하고 새 회차로 기록한다. 품질 개선 후 실행한 결과를 최초 baseline으로 교체하지 않는다. |

K01~K09에 필요한 산출물이 없거나 정상 제외된 경우에도 해당 예외 상태와 이유를 확인·기록한다. 산출물 부재를 품질 합격으로 처리하지 않는다.

규제·현지 판정은 제외 영역을 포함해 사람이 확인한 기대 처리와 대조하고 [원인 단계별 결함](aggregation.md#단계-진단-방식)으로 집계한다. 후속 회차는 원본 등급 전이와 baseline 결함 추적·신규 결함 기록을 포함한다. 비교 이력이 없는 최초 baseline에 후속 비교 결과를 요구하지 않는다.

### 규제·현지 판정의 표본 한계

고정 34장만으로 현지부적합 양성·규제 금지형 등 모든 유형의 미탐을 충분히 검증했다고 주장하지 않는다. [기존 100섹션 실측](../../../ai-experiments/2026-09-29_03-1-judge_run-v1.md)의 '7건'은 현지부적합 800항목 중 양성 7건(3섹션)을 뜻하며, 규제 전체 사례 수가 아니다. 같은 기록에는 규제 매칭 31건과 금지형 매칭 부재가 기록되어 있다. 이 수치를 새 baseline의 실제 분포로 사용하지 않는다.

부족한 유형의 합성 사례 보강은 후속 평가로 둔다. Baseline에서는 규제·현지 판정 결함의 내부 진단과 결함 추적 비교를 수행한다. [OI-54](aggregation.md#oi-54-규제-위험-표현-검출-재현율)의 별도 평가셋 재현율·오탐 건수와 섞지 않는다. [NFR-15](aggregation.md#nfr-15-인페인팅-텍스트-잔존)의 자동 측정법·분모·기준값도 아직 미확정이다.


## 이번 회차의 무수정 실행 조건

[2026-10-28 범위 변경](../../plan.md#이번-회차-측정-범위--pm-검토-대기)에 따라 N3의 AI 최초 섹션 선택과 N5의 자동 번역문을 변경하지 않는다. N3·N5의 필수 확인·경고 확인은 정상 서비스 경로로 수행하고 담당자·시각·최초/확인 후 값·경고 확인 근거를 보존한다. 증거가 없으면 confirmation_only로 추정하지 않는다. 요청을 자동 승인하거나 단계 상태를 직접 바꾸어 진행하지 않는다.

최초 미리보기는 N5 확인 전에 machine_snapshot으로 보존하고, 수정하지 않은 결과를 정상 N6 경로로 생성해 service_final로 보존한다. 두 체크포인트는 각각 H02·H03으로 평가한다. AI의 잘못된 섹션 선택·번역은 실행 중 고치지 않고 결함으로 기록한다. 예상치 못한 변경이나 필수 확인을 정상 수행할 수 없는 상태는 보존·보고하고 범위를 임의 확대하지 않는다.

H05와 사용자 수정 효과는 후속 서비스 평가 대상이다. 필수 확인의 변경 없음 기록은 측정 범위 준수 증거이며 사용자 수정 부담 0건 또는 실제 사용자 승인 성공의 증거가 아니다. PM은 기준 자료와 AI 평가를 검수하며 제품 결과를 수정하지 않는다.

### 측정 도구 후속 보완 — 이번 작업에서는 미구현

- 회차 측정 범위를 명시하고 무수정 회차에서 편집 요청·최초/최종 값 불일치를 검출한다. 기존 서비스 확인 절차와 수동 확인 근거는 유지한다.
- H05의 자동 0건/분포/평균 집계를 억제하고 미측정 사유를 보존한다. 사용자 수정 회복 분석을 생략하되 기준 정의와 후속 서비스 평가 기능은 유지한다.
- OP06은 내부 기록에 실험 조건과 해석 한계를 연결하고 발표에서 제외한다. PM 평가 수정과 제품 수정 신호를 혼동하지 않는다.
- 두 체크포인트 보존, H01~H04 기존 집계, 필수 확인 누락/편집 발생 차단, H05 미측정 출력, 비용 승인 보류를 합성 테스트로 확인한다. 기존 테스트 이력은 보존하며 새 범위 검증을 통과한 것으로 표시하지 않는다.

이 보완·비과금 검증과 PM 검토 및 사용자 최종 비용·실행 승인 전에는 공식 실측을 시작하지 않는다.

## 비과금 구현의 사람 개입 방식

아래는 범위 변경 전 구현 기능이다. 편집 지원은 보존하지만 이번 회차에서는 사용하지 않는다. 새 범위 구현·검증 완료를 뜻하지 않는다.

[실행 도구](../../../../tools/baseline/README.md)는 N3의 전체 섹션 선택과 N5의 번역문·경고를 사람이 확인할 때까지 다음 단계로 진행하지 않는다. 검수 요청 파일의 요청 ID·현재 상태·원본 연결을 고정하고, 사람은 별도 응답 JSON에 검수자와 편집 또는 진행 의사를 적어 실행 터미널에 경로를 입력한다. 응답 부재·오래된 상태·불일치 응답은 자동 승인하지 않는다. 제품 수정은 기존 SEC-03·CFM-02 함수를 사용하고 경고 확인은 사람이 입력한 목록만 CFM-04 처리에 전달한다.

N5 진입 직후 최초 미리보기를 복사한 다음 수정 입력을 받는다. 원본을 누락된 미리보기 대신 성공 산출물로 쓰지 않는다. N6 렌더 완료 후 최종 이미지를 복사하고 기존 저장 함수를 통해 저장 여부를 기록한다. H01의 산출물 보존과 OP01의 저장 완료를 구분한다. 원본별 수정 건수는 최초·최종 값으로, 중간 편집·경고 확인은 별도 증거로 남긴다. 사용자 추가 재생성은 현재 도구 범위에서 허용하지 않는다.

실행 회차의 최초 시작과 상품별 생성 점유 기록은 불변으로 생성한다. 프로세스 중단 후 같은 회차를 자동으로 처음부터 재실행하지 않는다. 잘못된 응답이나 중단 후 복구는 남은 시도·예산·원본 생성 이력을 검토하는 별도 작업이며 best-of 재생성으로 처리하지 않는다.
