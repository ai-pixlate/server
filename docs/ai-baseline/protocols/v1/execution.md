## 측정 실행 조건

실측은 실제 사용 조건과 기준 자료의 최종 확인, 예산·실행 승인, 승인된 smoke 점검, 공식 생성, K01~K09 평가 기준 보정, 공식 평가·사람 검수 순서로 진행한다. 기준 보정은 평가할 산출물을 확보한 뒤 공식 평가 전에 하며, 보정을 위해 공식 생성 결과를 다시 만들지 않는다. 준비 묶음의 생성이나 모델 없는 검증 통과는 이 작업들의 수행 또는 승인을 뜻하지 않는다.

| 항목 | 기준 |
|---|---|
| 측정 대상 | 확정된 릴리즈 1.0.0 커밋을 기준으로 한다. 실행에 영향을 주는 미커밋 코드 변경이 있는 상태에서는 공식 측정하지 않는다. |
| 실행 기록 | 제품 커밋, 평가 명세 버전, 모델·설정·프롬프트·사전·폰트·의존성 버전, 장비·운영체제를 기록한다. 제공되지 않는 외부 모델 버전 정보는 확인 불가로 표시한다. |
| 사용자 입력 | 원본 34장과 상품 메타데이터, 대상 언어·국가, 포함·제외·대체 선택을 고정한다. 실행 중 임의의 수동 수정으로 결과를 개선하지 않는다. |
| 실행 횟수 | 공식 생성은 원본별 1회로 한다. 품질이 낮다는 이유로 다시 생성해 좋은 결과만 선택하지 않는다. AI 평가는 [AI 평가 방식](evaluation.md#ai-평가-방식)을 따른다. |
| 실행 순서·동시성 | 원본 식별자 순서로 작업을 순차 실행한다. 모델 로딩 등 초기화 시간은 별도로 기록하고, 첫 작업의 초기 실행 여부도 표시한다. |
| 캐시 | 이전 회차의 생성 결과를 재사용하지 않는다. 모델 파일 등 실행 준비용 캐시는 허용하고, 외부 서비스의 캐시 사용이 확인되면 기록한다. |
| 재시도·시간 제한 | 측정 대상 릴리즈의 재시도·시간 제한 설정을 사용하고 실행 기록에 고정한다. 측정 도중 성공률을 높이려고 변경하지 않는다. |
| 후속 비교 | 평가 조건은 유지한다. 고도화에 따른 모델·설정 변경은 비교 대상 변경으로 기록하며, 장비·실행 환경이 달라진 속도 결과는 같은 조건의 성능 개선으로 해석하지 않는다. |

원본별 1회는 공식 작업 실행 횟수이며, 그 작업 내부의 릴리즈 설정에 따른 재시도는 같은 작업으로 기록한다.

실제 릴리즈 커밋·장비명 등 회차별 값은 실행 기록에 기입한다. 값의 기록과 도구·평가표 준비는 확정된 계획의 실행 작업이다.

### AI 에이전트의 수행 범위

AI 에이전트는 확정된 명세와 제공된 자료를 바탕으로 실행 설정 작성, 입력 검증, 결과 수집·정리와 평가 기록을 수행한다. 자료에서 확인할 수 있는 값은 먼저 확인하고, 사용자의 직접 작업이 필요하거나 측정 대상·평가 기준·실행 범위에 영향을 주는 결정만 질문한다. 확인되지 않은 상품 정보·처리 기대값·사람 검수 완료 여부를 임의로 채우지 않는다.

기준 자료 확인과 사람의 최종 판정은 [사람 검수 범위](evaluation.md#사람-검수-범위)를 따른다. 비용이 발생하는 실행은 [사전 예산 승인](#ai-실행자의-사전-예산-승인)을, 커밋·푸시는 [입력·결과 보관 방식](#입력결과-보관-방식)의 승인 규칙을 따른다.

### 격리 BE 실행 경로

통제된 환경에서 측정용 실행기가 해당 릴리즈의 BE 처리 흐름을 순차 호출하여 분석·판정·하류 처리·최종 렌더·산출물 저장을 수행한다. 실행 진입점은 CLI를 사용할 수 있다. 사전·용어집 공급, 섹션 제외, 실패 처리, 렌더 입력 조립과 원본별 이미지 조립은 기존 처리 코드를 재사용하며 별도 규칙으로 재구현하거나 생략하지 않는다.

격리 PostgreSQL과 해당 릴리즈의 마이그레이션·참조 데이터를 준비하고 실제 모델 어댑터를 사용한다. 작업 전달과 저장소는 격리 실행에 맞게 연결할 수 있으나, 시험용 가짜 모델·합성 사전·시험용 스타일 설정을 공식 생성에 사용하지 않는다. 운영 EC2·RDS·S3, 외부 API 서버와 별도 Celery 워커 배포를 필수 조건으로 두지 않는다.

같은 원본의 한 번의 실행에서 단계별 산출물과 최종 이미지를 수집한다. 기존 단계별 CLI로 생성 단계를 따로 다시 실행한 결과는 공식 회차에 섞지 않는다. 측정용 실행기 버전, DB 스키마, 사전·용어집·브랜드 메타데이터 등 참조 데이터의 스냅샷 식별자·해시, 정책 규칙·스타일 기본값, 저장소·작업 전달 방식과 장비·자원 제한을 회차 기록에 남긴다. 실행 경로나 환경이 달라진 처리 시간은 동일 조건의 성능 비교로 사용하지 않는다.

| 시점 | 고정 입력·행동 |
|---|---|
| N1 | 상품별 상품명·규제 분류·카테고리와 미국·영어를 기록한다. 같은 상품의 원본에는 같은 상품 메타데이터를 적용한다. |
| N3 | 서비스의 기본 판단을 수용하고 제외된 내용을 수동으로 되살리지 않는다. 이 판단을 평가 정답으로 사용하지 않는다. |
| N5 | 번역문을 수정하지 않는다. 해당 릴리즈의 확정 처리가 요구하는 미해결 경고를 정확히 기록하고 확인한다. 경고 확인은 번역 품질 합격을 뜻하지 않는다. |
| 최종 결과 | N6 최종 렌더와 저장된 이미지 확보까지 포함한다. ZIP 등 별도 내보내기는 평가하지 않는다. |
| 전체 제외 | 포함할 섹션이 없으면 N6 확정을 강제하지 않는다. 전체 제외 종료와 기대 처리에 대한 적합성을 구분해 기록한다. |

N1·N3·N5·N6는 기존 처리 흐름의 상태를 뜻하며 화면 조작을 요구하지 않는다. 격리 DB에 처리에 필요한 판매자·브랜드·작업 레코드를 준비한다. 운영 판매자 계정은 요구하지 않는다. 측정 작업을 다른 작업과 분리하고 장비의 동시 작업 여부를 기록한다.

상품의 서비스 카테고리와 실행용 호환값은 [평가셋의 상품 카테고리](dataset.md#상품-카테고리)를 따른다. 기존 체계의 용어집을 유지하고 실행용 `internal_category`를 작업에 직접 입력한다. 서비스 화면의 카테고리 선택과 표시 카테고리→내부 분류 매핑 기능은 이 측정에서 검증하지 않는다. 측정 준비 도구에서 새 카테고리 체계 지원을 위해 제품 로직을 변경하거나 용어집 코드를 임의 치환하지 않는다.

후속 측정에서 새 카테고리 체계나 용어집을 적용하면 변경 내용을 비교 조건에 기록한다. 해당 품질 차이를 모델 변경만의 효과로 해석하지 않는다. 측정 대상 릴리즈가 새 체계를 지원하게 되면 실행 전 호환값과 용어집의 일치를 다시 확인하며, 기존 확정 입력을 자동으로 바꾸지 않는다.

### 로컬 실행 환경과 재현 조건

| 항목 | 구성 |
|---|---|
| 장비·OS | 현재 Windows PC에서 BE·OCR·LaMa를 실행한다. 학교 GPU 서버와 운영 인프라는 연결하지 않는다. |
| Python | 측정 전용 가상환경을 사용하고 BE·OCR·GPU 의존성의 호환성을 검증한다. 기존 개발 환경은 유지한다. |
| OCR | 릴리즈의 OCR 모델·설정과 CPU 빌드 Paddle을 사용한다. CPU 실행 조건을 후속 측정에도 유지한다. |
| LaMa | 로컬 NVIDIA GPU와 호환되는 PyTorch CUDA 빌드를 사용한다. 학교 서버의 패키지 버전 재현은 요구하지 않는다. 릴리즈가 지정한 모델·가중치·정밀도는 유지한다. |
| DB | localhost 전용 PostgreSQL에 측정용 DB를 준비한다. Docker는 필수가 아니며 독립 실행형 설치도 허용한다. 릴리즈 마이그레이션과 확인된 참조 데이터를 사용한다. |
| 작업·저장 | 기존 격리 실행기의 순차 작업 전달과 로컬 파일 저장소를 사용한다. Redis·외부 API 서버·별도 Celery 워커·S3 배포는 요구하지 않는다. |

운영 환경과 동일한 구성보다 고도화 전후의 비교 조건 유지가 우선이다. 장비·OS·드라이버·Python·패키지·DB 버전과 설치 출처, 모델 파일 해시, 전원 연결·전원 모드·동시 작업·자원 제한을 회차에 기록한다. 설치 목록과 재설치에 필요한 파일 또는 고정된 배포 정보를 보존한다. 호환성 검증이 끝난 조합을 고정하며 준비 과정의 설치 성공만으로 실행 가능성을 확정하지 않는다.

후속 측정에서는 고도화 대상인 코드·모델·설정 변경을 명시하고 나머지 실행·평가 조건을 유지한다. 외부 모델은 제공자가 노출하는 모델 ID·버전·설정과 실행일을 기록하며 내부 버전을 완전히 고정할 수 있다고 가정하지 않는다. 장비 등 환경 변경이 불가피하면 기존 릴리즈도 새 환경에서 다시 측정해 비교 조건을 맞추되, 최초 baseline 기록은 보존한다. 조건을 맞추지 못한 속도 결과는 동일 환경 성능 비교로 해석하지 않는다.

환경 준비를 위해 입력 축소, 모델 교체, 사전·프롬프트·폰트 변경, 제외·재시도·실패·렌더 규칙 변경을 임의로 하지 않는다. 실제 입력의 메모리 수용 여부와 전체 연결은 별도 승인된 사전 실행에서 확인한다.

### 사전 실행 가능성 점검

- 입력이 제공된 뒤 원본 34장의 폭·높이·면적 목록, 실제 OCR 타일 조건, 실행 프로세스와 장비의 자원 제한을 확인한다.
- '100만 픽셀당 5GiB' 같은 미검증 선형 추정식을 실행 가능성 판정 기준으로 사용하지 않는다. 전체 섹션 면적만으로 타일 추론의 최대 메모리를 단정하지 않는다.
- 별도로 승인된 smoke 실행에서 폭이 큰 입력과 긴 입력의 경로를 확인한다. 가장 큰 섹션 1개 통과를 34장 전체의 실행 보장으로 해석하지 않는다. smoke는 공식 측정과 구분한다.
- 실행기 오류·잘못된 릴리즈 코드나 참조 데이터 연결·자원 설정 문제는 공식 측정 전에 정리한다. 실제 모델 전체의 연결과 산출물 보존을 확인한다. 고정한 정상 환경에서 릴리즈의 입력 처리 한계로 발생한 실패는 baseline 결과로 남긴다.
- 공식 측정 중 조건을 바꾸어 성공 결과로 교체하지 않는다. 사전 점검 계획의 승인은 실제 smoke 실행 승인이 아니다.

## 비용과 예산

| 항목 | 기준 |
|---|---|
| 비용 구분 | 이미지 생성 비용, AI 평가 비용, 격리 실행 인프라 비용을 분리한다. 기준 자료 작성·보정 비용도 공식 평가 비용과 구분해 기록한다. |
| 사용량 | 모델별 호출 수, 제공되는 토큰·이미지 사용량, 재시도 사용량을 기록한다. 실패한 호출에서 발생한 비용도 포함한다. |
| 금액 산정 | 실제 청구액을 확인할 수 있으면 사용한다. 사용량과 단가로 계산한 금액은 추정 비용으로 표시하고, 단가 출처·적용일·통화를 기록한다. |
| 로컬 실행 비용 | 확인 가능한 임대·과금 비용만 금액으로 계산한다. 전기료·장비 감가상각 등을 근거 없이 추정하지 않으며, 미산정으로 표시한다. |
| 시도 원본당 / 기술 처리 완료 원본당 실행 비용 | 전체 실행 비용÷시도 원본 수와 전체 실행 비용÷기술 처리 완료 원본 수를 함께 표시한다. 개별 작업에 배분할 근거가 없는 공통 비용은 별도 기록한다. 분모가 0이면 산출 불가로 표시한다. |
| 예산 관리 | 실제 측정 요청에서 승인된 예산 한도를 회차 기록에 남긴다. 한도 안에 끝낼 수 없다고 판단되면 추가 호출을 중단하고, 기존 결과와 미완료 범위를 보존한다. 계획 승인 자체를 유료 실측 승인으로 간주하지 않는다. |

원본당 실행 비용은 이미지 생성·격리 실행 인프라 비용을 대상으로 하며, AI 평가·기준 자료 작성·보정 비용과 구분한다. 확인할 수 없는 비용을 0원으로 처리하지 않는다.

기술 처리 완료 원본 수는 [원본 이미지 기술 처리 완료 비율](aggregation.md)의 정의를 따르며 산출물 생성 완료와 전체 제외 종료 건수를 함께 표시한다.

### AI 실행자의 사전 예산 승인

AI 에이전트는 비용이 발생하는 모델 호출 전에 실행 범위와 예상 금액을 사용자에게 제시하고 명시적 승인을 받는다. 사전 점검·공식 생성·AI 평가·기준 보정 비용을 구분하고, 추정 근거·단가 출처·통화·재시도 포함 여부·예상 범위와 승인받을 상한을 설명한다. 금액을 신뢰성 있게 추정할 수 없다면 그 한계와 제한된 점검 범위의 상한을 먼저 제안한다. 견적을 얻기 위한 유료 시험 호출도 승인 없이 수행하지 않는다.

승인된 범위·금액 상한·승인 시점과 근거를 회차 기록에 남기고 실행기의 호출·금액 한도에 반영한다. 설정 파일의 숫자만으로 사용자 승인을 대신하지 않는다. 여러 단계를 한 번에 승인받았다면 그 범위 안에서는 재승인을 요구하지 않는다. 포괄적인 예산 허용이나 과거 회차 승인을 새 실행의 무제한 승인으로 해석하지 않는다.

승인 상한을 초과할 것으로 예상되거나 승인 범위 밖의 추가 실행이 필요하면 추가 호출을 중단하고, 기존 결과를 보존한 뒤 변경된 예상 금액과 범위에 대해 다시 승인받는다. 실행 후 실제 사용량·확인 가능한 비용·추정 비용을 구분해 기록한다.

파일 검사·설정 준비·모델 없는 검증은 예산 승인 전에 진행할 수 있다. 이 절은 실제 모델 호출의 별도 승인 원칙을 완화하지 않는다.

| 기존 도구 재사용 | 확정 명세에 필요한 기록을 남길 수 있는 도구는 재사용한다. 기존 출력 형식을 정답 기준으로 삼지는 않는다. |
| 검수 자료 | 원본·결과·결함 위치·AI 근거를 함께 볼 수 있게 한다. 결과 전달 시 원본별 단계 산출물·최종 이미지·평가 근거를 찾을 수 있는 경로 또는 색인을 제공한다. 이미지로 생성되지 않는 단계는 구조화된 결과의 확인 위치를 안내한다. 검토용으로 추가한 주석·비교 이미지는 실제 파이프라인 산출물과 구분한다. 정적 비교 이미지와 평가표로 충분하면 별도 웹 UI를 만들지 않는다. |
| 누락 방지 | 원본 34장과 K01~K09의 기록 누락, 중복 식별자, 산출물 연결 오류를 자동 확인한다. 도구 검증용 실행은 공식 측정과 구분한다. |
| 결과 보존 | AI 판정과 사람 수정 이력을 보존한다. 재실행으로 이전 결과를 덮어쓰지 않는다. |

### 격리 실행 도구

[격리 DB 기반](../../../../tests/exec_db.py), [하류 전체 흐름 시험](../../../../tests/test_exec_downstream.py), [작업 순차 실행 기반](../../../../tests/exec_fakes.py)의 연결 구조를 활용해 측정용 실행기를 준비한다. 시험 파일을 그대로 공식 측정 명령으로 사용하지 않는다. 실제 모델을 호출하는 어댑터와 릴리즈의 처리 함수를 연결하며, 원본 34장·상품별 메타데이터·참조 데이터를 공급한다.

N5 경고의 기록·확인 전달, 전체 제외 종료, 원본별 순차 실행과 단계별 증거·시간·사용량 수집을 baseline 조건에 맞게 준비한다. 경고 확인 목록을 비워 보내거나 `translation_failed`가 있다는 이유만으로 일괄 중단하지 않는다. 기존 처리의 진행 불가 상태를 무시하거나 강제로 진행하지 않는다. 작업 전달 방식이 달라져도 릴리즈의 재시도·시간 제한과 종료 판정을 유지하는지 확인한다.

원본과 작업·시도의 연결을 보존하고, 응답 유실 시 실제 반영 여부를 확인해 중복 생성하지 않는다. 산출물과 평가에 필요한 DB 기록은 종료 전에 파일로 보존한다. 시험 기반의 DB 자동 삭제나 메모리 저장소 종료로 증거가 사라지지 않게 하며, 원본별 결과를 보존한 뒤 메모리를 정리한다. 실행기 보완과 시험은 측정 준비 작업이며, 실제 모델 호출은 별도 승인된 범위에서 수행한다.

## 입력·결과 보관 방식

| 항목 | 기준 |
|---|---|
| 입력 제공 | 사용자가 확정한 [고정 평가셋](dataset.md#평가-대상) 경로 `pipeline/samples/evaluation/gs-v1/`를 사용한다. 파일이 없거나 목록과 다르면 다른 위치의 이미지로 임의 대체하지 않는다. |
| 입력 동일성 | 실행 전 평가셋의 파일 목록·해시와 실제 원본을 대조하고, 사용한 평가셋 버전과 목록을 회차 기록에 보존한다. 원본 식별자·파일명·크기·해상도·SHA-256을 기록하며, 내용이 달라진 파일을 같은 고정 입력으로 취급하지 않는다. |
| 회차 구분 | 제품 버전·평가 명세 버전·회차 ID로 구분한다. 입력 목록, 실행 조건, 결과, 평가·검수 기록을 서로 연결한다. |
| 보관 형식 | 기계가 읽을 원시 기록은 JSON/JSONL, 집계·검수표는 CSV, 설명·요약은 Markdown으로 보관한다. 이미지 산출물도 함께 보존한다. |
| 저장 위치 | 이 교육용 프로젝트에서는 원본 이미지·중간 산출물·최종 이미지를 저장소에 보관하는 것이 허용되어 있다. 고정 원본과 목록은 평가셋 폴더에서 Git으로 관리한다. 중간·최종 산출물과 평가 기록은 원본 폴더에 섞지 않고 회차별 결과 위치에 보관한다. 문서에는 요약과 결과 묶음 식별자를 남긴다. 보관 허용은 자동 커밋·푸시 승인이 아니며, 커밋·푸시는 사용자 요청 시 수행한다. |
| 접근·백업 | 측정 참여자에게 필요한 접근만 허용하고, 결과 묶음은 주 보관본 외 별도 위치에 백업 1부를 둔다. 비밀번호·API 키·토큰 등 비밀 정보는 기록·저장소에 포함하지 않는다. |
| 보관 기간 | 고도화 비교와 최종 발표가 끝날 때까지 보존한다. 이후에도 사용자 결정 없이 자동 삭제하지 않는다. |

## baseline 완료 기준

| 항목 | 기준 |
|---|---|
| 대상 처리 | 원본 34건 모두에 산출물 생성 완료·전체 제외 종료·실패 등의 최종 실행 상태가 기록되어 있어야 한다. 전체 제외의 적합성(정상 제외·잘못된 제외·판단 불가)은 실행 상태와 별도 기록한다. 미실행 작업이 남으면 공식 측정은 미완료로 둔다. |
| 품질 기록 | 품질 지표별 등급 또는 예외 상태와 근거가 연결되어 있어야 한다. K01~K09 확인과 baseline B/C 문제 영역 기록이 완료되어야 한다. |
| baseline 실행 기록 | 원본 이미지 기술 처리 완료 비율·시간·사용량·비용을 집계하고, 수집 불가·미산정 항목은 이유를 표시해야 한다. |
| 사람 검수 | 확정한 필수·표본·확대 검수를 마치고, 불일치를 최종 판정 또는 판단 불가로 정리해야 한다. |
| 재확인 가능성 | 실행 조건·입력 목록·산출물·판정 근거가 연결되고, 결과 묶음과 백업을 확인할 수 있어야 한다. |

| 재실행 구분 | 평가 도구 오류 등으로 재측정하면 기존 회차를 보존하고 새 회차로 기록한다. 품질 개선 후 실행한 결과를 최초 baseline으로 교체하지 않는다. |

K01~K09에 필요한 산출물이 없거나 정상 제외된 경우에도 해당 예외 상태와 이유를 확인·기록한다. 산출물 부재를 품질 합격으로 처리하지 않는다.

규제·현지 판정은 제외 영역을 포함해 기대 처리와 대조하고 원본별 등급과 세부 집계를 남긴다. 후속 회차는 원본 등급 전이와 baseline 결함 추적·신규 결함 기록을 포함한다. 비교 이력이 없는 최초 baseline에 후속 비교 결과를 요구하지 않는다.

### 규제·현지 판정의 표본 한계

고정 34장만으로 현지부적합 양성·규제 금지형 등 모든 유형의 미탐을 충분히 검증했다고 주장하지 않는다. [기존 100섹션 실측](../../../ai-experiments/2026-09-29_03-1-judge_run-v1.md)의 '7건'은 현지부적합 800항목 중 양성 7건(3섹션)을 뜻하며, 규제 전체 사례 수가 아니다. 같은 기록에는 규제 매칭 31건과 금지형 매칭 부재가 기록되어 있다. 이 수치를 새 baseline의 실제 분포로 사용하지 않는다.

부족한 유형의 합성 사례 보강은 후속 평가로 둔다. 규제·현지 판정의 정탐·미탐·오탐 집계와 결함 추적 비교는 최초 측정 범위에 포함하며, 추가 OCR 정량 지표·일반화 평가의 보류와 구분한다.
