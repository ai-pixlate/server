## 확정한 추출·집계·재개 규칙

기존 `protocol.py`, `full_runner.py`, `validated-run-config.json`의 실제 동작을 그대로 공식 측정 기준으로 채택한다. 파일 해시는 [대조 기록](../../analyses/tq03-registration-20261124/audit.json)에 고정되어 있다. 최종판에도 같은 모델·설정·루브릭·프롬프트 구성·추출·집계·재개 동작을 적용하며 새 예외 정책을 추가하지 않는다.

1. 모델 출력은 `raw_output`으로 보존한다. 엄격 파서는 `Feedback: Reason: … Issues: … Direction: … [RESULT] N` 전체 형식을 요구한다. 완전 충족 `ok`는 0개, `format_error`는 487개, `output_limit`는 4개다. 형식 불일치를 생성 실패나 0점으로 바꾸지 않는다.
2. 별도 표지 추출은 Python `re.findall(r'\[RESULT\]\s*([1-5])(?!\d)', raw)`를 사용하고 **일치가 정확히 한 개**이면 `reported_score`로 보존했다. 엄격 파서의 `score`와 구분한다. 실제 491개 출력 재대조에서 집계용 점수 불일치는 0개였다.
3. 평균·분포는 `status in ('ok', 'format_error')`이면서 `reported_score`가 있는 항목만 사용한다. 출력 토큰 수가 384 이상이면 `output_limit`로 분류하고 표지가 있어도 평균에서 제외한다. `input_limit`(입력 2048 초과), 실행 오류도 점수 집계에서 제외하며 상태별 수를 남긴다. 토큰을 잘라 재평가하거나 한도를 자동 변경하지 않는다.
4. 기본 합계 970 / 점수 확보 449 = 평균 2.1603563474점(표시 2.16/5). 분포는 1점 28, 2점 345, 3점 61, 4점 6, 5점 9개다. 점수 없는 42개는 표지 미확보 38개와 출력 한도 4개로 분리한다. `score` 필드는 전부 null이며 `reported_score` 추출이 구조화 형식 충족을 의미하지 않는다.
5. 기존 GS-02-block-430의 본문 2점은 `body_only_score`로 보존된 보조값이다. 이것만 더한 기존 보조 통계는 450개 평균 2.16이다. 기본 449개 통계와 섞지 않으며 다른 본문 점수를 임의 복구하지 않는다. 최종판도 기본 통계에는 표지 점수만 사용한다. 기존 코드의 보조 표시 순서(표지 점수 우선, 없으면 저장된 body_only_score)와 별도 보조 통계는 유지하지만, 새 출력 본문에서 점수를 자동 추출하는 절차를 추가하지 않는다.
6. 재개 시 항목 파일이 없으면 실행하고, 파일이 있으면 기본적으로 건너뛴다. `retry_ids`에 명시한 항목만 기존 상태가 `error/output_limit/input_limit`일 때 재시도한다. `ok/format_error`의 재생성은 기존 코드가 거부한다. 자동 재시도나 새 최대 횟수 제한은 추가하지 않는다. 실행 오류는 해당 기록을 저장한 뒤 중단하며 다음 재개에서도 명시적인 재시도 선택을 따른다.
7. 결과 선택은 점수 비교가 아니라 **항목별 현재 저장 파일** 기준이다. 각 시도를 `attempts/<attempt_id>.json`에 보존하고 같은 내용을 `items/<키 해시>.json`에 원자적으로 저장한다. 허용된 재시도가 저장되면 실패·한도 상태여도 현재 항목 파일을 대체하며, 과거 최고점/성공값으로 되돌아가 선택하지 않는다. 집계는 attempts 전체가 아닌 items의 항목별 현재 결과를 읽는다. 기존 seed 결과는 해당 항목 파일이 없을 때만 넣고, 입력·프롬프트·실험 식별값을 확인한다.
8. 실제 전수 실행 기록은 신규 475개에 시도 파일 475개로 항목별 한 번씩이며 재시도 이력은 없다. 세션 중단 뒤 남은 113개를 재개한 것이 이미 완료한 362개의 재평가는 아니다. 위 재시도 동작은 기존 코드에 있는 그대로 채택한 것이며 실행되지 않은 재시도를 수행했다고 주장하지 않는다.
9. 점수 확보율은 `점수 확보 수 / 전체 적용 대상 수`로 병기한다. 평균은 점수 확보 수로 나누고, 결측은 0으로 대체하지 않는다. 점수 확보 0이면 평균은 미산출, 전체 대상 0이면 대상 없음으로 구분한다. TQ03 원시 상태를 H 지표의 `measured/evaluation_failed`로 자동 매핑하지 않는다.

기존 정규식의 소수·부가 텍스트 매칭 특성도 그대로 유지한다. 이번 결과에는 소수 표지나 복수의 유효 표지가 없었다. 발생하지 않은 예외를 위한 정규식 강화·새 차단 규칙·Baseline 재집계를 추가하지 않는다.

## 버전 비교와 표시

버전 간 블록 대응·비교·발표 방식은 **측정 착수의 선행 조건이나 미결 사항이 아니다**. 각 버전의 성공 번역 블록을 같은 규칙으로 측정하며, 대응 분석은 결과 해석 단계와 구분한다.

절대 평균을 독립적인 성능 주장이나 합격률로 발표하지 않는다. v1.0.1 Baseline과 최종판 변화 비교에 한정하며, 동일 모델의 편향이 상쇄된다고 단정하지 않는다. 특정 문체·라벨·성분·숫자에 대한 평가 편향은 버전별 문구 구성에 따라 다르게 작용할 수 있다. 모델의 지적은 확정 오류가 아닌 사람 검토 후보이며, 한국어 요약 번역·별도 분석·사람 수정 후보와 모델 원문을 구분한다.

각 버전에서 다음을 따로 기록한다(결과 파일 필드를 새 enum/API 계약으로 정하는 표가 아니라 보고 항목이다).

## 측정 규칙 확정과 별도 확인 상태

측정 규칙의 미결 사항은 없다. 위 코드·설정·해시를 기준으로 최종판에도 같은 동작을 적용한다. 최종판은 해당 버전의 성공 번역 대상·문자열·산출물 해시를 기록하고 별도 결과 폴더와 실험 식별값을 사용한다. 입력이 달라진 최종판에 Baseline 16개 seed나 491개 점수를 복사하지 않는다. 입력·코드·설정이 다른 기존 결과 폴더를 재사용하지 않는 것은 기존 prepare의 검증 동작이다. 원본 실험 파일의 `official_metric=False` 등 당시 상태 표기는 보존하고, 공식 기준 채택 사실은 이 명세로 연결한다.

- **원시 자료 접근성:** 로컬 원본과 해시는 확인했으며 팀 공용 보관·접근 위치는 확인되지 않았다. 다른 실행자가 원본 묶음을 확보하지 못한 경우의 실행 환경 문제이며, 측정 규칙 확정의 미결 조건으로 두지 않는다.
- **가중치 이용 조건:** 미확정 상태다. 기존 비상업적 소규모 연구 승인과 향후 상업적 지속 사용 허용을 구분한다. 측정 기준 확정이 이용 조건 확인을 대신하지 않는다.
- **실제 추가 실행:** 이번 작업은 명세 확정과 기존 자료의 오프라인 대조만 수행한다. 최종판 산출물 확보·Colab 환경 확인·추가 실행은 별도 요청 시 진행하며 이번 작업에서 모델을 호출하지 않는다.

기존 H01~H04 준비 묶음·지침 사본·동결 정답·채점 도구·실측 증거는 수정하지 않는다.
