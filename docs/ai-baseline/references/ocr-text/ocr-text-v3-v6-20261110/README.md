## 동결 내용과 검수 범위

- 112개·1,861줄의 ID·순서 유지. 원본에 없는 GS-02_002/sec_1_01 L005·006은 원문을 보존한 채 비활성화(활성 1,859줄, 평가 분모와 다름).
- GS-02_001/sec_1_03 L045는 사용자 육안 판독에 따라 `상품앞 @표시품목 : 부가세 면세품목`으로 수정. changes.json과 GT change_history에 근거를 보존.
- 기존 v1 12개 검수 이력 승계. 신규 100개 중 사용자 검수 47개, **AI만 검수 53개**. 오류 발견 0건 회신은 47개에 한정. 최종 동결 승인이 사람 전수검수 수행을 뜻하지 않는다.
- 기존 미전사 수용 이력·표본 검수 한계는 review-history-v2.json 원문 그대로 보존. 최신 포함/제외 범위와 함께 해석한다.
- 원본 이미지 바이트는 중복 복사하지 않고 inputs.json에 ID·경로·크기·해시로 고정. 외부 경로 이미지와 원시 출력은 별도 보존 자료이며 이 폴더만으로 모두 이동·백업됐다고 주장하지 않는다.

## 고정 부분 평가 규칙

**포함 105 / 정책상 제외 4 / 고정 undetermined 3**. 정확한 ID 목록은 evaluation-plan.json에 있다. Good all goodal, 제형 숫자 3, 배경 b3+의 세 섹션은 모든 후속 버전에서도 undetermined다. OCR 실패·정책상 비대상과 구분하고 결과에 따라 자동 복귀시키지 않는다. 이번 기준선에는 crop 평가를 도입하지 않는다.

분모는 포함 105개에서 활성·포함 GT의 정규화 문자 수 합계다. 분자는 같은 범위 S+D+I 합계이며 섹션 비율 평균을 사용하지 않는다. 105개에 추가 실패/미측정이 생기면 고정 부분 CER도 확정하지 않는다. 전체 112개 CER은 산출·표시하지 않는다. 후속 발표에는 **고정 105개 섹션 부분 CER**, 전체 범위·제외·보류·실패를 함께 표시한다.

v5 A2의 분리·병합 휴리스틱·반복 문구 대응 한계는 승인된 방법의 한계로 유지한다. 기존 v4 결과·v5 후보 결과는 그대로 보존하며 범위/방법 차이를 제품 개선율로 해석하지 않는다.

## 재현·검증

```powershell
python docs/ai-baseline/references/ocr-text/ocr-text-v3-v6-20261110/verify.py --check-inputs --check-source-evidence
```

manifest.json은 자신을 제외한 모든 동결 파일의 SHA-256을 가진다. manifest 자체 해시는 완료 보고에 별도로 제공한다. 이후 파일을 수정하지 않고 변경 시 새 버전을 만든다. validation.json에 Python/Unicode/플랫폼·원본 Git HEAD와 미커밋 상태를 기록했다. Git SHA만으로 이번 미커밋 구현을 재현할 수 없으므로 구현 바이트 스냅샷·해시를 함께 고정했다.

동결 전 합성·회귀 147개 통과. 실제 입력은 prepare_section만 호출했으며 문자 채점 호출 시 실패하도록 막았다. **105 ready / 4 not_applicable / 3 undetermined**, 실제 metrics 모두 null을 확인했다. 기존 동결본·결과·원시 증거 보호 해시 356건을 확인했다(중복 가능, 독립 원시 파일 수 아님).

최초 v6 CER은 별도 사용자 실행 승인 후 가능하다. 호출 시 GT의 active 필드를 보존하고 동결본 approval을 검수 근거로 사용한다. 공통 필터·v5 대응·고정 부분 집계는 동결된 코드 해시와 일치해야 한다. 과거 후보 preflight CLI의 미승인 기본값을 승인 근거 없이 강제 변경하는 방식은 사용하지 않는다. 동결 입력을 읽는 실행 연결에서 ID·이미지·GT·출력·정책 해시를 먼저 검증한다.

2·3차에는 동일 원본·GT·범위·명세·구현을 적용하고 제품 SHA·보정 후 출력·환경/설정·출처만 버전별 기록한다. 새 출력의 대칭 범위 연결은 다시 검증한다. 영역 경계 교차 등 새 문제가 발생하면 추가 미측정으로 기록하며 고정 부분값 확정도 중단한다.

이번 작업은 동결과 검증만 수행했다. CER/OCR/API 호출·커밋·push·PR은 하지 않았다. 동결본이 GitHub에 보존됐다는 의미도 아니다.
