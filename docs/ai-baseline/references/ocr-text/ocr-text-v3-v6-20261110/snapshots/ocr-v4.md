# OCR 텍스트 기반 CER 채점 명세 v4

상태: 사용자 텍스트 동결 승인 반영 · v4 채점 기준. 동결·채점 도구 사용법은 [도구 안내](../../../../tools/baseline/ocr.md)를 따른다. 2026-11-04 사용자 범위 변경에 따른 새 명세이며 [v3](../../../ai-experiments/2026-09-25_02-ocr_scoring-spec-v3.md)를 덮어쓰지 않는다. 현재 승인 범위는 텍스트 정답 동결과 채점기 구현·합성 검증까지다. 실제 v1.0.1 CER 측정·OCR 실행은 하지 않는다.

## 1. 범위와 출력 경계

평가 입력은 기존 고정 섹션 12개, 전사 초안 369줄이다. 전사 정확성·누락 전수 확인 완료 및 오류 0건은 사용자의 채팅 회신을 근거로 기록한다. 좌표 정확성·겹침 38건 검수는 생략하며 텍스트 검수 완료로부터 좌표·태그 검수 완료를 추론하지 않는다. 연결 순서는 후속 사용자 결정으로 기존 `lines[]` 배열 순서를 채택했다.

평가 대상은 실제 서비스가 사용하는 **OCR 보정 후 `OcrResult.regions[].text`**다. 코드 근거는 [ocr.run](../../../../pipeline/stages/ocr.py), 이를 호출하고 반환값을 병합 단계로 전달하는 [analyze.py](../../../../pipeline/analyze.py)다. 해당 제품·설정에서 활성화된 호출 내 중복 제거, 타일 간 중복 정리, 보완 OCR·국소 재인식이 완료된 반환값을 사용한다. 짧은 섹션에 적용되지 않는 처리를 별도로 실행하지 않는다.

엔진의 원시 `rec_texts`, 진단 중간 후보, 블록 병합·역할 분류 결과, 번역문은 대체 입력으로 쓰지 않는다. 여기서 보정은 제품 OCR 단계의 후처리이며 평가자가 맞춤법을 고치는 것이 아니다. 제품 내부의 좌표 사용은 유지하되 **채점기는 bbox/poly를 읽어 정렬·매칭·필터링하지 않는다.** 제품 SHA·설정·모델·후처리 경계·입출력 해시·시도 ID를 기록한다. v1.0.1 및 향후 버전도 같은 반환 경계를 사용한다. 현재 코드만으로 과거 산출물의 경계가 검증됐다고 단정하지 않는다.

## 2. 연결 순서와 정규화

- 정답: 별도 텍스트 동결본의 `order` 순서. 사용자 결정에 따라 기존 JSON의 `lines[]` 배열 순서를 그대로 채택하고 `line_id`와 원래 인덱스를 보존한다. 별도 동결본의 `order`는 이 배열 순서와 일치해야 한다. bbox나 문자열 내용으로 재정렬하지 않는다.
- 출력: 보존된 보정 후 `regions` 배열 순서 그대로. `region_key` 정렬·좌표 정렬·정답과 가장 유사한 순열 탐색을 하지 않는다. 배열 순서가 서비스 출력의 일부이므로 순서 오류도 문자열 차이에 반영된다. 순서가 소실된 저장 형식은 추측 복원하지 않고 `undetermined`로 둔다.
- 각 문자열을 NFC로 정규화한 뒤 아래 공백을 전부 제거하고 구분자 없이 연결한다. 섹션 경계를 넘어 연결하지 않는다. Unicode 코드포인트 단위로 계산하며 UTF-8 바이트·UTF-16 코드 유닛·그래핌 수가 아니다.
- 제거 공백: U+0009–000D, U+0020, U+0085, U+00A0, U+1680, U+2000–200A, U+2028–2029, U+202F, U+205F, U+3000. U+200B와 U+FEFF는 그대로 둔다. 사용한 Unicode 정규화 데이터 버전을 기록한다.
- 대소문자·문장부호·전각·단위 표기는 유지한다. NFKC·띄어쓰기 교정·맞춤법 보정·사전 치환은 하지 않는다.
- 보조 공백 유지 CER은 이번 v4 범위에서 산출하지 않는다. OCR02와 별개로 필요 시 후속 합의한다.

## 3. OCR01 계산·누락·반복

평가 단위는 **섹션 전체 텍스트 쌍**이다. 정답 R과 출력 P의 최소 Levenshtein 거리(치환·삭제·삽입 각각 비용 1)를 구한다. 분자는 `S+D+I`, 분모 N은 정규화된 정답 코드포인트 수, `CER=(S+D+I)/N×100`이다. 100%를 초과해도 자르지 않는다.

동률의 S/D/I 내역은 문자열 끝에서 역추적하며 일치→치환→삭제→삽입 순서로 동일 최소 비용 경로를 선택한다. 총 거리와 각 내역을 보존한다. 이는 좌표상 줄별 오류나 원인을 확정하는 값이 아니다.

누락·추가·반복 텍스트는 전체 문자열 편집거리에 반영한다. 임의 줄 매칭, 출력 중복 제거, confidence 필터, 최적 줄 재배열을 하지 않는다. 반복 문구는 정답과 출력 양쪽에서 발생 횟수를 그대로 유지한다. 누락이 항상 특정 줄의 삭제만으로 배분된다고 주장하지 않는다. 예를 들어 정답 `AB`, 출력 `ABAB`는 추가된 두 문자를 삽입으로 처리한다. 정답 두 줄 `A`, `B`와 출력 한 줄 `AB`는 같은 문자열이며 분리·병합 품질을 측정하지 않는다.

정상 성공 반환 `regions=[]` 또는 모든 text가 빈 문자열이면 P는 빈 문자열이고 N>0에서 삭제 N건이다. 파일 누락·실행 실패를 빈 문자열로 대체해 100% CER로 만들지 않는다. text 필드 누락/null/잘못된 형식은 유효한 빈 문자열이 아니다.

## 4. 제외와 예외 상태

좌표를 쓰지 않으므로 v3의 영역 대응·mixed_scope·제외 줄 대응 출력 제거를 적용하지 않는다. 로고·제품 라벨·회전·겹침 텍스트는 텍스트 평가에서 별도 제거하지 않는다. 후속 처리 대상만의 CER과 rotated 부분 CER도 이번에는 산출하지 않는다.

**사용자 확정: L008은 빈 정답 유지.** `GS-02_014/sec_1_09 L008`의 원문 text는 빈 문자열로 유지하며 기존 `illegible` 태그와 줄 ID도 변경하지 않는다. 해당 줄을 동결 자료에서 삭제하지 않는다. 정답 연결 시 기여 글자 수는 0이며, 이 사유로 섹션을 제외하거나 `undetermined`로 두지 않는다. 섹션의 다른 정답 글자는 정상적으로 분모에 포함한다.

보정 후 OCR 출력은 해당 위치의 텍스트를 포함해 그대로 연결한다. 좌표·유사도·신뢰도·번역 제외 여부를 이용해 제거하지 않는다. 빈 정답에 없는 출력 문자는 전체 문자열 최소 편집거리에 반영되며, 위치별 삽입 오류로 독립 확정하지 않는다. 판독 불가 위치를 빈 문자열로 채택한 기준상의 한계를 결과에도 명시한다. 이 결정은 L008에 한정하며, 향후 다른 판독 불가·잘림 항목에 자동 적용하지 않는다.

| 상태 | 처리 |
|---|---|
| measured | 승인된 텍스트 정답·순서·입력 해시·보정 후 출력 경계가 유효하고 계산 성공 |
| undetermined | 순서·입력/출력 경계 등 필수 근거 미정; 수치 미산정 |
| no_output | 기대한 보정 후 산출물 없음·실행 실패. 사유 기록 |
| evaluation_failed | 산출물 파싱·채점·기록 실패. 빈 결과로 간주하지 않음 |
| not_applicable | 승인된 평가 범위에서 정답 글자 N=0. `— / 해당 대상 없음`, 출력 문자 수는 별도 기록 |

적용 대상은 있으나 measured 섹션이 0이면 `— / 정상 측정 0건`과 원인별 개수를 기록한다. 전체 CER은 measured 섹션의 `Σ(S+D+I)/ΣN`이며 섹션 비율 평균을 쓰지 않는다. 예정 12개 중 측정·보류·출력 없음 등을 공개하고 유효 분모가 다른 결과를 동일 범위로 비교하지 않는다.

## 5. 좌표 검증 없는 별도 텍스트 동결 설계

기존 v3 정답·history·verified·bbox·이미지·원시 실측 증거는 수정하지 않는다. `truth.py freeze`는 좌표까지 검증하는 기존 기능으로 유지하며 v4 동결에 사용하지 않는다. 자동 검사를 통과시키기 위해 겹침 태그를 붙이지 않는다.

사용자 승인에 따라 `docs/ai-baseline/references/ocr-text/<version>/`에 별도 동결본을 만든다. 도구 전용 필드·파일 형식은 [도구 안내](../../../../tools/baseline/ocr.md)를 따른다. 승인 근거 원문은 approval.json, 동결 시점 명세 바이트는 spec-v4.txt에 함께 보존한다.

| 파일 | 최소 기록 |
|---|---|
| text_units.jsonl | 섹션 ID, 원본 정답 경로·SHA-256, 입력 이미지 SHA-256·크기, 줄 ID·원본 인덱스·명시적 order·원문 text. 좌표는 포함하지 않음 |
| manifest.json | 텍스트 전용 버전·상태·승인자/승인 근거·시각, v4 명세 경로/커밋/해시, 파일별 SHA-256, 계획/포함/보류 섹션 목록과 이유, 원본 태그 참조 및 텍스트 검수 범위 |
| README.md | 사용자 전사 검수 완료·오류 0건, bbox 검수 생략, lines[] 순서 채택의 사용자 결정 근거, 제외 결정, 출력 노출 이력(미확인 시 미확인), 사용 제한 |

절차: 원본 해시 고정 → 원문 text와 ID를 무손실 추출 → 12개/369줄·누락/중복 ID·이미지 해시 대조 → 추출 순서가 원본 lines[]와 일치하는지 검증 및 L008 빈 정답 유지 확인 → 추출 전후 전사 동일성 검증 → 사용자 승인 근거를 기록하고 별도 텍스트 버전 동결. 정규화 문자열은 파생값이며 원문을 덮어쓰지 않는다. bbox 겹침은 동결 실패 조건이 아니며 텍스트 동결이 위치 품질 승인을 뜻하지 않는다.

## 6. 후속 구현·검증과 한계

출력 배열 순서 보존, 공백/NFC/코드포인트 처리, 누락·반복·빈 출력·잘못된 파일·편집거리 동률·0분모를 합성 사례로 검증한 뒤 채점한다. 동결·채점 도구는 실제 출력이 아닌 합성 데이터로 검증한다. 기존 9개 출력의 입력 동일성 근거는 재사용하되 보정 후 반환 경계까지 연결 확인해야 한다. 나머지 표본의 근거 부족·미도달 상태는 [자료 점검](../../ocr-preflight.md)을 따른다.

텍스트 동결은 사용자 승인 범위다. 남은 결정은 실제 측정 및 부족한 출력 보완 실행 범위다. OCR02는 계속 보류한다. v3의 위치 기반 지표와 v4 섹션 문자열 CER은 직접 비교하지 않으며 향후 비교는 동일 동결본·v4·입력으로 맞춘다.
