# OCR01 번역 대상 텍스트 CER — v6 범위 명세 초안

## 2026-11-10 승인 결정과 고정 부분 평가

이 절은 아래 과거 준비 상태·미결 표현보다 우선한다. [새 GT·범위 후보](../../preparations/ocr-v6-gt-candidate-20261110/README.md)는 사용자 최종 검토 전이며 아직 동결하지 않았다.

- 기존 112개 입력을 유지하고 별도 crop 평가는 이번 기준선에 도입하지 않는다.
- GS-02_002/sec_1_01의 L005·L006은 원본에 없는 데이터이므로 새 GT 후보에서 `active=false`로 비활성화한다. 기존 ID·텍스트·순서와 변경 이력을 보존한다. 원본 v2는 수정하지 않는다. 비활성화 근거는 `not_present_in_source`와 사용자 승인으로 연결하며 OCR에는 동일 문자열 제거 규칙을 적용하지 않는다. 실제 영역 안에 추가 OCR이 있으면 삽입 후보로 유지한다.
- GS-01_002/sec_1_23, GS-03_005/sec_1_01, GS-03_014/sec_1_03은 모든 후속 버전에서 고정 `undetermined`다. 정책상 제외·OCR 실패가 아니며 출력이 바뀌어도 자동 채점하지 않는다.
- 후보 목록은 포함 105 / 정책상 전체 제외 4 / 고정 undetermined 3이다. 정확한 ID는 `evaluation-plan.json`으로 고정한다. 후보의 연결 검증과 GT 완전성·최종 동결 승인은 별개다.
- 공개 가능한 값은 **고정 105개 범위의 부분 CER**이다. 분모는 그 범위에 포함된 활성 GT의 정규화 문자 수 합계이며, 분자는 같은 범위의 S+D+I 합계다. 제외 4개와 보류 3개를 0오류로 넣지 않는다. 대상 105개 중 하나라도 추가 미측정/실패/GT 불완전이면 고정 부분 CER도 확정하지 않는다. 진단용 측정 부분값은 별도로 표시한다.
- 전체 112개 CER은 산출하지 않는다. 부분 CER·측정 범위·4개 제외·3개 보류 및 추가 실패를 함께 공개한다. v1.0.1·2차·3차에 같은 입력/GT/범위/채점기 버전·해시를 적용한다. 범위 변경은 새 기준선이며 기존 v4 공식 결과·v5 후보 결과를 덮어쓰지 않는다.

2026-11-09 사용자 정책 결정 반영. **평가 목적·제외 정책은 확정, 영역 연결·채점 구현·GT 동결·공식 전환은 미완료**. 기존 [v4](ocr-v4.md)·[v5 후보](ocr-v5.md), OCR Text v1/v2와 결과는 그대로 보존한다. v6은 새 범위 명세를 구별하기 위한 초안 이름이며 공식 채점기 버전 승인이 아니다.

## 평가 목적과 적용 범위

OCR01은 **원본 기준으로 고정된 번역 대상 텍스트의 문자 오류율(CER)**이다. 서비스 보정 후 OCR 최종 반환값을 평가한다. GS-01~03의 112개 고정 섹션 이미지를 유지하며, N3 최종 제외·실제 번역 성공/실패·제품의 라벨 판정·OCR confidence로 평가 분모를 바꾸지 않는다. GS-01_001도 N3 제외와 무관하게 대상 문구를 평가한다.

사용자 확정 정책:

- 제품 용기·패키지 인쇄, 명시적으로 적용되는 상품 브랜드 로고는 제외한다.
- 논문 자체의 제목·저자·본문·표·캡션·참고문헌은 모두 제외한다. 상세페이지가 별도로 작성한 시험 결과·효능 설명·원료 주석은 포함한다. 논문 위에 겹친 별도 설명도 포함하며, 논문 이미지라는 이유로 통째로 지우지 않는다.
- 기프트카드 자체 인쇄는 제외하고 별도 구매·혜택 안내는 포함한다.
- 인증 마크의 로고·심볼 내부 문구는 제외하고 별도 인증·효능 설명은 포함한다. 원형 배치라는 이유만으로 일반 시험 결과 안내를 인증 마크로 간주하지 않는다.
- 협업·타브랜드 로고·패키지 인쇄는 제외하고 상세페이지 일반 설명은 포함한다.
- 설명·효능·사용법·주의사항·수치·단위·각주는 번역 대상이면 작은 글씨라도 포함한다.
- 특허증과 시험성적서 내부 문구는 모두 번역·OCR 평가에서 제외한다. 상세페이지에 별도로 작성한 효능 설명·시험 결과 요약·인용문은 포함한다. 문서 위에 겹친 별도 인용문도 문서 내부 문구와 구분한다. 다른 종류의 인증서 전체로 제외를 임의 확대하지 않는다.
- 원본에서 고정한 번역 대상 영역 밖의 얼굴·배경 등 비텍스트 영역 오검출은 OCR01 CER에서 제외한다. 번역 대상 영역 내부의 오검출은 삽입 오류로 반영한다. OCR 출력이나 GT 일치 여부로 번역 대상 영역을 사후 축소하지 않는다.
- 일반 설명은 포함하고 로고·심볼 내부 문구는 제외한다. `Good all goodal` 같은 혼합 반환값을 전체 포함하는 예외는 없다. 안전한 분리가 검증되지 않으면 해당 영역 채점을 보류하며 문자열을 임의 수정·분리하지 않는다.
- 위 정책에 해당하는지 모호한 개별 영역은 사용자 판단 대상으로 남긴다. 판독 불가를 빈 GT로 바꾸거나, CER가 높다는 이유로 제외하지 않는다.

이 정책의 서비스 적용 의도는 사용자 결정이지만, v1.0.1에 논문 제외 구현이 있었다는 뜻은 아니다. 현재 근거는 [영역 연결 보고서](../../analyses/ocr-scope-linkage-20261109/README.md), 서비스 후속 확인 사항은 [PM·BE 공유 초안](../../analyses/ocr-scope-linkage-20261109/pm-be-policy-note.md)에 기록한다. 이 명세로 제품 동작·API·DB 계약을 변경하지 않는다.

## 영역과 GT·출력의 대칭 범위

원본 이미지의 큰 의미 영역을 포함/제외/검토 대상으로 주석한다. bbox 정확성 점수는 산출하지 않는다. 현재 주석은 대략적인 위치 안내이며 사각형 안의 모든 문자를 같은 대상으로 확정한 마스크가 아니다. 포함 문구를 포장 사진과 함께 덮거나, 논문 위 효능 설명을 제외하지 않도록 범위 연결 검토가 필요하다.

GT line ID → 승인된 범위와 OCR region → 같은 범위의 연결을 별도로 보존한다. GT에서만 텍스트를 제거하거나, 출력과 문자열이 비슷한 GT만 선택하지 않는다. 기존 텍스트 전용 동결본에는 검증된 줄별 범위 연결이 없으므로 자동 필터 입력으로 바로 사용할 수 없다.

후속 필터 구현 전 확정할 조건:

1. 원본/범위/GT 버전과 해시가 일치하고 정책 미결이 없어야 한다.
2. 하나의 OCR 결과가 포함·제외 영역을 함께 덮으면 문자열을 임의 분할하지 않는다. 원본과 연결을 확인하기 전 `undetermined`로 관리한다. 완결되지 않은 섹션을 일부 좋은 문자만 골라 완결 결과로 표시하지 않는다.
3. 누락된 대상 GT는 D, 대상 범위의 추가·중복 출력은 I로 유지한다. 비대상 판정에는 원본 의미 근거가 필요하다. 오검출 좌표가 제외 영역으로 이동해 삽입 오류가 숨겨지는 편향도 검증한다.
4. 큰 사각형의 부분 교차는 검토 후보 생성에만 쓴다. 겹침 비율/중심점 임계값이나 포함·제외 우선순위를 이번 초안에서 임의 확정하지 않는다.
5. GT 범위 연결, 출력 경계 통과, 영역 중첩, 좌표 부재/범위 이탈, 정책 미결을 구별해 기록한다. 출력 원문·해시·region ID는 그대로 보존한다.
6. 섹션 내 모든 GT 줄과 모든 OCR 영역에 누락·중복 없는 범위 연결이 있어야 한다. 기하 교차 후보만 있는 항목, 사람 확인이 필요한 의미 판정, 포함/제외가 섞인 단일 OCR 문자열이 남으면 해당 섹션의 채점을 차단한다. 자동 분할이나 문자열 유사도에 따른 제외를 하지 않는다.
7. 빈 OCR 문자열은 대상 GT를 삭제하거나 비대상으로 바꾸는 근거가 아니다. GT 완전성·범위 승인과 출력 연결 검증은 별도이며 모두 충족해야 한다. 현재 혼합 33개는 검증 미완료로 채점 가능 0개다. 이는 실행 실패나 CER 결과가 아니다.

### 사용자 검수 후 정책 보완

2026-11-09 후속 사용자 확정이 검수 JSON의 D05·D06·G01·G02 해석보다 우선한다. [정책 반영·영역 연결 재검토](../../analyses/ocr-v6-policy-followup-20261109/README.md)를 현재 근거로 사용한다. 과거 33개 혼합 섹션 점검은 당시 범위의 이력이며 특허증·시험성적서 2개가 추가로 혼합이 된다. 번역 대상 영역을 먼저 고정해야 하므로 기존 I0 전체 포함 기본값을 비텍스트 영역까지 채점하는 승인 규칙으로 사용하지 않는다. 원본 기반 포함 영역 및 문서 위 별도 인용문 경계를 검증하기 전 공식 채점은 차단한다.

## 계산·예외·집계

범위가 승인되고 완전한 GT/출력 연결이 확보된 섹션에만 계산한다. `CER = (ΣS + ΣD + ΣI) / ΣN × 100`; N은 **포함된 GT의 정규화 문자 수**다. 문자 수로 가중 집계하며 섹션별 비율을 단순 평균하지 않는다. 100% 초과를 자르지 않는다.

NFC·공백 제거·코드포인트·대소문자/문장부호 보존 및 반복 횟수는 기존 명세를 유지한다. 줄 내부 순서를 보존하고, v5 A2 순서 대응은 후속 검증 후보로 재사용한다. v5의 휴리스틱/분리·병합 한계를 해결됐다고 간주하지 않는다.

- 범위상 대상 없음: `not_applicable`, N=0, CER `— / 해당 대상 없음`. 라벨/논문 전용과 무문자 이미지를 사유로 구분하고 출력 증거는 보존한다.
- 포함 대상은 있으나 GT 불완전·정책/경계 미정: `undetermined`. 0오류나 비대상으로 대체하지 않는다.
- 정상 OCR 빈 반환: 대상 N자 삭제. 실행 실패·사용 가능한 출력 없음은 `no_output`; 파일·해시·형식 검증 오류는 `evaluation_failed`로 산출을 차단한다.
- 대상은 있지만 정상 측정 섹션이 0개: `— / 정상 측정 0건`, 원인별 수를 함께 표시한다.
- 전체 112개·대상·비대상·미결·실패·실제 측정 섹션 수, GT 문자 분모를 공개한다. 미측정 GT가 불완전하면 전체 문자 분모를 추측하지 않는다. 일부만 계산한 값을 112개 전체 결과로 부르지 않는다.

## 재현과 버전 비교

### 공통 범위 필터 후보

[고정 영역·필터 검증 기록](../../preparations/ocr-v6-fixed-scope-20261109/README.md)의 후보는 원본 픽셀 좌표와 이미지 해시를 사용한다. GT/출력 모두 같은 범위 분류 함수를 사용하며, 미확인 영역은 제외하지 않고 차단한다. 별도 인용문이 문서 제외 영역과 겹치면 포함 주석에 차감할 문서 영역 ID를 명시하고 양쪽 연결을 검증한다. 이는 후보 구현 규칙이며 전체 112개 영역 승인·공식 전환이 완료됐다는 뜻은 아니다. GT/OCR 원문은 보존하며 v5 연결용 원문 배열 생성과 실제 CER 실행은 분리한다.

112개 원본 바이트, 정책 버전, 승인된 영역, GT line 범위 연결, 사용자 승인, GT·명세·필터·채점기 해시를 함께 고정한다. 제품별 보정 후 출력·제품 SHA·환경·설정·출처도 기록한다. v1.0.1·2차·3차에 동일 입력/정답/범위를 적용하며 제품의 N3/라벨/로고 출력으로 범위를 다시 만들지 않는다.

기존 v4/v5와 분모가 달라질 수 있으므로 새 결과를 과거 값 대비 OCR 개선률로 해석하지 않는다. 동일 새 기준으로 각 버전을 평가한 뒤에만 비교한다. 이번에는 새로운 GT·점수·필터를 만들지 않았으며, OCR02·H01~H05·OP01~OP07 정의는 변경하지 않는다.

## 섹션 유형별 검증 조건 (2026-11-09)

[유형별 검증 보고서](../../preparations/ocr-v6-type-validation-20261109/README.md)를 최신 필터 검증 결과로 참조한다. 전체 포함은 원본 이미지 해시에 결합된 제외 요소 없음 근거가 있을 때 GT 줄 위치를 요구하지 않는다. 모든 문자열과 누락·중복·삽입은 유지한다. 전체 제외는 정책 근거를 요구하고 not_applicable로 분리한다. 혼합은 기존 GT·OCR 대칭 영역 규칙을 그대로 적용하며 미검증 경계와 혼합 문자열을 차단한다. 이전 109개 확인 필요 수는 개선 전 이력이다. 이 조건은 GT 전사 승인이나 CER 공식 전환을 의미하지 않는다.

## 사용자 제외 판정과 연결 후속 검증 (2026-11-09)

최신 범위 후보와 필터 검증 현황은 [제외 판정 적용 보고서](../../preparations/ocr-v6-policy-application-20261109/README.md)를 참조한다. 위 검증 수치·미구현 표현은 각 점검 당시 이력이며 전체 v6 승인 상태를 뜻하지 않는다.

- `GS-03_005/sec_1_01`의 제형 숫자 `3`과 `GS-03_014/sec_1_03`의 옅은 배경 `b3+`는 사용자 채팅 판정으로 제외한다. 일반 설명의 숫자 3이나 검정 전경 설명까지 제외하지 않는다.
- 정책 판정과 범위 연결 검증은 별개다. 제형 숫자 GT의 확인된 범위는 제외하되 각주까지 걸치는 OCR 출력은 보류한다. 배경 b3+는 제외 정책을 기록했어도 전경 제목과의 연결이 해소되지 않으면 GT만 강제 제거하지 않고 섹션을 차단한다.
- 범위 sidecar의 `required_decision`은 해당 원문의 고정 정책(`include`/`exclude`)이고 `policy_evidence`는 해시로 연결한 사용자 근거다. 필터 결과가 이 정책과 다르면 `policy_scope_connection_unresolved`로 차단한다. 사용자 판정이 좌표 검증을 대신하지 않는다.
- `unresolved_connections`는 원본의 겹침·경계 연결 미결을 기록한다. 모든 반환 영역이 기하상 분류되더라도 이 값이 남으면 채점 입력으로 넘기지 않는다.
- 정상 반환의 정확한 빈 문자열 `""`에는 필터링할 문자가 없다. 전체 제외 이외 섹션에서는 원문 빈 레코드를 보존하고 이 레코드의 경계 교차만으로 차단하지 않는다. 포함 GT는 그대로 남으므로 누락을 감추지 않는다. 공백 문자열·없는 출력·실행 실패는 이 예외로 통과시키지 않는다. GT 미검증과 섹션 범위 차단도 유지한다.

이번 연결 검증은 GT 원문·줄 순서·동결본을 바꾸지 않는다. 필터 준비 완료와 GT 완전성·v5 대응 방식 검증·v6 공식 전환/채점 승인은 별개다.

### 연결 보완 및 빈 GT 처리

최신 후보 범위는 [기술적 연결 보완](../../preparations/ocr-v6-connection-repair-20261109/README.md)에 기록한다. 이전 82개 완료·30개 차단은 보완 전 이력이다.

정확한 빈 GT 문자열에도 구분할 문자가 없으므로 위치를 발명하지 않고 빈 원문 줄을 보존한다. 별도 사용자 근거가 있는 빈 GT 제외만 제외로 기록한다. OCR는 이 빈 GT와의 유사도나 존재 여부에 관계없이 원본 영역으로 독립 분류하므로 삽입 문자를 숨기지 않는다. 비어 있지 않은 GT의 위치 연결, 공백 문자열, GT 완전성·정책·섹션 차단은 완화하지 않는다. 이 조건은 GT 전사를 바꾸거나 누락된 정답을 빈 문자열로 대체하는 허가가 아니다.
