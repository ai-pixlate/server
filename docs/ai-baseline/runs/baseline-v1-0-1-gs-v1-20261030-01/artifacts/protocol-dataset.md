# 고정 평가셋

> 상태: 기존 지표 정의 유지 · 2026-10-28 회차 범위 변경 PM 승인 완료(2026-10-28 사용자 확인) · 공식 생성 미실행 · 기준 자료 동결 후 공식 채점

## 평가 대상

GS-01~03은 버전 간 품질 비교용 고정 평가셋이다. [OI-54 규제 위험 표현 검출 재현율](aggregation.md#oi-54-규제-위험-표현-검출-재현율)을 측정하는 별도 평가셋을 대신하지 않으며, 이 평가셋의 결과를 NFR-14 충족 근거로 사용하지 않는다.

1.0.1 baseline과 후속 버전 측정에는 GS-01~03의 원본 34장 전체를 동일하게 사용한다.

GS-01~03 원본 34장은 baseline과 후속 고도화 실측에서 공통으로 사용하는 고정 평가셋 `gs-v1`이다. 저장 위치는 `pipeline/samples/evaluation/gs-v1/`이며, 상품별 하위 폴더에 원본을 보관한다. 아래 표의 파일 경로는 이 폴더를 기준으로 한다.

평가셋 버전은 제품 릴리즈 버전과 독립적으로 관리한다. 업로드 후 확인한 파일 목록·크기·해상도·SHA-256을 같은 폴더의 `manifest.json`에 보존한다. 각 측정 회차는 이 목록과 원본 해시를 대조한다.

고정한 원본은 덮어쓰거나 재인코딩·축소하지 않는다. 평가셋을 변경해야 하면 새 버전으로 보관하고 기존 `gs-v1`을 유지한다. 서로 다른 평가셋의 결과를 동일 입력에 대한 품질 개선으로 비교하지 않는다.

| 상품 묶음 | 상품 | 포함 파일 | 파일 수 |
|---|---|---|---:|
| GS-01 | 구달 어성초 선크림 | `GS-01/GS-01_001.jpg` ~ `GS-01/GS-01_002.jpg` | 2 |
| GS-02 | 셀리맥스 레티날 부스터 | `GS-02/GS-02_001.jpg` ~ `GS-02/GS-02_014.jpg` | 14 |
| GS-03 | 비클리닉스 톤업 바디로션 | `GS-03/GS-03_001.jpg` ~ `GS-03/GS-03_018.jpg` | 18 |
| 합계 | 상품 3종 | 각 범위의 모든 파일 | 34 |

고정 사용자 입력의 규제 분류는 GS-01=`otc`, GS-02·GS-03=`cosmetic`으로 확정한다. 같은 상품의 모든 원본에 동일하게 적용한다.

### 상품 카테고리

서비스 카테고리는 `category_master_v1_2026-10-19.xlsx`의 표시 카테고리와 용어집 분류로 기록한다. 기존 체계의 용어집을 사용하는 1.0.1 baseline 실행값은 별도로 고정한다.

| 상품 | 표시 코드·카테고리 | 용어집 분류 | baseline 실행용 `internal_category` |
|---|---|---|---|
| GS-01 | SN-01 · 선케어 > 선크림 | G04 · 선케어 | `Sunscreens & Tanning Products` |
| GS-02 | SK-02 · 스킨케어 > 에센스/세럼/앰플 | G01 · 스킨케어-기초 | `common` |
| GS-03 | BD-05 · 바디케어 > 바디로션/크림 > 바디로션 | G10 · 바디 | `common` |

실행용 값은 기존 릴리즈·용어집에 대한 호환 입력이며 새 마스터의 공식 매핑이 아니다. GS-02·03의 서비스 분류를 공통 분류로 변경한다는 뜻이 아니다. 카테고리 마스터 버전과 실제 사용한 용어집 스냅샷·해시를 함께 보존한다.

기존 개발용 입력본에서 제외했던 원본과 영역도 공식 평가셋에 포함한다. 기존 모델 출력과 과거 오류를 정답으로 사용하지 않는다.

기존 OCR 품질 표본 12개의 1.0.1 baseline 실행 제한은 [확정 결정](../../decisions.md#ocr-품질-표본의-실행-제한)에 따라 해제한다. 정답 초안은 보존하며 검수된 정답으로 취급하지 않는다.

## 평가 대상과 단위

### 고정 식별 단위

- `evaluation_run_id`: baseline 또는 고도화 평가 회차
- `dataset_id`: 동일한 고정 평가셋
- `case_id`: `GS-01`, `GS-02`, `GS-03`
- `source_key`: 회차 간 변하지 않는 원본 이미지 키

권장 `source_key` 형식:

```txt
GS-01-IMG-001
GS-01-IMG-002
GS-02-IMG-001
```

DB의 `source_image_id`, `section_id`, `block_id`는 실행마다 달라질 수 있으므로 회차 간 고정 분모로 사용하지 않는다.

### 고정 기준 단위 `reference_unit`

- `text_span`: 원본에서 실제로 보이는 하나의 텍스트 범위
- `semantic_block`: 함께 읽혀야 하는 텍스트 묶음과 기대 역할
- `critical_fact`: 수치·단위·제품명·용법·주의사항 등의 원자 정보
- `protected_visual`: 상품 형상·브랜드 로고·보존해야 할 시각 요소
- `policy_expectation`: 유지·제외·경고·대체·현지 부적합 기대 처리
- `layout_region`: 텍스트가 배치돼야 하거나 침범하면 안 되는 영역

`critical_fact` 중요도:

- `critical`: 잘못되면 구매·사용·규제 판단이 달라지는 정보
- `important`: 상품 이해와 사용에 중요한 정보
- `normal`: 보존 대상이지만 핵심 위험도는 낮은 정보

### 실행마다 달라지는 후보 단위

섹션, 텍스트 블록, OCR 영역, 줄, 산출물, 실행 시도, 모델 호출은 해당 회차의 결과를 설명하는 단위로 사용한다.

### 기준 단위와 실행 결과의 대응

- `exact`
- `partial`
- `split`
- `merged`
- `missing`
- `spurious`

고도화 후 섹션·블록 수가 달라져도 동일한 `reference_unit`을 기준으로 비교한다.

위 식별자와 대응 관계는 평가 문서의 개념 정의다. 최소 필드와 JSON·JSONL 연결은 [8단계 결과 구조](../../runs/README.md)를 따른다. 권장 `source_key`는 기존 원본 파일명을 변경하라는 의미가 아니다.

## 평가 구성

| 구성 | 범위 | 용도 |
|---|---|---|
| 공식 고정 평가셋 | 원본 34장 전체 | 전체 처리와 최종 품질의 버전 간 비교 |
| 중점 확인 영역 | 고정 평가셋 안의 주요 정보·취약 영역 | 수치 보존·로고 보호·배경 복원 등의 개선과 퇴행 추적 |
| 기존 단계별 입력본 | 기존 32장·100섹션 묶음 | 특정 단계의 원인 분석과 개발 중 회귀 확인 |

중점 확인 영역은 별도의 추가 표본이 아니다. 상품 → 원본 파일 → 원본 내 영역의 관계를 유지하고, 원본 파일과 좌표·내용으로 영역을 연결한다. 과거 섹션 번호는 참고값으로 사용한다. 분할 방식이 바뀌어도 같은 원본 영역을 비교하며, 과거 섹션 수를 고정하지 않는다.

## 중점 확인 영역

중점 확인 영역은 사전 핵심 영역 9곳과 1.0.1 baseline에서 확인된 B/C 문제 영역 전체로 구성한다. 원본 34장 전체 평가를 보완하며, 중점 영역만으로 전체 품질을 판단하지 않는다. 기존 B/C 문제 영역은 사용 가능성 판정에서 확인된 결함 위치로 이어받되, 현재 결함 유형·심각도는 [평가 기준](evaluation.md#실패결함평가-문제의-구분)을 따른다. K01~K09는 [사람 검수 대상](evaluation.md#7단계-사람-검수-프로토콜)에 포함한다.

| 구분 | 선정 시점 | 선정 기준 | 목적 |
|---|---|---|---|
| 사전 핵심 영역 | baseline 측정 전 | 상품별 3곳, 총 9곳. 중요한 수치·문구, 상품·로고, 복잡한 배경과 배치를 포함 | 반드시 유지해야 할 정보와 시각적 요소 확인 |
| baseline 문제 영역 | baseline 평가 후 | 1.0.1 baseline에서 B/C로 판정된 결함의 위치 전체 | 고도화에 따른 해결 여부와 재발 추적 |

하나의 영역에 여러 확인 항목을 포함할 수 있다. 사전 핵심 영역은 정보의 중요성과 시각적 특성을 기준으로 선정하며, 과거 개발 중 오류가 있었다는 이유만으로 선정하지 않는다.

영역은 판단에 필요한 주변 문맥과 배경까지 포함한다. 표는 제목·단위·각주를 함께 확인하고, 상품 보호는 상품 윤곽과 인접 편집 영역을 함께 확인한다.

### 영역별 기록

| 항목 | 내용 |
|---|---|
| 영역 ID | 버전이 바뀌어도 유지할 식별자 |
| 원본 식별자·좌표 | 원본 파일 식별자와 확인할 사각형 영역 |
| 구분 | 사전 핵심 영역 / baseline 문제 영역 |
| 관련 지표·결함 | 핵심 지표와 보호·복원·번역·배치 결함 등 |
| 기대 조건 | 해당 영역에서 유지하거나 충족해야 할 구체적인 조건 |
| baseline 판정·근거 | 1.0.1 baseline 측정 후의 판정과 근거 |
| 후속 판정·변화 | 후속 버전의 판정, 개선·동일·퇴행 및 근거 |

baseline 문제 영역은 같은 원인·유형끼리 묶어 검토하되 개별 위치를 모두 보존한다. AI 에이전트가 위치와 근거를 정리한다. 사람의 상세 확인 범위는 [7단계 사람 검수 프로토콜](evaluation.md#7단계-사람-검수-프로토콜)을 따른다.

해결된 baseline 문제 영역도 삭제하지 않고 재발 여부를 확인한다. 후속 버전에서 새로 발생한 문제는 전체 평가에서 찾아 기록한다.

## 비교 결과

상품별·전체 집계와 결함 추적은 [공식 버전 비교](aggregation.md#공식-버전-비교)를 따른다. 영역 ID와 결함 ID를 구분하며, K01~K09는 전체 평가를 보완하는 중점 영역이지 모든 지표의 분모가 아니다.

상품마다 원본 파일 수가 다르다. 이 평가셋은 동일 상품의 버전 비교에 사용하며 새로운 상품 전반에 대한 성능으로 확대 해석하지 않는다.

## 평가 기준 자료

AI 에이전트가 다음 항목을 정리하고 사람이 핵심 내용을 확인한다. 확인한 기준 자료는 후속 측정에서도 재사용한다.

- 반드시 보존할 상품명·수치·단위·주의문구
- 보존해야 할 상품·로고·패키지 영역
- 번역·제거·유지할 내용과 사용자 선택 조건
- 1.0.1 baseline 측정에서 문제가 확인된 영역 — baseline 측정 결과를 바탕으로 정리하고 후속 버전 비교에 사용한다.

사용자 선택과 처리 기대값을 기록해 의도적인 제외와 잘못된 누락을 구분한다. [사용자 수정 규칙 초안](evaluation.md#사용자-수정-규칙-초안)을 적용하고 [PM 검수 조건](evaluation.md#7단계-사람-검수-프로토콜)과 [박스 수정 기능 상태](evaluation.md#n5-박스-수정-기능-확인)를 따른다. 기존 명세의 일반 수정 규칙과 달리 이번 회차에는 [사용자 결정의 무수정 조건](../../plan.md#이번-회차-측정-범위--pm-승인-완료)을 적용한다(PM 승인 완료(2026-10-28 사용자 확인)). AI 최초 선택을 유지하더라도 이를 정책 기대값의 정답으로 삼지 않는다.

| 항목 | 기준 |
|---|---|
| 기준 자료의 내용 | 원본별 핵심 정보와 보호 대상, 유지·제거·번역 또는 대체할 내용을 기록한다. |
| 번역의 허용 범위 | 의미가 같은 자연스러운 표현 변경은 허용한다. 핵심 정보·조건·부정 표현의 누락이나 근거 없는 내용 추가는 허용하지 않는다. |
| 숫자·단위 | 원문의 값과 단위를 기본으로 유지한다. 변환이 필요한 경우 적용 규칙을 기준 자료에 명시한다. |
| 처리 기대값 | 서비스 정책과 고정된 사용자 선택을 기준으로 유지·제거·변경의 기대값을 정한다. 평가 대상 모델의 출력을 정답으로 사용하지 않는다. |
| 원본 자체의 결함 | 원본의 잘림·판독 불가 등은 모델이 새로 만든 오류와 구분한다. 근거 없는 복원을 정답으로 요구하지 않는다. |
| 기준의 재사용 | 확인된 기준 자료는 후속 버전 평가에도 동일하게 사용한다. 기준 오류를 수정하면 비교 대상에도 같은 기준을 적용한다. |

## 규제·현지 판정의 기대 처리

기대 처리는 원본 좌표·해당 문구에 연결하고, 섹션 포함·제외 판단과 포함한 텍스트의 대체·완충 지시를 분리한다. 새로 생성된 섹션 번호에만 정답을 묶지 않는다.

규제사전·현지부적합사전, 상품 규제 분류, 적용 정책·예외와 기록된 사용자 선택을 구분해 사용한다. 이번 회차의 실제 선택은 AI 최초 선택을 유지하지만 PM이 검증할 정답 정책 기대는 독립적으로 유지한다. 잘못된 자동 제외를 정답 제외로 재분류하지 않는다. PM이 사전·분류·문맥 기대값을 확인한다. 평가 대상 모델이나 평가 AI가 내린 판단으로 기대값을 채우지 않는다. 핵심 정보와 불확실한 기대값은 PM이 확인해 동결한다. [34장 기준 자료 초안](../../runs/reference-preparation-20261027/README.md)은 원본 좌표에 연결된 검토 후보이며 동결본이 아니다. 사람이 확인한 기대값이 없는 항목은 공식 정확도 비율이 아니라 참고용 진단으로만 사용한다. 허용·조건부 표현은 [규제 표현 처리 기준](evaluation.md#규제-표현-처리-기준)을 따른다.

정책대로 섹션 전체를 제외하면서 유용한 내용도 사라진 경우에는 정책 준수 여부와 정보 손실을 구분한다. 섹션 전체 제외 정책을 기준으로 삼으면서 부분 보존을 정답으로 요구하지 않는다. 기대 처리 자체가 바뀌면 동일한 기준을 비교 대상에 적용한다.

GS-01_001의 리뉴얼 안내와 GS-03_018의 상품정보 표처럼 보존할 정보와 교환·환불 규정 또는 국내 연락처가 함께 있는 경우, 제외 대상 문구를 원본 좌표로 표시한다. 실제 분할에서 그 문구를 포함하는 섹션 전체를 제외하는 것을 기대 처리로 삼고, 함께 사라지는 유용한 정보는 정보 손실로 별도 기록한다. 원본 이미지 전체를 일괄 제외하거나 정상 제외를 번역 누락으로 중복 판정하지 않는다.

GS-01의 SPF 50+·PA++++ 및 원본 시험값은 수치 보존 대상으로 기록한다. 사전이 요구하는 미국 시험 조건의 충족 여부는 별도 증빙이 없는 동안 확인 불가로 구분하고, 해당 조건을 적합으로 확정하지 않고 `undetermined`로 구분한다. 원문 수치 보존과 규제 조건 충족은 서로 다른 평가 대상이다.

GS-02_007·GS-02_010·GS-03_005·GS-03_015의 각질층 착색 관련 표현은 RG-025의 색소침착 개선 대상으로 판정하지 않는다. 해당 원본의 개선 수치·효능 문맥을 포함한 기대값이며, 질문형 표현에만 한정하지 않는다. 이 사유로 제외하거나 RG-025 대체 표현으로 수정할 것을 요구하지 않고, 원문의 의미·수치·시험 조건을 보존하는 번역을 기대한다. 같은 이미지의 다른 규제·현지 부적합 표현은 별도로 판정하며, 이 기준을 모든 착색·색소침착 표현의 허용으로 확대하지 않는다.

화장품의 명확한 미백·whitening·lightening 효능 주장은 RG-024에 따라 섹션을 유지하면서 사전의 대체 표현으로 수정하는 것을 기대한다. 다른 제외 사유가 함께 있으면 해당 제외 정책을 적용한다. 일시적인 톤업·톤 커버 표현만으로는 RG-024를 적용하지 않는다. 사전에서 `brighten`을 검출어에서 제외했으므로, ‘밝아진다’처럼 의미가 갈리는 표현은 효과의 지속성만으로 적용을 확정하지 않는다. 사전·문맥만으로 적용 여부가 명확하지 않은 표현은 해당 규제 판정의 기대값을 판단 불가로 구분하고, 수치 보존·번역 누락·이미지 훼손 등 다른 항목은 별도로 평가한다. 이 구분은 RG-024의 평가 기준이며 모든 밝아짐 표현의 허용이나 이미지 전체의 평가 제외를 뜻하지 않는다.
