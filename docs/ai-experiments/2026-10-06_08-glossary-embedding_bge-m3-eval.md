## 3. 조건

- 고정: `BAAI/bge-m3` dense 1024 · `normalize_embeddings=True` · 코사인 · `max_seq_length=512` · sentence-transformers 6.1.0 ·
  qdrant-client 1.19.1 로컬 모드(서버·Docker 없음) · CPU(torch 2.14.0+cpu) · RAM 8.4GB · Python 3.13
- 검색 필터: `target_lang='en'` AND `internal_category ∈ {작업 카테고리, 'common'}`(카테고리 미지정 문항은 필터 없음) [PRD F-SRC-04b]
- 비교(조건 이름 `종류필터:치환:묶음`)
  - 종류필터 `all` = 없음 / `split` = 전성분 문단은 `term_kind='ingredient'`만, 그 밖은 성분 제외
  - 치환 `fix` = 전성분 문단 쿼리에만 데이터팀 규칙(듬·륨·둠→듐 · 을→올 · 를→롤 · 헬·핵→헥 · 넷→넨) 적용
  - 묶음 `whole` = 전성분 문단 1회 검색 / `split` = 쉼표로 나눠 성분마다 검색 후 ID별 최고점으로 합침(`1,2-…` 숫자 쉼표 보호)
  - 임베딩 문자열 `ko` = `term_ko` / `ko_en` = `term_ko | term_target`
- 후보: 검색 요청마다 30개(통째 · 조각 같음). 조각 결과는 합친 뒤 점수순으로 줄 세우고, 평가에 쓴 후보 전부를 보존한다(분할 묶음은 평균 132개).
- 지표 — **모든 조건을 같은 최종 후보 수 K(1 · 3 · 5 · 10 · 20 · 30)로 채점**
  - Hit@K · MRR(정답 = must ∪ any) / 성공@K = must 전부 + (any가 있으면) any 하나 이상이 최종 상위 K 안
  - 보조 `@5n`(전성분 묶음만): K = 5 × **입력에서 센 조각 수**(정답 개수와 무관). 고정 K 표와 섞지 않는다.
  - 음성 오탐률: 일반 음성 25문항의 1등 점수 ≥ t 비율. 카테고리 차단 2문항은 금지 ID 노출 · 카테고리 누출로 따로 센다.

## 5. 판단

**보류** — 검색 단계 방향은 아래로 좁혀졌으나 운영 계약(BE 확인 필요)·실제 OCR 블록 평가·음성 표본이 부족해 채택하지 않는다.

- 전성분 문단은 **쉼표로 나눠 성분마다** 검색해야 한다 — 같은 최종 후보 10개에서 성분 전부 회수 ko 0.10 → 1.00, 30개에서 0.18 → 1.00
  (ko_en 30개 0.22 → 0.98). 비용은 검색 요청 +23% · 검색 시간 약 1.3배. 묶음에 넘길 후보 수는 성분 수에 비례해야 한다(고정 5개면 ko 0.72).
- 문구·인증 블록은 성분을 빼고 검색한다(문구 5위 0.785 → 0.816 · 쓰지 말 표현 1등 0.478 → 0.565).
- 임베딩 문자열은 문구·인증 `ko_en`(문구 5위 0.877), 성분 `ko`가 유리하다(전성분 분할 @10 ko 1.00 · ko_en 0.73) — 두 컬렉션 분리 후보.
- 성분 OCR 치환은 오독 0.972 → 1.000. 정상 성분명 26개를 바꾸지만 ko 검색에서는 손상 없음(ko_en 1건).
- 임계값 0.55~0.57은 잠정 관찰값이다(0.55에서 일반 음성 25문항 중 1건, 0.57부터 0건). 음성 25문항(수작업)으로 확정하지 않는다.
  카테고리 차단은 필터로 막혀 금지 ID 노출 0이다.
- 로컬 모드는 실험용이다. 운영 검색 지연(필터 시 ~0.5초/쿼리)과 메모리를 보면 pgvector 또는 Qdrant 서버로 옮겨야 한다.
