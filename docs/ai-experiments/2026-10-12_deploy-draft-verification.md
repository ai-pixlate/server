## 1. 질문

선택 커밋의 배포를 준비하면서 Redis 보존, 이미지 고정, 워커별 키 주입, 로그 정제·정상 종료 및 제한된 모델 검증을 위한 운영 도구가 의도한 조건을 만족하는가?

관련 정본: `docs/ai/be-handoff.md`, `docs/ai/contract.md`의 실행·인계 계약, `docs/ai/integration-decisions.md`. 이 기록은 HTTP 제어 계층이나 새로운 운영 계약을 정의하지 않는다.

## 2. 표본

- 앱 이미지 1개와 OCR 이미지 1개.
- 가짜 Docker를 사용한 배포 스크립트 시나리오 7개. 개별 시나리오 목록·assertion은 미제공.
- 실제 기준 커밋의 Celery 워커를 이용한 로그 정제·종료 시험. 세부 반복 횟수는 미제공.
- GPU 기동 게이트 확인, Gemini 키 존재 확인, GPU 검증 도구 문법 확인.
- 실제 Gemini 유료 요청, 학교 GPU LaMa 실행, 운영 큐 통합 시험: 없음.

## 3. 조건

- 빌드 환경 보고: 로컬 PC 8코어, Docker 메모리 4GB. 기준 커밋의 앱 이미지 약 608MB, OCR 이미지 약 2.58GB. 이미지 크기는 메모리 요구량이 아니다.
- 초안 파일 보고: `start-pixlate.sh`, `redact_run.py`, `gpu-worker.sh`, `gemini_check.py`, `gpu_check.py`, `checks.md`, `RUNBOOK.md`. 파일 해시·내용은 미확보이며 이 기록에는 추가하지 않는다.
- 배포 모드 안: `maintenance`는 Redis만 유지, `validate`는 API를 루프백에만 공개하고 워커·복구는 중지, `live`는 API 외부 공개와 워커·복구 실행. 현장 적용 완료가 아니라 초안의 의도다.
- 비밀 값·연결 주소·버킷 이름·메시지 본문·원문 로그는 저장하지 않는다. 모델 캐시와 컨테이너 이미지는 Git 기록에 포함하지 않는다.

## 4. 결과

판정 기준: 모의 시험, 실제 프로세스 시험, 환경 준비, 모델 호출, 큐 통합, 서비스 소비 재개를 구분한다. 하위 범위의 성공으로 상위 범위를 완료 처리하지 않는다.

### 4.1 보고받은 시험 결과

- 앱·OCR 이미지: 두 이미지 모두 `pip check` 통과. OCR 정상 실행을 뜻하지 않으며, Linux CPU 오류는 [별도 OCR 기록](2026-10-12_02-ocr_linux-cpu-deployment-smoke.md)에 남겼다.
- `start-pixlate.sh`: 가짜 Docker 시나리오 **7개 통과**. 모든 모드에서 Redis `rm`·`run` 호출 0회. 재부팅을 가정한 반복 실행에서 컨테이너를 재생성하지 않았고 Gemini 파일이 없으면 워커 기동 전에 중단했다고 보고됨. 실제 EC2 재부팅 시험은 아니다.
- `redact_run.py`: 실제 Celery 시작 배너·연결 오류의 시험 출력에서 원문 비밀 검출 **0건**으로 보고됨. `docker stop` 시 웜 종료와 종료 코드 **0**, 일반 종료 코드 **3**, SIGKILL 종료 코드 **137** 전달 확인. 시험 입력·원본 출력이 없어 모든 오류 경로의 비노출을 보장하는 결과로 확대하지 않는다.
- `gpu-worker.sh`: 게이트 파일이 없으면 시작하지 않음을 확인했다고 보고됨. Pod 재시작 시 자동 소비 방지는 초안의 의도이며 실제 학교 환경의 재시작 결과는 미제공.
- `gemini_check.py`: 요청 없이 키 존재만 확인하는 모드에서 없으면 종료 코드 **3**, 있으면 **0**. 실제 요청 모드는 미실행. 테스트 키의 실제 사용 가능 여부를 검증한 결과가 아니다.
- `gpu_check.py`: 문법 확인만 수행. torch·CUDA·가중치 로드·추론은 미검증.
- 이미지의 Gemini SDK: `google-genai 2.29.0`으로 보고됨. 담당자는 기본 요청 시도 1회 동작을 확인하고 검증 스크립트에서 요청 시도 횟수를 1회로 명시했다고 보고했다. SDK 소스·스크립트 원문은 미확보이며 실제 유료 요청이나 요청 횟수 실측은 없다. 추가 재시도 1회를 허용했다는 뜻으로 읽지 않는다.

### 4.2 미실시와 남은 확인

- 외부 유입은 제한 검증 종료까지 차단하는 계획이다. 정상 소비 재개는 별도 판단이다.
- 지정할 수 있는 인페인트 대기 시도가 없다고 보고돼 **LaMa 큐 소비·통합 검증 미실시**로 계획했다. 검증용 작업을 임의 생성하지 않는다.
- GPU 접근·승인된 S3 자격 제공 방식·OCR 자원·백업 및 복구 담당과 절차는 미확정이다.
- DB는 PostgreSQL 16.15, 백업 도구도 16.15 사용 가능으로 보고됐으나 백업·복구 성공 결과는 없다. 마이그레이션도 미실시다.
- 모드 간 전환, 옛 이미지에서 새 digest로의 교체, 환경 파일·포트·캐시 마운트 변경 반영은 개별 시험 결과가 미제공이다. Redis는 보존하되 설정이 바뀐 애플리케이션 컨테이너까지 무조건 재사용해서는 안 된다.
- 보고된 현장 시작 스크립트에는 Redis 재생성과 가변 `latest` 이미지 사용 위험이 남아 있다. 수정 초안이 현장에 설치됐다고 간주하지 않는다.

## 5. 판단

**보류 — 배포 도구 초안과 일부 로컬 시험 결과만 확보한 상태다.**

초안의 방향과 개별 보고 결과는 후속 검토 근거로 보존한다. 그러나 OCR 실행 오류와 자원 부족 가능성, 미확정 접근·자격·백업 절차가 남아 있으며 초안 원문도 별도 검토가 필요하다. 환경 준비, 제한된 모델 검증, 큐 통합 검증, 정상 소비 재개를 모두 완료로 기록하지 않는다.

다음은 OCR 수정 커밋 확보, 새 SHA 기준 이미지 재빌드, 실제 자원 측정, 접근·백업 절차 확정, 초안의 모드 전환·설정 반영 확인이다. 인페인트 대기 시도가 없는 상태에서는 큐 통합 검증을 했다고 보고하지 않는다.
