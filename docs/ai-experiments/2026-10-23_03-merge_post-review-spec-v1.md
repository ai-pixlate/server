# 2026-10-23 ③ OCR 후처리 교차 블록 병합 검수 명세 v1

③ OCR 후처리 점검(`2026-10-23_03-merge_post-gutter-check.md`, `open-questions.md` #86)의 대리 사례 33건을 섹션 이미지와 대조할 때 쓰는 분류 기준이다. 질문은 하나다: 같은 후보 영역에서 가로줄 범위가 교차하는 블록들이 한 문단으로 합쳐질 때, xycut 재조립(묶음 안의 모든 줄을 가로줄 순번 → x로 다시 정렬)이 끈 상태(블록 순서대로 줄을 이음)보다 이미지가 의도한 연결 · 순서에 맞는가. 정답 데이터 작성 명세가 아니며, 이 명세로 낸 집계는 **검토한 33건의 관찰값**이다.

## 1. 대상과 묶음

사례 ID는 `원본/섹션/끈 상태 최종 블록 키`(예: `GS-01_002/sec_1_06/blk_011`)로 고정한다. 결과는 아래 세 묶음을 **따로** 집계한다.

| 묶음 | 조건 | 건수 | 목적 |
|---|---|---|---|
| A 순서 비교 | 범위 같음 · 순서 다름 | 14 | 핵심 비교 — 어느 순서가 맞는가 |
| B 순서 같음 | 범위 같음 · 순서 같음 | 5 | 두 방식에 공통인 오류 · 허용 여부 확인 |
| C 범위 다름 | xycut 블록들의 영역 합이 끈 상태 문단과 다름 | 14 | 범위 판단 |

- "범위 같음"은 끈 상태 최종 문단의 원시 영역 집합과 xycut 재조립 블록의 영역 집합이 정확히 같다는 뜻이다.
- **xycut 쪽은 과거 문단(끈 상태 · `llm_assist` v1 실제 출력 1회)을 기준으로 만든 대리 병합 결과다.** 실제 xycut + LLM이 그 묶음을 선택한다는 뜻이 아니다. C의 `scope_xycut`도 "이 재구성 범위가 더 적절하다"는 뜻일 뿐이다.

## 2. 판정 기준

이미지에서 문장 · 단어 · 각주가 의도한 연결과 읽기 순서를 기준으로 판단한다. 독립적인 두 칸이나 항목은 각각의 문맥이 유지되는지도 확인한다.

- 각주 기호: 본문에 붙은 위첨자(`성분*`)는 대응 단어 바로 뒤에 이어져야 한다. 각주 설명 앞의 기호(`* 인체적용시험 …`)는 그 설명 앞에 있어야 한다. 둘을 구분해 본다.
- 단순 OCR 오탈자는 순서 판정에서 무시한다.
- 중복 검출 조각(#40)이나 오탈자 때문에 어느 순서가 맞는지 구분하기 어려우면 억지로 고르지 않고 `undecidable`로 남기고 태그를 붙인다. 판정을 가리지 않는 경우에만 무시한다.
- 판정은 사례마다 하나. 아직 보지 않은 사례는 "미검수"이며 `undecidable`과 다르다.
- 검수자는 번역 대상이 아닌 영역(예: 제품 라벨로 본 사례)을 읽기 순서 검수에서 제외할 수 있다. 제외한 사례는 판정 없이 **미평가**로 두며 `undecidable`이나 검수 완료로 세지 않는다. 검수자가 제품 라벨로 본 것과 ④ 라벨 판정기의 실제 판정은 별개다(2026-10-23 검수에서 적용).

## 3. 분류

### 3.1 A · B — 순서

| 분류 | 조건 |
|---|---|
| `xycut_better` | xycut 순서가 의도한 연결 · 순서에 맞고 끈 상태는 맞지 않는다 |
| `off_better` | 끈 상태 순서가 맞고 xycut은 맞지 않는다 |
| `both_ok` | 두 순서 모두 허용된다(의도한 연결이 둘 다 유지됨) — **개선이 아니라 둘 다 허용** |
| `both_wrong` | 두 순서 모두 맞지 않는다 |
| `undecidable` | 이미지로 판단할 수 없다(작음 · 겹침 · 중복 조각 · 판독 불가 등) |

### 3.2 C — 범위

| 분류 | 조건 |
|---|---|
| `scope_xycut` | xycut 재구성 범위가 더 적절하다 |
| `scope_off` | 끈 상태 범위가 더 적절하다 |
| `scope_both_ok` | 두 범위 모두 허용된다 |
| `scope_both_wrong` | 두 범위 모두 적절하지 않다 |
| `undecidable` | 이미지로 판단할 수 없다 |

### 3.3 원인 태그(여러 개 가능)

`superscript`(위첨자 · 각주 기호) · `fragment`(같은 줄 조각) · `package`(제품 패키지 글자) · `document`(문서 이미지 글자, #39) · `duplicate`(중복 검출, #40) · `typo`(오탈자) · `other`. 메모(`note`)에 근거를 짧게 적는다.

## 4. 기록과 집계

- 검수 페이지(`docs/ai-experiments/tools/merge_post_review_page.py`)에서 고르면 브라우저에만 저장되고, 중간에도 TSV로 내보낼 수 있다. TSV 열: `case_id` · `group` · `section` · `final_block` · `judgment` · `tags` · `note` · `reviewed`. 파일은 `docs/ai-experiments/runs/`에 두고 커밋하지 않는다.
- TSV 제출은 필수가 아니다. 검수자가 페이지를 보고 채팅 등으로 **정성 의견**만 전달해도 된다. 그때는 의견을 정성 의견으로 점검 기록에 옮기고, 사례별 판정 · 분류 · 건수를 만들어 채우지 않는다(묶음별 집계도 하지 않는다). 2026-10-23 검수는 이 방식이었다(점검 기록 4.1).
- 집계는 A · B · C를 섞지 않는다. B의 `both_ok`를 A와 합쳐 "대부분 개선"으로 해석하지 않는다. 미검수 · `undecidable`은 따로 센다.
- 사람 검수 결과는 점검 기록(`2026-10-23_03-merge_post-gutter-check.md`)의 결과 · 판단 절에 **에이전트 관찰과 구분해** 적는다. 비율을 성능으로 주장하지 않고 합격 기준 수치를 만들지 않는다.

## 5. 결과 해석(제안 — 기준값은 사용자가 정한다)

- A에서 `xycut_better`가 우세하고 `off_better`가 특정 유형에 몰리지 않으면: 재정렬 규칙을 유지한 채 3단계 판단을 정리하고 4단계 품질 · 파라미터 확인으로 진행한다.
- `off_better`가 특정 태그(예: `superscript`)에 반복되면: 그 유형을 4단계 실험 대상(가로줄 허용치 · 높이비 비교)으로 올린다. 규칙을 곧바로 바꾸지 않는다.
- `undecidable`이 몰린 유형(`document` 등)은 #39와 연결해 따로 다룬다.
- 표본은 고정 입력본 100섹션에서 나온 33건이다. 결론은 이 표본 범위로 한정한다.
