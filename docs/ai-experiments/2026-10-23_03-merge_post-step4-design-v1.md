# 2026-10-23 ③ OCR 후처리 4단계(품질 · 파라미터 확인) 실험 설계 v1

`open-questions.md` #86의 4단계 설계다(사용자 승인 2026-10-23). 3단계 켬/끔 비교(`2026-10-23_03-merge_post-onoff-compare.md`)가 남긴 결함 후보 — 큰 글자 문단의 후보 영역 과분할, 작은 중첩 조각이 낀 줄의 분리 — 를 줄이는 방법이 지금의 이점(칸 단위 읽기 · 같은 줄 조각 합치기 · 위첨자 순서)을 깨지 않는지 본다. 기본 활성화 판단의 근거를 만드는 것이 목표이며, 이 설계와 실험 결과는 정본 규칙이 아니다.

## 1. 원칙

- 파이프라인 코드를 바꾸지 않는다. 변형 규칙은 실험 도구 안에서만 구현한다(실험 중에만 함수를 바꿔 끼움). 변형마다 별도 프로세스로 실행해 한 변형이 다음 실험에 남지 않게 한다.
- LLM 호출 없이 `blocks-input-v1` 100섹션의 휴리스틱으로 비교한다. **비교 기준은 현행 후처리(A0/B0)다.** 후처리를 끈 결과는 참고로 병기하고, 과거 LLM 최종 결과를 같은 조건의 성능 비교처럼 다루지 않는다.
- 실험마다 코드 기준 커밋 · 작업 트리 변경 여부 · 설정 · 변형 이름 · 입력본 지문(`blocks-input-v1/SHA256SUMS`의 SHA-256)을 기록한다.
- 채택할 규칙과 값은 결과를 본 뒤 사용자가 정한다. 값은 "확정" 전까지 잠정이다(`README.md` 4.1).

## 2. 점검 세트 — 결함 확정이 아니라 결함 후보

A0(현행 후처리, 기본 config + `merge.xycut = true`)를 기준으로 추출해 사례 ID를 고정한다. 사례는 원시 영역 집합으로 정의하므로 변형마다 블록 번호가 달라도 같은 사례를 가리킨다. 여러 세트에 걸친 사례는 표시하고, 세트 건수를 더해 전체 건수로 쓰지 않는다.

| 묶음 | 질문 | 추출 기준 |
|---|---|---|
| S1 과분할 후보 | 실제로 이어져야 할 문단이 잘렸는가 | (a) 끔 휴리스틱 블록 하나가 A0에서 서로 다른 후보 영역의 블록 여러 개로 나뉨 (b) 끈 상태 LLM 최종 블록(입력본 `merge/`) 하나가 A0에서 서로 다른 후보 영역에 걸침 |
| S2 줄 끊김 후보 | 같은 줄로 이어야 할 조각이 분리됐는가 | 끔 휴리스틱 블록 하나가 A0에서 같은 후보 영역 안 블록 여러 개로 나뉨 |
| S3 칸 분리(회귀 확인) | 칸 단위 읽기가 유지되는가 | 끔 대비 A0에서 후보 영역 사이 순서 변화가 있는 섹션. 사람 확인용 대표 섹션은 따로 표시 |
| S4 조각 · 위첨자(회귀 확인) | 지금의 개선이 유지되는가 | (a) 끔 휴리스틱 블록 여러 개가 A0에서 한 블록으로 합쳐짐 (b) 교차 블록 병합 점검의 범위 같은 대리 사례(`2026-10-23_03-merge_post-gutter-check.md`) |

- 과거 LLM이 한 문단으로 묶었다는 것은 후보로 뽑는 근거일 뿐 합쳐야 한다는 뜻이 아니다. 제품 라벨 · 독립 항목은 분리가 맞을 수 있다.
- 제품 라벨 사례는 사람 핵심 검수에서 제외하고 자동 점검(불변식 등)에는 남긴다. ④ 라벨 1회 실측(`label-run-v1`)이 true로 본 블록에 속한 사례는 "라벨 판정기 힌트"로 표시한다 — 힌트는 사람 판단이 아니다.

## 3. 변형 — 한 요소씩, 두 차례

| 차수 | 변형 | 바꾸는 것 |
|---|---|---|
| 기준 | A0 | 현행 후처리(잠정값) |
| 참고 | OFF | `merge.xycut = false` |
| **1차** | A1 | `xycut_gap_ratio` 1.0 / 1.2 / 1.5(기존 키) |
| **1차** | B3 | 가로줄의 `Line` 나누기에서 높이비 조건만 끔(gutter · 블록 병합의 높이비는 그대로) — 실험 도구에서만 |
| **1차** | C | `line_center_tol` 0.35 / 0.7, `line_center_tol_min_px` 12(기존 키) · 가로줄의 `Line` 나누기에 기존 가로 간격 조건(`line_gap_min` · `line_gap`)을 다시 더함 — 실험 도구에서만 |
| **1차** | D | `merge.fullwidth = true` — 바뀐 줄을 모두 목록으로 뽑아 의도 밖 변환이 없는지 본다 |
| 2차 | A2 · B1 | 1차로 해결되지 않은 사례에만 검토. 착수 전 규칙 정의 필요 |
| 후순위 | A3 · B2 | 필요성이 확인될 때만 |

- 1차는 변형마다 한 요소만 바꾼다. 효과가 확인된 것만 2차에서 조합한다.
- 2차 착수 전에 정할 것: A2 — 여백 위아래에 높이가 다른 상자가 여러 개일 때의 대표 높이, 두 칸의 서로 다른 줄을 이웃으로 보지 않는 방법. B1 — 작은 조각이 떨어진 뒤 다음 큰 글자를 어느 조각에 이을지. B2 — "크게 겹침" · "작음"의 기준, 비교에서 건너뛴 영역을 넣을 `Line`.
- A3(후보 영역 재병합)는 승인된 영역 경계 규칙을, B2(중첩 조각 예외)는 #40의 판단을 바꾼다. 필수 범위가 아니다.

## 4. 측정과 판단

- 자동 측정(변형마다): 불변식 위반, 블록 수, 역할 분포, 후보 영역 수, A0 대비 결과가 바뀐 섹션, 점검 세트 사례별 상태(S1 — 사례가 걸친 블록 수 · 후보 영역 수, S2 — 블록 수 · `Line` 수, S3 — A0 대비 순서 변화, S4 — 합쳐진 블록 유지 · 대리 재조립 텍스트 변화).
- **구조 지표는 원인 분석용이다.** 블록 수 · 교차 쌍 · 영역을 넘는 과거 문단 수가 줄었다고 좋아진 것으로 보지 않는다.
- 사례 제시: 대표 사례와 함께 악화 후보 · 판단 불가 사례를 보여 준다. 검수는 채팅 정성 의견으로 받으며 TSV는 선택이다.
- 판단: **사람이 실제 과분할 · 줄 끊김으로 확인한 사례가 개선되고, 칸 분리 · 조각 · 위첨자 사례에서 새로운 오류가 생기지 않는 후보를 고른다.**

## 5. 채택과 활성화

- 휴리스틱 실험만으로 정할 수 있는 것은 규칙 후보 선택까지다.
- 실제 LLM 실행은 선택 사항이다(비용 · 사전 예산 승인 필요). 생략하면 LLM을 포함한 ③ 전체 경로의 품질은 미검증으로 남긴다.
- 기본 활성화는 그다음 별도 결정이다. BE 검토 · 연동은 하지 않고 `be-handoff.md` 10절로만 유지한다.
- 채택 후보는 사용자 승인 뒤 코드 · 테스트 · 문서를 함께 준비하고, 커밋은 별도 요청 때 한다.
