## 4. 결과

판정 기준: 1차 사람 판정과의 일치(이어져야 함 → 한 블록 또는 LLM이 합칠 수 있는 한 후보 영역, 나뉘어야 함 → 나뉜 채 유지), 불변식 위반 0, x 절단(칸) 회귀 없음. 구조 지표는 원인 분석용이다.

### 4.1 사람 판정 사례의 경계 기하

후보 영역 경계를 사이에 둔 위아래 블록의 `간격 ÷ min(위 줄 높이, 아래 줄 높이)`(같은 사례에 경계가 여럿이면 모두):

| 사람 판정 | 사례(경계 비율) |
|---|---|
| 이어져야 함 | `GS-02_008/sec_1_04:reg_0020` 0.32 · `reg_0018` 0.75 · `GS-02_013/sec_1_02:reg_0024` 0.60 · 0.60 · `reg_0023` 0.70 · 0.60 · 0.60 · `GS-02_014/sec_1_11:reg_0021` 0.92 · 0.92 · `reg_0025` 0.96 · 0.83 · 0.93 |
| 나뉘어야 함(y 절단) | `GS-02_013/sec_1_02:reg_0001` 0.34(`효과는 압도적으로` / `자극은 최소한으로`) · `GS-02_014/sec_1_05:reg_0003` 0.89 |
| 나뉘어야 함(x 절단, 나란한 칸) | `GS-03_012/sec_1_01` 3건(문장 · `100%` 배지) |
| 둘 다 허용 | `GS-02_008/sec_1_04:reg_0013` 0.36 |

모든 y 경계는 위아래 블록의 가로 겹침이 0.99 이상이다(위아래로 쌓인 문단). **이어져야 할 사례(0.32~0.96)와 나뉘어야 할 y 사례(0.34 · 0.89)가 겹친다** — 특히 `reg_0020`(0.32, 이어져야 함)과 `reg_0001`(0.34, 나뉘어야 함)은 같은 모양의 두 줄 큰 제목이다. 이 경계 비율 하나로는 둘을 가를 수 없다.

### 4.3 "y 절단으로만 나뉜 후보 영역끼리는 LLM 병합 허용" 안의 구조적 영향

| 항목 | 값 |
|---|---|
| 이웃 후보 영역 경계(깊이 우선 순서로 연달은 영역 쌍) | 619 — 그중 y 절단만 301 |
| 끈 상태 LLM 최종 블록 중 후보 영역을 넘는 것 | 17 — 그중 y 절단만 넘는 것 8 |
| 사람이 "이어져야 함"으로 본 6건 | 6건 모두 y 절단으로만 나뉨 → 이 안이면 LLM이 합칠 수 있다 |
| 사람이 "나뉘어야 함"으로 본 5건 | x 절단 3건(`GS-03_012`)은 계속 막힘. y 절단 2건(`reg_0001` · `GS-02_014/sec_1_05:reg_0003`)은 LLM 판단에 맡겨짐 |

- 점검 세트의 S1(b) 사례는 과거(끈 상태) LLM이 한 문단으로 묶은 것이다. 과거 LLM은 사람이 나뉘어야 한다고 본 y 절단 2건도 묶었다 — 이 안에서 같은 판단이 반복되면 그 2건은 합쳐진다. 실제 LLM이 `region`이 붙은 xycut 입력에서 어떻게 판단할지는 LLM 실행 없이 알 수 없다.
- 이 안은 승인된 규칙(후보 영역은 LLM이 넘지 못한다 — `pipeline.md` 7.2절, Q1 처리)을 y 절단에 한해 바꾸는 것이라 채택에는 사용자 결정이 필요하다. x 절단(칸)은 R 결과대로 경계로 유지하는 것이 전제다.

### 4.4 전각 변환(D)의 평가 가능성

- 로컬 OCR 결과 JSON 758개 전체에서 U+FF01~FF5E · U+3000 문자가 든 영역은 **0개**다.
- 현재 설정의 인식 모델 `korean_PP-OCRv5_mobile_rec`(로컬 캐시 `~/.paddlex/official_models/`, `config.json`의 문자 사전 11,945자)에 **U+FF01~FF5E · U+3000이 하나도 없다**(반각 `%` · `,`은 있음). 현재 OCR 설정에서는 인식 결과에 전각 문자가 나올 수 없으므로, 전각 변환은 현재 엔진 기준으로 바꿀 것이 없다. seed-builder가 많은 변환을 본 것은 다른 인식 모델을 썼기 때문으로 보인다(그 PR은 `PP-OCRv5_mobile_rec` · 영어 이미지).
- 그래서 D는 실제 출력으로 평가할 수 없다. 인식 모델을 바꾸거나 다른 경로에서 전각 문자가 들어오는 경우에만 의미가 있다. 단위 테스트(`tests/test_pipeline_merge_post.py`)가 변환 범위 · 원시 보존을 확인한다.

## 5. 판단

보류(3차는 조사 · 준비 · 로컬 검증이며 규칙 · 값 · 스위치를 바꾸지 않는다). 아래는 에이전트 판단이며 사람 판단이 아니다.

- **기하 규칙(A1 · A2)만으로는 과분할을 사람 판정대로 가르기 어렵다**: 같은 모양의 두 줄 제목이 이어져야 할 때와 나뉘어야 할 때가 경계 비율로 구분되지 않는다(4.1). A2는 x 절단을 건드리지 않아 A1의 칸 합침 회귀는 없지만, `효과는 압도적으로`를 모든 r에서 잘못 합친다. A2를 단독 채택할 근거는 약하다.
- **y 절단만 LLM 병합 허용 안이 구조상 가장 들어맞는다**: 이어져야 할 6건을 모두 LLM 판단 범위에 넣고, 칸(x 절단) 사례는 계속 막는다. 다만 나뉘어야 할 y 사례 2건의 결과가 LLM에 달려 있고, 승인된 영역 경계 규칙의 변경이다. 이 안을 검토하려면 실험 도구에 조립 규칙을 구현하고 LLM 포함 실행(4.5)이 필요하다.
- **전각 변환은 현재 인식 모델에서 효과가 없다**: 활성화 판단에서 "켜도 바뀌지 않음"으로 다루고, 인식 모델을 바꿀 때 다시 본다.
- 이 결과로 기본 활성화 승인 · 값 확정 · 품질 검증 완료를 표시하지 않는다.
