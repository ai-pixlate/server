# 2026-11-23 A+ 이미지 칸 누끼 시험(1 · 2회차)

> 1회용 스크립트로 돌린 시험이다. 레포 코드는 쓰지 않았다(7칸 구성 결과만 입력으로 썼다). 판정은 모두 **에이전트 육안**(축소 비교 그림과 가장자리 확대본)이며 사람 검수가 아니다. 결론은 아래 표본 범위에 한정한다.

## 1. 질문

A+ 이미지 칸을 "원본 크롭 + 누끼"로 만들 수 있는가(`docs/ai/open-questions.md` #98). 나눠 본 것:

1. 어떤 사진을 누끼할지를 무엇으로 정하는가 — 7칸 구성의 `fit` 값으로 충분한가, 모델에게 따로 물어야 하는가.
2. 누끼 모델에 무엇을 넣는가 — 원본 섹션 / 글자를 지운 섹션(⑥ 결과) / 원본 + 글자 영역 투명 처리.
3. 여러 덩어리가 나왔을 때 규칙으로 고를 수 있는가.
4. 경계 보정(alpha matting)을 켜는 것이 나은가.

## 2. 표본

- 1회차: GS-01 한 원본(`GS-01_002`)의 7칸 구성이 고른 사진 8장.
- 2회차: GS-01(한 원본) · GS-02(원본 13장 · 섹션 47개) · GS-03(원본 17장 · 섹션 38개)의 7칸 구성이 고른 사진 **22장**(GS-01 8 · GS-02 7 · GS-03 7). GS-02 · GS-03의 7칸 구성은 이 시험을 위해 1회씩 돌렸다 — 입력 번역은 용어집 · 표현 지시 없이 만든 개발용이고 번역 실패 블록(GS-02 15개 · GS-03 16개)은 재료에서 빠졌다.
- 섹션 이미지는 고정 입력본 `downstream-input-v1`, 글자를 지운 섹션은 `inpaint-bg-v1_2026-09-30`(22장 중 1장은 지운 이미지가 없었다).

## 3. 조건

- 고정: `rembg` 2.0.87 · `onnxruntime` 1.32.0(CPU) · 모델 `birefnet-general` · Windows 11 · Python 3.12.10. 자를 자리를 가로 · 세로 12%씩 넓혀 자른 뒤 누끼하고, 알파 128 이상을 대상으로 보고 다시 맞춰 잘랐다.
- 비교:
  - 누끼 여부 — 사진 조각을 모델(`gemini-3.8-flash`, 상품당 1회 호출)에 보내 종류와 누끼 적합 여부를 물었다. 7칸 구성의 `fit`(`contain` · `cover`)과 대조했다.
  - 입력 — A 원본 / B 글자 지운 섹션 / C 원본 누끼 결과에서 번역 대상 글자의 OCR 영역을 투명하게.
  - 덩어리 선택(B 위에) — 모델이 준 원래 상자 안에 면적의 절반 이상이 들어가는 덩어리만 남김.
  - 경계 보정(B 위에) — `alpha_matting=True`.

## 4. 결과

판정 기준: 대상(제품 · 원료 · 제형)만 남았는가 / 글자 · 그래픽이 함께 따였는가 / 대상에 구멍 · 잘림이 있는가.

| 비교 | 결과 |
|---|---|
| 누끼 여부(모델 판단) | 적합 11장 · 부적합 11장. 부적합 11장은 인물 · 손이 함께 있는 장면 5, 근거 그림(현미경 · 전후 · 도식) 4, 질감 배경 위 제품 1, 콜라주 1. 실제 누끼 결과와 어긋난 판단을 찾지 못했다(질감 배경 위 제품 1장은 판단이 갈릴 수 있다) |
| `fit`만으로 정하면 | `contain` 16장이 누끼로 가고 그중 5장이 부적합이었다(근거 그림 3 · 질감 배경 위 제품 1 · 손에 든 제품 1). 적합 11장은 모두 `contain`이었다 |
| A 원본 입력 | 22장 중 4장에서 한글 문구가 대상과 함께 따였다(적합 11장 중에서는 2장) |
| B 글자 지운 입력 | 위 4장의 글자 섞임이 없어졌다. 적합 11장 중 7장은 대상만 남았고, 4장은 붙은 그래픽 · 소품이 남았다(글자만 지워진 빈 배지 원, 잎 옆 점선 원, 튜브 뒤 막대 소품, 제형 방울의 지시선) |
| C 글자 영역 투명 | 3장에서 대상에 네모난 구멍이 났다(인물 얼굴 포함) |
| 덩어리 선택 규칙 | 22장 중 21장이 덩어리 1개여서 규칙이 작동하지 않았다. 붙은 그래픽은 대상과 한 덩어리였다. 평가 불가 |
| 경계 보정 | 어두운 배경 위에서 가장자리가 더 지저분했다(확대 4장). 보정을 끄면 윤곽은 깨끗하나 1~2픽셀 밝은 띠가 보였다 |

그 밖에:

- 1회차에서 자를 자리를 넓힌 뒤 대상에 맞춰 다시 자르자, 7칸 구성이 제품을 잘라 고른 사진 1장이 온전하게 나왔다.
- 라인업 제품 사진은 원본이 작았다(예: 134×303픽셀).
- 시간: CPU에서 모델 1회 약 8초(22장 · 변형 5종 합계 547초). GPU는 재지 않았다.
- 가중치 파일은 약 928MiB다.

## 5. 판단

- **채택**: 누끼 여부를 모델이 사진마다 판단 · 글자 지운 섹션에서 넓혀 자르기 · `birefnet-general` · 경계 보정 끔 · 대상에 맞춰 다시 자르기.
- **기각**: `fit`만으로 누끼 여부 결정, 글자 영역 투명 처리(C), 경계 보정.
- **보류**: 덩어리 선택 규칙(평가 불가), 붙은 그래픽 · 소품 제거(자동 처리 없음 — 사람 확인), 밝은 띠를 줄이는 가장자리 줄이기와 작은 조각 제거(이 시험에서는 돌리지 않았다).
- 한계: 누끼 여부 판단은 **사진 조각을 따로 보낸 별도 호출**로 시험했다. 7칸 구성 호출에 합쳤을 때의 정확도는 이 시험으로 알 수 없다. 표본은 화장품 3개 상품 22장이다.
