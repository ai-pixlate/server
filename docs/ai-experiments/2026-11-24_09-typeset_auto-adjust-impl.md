  닿지 않던 확장도 막혔다. PM 정책(「다른 글과 겹치지 않는 여백까지」 · 「같은 빈자리를 차지하지 않는다」)과 맞는 쪽이지만 보수적이다.

### 5.4 실패해도 시도 상태 유지(규칙 `typeset-adjust/3`, PM 승인 2026-11-25)

PM이 11-24의 「끝까지 넘치면 조정 전 상태로 복원」을 「마지막 시도를 남기고 넘침 보고 — 사용자가 이어서 고친다」로 바꿨다(사용자 전달).
사용자에게 따로 표시하지 않는다. 구현:

- 넘침이 남아도 마지막 시도(줄바꿈 · 폭 확장 · 축소)를 시스템 조정으로 남긴다. 시도로 바뀐 것이 없으면 원래 그대로.
- 축소는 0.90에서도 넘치면 넘침이 줄어드는 한 0.90을 남긴다. 폭 확장 단독으로 나아지지 않았고 축소도 남지 않으면 넓힌 폭은 남기지 않는다.
- 남긴 블록의 자리(박스 ∪ 글자)를 다음 블록의 장애물에 반영한다(해소된 블록과 같다). 이웃과 새로 겹치면 남기지 않는다(5.3 규칙).
- 같은 입력을 다시 쟀을 때 넘치는 해소 블록(`not_reproducible`)도 조정을 버리지 않고 넘침으로 보고한다.

| | `/2`(복원) | `/3`(시도 유지) |
|---|---:|---:|
| 해소 | 250 | 261 |
| 넘침 남음 | 165(모두 원래 입력) | 154(시도 남김 151 · 바뀐 것 없음 3) |
| 판정 후: 정상 · 배치 영역만 넘침 · 섹션 밖 잘림 | 324 · 154 · 11 | 335 · 151 · **3** |

- 해소가 11 늘고 줄어든 블록은 없다 — 넘친 채 남은 블록의 글자가 줄거나 넓게 흩어져 차지하는 자리가 작아져, 뒤 블록이 쓸 여백이 늘었다(이 표본 기준).
- 남긴 시도의 남은 넘침은 원래 넘침 대비 p10 · 중앙 · p90 = 0.03 · 0.40 · 0.80, 축소 0.90 포함 136, 폭 배율 중앙 1.28 · p90 2.07.
- 섹션 밖 잘림 14블록: 조정 후 잘림 3(픽셀 손실 확인) · 배치 영역만 넘침 7 · 정상 4.
- 에이전트 1차 분류(`followup`, 남긴 시도 기준): 측정 환경 의심 22 · 가장자리 6 · 높이를 더 쓰면 풀림 70(복잡한 바탕 5) · 더 줄이면 풀림 39 · 문구 수정 17.
- **측정 환경 주의(2026-11-25 발견)**: FE 고정본 CSS가 `src: local('Pretendard …')`를 먼저 찾아, 이 PC에 Pretendard OTF가 설치(11-25 15:16)되자
  측정 도구의 글자 경계(ink)가 338블록에서 1px 달라졌다. 줄바꿈 · 넘침 판정이 달라졌는지는 가르지 않았다(이 PC는 TextMetrics 정수화 환경이라 차이 중
  글꼴 파일 몫도 분리하지 않았다). 서버 이미지에는 설치본이 없으므로 로컬 측정 도구는 내려주는 CSS에서 `local(...)`을 빼 고정 웹폰트로 그린다
  (`env.fontsLocalStripped`). 이 조건으로 조정 전 측정이 `/2`와 491/491블록 같았다.

## 6. 판단

**채택(구현) · 로컬 측정 범위** — 자동 조정과 경계 판정을 PM 결정대로 구현했고, 이 표본의 로컬 측정에서 동작을 확인했다.
수치는 로컬(Windows · Chromium 149) 결과이며 서버 HTML 렌더 환경과 같다고 보지 않는다. 사람 육안 검수 전이다.

구현 결정(정책이 정하지 않은 세부):
- 블록 처리 순서: 넘친 블록을 위 → 아래, 왼쪽 → 오른쪽(박스 y · x · blockId). 입력 순서와 상관없이 같은 결과.
- 여백 점유: 블록을 하나 조정할 때마다 그 블록의 자리(박스 ∪ 그린 글자)를 갱신한다. 조판 대상이 아닌 블록은 원래 박스. 원래부터 겹친 이웃은 그 블록의 한계에서 뺀다.
- 실패 복원: 시도는 기록(`attempt`)만 하고 렌더 입력 · 시스템 조정은 원래 값. 같은 입력을 다시 쟀을 때 넘치면 조정을 버린다(`not_reproducible`).
  → **`/3`(PM 승인 11-25)에서 바뀜**: 넘침이 남아도 마지막 시도를 남긴다(5.4).
- 폭: 다 들어가는 최소 폭. 최대 폭에서 안 들어가면 최대 폭으로 축소를 시도하고, 축소로 해소되면 그 배율에서 들어가는 최소 폭으로 다시 줄인다.
- 높이 확장은 하지 않는다(PM 순서에 없음 — PR #141 BWES90D와 다른 점).

## 7. 반영

정본(`contract.md` · `pipeline.md` · config) 변경 없음. `dev.md` 1절(코드 위치) · `status.md` ⑨ 행에 구현 상태만 적었다.

서버 HTML 렌더 환경 재측정 — 이 PC에 BE 환경이 없어 하지 않았다. BE 워커 환경(서버 렌더러 환경 변수 `PIXLATE_FE_INTERNAL_ORIGIN` ·

```bash
python docs/ai-experiments/tools/typeset_auto_adjust_run.py run --backend server --input $R/input.json --out $R/server
python docs/ai-experiments/tools/typeset_auto_adjust_review.py page --run $R --env local --env server
```

남은 확인: ① 서버 측정 오차(probe는 섹션 밖 촬영이 필요해 서버 세션으로 돌지 않는다 — 서버 세션에 섹션 밖 촬영을 더하거나 같은 Linux 이미지에서 local 백엔드로 재기)와 간격 2px 재확인
② 로컬과 해소 · 실패가 갈리는 블록(특히 남은 넘침 2px 이하 24블록) ③ 측정 횟수 기준 처리 시간(서버 한 번 렌더 = 섹션 그림 + 측정).

BE · FE 연결(후속, 구현을 막지 않음):
- **저장 계약**: 시스템 조정 `{box, fontScale, lineBreakApplied}` 중 박스 자리가 `layout_adjust.system`(migrations 0013: `font_scale` · `line_break_applied`)에 없다.
  셀러 조정과의 합성 우선순위 · 재사용/무효화 조건도 미정(`open-questions.md` #87).
- **실행 연결**: 1차 번역 뒤 섹션마다 `typeset_adjust.adjust_section`을 한 번(원본 규격 경로만, A+ 제외), 서버 HTML 렌더 세션으로 측정기를 만든다
  (`app.html_render`에 측정만 하는 입구가 없다 — 지금은 렌더 = 촬영 + 측정). 결과의 `renderBlocks`(또는 저장된 시스템 조정 + `apply_system`)로 렌더 입력을 만든다.
- **N5 수정 뒤**: 자동 조정을 다시 부르지 않고 조정값을 유지한 렌더 입력으로 렌더한 뒤 `typeset_boundary.judge_render`로 넘침 · 잘림을 다시 판정한다.
- **경계 판정 연결**: 섹션 렌더 결과마다 `judge_render`, 최종 출력은 `judge_final`(포함 섹션 순서 · 높이). 확정 차단 · N6 오류 · 화면 표시 · 대상 키는 #88.
- **측정 실패 블록**: 글꼴에 없는 글자 하나로 섹션 렌더 전체가 실패한다 — 처리 방식은 BE · FE 결정.
- **글꼴 local() (FE)**: Pretendard 고정본 CSS가 `local('Pretendard …')`를 먼저 찾는다. 이 PC에 Pretendard가 설치되자 측정 도구의 글자 경계가
  1px 달라졌다(338블록, 5.4). 셀러 PC(N5)와 서버 Chromium(N6 최종 이미지 — FE 내부 렌더 경로) 사이에도 같은 차이가 생길 수 있으나,
  줄바꿈 · 판정에 영향이 있는지는 확인하지 않았다. FE 확인 사항.
