# GS-03 JOB-06 단일 재시도 실행

## 1. 질문

기존 v1.0.1 제품 로직과 `HOW\nTOSF`를 변경하지 않고 Task 227 / Block 232를 JOB-06으로 한 번 재시도하여 N5·N6 및 H02~H04로 진행할 수 있는가?

## 2. 표본

원본 중단 회차 `gs03-supplement-20261126-r3-recovery1-attempt2`를 별도 회차 `gs03-supplement-20261127-r3-job06`과 전용 DB `px_baseline_gs03_supplement_20261126_r3_recovery2`로 복제했다. 자료는 저장소 로컬 `.cache/<회차>/`에 보존한다. 공식 Baseline과 원본 중단 DB·증거는 변경하지 않았다.

## 3. 조건

사용자가 2026-11-27 직접 승인한 추가 번역 모델 요청 최대 1회·요청 예약 $1.04, 기존 163회·$9.21462925 승계, 누적 500회·$25를 적용했다. 제품 `bfa3b700`, Gemini 블록 병합 제한 120초, 번역 제한은 기존 60초다. 모델·프롬프트·OCR·번역 규칙은 불변이다. 성공 시 N5 무수정 자동 확인은 사람 검수로 기록하지 않는 정책이며, N3는 반복하지 않는다.

실행 도구에 N4 JOB-06 전용 분기와 `SingleRetryMeter`를 추가했다. 현재 작업이 승인된 사용자 재시도 번역·Block 232인지 확인하고 요청 164 이후 모델 호출을 차단한다. 제품 JOB-06이 만든 작업의 retry_count=2/max_retry=2와 단일 대상을 워커 처리 전에 확인한다. 기존 제품 로직이나 자동 재시도 한도는 변경하지 않았다.

실행 전 회귀 테스트 **178개 통과**. DB·원장·객체 310개·고정 환경 검증을 통과했다. 최초 사전 검사에서 원본 배경 재사용 객체 2개의 `verified_key=null`을 누락으로 처리했으나, 제품의 정상 `source_ref`와 파일 해시를 확인해 검사기를 보완하고 회귀 검증했다. DB나 객체를 고친 것이 아니다.

## 4. 결과

JOB-06은 새로운 사용자 재시도 **Task 265**, Block 232, retry_count=2를 만들었다. 2026-11-27 10:44:16 KST에 모델 요청 **164번** 예약 기록이 생성됐다. 이후 표준 오류에 다음 네이티브 종료 오류가 남았다.

```text
forrtl: error (200): program aborting due to window-CLOSE event
```

## 5. 판단

**중단·미확정.** JOB-06 대상 선정과 범위 제한은 작동했지만 네이티브 프로세스 종료로 모델 결과를 확보하지 못했다. 실제 이미지가 없어 공통 시각 결함 분석이나 H02~H04 점수를 만들지 않았다. PM에게는 체크포인트 부재·평가 예외를 확인받아야 하며 품질 채점 완료로 표시하지 않는다.

후속 실행 전에 별도 비과금 작업으로 Windows 종료 이벤트와 프로세스 수명 문제를 확인할 필요가 있다. 요청 164가 결과 미확정인 상태이므로 이번 승인으로 추가 호출하지 않는다. 제품 재시도 횟수 초기화·원문 변경·새 회차는 별도 승인 없이 수행하지 않는다.
