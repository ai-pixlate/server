# GS-03 JOB-07 → N3 → SEC-04 → N4 신규 실행 준비 (2026-11-27)

## 3. 조건과 연결

제품 `bfa3b700`, GS-03 원본 18장, OCR 원문·모델·프롬프트·용어집·재시도 정책 유지. 병합 타임아웃 120초 설정을 유지하지만 N2는 호출하지 않는다.

`tools/baseline/gs03_n4_restart.py`가 새 모드를 준비·검증한다. 실제 실행 시 `app.routers.jobs.abort_job`(JOB-07)으로 N3에 돌아간 다음 기존 무대기 N3 처리와 `app.routers.sections.proceed`(SEC-04)를 사용한다. 이후 기존 N4→N5→N6 경로, `machine_snapshot`/`service_final` 수집을 재사용한다. N3/N5는 무수정 자동 처리이며 `human_reviewed=false`다. 사람 검수를 수행했다고 표시하지 않는다.

`gs03_scheduled`→Task Scheduler→무콘솔 감독자→`gs03_launch`→`gs03_runner`에 새 모드를 연결했다. 새 회차 배타 실행 claim, 기존 시작 기록 차단, 별도 승인 검증, 누적 비용 Meter를 유지한다. 이번에는 모델 호출을 차단한 DB probe만 스케줄러로 실행했다.

## 5. 예상 호출·비용와 실행 판단

승계 원장을 바이트 단위로 복사했다. **기존 164회·예산 점유 $10.25462925**, 요청 164의 미확정 예약 **$1.04**를 유지한다. 요청 164의 실제 응답·청구는 여전히 미확정이며 예약을 환급하지 않았다. 누적 점유는 확인 토큰 기반 추정 $0.89462925 + 미확정 예약 $9.36이며 실제 청구 금액이 아니다.

`estimate()`는 기존 N2 1~89, N4 90~163, JOB-06 164를 구분한다. 기존 N4 로그의 실제 SDK 요청은 다음과 같다.

| 단계 | 요청 | 사용량 확인분 비용 추정 | 미확정 요청/예약 |
|---|---:|---:|---:|
| label | 36 | $0.12188850 | 1회/$1.04 |
| translate | 38 | $0.20236200 | 4회/$4.16 |
| N4 합계 | 74 | $0.32425050 | 5회/$5.20 |

처음 요청은 label 36 + translate 36 = 72회였고 번역 자동 재시도 2회가 더 있었다. 따라서 **약 72~74회를 계획의 출발점**으로 삼되, 새 모델 결과·번역 분할·실패/재시도에 따라 달라질 수 있다. 새 label task 37개와 SDK 36회가 다른 것은 task와 API 요청을 구분하기 때문이다. N5/N6 고정 제품 경로는 최종 렌더/저장으로, 별도 Gemini 평가 호출을 추가하지 않는다. GPU 로컬 처리 시간/실패 위험은 별도로 존재한다.

동일 N4 사용량·미확정 패턴이 반복되는 경험 시나리오:

- 추가 74회, 점유 **$5.52425050**.
- 누적 **238회·$15.77887975**.
- 기존 상한 유지: 누적 **500회·$25**, 현재 잔여 **336회·$14.74537075**.
- 모두 성공하고 사용량이 비슷하면 점유가 낮아질 수 있으나, 보장하거나 실제 청구액으로 표시하지 않는다. 단가는 기존 준비에서 고정한 입력 $0.75/출력 $3.75 per million 기준이며 이번에 새 요금 조회나 API 접근 시험을 하지 않았다.
- 매 요청 직전 $1.04 예약을 검사한다. 사용량이 계속 미확정이면 잔여 예산으로 14회까지만 추가 예약 가능하며 15번째는 차단된다. 예산 때문에 18장 완성을 보장할 수 없다.
- 같은 번역 실패가 반복될 수 있다. 기존 자동 재시도만 수행하며, 한도를 소진하면 중단한다. 추가 JOB-06/전체 재실행을 자동으로 수행하지 않는다.

**판단: 준비·공식 전이·Windows 실행 경로는 검증 완료. 유료 실행은 아직 차단 상태.** 다음 승인은 새 회차의 JOB-07→N3→SEC-04→N4 전체 및 N5/N6 진행에 대한 실행·비용 승인이다. 누적 164회/$10.25462925와 미확정 예약을 승계하고 500회/$25를 유지하는 범위를 권장한다. 이는 과거 단일 Block 232 재시도와 다른 범위다. 18장 확보는 목표이며 실패 상태/미생성은 그대로 기록한다.

실행 전 고정 환경의 DB/GPU/모델 자산 및 요금 유효기간을 재확인하고, 명시 승인 근거를 새 manifest에 기록해야 한다. 인증 비밀값은 로컬 파일만 사용한다. 실행은 다음 형태이며 **이번에 실행하지 않았다**:

```text
<고정 Python> -B -m tools.baseline.gs03_scheduled <새 회차 경로> --url-file <새 DB 비밀 파일> --environment-file <로컬 환경 JSON> --execute-models
```

Task Scheduler는 부모 터미널 종료와 독립적이지만 로그아웃·재부팅·전원 중단까지 견디는 기능은 아니다. 로그인·깨어 있는 장비를 유지한다. 같은 회차의 started/claim 삭제나 자동 재개는 금지한다.

## 6. 반영

PR #161 실행 도구에 새 모드만 추가했다. 준비/전이 검증·누적 예산·승인 차단 테스트를 추가했다. 기존 제품 코드·공식 Baseline·원본 중단 DB/증거는 변경하지 않았다. PR 병합, CI 완료 대기, 모델 호출, 제품 이미지 생성 없음.
