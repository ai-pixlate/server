## 1. 원본 규격 유지 경로와의 관계

규격 변경 경로는 원본 규격 유지 경로(`pipeline.md` 1절)의 ①~⑧ 가운데 아래 단계가 끝난 뒤에 실행하고, 그 결과를 입력으로 받는다(2절).

| 입력 | 만드는 단계 | 쓰는 곳 | 출처 |
|---|---|---|---|
| 섹션 | ① | 섹션 내용 라벨 · 7칸 구성 — ①의 섹션을 그대로 쓴다 | [사용자 결정 2026-11-23 · 2026-11-25] |
| 블록의 원문과 역할(`role`) | ② · ③ | 섹션 내용 라벨 — 섹션의 글로 블록 원문을 함께 보낸다 · 7칸 구성 — 역할이 들어갈 칸을 정한다(4.2) | [A+ 변환기 §3] [PM 결정 2026-11-24] |
| 제품 라벨 판정 · 브랜드 로고 제외 | ④ · ⑤ | ⑥이 지우지 않을 글자와 ⑧이 번역하지 않을 블록을 정한다. 이 경로는 그 판정을 ⑥ · ⑧의 결과를 통해 받는다 | [개발계획 2.1] [PoC 0장] |
| 글자를 지운 섹션 이미지 — ④ · ⑤가 보호한 제품 인쇄 글자와 로고는 남아 있다 | ⑥ | 이미지 칸 누끼(4.5) | [사용자 결정 2026-11-24] |
| 1차 번역 — 라벨 · 로고로 제외된 블록은 번역이 없다 | ⑧ | 7칸 구성 — 문구의 재료(4.1) | [사용자 결정 2026-11-23] |

- **AI 산출물의 끝은 슬롯 내용**(`AplusModule`)이다. HTML 템플릿 · 글자 맞춤 · 캡처는 범위 밖이다. [사용자 결정 2026-11-23]
- **템플릿 렌더는 FE가 하고 글꼴은 Pretendard다.** [사용자 결정 2026-11-24]
- 참고 렌더러는 육안 검수 도구로만 쓴다(`docs/ai-experiments/tools/aplus_review/`). 검수 도구는 글꼴만 Pretendard로 맞췄고 글자 자동 축소 · 템플릿 HTML은 조판 계약(`contract.md` 6.4) · FE 구현과 달라, 그 이미지의 글자 크기 · 넘침은 최종 결과의 근거가 아니다. [사용자 결정 2026-11-24]
- 서비스 흐름에서 두 경로가 갈리는 지점 · 화면 · 저장은 정하지 않았다 — `BE 확인 필요`(6절).

## 2. 실행 순서

```text
[원본 규격 유지 경로 — pipeline.md 1절]
① 섹션 분해
→ ② 텍스트 추출
→ ③ 줄·문단 병합 및 역할 분류
→ ③-1 AI 섹션 판정 → 정책 적용
→ [섹션 확인 — 사용자 개입 1]
→ ④ 제품 라벨 판정
→ ⑤ 브랜드 로고 제외
→ ⑥ 인페인팅 / ⑧ 로컬라이징 번역

[규격 변경 경로 — 이 문서]
→ 섹션 내용 라벨
→ 7칸 구성 (템플릿 · 칸별 블록 · 사진 자리 · 누끼 여부)
→ 압축 (2차 번역 — 템플릿 한도를 넘은 글 칸만)
→ 압축 뒤 규칙 검사 (압축이 문구를 바꾼 글 칸만 — 기록만)
→ 이미지 칸 누끼
→ 슬롯 내용
→ [템플릿 렌더 — FE]
```
[계약 1.1] [개발계획 4.3] [사용자 결정 2026-11-23 · 2026-11-24 · 2026-11-25 · 2026-11-26]

- 위쪽은 이 경로가 결과를 받는 단계만 적었다. 단계마다 무엇을 받는지는 1절 표를 따른다.
- **섹션은 ①의 것을 그대로 쓴다.** A+ 모듈 안에서 섹션을 다시 자르지 않는다 — 참고 변환기 방식(그림 파일 단위로 경계를 다시 고르기)을 세 상품에 시험했을 때 ①보다 크게 나뉘었다(`docs/ai-experiments/2026-11-25_aplus_resplit-trial.md`, 에이전트 집계 — 사람 검수 아님). [사용자 결정 2026-11-25]
- **④ · ⑤는 ⑥보다 먼저 끝나야 한다.** 라벨 · 로고를 마스크에서 빼지 않으면 제품 패키지 인쇄 글자까지 지워진다. 누끼는 ⑥이 만든 이미지에서 제품을 따므로(4.5), ④ · ⑤가 없으면 인쇄 글자가 지워진 제품이 나온다. [PoC 0장] [`pipeline.md` 4절]
- 라벨 · 로고로 제외된 블록은 번역하지 않으므로 문구 재료에도 없다. [개발계획 2.1] [`pipeline.md` 5절]
- ④ 이후 단계는 포함으로 확정된 섹션에만 수행한다. 그래서 ⑥ · ⑧의 결과는 포함 섹션에만 있다. [계약 1.1, 1.4]
- **섹션 확인에서 제외된 섹션의 사진은 쓰지 않는다.** 제외된 섹션은 번역이 없어 문구 재료가 아니고, 사진 재료도 아니다. [사용자 결정 2026-11-26] 제외된 섹션을 섹션 내용 라벨 호출에 보내는지는 `미정`이다(`open-questions.md` #94).

- 칸마다의 흐름은 **블록 골라 넣기 → 넘치면 압축 → 규제 재검증 → 블록 출처 남기기**다. 빈 칸 보충으로 채우는 칸도 같은 흐름이다. [PM 결정 2026-11-24]
- **압축(2차 번역)은 7칸 구성 다음에 실행한다**(4.7). 누끼는 글과 무관해 압축과 순서를 따지지 않는다. [사용자 결정 2026-11-26]
- **규제 재검증 가운데 규칙 검사는 압축 다음에 실행한다**(4.8). [사용자 결정 2026-11-26] 규제 재검증의 나머지와 빈 칸 보충이 위 순서의 어디에 들어가는지와 입력 · 출력은 `미정`이다(`open-questions.md` #96).
- 「항상 7장」은 필수가 아니다. 일정이 모자라면 A+ 일 가운데 빈 칸 보충을 가장 먼저 미룬다. [PM 결정 2026-11-24]

## 4. 규칙

### 4.1 문구

- **문구는 1차 번역 블록을 선별해 채운다.** 한국어 원문에서 영어를 새로 쓰지 않는다. [사용자 결정 2026-11-23]
- 1차 번역 블록을 역할에 맞게 원래 순서로 골라 넣는다. [PM 결정 2026-11-24]
- **템플릿(A/B) · 칸별 블록 · 사진 자리는 모델이 고르고, 문구는 1차 번역 그대로 코드가 넣는다.** [사용자 결정 2026-11-23]
- 코드가 강제하는 것: 그 칸 라벨의 섹션 블록만 · 한 블록은 한 곳에만 · 원래 순서(섹션 순서 → `block_order`) · 다음 블록을 더하면 한도를 넘을 때 그 앞에서 중단 · 첫 블록이 넘으면 그 블록만 넣고 초과 표시. 한도 초과는 표시만 하고 자르지 않는다. [사용자 결정 2026-11-23] [A+ 변환기 §5]
- 역할(`role`)만으로 칸을 정하는 규칙은 쓰지 않는다 — GS-01 한 원본에서 장식 문구를 제목으로 뽑았다. 역할은 모델이 고른 블록이 들어갈 수 있는 칸을 제한하는 데 쓴다(4.2). [사용자 결정 2026-11-23] [PM 결정 2026-11-24]
- 압축은 별도 과업(2차 번역 선별 → 압축)에 연결한다. [사용자 결정 2026-11-23] 선별은 7칸 구성의 블록 골라 넣기이고, 압축은 4.7을 따른다. [사용자 결정 2026-11-26]

### 4.2 블록 역할 → 칸

| 역할 | 들어가는 칸 | 출처 |
|---|---|---|
| `title` | `headline` · 항목 제목 | [A+ 규격 설명 §6] |
| `body` | `body` · 항목 설명 | [A+ 규격 설명 §6] |
| `caption` | 1A · 3A의 `subheadline`과 항목 칸(4.3) | [A+ 규격 설명 §6] |
| `price` | 넣지 않는다 — 템플릿 14개에 가격 칸이 없고 가이드가 가격 · 할인 정보를 금지한다 | [PM 결정 2026-11-24] |
| `caution` | 12월에는 넣지 않는다 — 7칸에 맞는 자리가 없다. 어디에 담을지는 이후 과제다(`open-questions.md` 4절) | [PM 결정 2026-11-24] |

- `title` · `body` · `caption`의 칸 연결은 데이터 담당 제안대로 한다. [PM 결정 2026-11-24]
- `label` 칸은 블록에서 가져오지 않고 템플릿마다 정해진 값을 쓴다 — 1A 브랜드명 대문자 · 3A 「KEY INGREDIENT」 · 7A 「OUR STORY」. 고정 `label`(3A · 7A)은 코드가 채우고, 1A는 브랜드명 공급원이 정해질 때까지 비운다. [A+ 규격 설명 §6]
- 이 표는 `spec.json`의 `block_roles`와 템플릿의 `label_source`에 둔다. 7칸 구성은 이 표를 강제한다 — 모델이 고른 블록 가운데 역할이 그 칸에 맞지 않는 것은 빼고 기록하며, 그 칸의 템플릿 어디에도 들어갈 수 없는 역할의 블록은 모델에게 보내지 않는다. [PM 결정 2026-11-24]

### 4.3 `caption`의 항목 연결

모두 데이터 담당 답변(2026-11-24)이다. [A+ 규격 설명 §6]

- `caption`은 항목의 빈 자리만 채운다 — 그 항목에 `title` 블록이 없으면 항목 제목, `title` 블록은 있고 `body` 블록이 없으면 항목 설명에 넣고, 둘 다 있으면 넣지 않는다(설명에 덧붙이지 않는다).
- 넣는 템플릿은 항목마다 사진 · 아이콘 · 스와치가 있는 4B · 5B · 6A · 3B · 7B · 5A와 효능 칸 2A다. 4B · 5A · 2A는 항목 제목만 쓰므로 `title` 블록이 있으면 넣지 않는다. 2B · 6B에는 넣지 않는다.
- 2A는 짧은 효능 문구면 역할이 `title`이든 `caption`이든 항목에 넣는다 — 우리 블록 분류의 `caption`은 사진 설명보다 넓어(보조 라벨 · 짧은 설명 · 각주 포함) 체크 문구형 효능이 `caption`으로 온다.
- `caption`은 효능 포인트일 때만 넣고 각주 · 출처 · 시험 조건은 넣지 않는다.
- 코드는 역할과 빈 자리만 강제한다. `caption` 블록이 효능 문구인지 각주인지는 역할로 구분되지 않아 모델이 고른다(프롬프트 지시).

### 4.4 글자 수 한도

- 한도는 두 층이다. [PM 결정 2026-11-24]
  - **템플릿 한도**(`char_limits`) — 데이터 담당 엑셀의 「우리 템플릿 한도」. 2차 번역(압축)의 목표다.
  - **가이드 상한**(`module_spec`의 칸당 상한) — 넘으면 안 되는 바깥 한계로만 쓴다.
- 두 한도는 `char_limits`와 `module_spec` · 칸별 `guide_field` 대응으로 나눠 담는다. 자체 배치 템플릿(2B · 3B · 5A)과 1A · 3A의 `label` · `subheadline`은 대응하는 가이드 필드가 없다. [A+ 규격 설명 §1 · §2 · §3]
- 자료에 값이 없으면 한도를 만들지 않고 `미정`으로 둔다. [`README.md` 2절]
- 값의 정본은 `spec.json`이다. 1A 제목 40자는 「우리 템플릿 한도」 값이다(PM 확인). 6B 줄글형 본문은 칸당 상한에 맞춰 250자다. [PM 결정 2026-11-24]
- 엑셀에 값이 없던 조합은 데이터 담당 답변(2026-11-24)으로 받았다 — 2A 항목 2개 45 · 3B 항목 2개 제목 26 / 설명 70 · 6B 항목 4개 설명 60 · 5A 옵션 이름 15 · 5B 항목 제목 2개 45 / 3개 26 / 4개 20. 렌더러로 그려 넘치지 않는 최대 길이에서 여유를 둔 값이다. 항목 2~4개의 모든 조합에 한도가 있다. [A+ 규격 설명 §3]
- 한도의 아마존 기준은 원 작성자가 대행사 가이드로 확인했고 셀러센트럴 화면은 미확인이다. [A+ 변환기 §4]
- **한도 초과 표시**는 개발 중 확인용으로만 쓰고 N5 화면에는 띄우지 않는다. 압축해도 한도에 못 맞춘 칸은 1차 번역으로 채우고 12월에는 따로 표시하지 않는다. [PM 결정 2026-11-24]

### 4.5 이미지 칸 — 원본 크롭 + 누끼

[사용자 결정 2026-11-24]

- 누끼 여부는 7칸 구성 호출에서 모델이 사진마다 판단한다(`AplusImage.cutout`). 코드는 그 답을 바꾸지 않는다.
- 누끼할 사진은 글자를 지운 섹션 이미지(⑥ 결과)에서 자를 자리를 넓혀 자른다. 지운 이미지가 없으면 원본에서 자르고 확인 표시를 남긴다.
- 전경 분리 모델은 `birefnet-general`이고 경계 보정(alpha matting)은 쓰지 않는다.
- 가장자리를 안쪽으로 줄이고 작은 조각을 지운 뒤 남은 대상에 맞춰 다시 자르고 투명 여백을 둔다.
- 누끼를 하지 않거나 실패한 사진은 원본 크롭을 쓴다.
- 근거 시험은 `docs/ai-experiments/2026-11-23_aplus_cutout-trial.md`(세 상품 22장, 에이전트 육안 — 사람 검수 아님)다. 설정 키는 `pipeline.md` 3절 `aplus_cutout.*`.

### 4.6 빈 칸 보충

- 참고 규칙은 LLM이 보충 문구를 새로 쓰고 "규제 검사를 통과한 정보로만"을 전제로 한다. 이 모듈은 아래처럼 다르게 한다. [A+ 변환기 §7]
- 데이터 담당 보충 규칙(채우는 순서 · 없는 내용은 만들지 않기)을 따르되 **재료는 1차 번역 블록만** 쓴다. 영어를 새로 쓰지 않고, LLM은 어떤 보충이 가능한지 판단하는 데만 쓴다. [PM 결정 2026-11-24]
- 채우는 순서 9단계: 같은 칸 한 장 더(효능 · 제품 소개 · 신뢰·증명 · 옵션·라인업 · 성분) → 제품 디테일 → 추천 대상 → 제형 · 사용감 → 제품 사진 중심 한 장. [A+ 규격 설명 §7]
- 원칙: 없는 내용을 만들지 않는다 · 안내/FAQ/로고/리뷰는 재료가 아니다 · 같은 보충 유형은 한 번만 · 다른 칸의 문구 · 사진을 되풀이하지 않는다 · 7칸 밖 라벨도 재료가 될 수 있다. [A+ 규격 설명 §7]
- 보충 칸에는 보충 유형(`fill_type`)을 표시하되 이미지에는 그리지 않는다. [A+ 규격 설명 §7]
- 자료의 "항상 7장"은 따르지 않는다(2절). [PM 결정 2026-11-24]

### 4.7 압축(2차 번역)

[사용자 결정 2026-11-26]

- **받는 것은 7칸 구성 결과와 적용 분류의 규제 행이다.** 블록 목록 · 이미지 · 한국어 원문은 받지 않는다 — 1차 번역문만 고쳐 쓰고 한국어 원문에서 영어를 새로 쓰지 않는다(4.1).
- **선별을 다시 하지 않는다.** 7칸 구성이 한도 직전에서 뺀 블록을 다시 넣지 않고, 칸의 출처 블록(`origin_block_keys`)을 바꾸지 않는다.
- 대상은 템플릿 한도를 넘은 글 칸이다. `label` 칸은 블록에서 오지 않으므로(4.2) 대상이 아니다. 대상이 없으면 모델을 부르지 않는다.
- 모델에는 글만 보낸다. 대상이 있는 칸(모듈)마다 그 칸의 글 전부를 보내고, 대상 글에 한도를 붙인다 — 나머지 글은 문맥이며 고치지 않는다.
- 호출은 상품당 1회다. 채택되지 않은 칸만 실제 글자 수와 문제를 알려 다시 묻는다(횟수는 `aplus_compress.max_retries`). 모델이 줄일 수 없다고 답한 칸은 다시 묻지 않는다.
- 줄이는 기준은 프롬프트에 있다(`pipeline/prompts/aplus_compress.md`): 지금 문구만 고쳐 쓰고 없는 내용 · 수치를 더하지 않는다 · 군더더기 → 같은 뜻의 짧은 표현 → 덜 중요한 수식어 순으로 줄인다 · 숫자 · 단위는 값 그대로 둔다 · 제품명 · 브랜드명 · 성분명은 줄이지 않는다 · 완화 표현을 지워 효능을 단정으로 바꾸지 않는다 · 받은 규제 표현을 새로 쓰지 않는다 · 대소문자 방식과 `#` · `+` · `*`를 유지한다 · 기준을 지키며 못 맞추면 줄일 수 없다고 답한다.
- **글자 수는 코드가 센다.** 답이 템플릿 한도 안이고, 비어 있지 않고, 1차 문구에 없던 숫자가 없고, 1차 문구에 없던 규제 매칭이 없을 때만 그 칸의 문구를 바꾼다. 덜 줄어든 답은 쓰지 않는다.
- **압축도 규제를 반영한다.** 규제 행 가운데 허용이 아닌 행의 영어 표현을 「새로 쓰지 않을 표현」으로 모델에 주고, 답에 1차 문구에 없던 규제 매칭이 새로 생겼는지를 코드가 확인한다. 매칭은 원본 규격 유지 경로의 번역문 규칙 검사(`pipeline/stages/text_check.py`)와 같다. 새 매칭이 생긴 답은 채택하지 않고 다시 묻는다. 번역문 LLM 규제 판정은 압축에 넣지 않는다.
- **1차 문구에 원래 있던 규제 표현은 압축이 고치지 않는다.** 압축의 일은 줄이는 것이다.
- 규제 행을 받지 못하면 규제를 반영하지 않고 그 사실을 기록에 남긴다. 규제 사전 데이터 오류는 전체 실패이며 통과로 바꾸지 않는다.
- `BE 확인 필요`: 규제 행과 상품 규제 분류를 압축 단계에 공급하는 방식(`open-questions.md` #94). 합의 전에는 개발용 실행 도구가 로컬 사전으로만 돌린다.
- 못 맞춘 칸은 1차 번역 그대로 둔다(4.4). 1차 번역이 가이드 상한까지 넘는 칸에도 따로 규칙을 두지 않는다 — 1차 번역으로 두고 기록에 두 한도를 남긴다(`open-questions.md` #94).
- 어느 칸의 문구가 바뀌었는지는 압축 결과의 칸별 기록(`AplusCompressedField`)으로 안다. 슬롯 내용(`AplusModule`)의 모양은 바꾸지 않는다. 칸별 기록은 AI 내부 형식이며 인계 형식이 아니다(6절).
- 첫 호출이 실패하면 전체 실패이고 7칸 구성 결과를 그대로 쓴다. 다시 묻는 호출이 실패하면 그때까지 채택된 칸은 살리고 남은 칸은 1차 번역으로 둔다.
- 근거 시험은 `docs/ai-experiments/2026-11-26_aplus_compress-trial.md`(세 상품 · 대상 19칸, 에이전트 집계 — 사람 검수 아님)와 규제를 반영한 `docs/ai-experiments/2026-11-26_aplus_compress-regulation-trial.md`(같은 세 상품, 새 규제 매칭으로 거절된 답 없음)다. 설정 키는 `pipeline.md` 3절 `aplus_compress.*`.

### 4.8 압축 뒤 규칙 검사

[사용자 결정 2026-11-26]

- 규제 재검증(3절) 가운데 **규칙 검사만** 한다. 번역문 LLM 규제 판정을 이 경로에 돌릴지는 `미정`이다(`open-questions.md` #96).
- **압축 다음의 독립 단계이고 결과는 기록만 한다.** 새 규제 매칭은 압축이 채택 때 막으므로(4.7) 이 단계는 바뀐 문구의 검사 결과와 강제 용어 적용 여부를 남긴다. 문구를 바꾸지 않고 압축의 채택을 되돌리지 않는다 — 원본 규격 유지 경로와 같다(검사 결과로 번역문을 바꾸지 않는다, `contract.md` 5.1).
- **대상은 압축이 문구를 바꾼 칸뿐이다.** 바뀌지 않은 칸의 문구는 블록의 1차 번역 그대로이므로 다시 검사하지 않는다. 여러 블록을 이어 붙인 칸도 다시 검사하지 않는다.
- 검사는 원본 규격 유지 경로의 번역문 규칙 검사(`pipeline/stages/text_check.py`)를 그대로 쓴다 — 영어 규제 표현 재대조와 강제 용어 적용 여부다. 새 검사 규칙을 만들지 않는다.
- 받는 것은 압축 결과 · 바뀐 칸의 출처 블록 한국어 원문 · 적용 분류의 규제 행 · 용어 목록이다. 용어 목록을 받지 못하면 강제 용어를 검사하지 않고 그 사실을 기록에 남긴다 — 빈 용어 목록과 다르다.
- 1차 번역에 원래 있던 규제 표현을 칸에 표시하는 것은 이 단계가 하지 않는다. 블록의 검사 결과를 칸에 잇는 일이며 `미정`이다(`open-questions.md` #96).
- 칸별 기록(`AplusRecheckedField`)은 AI 내부 형식이며 인계 형식이 아니다(6절). 기록에 리비전은 없다 — 압축 문구는 블록의 리비전이 아니다.
- 사전 · 용어 데이터 오류는 전체 실패이고 통과로 바꾸지 않는다. 문구는 그대로다.
- `BE 확인 필요`: 규제 행 · 용어 목록 · 블록 원문을 이 단계에 공급하는 방식과, 칸 단위 검사 결과의 저장 · 식별(`open-questions.md` #96). 합의 전에는 개발용 실행 도구가 로컬 사전으로만 돌린다.
- 근거 시험은 `docs/ai-experiments/2026-11-26_aplus_recheck-trial.md`(세 상품 · 바뀐 12칸, 강제 용어 검사 없음)다.

## 5. 규격 데이터

- **규격 데이터 정본은 레포 파일** `pipeline/data/aplus/spec.json`이다. [사용자 결정 2026-11-23]
- 레포 JSON을 먼저 두고, 값은 데이터 담당 엑셀과 같게 맞추며 출처 · 확인일 칸을 포함한다 — 나중에 DB 시드와 두 벌이 되지 않게 한다. [PM 결정 2026-11-24]
- 규격 데이터는 DB에 적재하지 않고 이 파일에만 둔다. 가이드 상한 표(DB `module_spec` 표의 행)와 템플릿 14개의 정의(같은 표의 `slot_spec` 열) 모두 해당한다. [사용자 회신 2026-11-26] [사용자 결정 2026-11-26]
- 담는 것:

| 키 | 내용 | 출처 |
|---|---|---|
| `canvas` | 모듈 한 장의 크기(970×300) | [A+ 렌더러] |
| `slots` | 7칸의 이름과 칸마다 고를 수 있는 템플릿 2개 | [A+ 변환기 §4] |
| `labels` | 섹션 내용 라벨 19종과 라벨 → 칸 표, 사진을 가져오지 않는 라벨 표시 | [A+ 변환기 §3] |
| `templates` | 템플릿 14개의 치수 · 필수 칸 · 반복 항목 범위 · 배치 변형 · 템플릿 한도(`char_limits`) · 아마존 모듈 대응 · `label_source` | [A+ 렌더러] [A+ 규격 설명 §2 · §3] |

| `block_roles` | 블록 역할 → 칸 표(4.2 · 4.3) | [A+ 규격 설명 §6] |
| `template_limit_source` | 템플릿 한도의 출처 | [A+ 규격 설명 §3] |

- 템플릿 → 모듈 대응은 엑셀을 따른다 — 1B = Image & Text Overlay · 2B = 자체 배치. [A+ 규격 설명 §1]
- 가이드 상한은 민간 가이드 값이며 아마존 화면으로 확인하기 전이다. [A+ 규격 설명 §1]
