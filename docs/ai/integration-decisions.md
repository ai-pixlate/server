## 2. 결정 목록

**현재 적용 주의**: D8이 현지 uncertain·겹침·규제 분류의 이전 PM 대기 상태를 갱신한다. D1~D7의 N3 차단/N4 실패 유지·호출 범위·유형 경계는 D8 C1~C4와 함께 읽고, 충돌 지점을 재합의 없이 구현하지 않는다. 이전 기록의 PM 보류 표시는 해당 당시 상태다.


### D1 — 실행 경계와 처리 대상

- N3는 섹션 확인, N5는 검수. 사용자가 보는 진행 경계는 기존 proceed 한 번이며, ④→⑤→⑥⑦⑧은 N4 안에서 수행한다. 포함 섹션이 없으면 진행을 거절하고 proceed 전에 인페인트를 생성하지 않는다.
- proceed에서는 대표 행과 최초 작업만 만든다. ④~⑧ 전체를 미리 만들지 않는다. ④⑤가 유효하게 완료되고 입력이 준비된 뒤 ⑥⑦⑧을 함께 생성하며 서로의 완료를 직렬로 기다리지 않는다.
- ④⑤의 정상 완료는 `(true, NULL)` 생략 제외, `(false, true)` 로고 제외, `(false, false)` 하류 대상 세 조합이다. 라벨 NULL은 로고 값과 무관하게 미완료다. 옛 DB 값만으로 이번 실행의 완료를 판단하지 않는다.
- `is_excluded`는 하나라도 true이면 true, 둘 다 false이면 false, 나머지는 NULL. 기존 0003과의 불일치는 후속 마이그레이션 대상이며 반영 전 하류 큐를 생성하지 않는다.
- N5는 현재 실행의 필수 ⑥⑦⑧ 작업이 모두 성공 또는 정상 생략 완료일 때만 연다. 실패 시 N4·진행 중 상태를 유지하고 실패는 개별 작업에 둔다. 처리 대상 없음은 호출 없이 성공으로 집계한다. 빈 문자열 블록은 번역·텍스트 조판에서 제외하며 블록 0개와 구분한다.
- 반영: `pipeline.md` 1.1, `contract.md` 2.4·11, 루트 `README.md` 작업 흐름. 관련: #63·#64.

### D2 — 실행·시도와 결과 유효성

- 한 proceed를 `unit_type=job`인 대표 작업 행으로 식별하고 개별 작업을 연결한다. 실행·시도 연결 컬럼과 task_type은 미정이다. 블록·작업 revision은 기존 번역문·배치 계약용이며 실행 ID로 쓰지 않는다.
- 최초에도 존재하는 해당 `job` 행을 잠그는 기준으로 단계·활성 실행 확인, 대표 행·최초 작업 생성, N4 전환을 한 트랜잭션에서 처리한다. 채팅의 "작업 행 잠금"은 아직 없는 대표 행만 잠근다는 뜻으로 적용하지 않는다. 동시·중복 proceed로 새 실행을 중복 생성하지 않는다.
- 각 결과 반영·후속 작업 생성·N5 전환 시 대표 실행과 현재 시도의 유효성을 해당 변경과 같은 트랜잭션에서 검사한다. 중단도 같은 대표 행 기준으로 원자적으로 처리한다. 전체 모델 실행을 하나의 장시간 트랜잭션으로 묶는 뜻은 아니다.
- 재시도는 같은 대표 행 아래 새 개별 행을 만들고 이전 실패 행은 이력으로 보존한다. 같은 대상·단계의 현재 유효 시도만 집계하며, 이전 시도의 늦은 결과와 중단된 실행의 재시도·후속 작업·N5 전환을 허용하지 않는다. 한도는 시도 간 누적하고 중복 재시도 생성을 막는다.
- 큐 등록 실패 시 N4·대표 행을 유지하고 대기 행을 복구한다. 중복 전달의 중복 실행을 억제하고 결과 반영·후속 생성·상태 전환 효과는 중복되지 않게 한다. 장애 복구에서 계산 자체가 재수행되지 않는다는 보장은 하지 않는다. 복구 주체·조건·횟수는 구현 전 명세 대상이다.
- 반영: `contract.md` 11, `db-map.md` 3.6, 루트 `README.md`. 관련: #16·#64·#65.

### D3 — 초기 분석 인계

- 경계는 `analyze()`와 `AnalyzeResult` 버전 1. ①②③만 수행한다. 개발용 Split 버전과 DB JSON 버전은 별개이며 호환 규칙 변경은 BE 합의 후 버전에 반영한다.
- BE 워커가 절대 로컬 경로로 호출하고 검증·업로드·저장·임시 키→DB ID 변환을 담당한다. 임시 키는 분석 실행 범위에 묶이며 모르는 키는 저장 실패다. 줄·영역 키의 섹션 내 유일 범위는 유지한다.
- N3는 현재 유효한 초기 분석과 그에 대응하는 ③-1·③-1′ 결과 준비 후 연다. 이 초기 분석 실행은 proceed의 N4 실행과 구분한다. 각 단계 결과·참조를 일관되게 저장하고 부분 저장을 준비 완료로 노출하지 않는다.
- `range`는 추가하지 않는다. 섹션은 원본 전체 폭의 `[top_offset, top_offset + height)`이며 BE가 원본 기준 section.bbox를 파생한다. 블록 좌표는 섹션 로컬 정수 픽셀. ④의 0~1000 좌표는 모델 입력용이다.
- 원시 영역 score는 인식 신뢰도(현재 `rec_scores[i]`, 0~1), 블록 신뢰도는 구성 영역 최솟값이다. 인페인트는 영역 score를 사용한다. 0.5 유지와 임계값 품질 검증은 별개다. 빈 문자열 블록·role은 보존하되 의미 분류와 번역·텍스트 조판에 사용하지 않는다.
- 반영: `contract.md` 1.1·2.5·3·11, `db-map.md`, `dev.md`. 관련: #13·#34·#35·#36.

### D4 — 불확실·겹침·실패와 근거 보존

- `uncertain`은 완료된 판단 결과다. 불확실성만으로 자동 재시도하거나 present·absent·needs_fix로 바꾸지 않는다. 규칙 겹침과 `conflict_group` 자체를 위반 확정 배지로 쓰지 않는다.
- 호출 실패·시간 초과·잘못된 응답은 미완료이며 N3를 열지 않는다. 유효한 선행 결과·입력이 있으면 실패 단계만 재시도하고, 입력·사전·설정이 바뀌면 영향받는 단계부터 처리한다. 무조건 자동 반복하는 뜻은 아니며 재시도 가능 조건·단위·횟수는 미정이다.
- AI 판단 이유·사전 사유·겹침 근거는 분리한다. 모든 판정과 대응 finding을 보존하며 실제 사용한 사전 항목만 연결한다. 블록·매칭 구간은 있을 때 연결하고 이미지 전용 근거에는 만들지 않는다. 근거 종류와 설명을 보존한다.
- 사용자 포함·되살리기는 최종 포함 상태를 바꾸며 AI 판정 원본을 바꾸지 않는다. 화면 대표 사유를 고르더라도 다른 판정을 삭제하지 않는다.
- 반영: `contract.md` 4.3·8, `pipeline.md` 7.3. 관련: #43~#46·#48. 포함·제외·사용자 확인 정책은 PM 대기.

### D5 — 사전 실행 묶음과 이력

2026-10-07 보완: 아래 당시 미정이던 판정 스냅샷 저장 위치는 D6에서 audit_log.detail로 확정했다. 실행 묶음 전체 보존 위치·기간과 JSON 키는 여전히 미정이다.

- BE가 분석 실행 시작 시 DB 적재본으로 고정 묶음을 하나 만든다. AI는 실행 중 최신 DB나 같은 원본으로 만든 다른 묶음을 읽어 교체·대조하지 않는다. 원본과 DB 적재의 정합성은 적재 시 검증한다.
- 원본 ID→DB PK와 당시 내용의 대응은 BE가 묶음 생성 시 고정한다. 사전 참조로 AI는 RG·LC 원본 ID를 반환한다. ID 없음·묶음 밖 ID·당시 내용 불일치는 다른 행에 붙이거나 근거 ID를 비워 성공 처리하지 않는다.
- 서비스 판정값과 `source_verdict_status`의 원값을 구분하고 원값 누락을 추정 복원하지 않는다. AI 미지원 값은 공급 전에 거부한다. DB 적재 허용과 AI 공급 가능은 별개다.
- 결과는 실행 묶음의 ID·근거로 저장한다. 최신 DB와 달라졌다는 이유로 거절하거나 새 묶음으로 자동 재실행하지 않는다. 실행 버전·해시·사유·근거는 분석 실행에 보존하며 현재 행 조회로 과거 문구를 바꾸지 않는다.
- 이미 복사한 스냅샷은 원본 행 삭제 후에도 보존한다. 스냅샷 없이 연결만 있거나 식별 관계가 깨진 경우는 저장 실패다. 삭제 후 필수 FK를 보존하는 구체 방식은 미정이며, 임의 연결·근거 ID 제거로 성공 처리하지 않는다.
- 현재 AI 개발용 필수값을 DB에서 얻지 못하면 임의로 채우지 않는다. 정책 규칙 공급처·버전·해시, 일관된 조회, 공급 대상 행, 필드별 공급·누락 규칙, 묶음 보존 위치·기간, 스냅샷 위치, 대체 표현 문자열→배열 변환은 구현 전 명세 대상이다. 변환 규칙 확정 후 BE가 묶음 생성 시 한 번 수행하고 AI 실행 중에는 나누지 않는다.
- 반영: `contract.md` 9.1, `db-map.md` 3.7, `dev.md` 3.1. 관련: #3·#49·#71. PM 보류 정책은 승인되지 않았다.

### D6 — 판정·근거 저장과 재분석

- 기록일 2026-10-07. 출처는 사용자가 전달한 BE #48 회신문과 승인한 추천안·후속 content_type 회신문이다. 판정·근거 저장 원칙은 확정, JSON 키·API 상세는 구현 전 명세다.
- finding 6필드는 `section.content_findings.findings[]`, 정책 판정은 `section_verdict`, 대응·검사 범위·실행 당시 사전 스냅샷과 복수 근거는 `audit_log.detail`에 둔다. 새 테이블 없이 기존 위치를 사용하고 개발용 JudgeResult·PolicyResult 전체를 계약으로 승격하지 않는다.
- 초기 분석 실행은 `job_async_task`의 `task_type=ocr`, `unit_type=job` 행으로 식별한다. N4 대표 행을 translate로 확정한 것이 아니며 대표·개별 단계·재시도 task_type은 미정이다.
- 사용한 사전의 external_id와 스냅샷 객체는 필수다. 원래 없는 조문·URL·대체 표현·source_verdict_status는 NULL로 보존한다. 복수 근거와 원본 상태는 실행 스냅샷 배열에 둔다. 판정 행을 만들지 않아도 검사 범위·사용한 사전·정책 식별자와 버전을 audit에 남기며 판정 ID 목록은 비어 있을 수 있다.
- 문자 구간은 당시 source_ko의 정규화 전 Unicode 코드 포인트 `[start, end)`이며 matched_text는 해당 부분 문자열이다. 당시 원문·구간·매칭 문구를 복사하고 나중의 블록 조회로 과거 구간을 해석하지 않는다. problemText는 판정 행의 대표 문구 하나이며 전체 목록이 아니다.
- 현재 채택 대상인 초기 분석 실행만 이전 내용의 audit 기록·새 finding/판정·현재 실행 연결·완료를 한 트랜잭션으로 반영한다. 취소·오래된 실행의 늦은 결과는 반영하지 않는다. 실패는 uncertain이 아니며 N3를 열지 않는다. 최초 분석에 기존 유효 결과가 없으면 content_findings=NULL, 실패한 재분석은 기존 결과를 보존하되 이번 실행 성공으로 보지 않는다.
- original_verdict는 현재 채택한 분석 실행의 사용자 조정 전 정책 결과다. 사용자 포함·되살리기는 bucket·exclusion_reason·excluded_stage만 변경한다. 새 분석이 성공해 채택되면 원본을 교체하고 이전 원본은 audit에 보존한다.
- 반영: `contract.md` 4.4, `db-map.md` 3.2·3.4·3.6·3.7. 관련 #48·#46·#49·#71. 사전 단수 FK와 복수 연결의 상세, JSON 키·API는 미결이다.

### D7 — content_type 의미와 지원 범위

- content_type은 검사 대상이며 finding.status는 present·absent·uncertain이다. 사전 external_id·정책 결론과 분리하고 present를 위반 확정으로 해석하지 않는다. 기존 external_id 자체를 다른 분류 문자열로 바꾸지 않는다.
- 완료 finding은 합의한 6필드를 가진다. finding_key는 그 분석 실행의 그 섹션 안에서만 유일하다. image는 빈 블록 목록, image_and_text는 실제 텍스트 근거만 연결하고 임시 키→이번 실행 DB ID 변환은 BE가 맡는다. 사전 연결은 0개 이상이다.
- 미지원·미검사를 other·absent·uncertain으로 바꾸지 않는다. 검사하지 않은 항목은 finding을 만들지 않고 실행 검사 범위를 별도로 남긴다. 특정 문구·사전 항목의 absent를 유형 전체의 부재로 확대하지 않는다.
- 같은 유형이라도 판단 범위·근거가 다르면 finding_key를 나눈다. 사전 대응만으로 합치거나 복제하지 않는다. 사전 없는 이미지 판단에도 유형의 판정 기준이 필요하다. 개발용 사전 ID content_type과 사전 항목당 finding 1개·근거 합집합은 통합 규칙이 아니다.
- 기준·방법이 준비된 유형만 지원한다. 실제 목록 확정 전 BE가 허용값을 만들지 않고, 확정 후 목록 밖 값은 content_findings 저장 전에 거절한다. before_after 예시와 LC/RG ID는 운영 유형 목록이 아니다. 별도 API 합의 전 프론트에 content_type을 노출하지 않는다.
- 반영: `contract.md` 4.5, `pipeline.md` 7.3, `dev.md` 3.1. #4의 실제 지원 목록·판정 기준·사전 대응표는 미결이다. 채팅의 22유형은 미승인 후보이며 운영 enum·계약값으로 반영하지 않는다.

### 5.3 남은 초안 작성과 PR 리뷰 순서

1. **C1부터 구체화**: PM이 직접 답한 현지 실패 정책을 실행 완료·진행 조건으로 연결한다. C2·C3을 함께 정리한 뒤 실제 content_type 목록을 확정하고, C4는 단계별 대체 처리 표로 검토한다.
2. **분석·판정·사전 묶음**: 유형·판정 기준·사전 대응, verdict_status/verdict_type·배지·사유 코드 매핑, audit JSON/API, 공급 필드·버전·해시·대체 표현 변환·보존을 작성한다.
3. **하류 산출·검수 묶음**: style 키·단위·NULL, auto_adjust 역할, 번역 입력과 상품별 검증 정보, 렌더 overflow·char_limit, 신호 코드·노출을 작성한다.
4. **실행·운영 묶음**: 대표/개별/재시도 task_type, 연결·현재 시도 집계, 생략 표현, 오류·한도·복구·취소·중복 전달을 작성한다. 구조 초안은 앞 묶음과 병행하되 단계 입출력 확정 후 완료 조건을 맞춘다.
5. **문서 PR 리뷰**: 전체 초안을 한 PR로 제출하고 위 세 묶음 순서로 리뷰한다. 기존 확정 / 새 제안 / BE 작성 필요 / PM·데이터 확인을 표시한다. BE는 동의·구체 대안·보류 사유를 남기고 소유 상세를 보완한다. API 문서 반영은 feature/api-tracking 관리 흐름에 연결한다.

AI는 모델 입출력·판정 능력·산출물 의미와 대표 사례를 작성하고, BE는 저장·API·트랜잭션·작업·복구 상세를 작성한다. 양쪽 경계와 실패 의미는 공동 리뷰한다. 사용자 정책·지원 범위 변경은 PM, 사전 의미·충돌 데이터는 데이터 담당 확인이 필요하다. 이 절은 역할 제안이며 상대 담당의 리뷰 완료를 뜻하지 않는다.

**완료 기준**: 각 항목에 담당, 입출력·저장/API 대응, 필수/NULL/생략/실패 조건과 대표 사례가 있고, 미결 항목의 영향 범위가 명시돼야 한다. 확정된 부분만 소유 계약에 옮기며 코드·마이그레이션 구현은 별도 작업으로 진행한다. 관련 없는 PRD 전체를 옮기지 않는다.

#### 재분석·재시도와 proceed 경쟁 처리 제안

1. 재분석 시작 후 기존 판정은 보존하되 현재 입력과의 유효성을 별도로 판단한다. 실패했다는 이유만으로 기존 결과를 새 입력에 유효하다고 간주하지 않는다.
2. 입력·사전·설정이 달라졌거나 유효성을 확인할 수 없으면 이전 결과로 자동 진행하지 않는 안을 추천한다. 입력이 동일하고 이전 실행이 유효하면 실패한 새 시도를 정리한 뒤 기존 실행을 채택 대상으로 유지할 수 있는지 BE가 제안한다. 새 복귀 버튼이나 API를 여기서 요구하지 않는다.
3. 사용자 포함·되살리기와 진행 중 재시도 결과가 서로 덮어쓰지 않도록, N3 전환/proceed 직전에 현재 실행·시도·입력·bucket을 같은 트랜잭션 기준으로 확인하는 안을 추천한다. 재시도 시작과 proceed가 경합하면 하나의 결과만 채택되게 한다.
4. 실패 결과를 허용 예외로 처리해 N3에 넘긴 뒤 늦게 도착한 성공 결과가 bucket·판정을 바꾸지 않도록 해당 시도의 수락 가능 여부를 닫는다. 종료·취소·실패의 구체 저장값은 BE 명세다.

#### BE에 남기는 결정 목록

- **완료 집계:** ocr·job 실행 안에서 개별 실패를 보존하면서 N2 종료를 어떻게 표현할지. 이전 합의의 현재 유효 시도만 집계하는 원칙을 유지할지와 구체 연결.
- **결과 저장:** PRD의 현지 NULL과 현재 통합 content_findings(규제·현지 finding)의 관계. 현지 실패 때문에 정상 규제 finding까지 지우지 않도록 하되 새 JSON 키를 임의로 정하지 않음. 전체 6필드 구조·검사 범위/audit와 맞출 것.
- **실패의 범위:** 현지 사전 조회만 실패한 경우와 공통 묶음 생성·스냅샷 무결성 실패를 어떻게 구별할지. 실제 사용하지 못한 사전은 사용했다고 기록하지 않을 것.
- **재분석 표시:** 이전 유효 결과를 남긴 상태에서 이번 실행의 판정 실패/검사 미수행과 기본 제외 정책을 어느 실행·화면에 적용할지. 기존 결과 보존을 이번 성공으로 표현하지 않을 것.
- **재시도와 진행:** 재시도 종료 시점·횟수·진행 차단·취소와 늦은 결과 무효화, N3에서 재시도를 시작할 수 있는지. 자동 무한 반복 금지.
- **화면·API:** auto_local/auto_local_failed, 배지 없는 판정 실패, 검사 미수행 안내를 기존 상태·오류·API에 어떻게 대응시킬지. 실패 안내 때문에 가짜 section_verdict/finding을 만들지 않을 것.
- **테스트할 경합:** proceed와 재시도 동시 요청, 실패 확정 후 성공 지연 도착, 재분석 실패 후 옛 결과 보존, 전 섹션 제외에서 되살리기, 사전 조회만 실패와 스냅샷 손상의 구분.

### 5.5 C2 — 현지 검사 호출 범위（추천안·미확정）

### 5.6 C3 — 유형·사전·finding 대응（추천안·미확정）

| 사례 | 추천 결과·검토점 |
|---|---|

#### N5 집계·재시도 추천

- 작업 성공, 대상 없음의 정상 생략, 정책상 허용된 실패 대체를 구분해 집계한다. 세 범주는 설명용이며 새 DB status가 아니다. 실패를 성공으로 덮어쓰지 않고, BE가 실제 저장값·API 표현을 제안한다.
- 현재 유효 실행·시도만 대상으로 모든 필수 작업이 성공/생략 또는 **승인된 실패 대체**로 정리되고, 검수에 필요한 결과·실패 표시가 준비됐을 때 N5에 진입하는 안을 검토한다. 재시도 대기/실행 중에는 아직 정리된 결과로 보지 않는 안을 추천한다.
- 대체 허용은 단계별 명시 목록으로 정한다. 인페인트·렌더·번역의 PRD 근거가 있다고 스타일·상류 판정·저장 오류까지 일괄 허용하지 않는다. 정책 미합의인 상태에서 기존 N4 차단을 먼저 제거하지 않는다.
- 같은 실행의 유효한 성공분은 보존한다. 실패 단계 재시도로 출력이 바뀌면 그 출력을 소비한 조판·렌더 등도 무효화/재생성해야 한다. 예: 내부 인페인트 재시도로 배경이 바뀌면 이전 배경의 렌더는 최신 결과가 아니다. 관계없는 번역·스타일은 입력 유효성을 확인해 재사용한다.
- 번역 실패 후 직접 입력은 N5 수정 흐름과 revision·재검사·재렌더에 연결한다. 이전에 출력한 원본 대체 화면이나 실패 상태가 새 결과의 성공을 가리지 않도록 현재 결과를 기준으로 표시한다.
- N5 진입 허용은 최종 확정·내보내기 허용이 아니다. 실패/빈 번역문/대체 원본에 대한 N5 확인 및 최종 출력 조건은 관련 조항을 별도 검토한다. 이번에 새 확인 창이나 최종 출력 예외를 만들지 않는다.
- 중단·재진행은 이전 대표 실행을 무효화하고 새 실행을 사용한다. 산출물 재사용은 입력·판정·revision 유효성을 따로 확인하며, 취소된 워커의 늦은 결과 반영을 허용하지 않는다.

|---|---|

BE는 단계별 작업 상태·대체 결과 참조·실패 원인·N5 응답·자동 재시도 종료와 사용자 재시도 경계·후속 렌더 무효화·집계 트랜잭션을 제안한다. AI는 스타일 필수/NULL, 번역 실패 블록 처리, 배경 대체와 렌더 의존성을 정리한다. PM은 기존 하류 성공 필수 합의를 PRD 예외로 변경할지와 복합/전부 실패·최종 확정 범위를 확인한다. **C4는 아직 승인된 운영 예외가 아니다.**

다음 작업은 C1~C4의 리뷰 결정표를 묶은 뒤, 분석·판정 묶음의 verdict_status/verdict_type·배지·사유 코드 매핑 초안을 작성하는 것이다. 후보와 확정값·기존 API 차이를 분리하고 전체 문서 PR 리뷰로 연결한다.

#### 섹션 집계·표시·빈 값

- 제외형 판정이 하나라도 있으면 섹션 제외라는 PM 정책을 따른다. 단수 exclusion_reason에 규제·현지·실패가 동시에 해당할 때의 우선순위는 아직 없다. 사전 순서나 마지막 행으로 정하지 않고 BE·PM이 결정한다. 모든 판정은 보존한다.
- N3 제외 섹션은 포함형까지 전체 판정 행을 표시한다. 포함 섹션의 주의는 PRD의 N5 흐름과 맞추며, 배지 계산을 FE나 export가 각각 다시 하지 않도록 역할을 정한다. 사용자 되살리기는 restored_by_user와 원래 판정을 남기고 원본 상태를 고치지 않는다.
- 대체 표현 있음은 NULL 여부만으로 임의 확정하지 않는다. 빈 문자열·공백·배열/문자열 변환·자리표시자·부적합 데이터의 취급을 명세한다. 누락/잘못된 형식을 금지형으로 자동 바꾸거나 임의 대체 표현을 만들어 포함시키지 않는다. RG-021/022의 값 검증과 번역 준비는 별도 계약이다.
- 사전 원값→서비스 정책값→배지→섹션 권고→사용자 bucket의 각 층을 연결하되 원본 스냅샷은 불변이다. 기존 행의 원값을 새 이름에서 역추정하지 않는다. 이전 enum과 새 enum을 혼합해 내보낼지 여부는 API 호환 명세에서 정한다.
- 운영 겹침 규칙으로 억제된 매칭은 판정 대상에서 제외하는 방향이지만 원시 근거·억제 관계를 보존한다. 겹침 전용 배지를 만들지 않고 살아남은 판정의 개별 배지를 사용한다. 신호 코드 compliance_flags/SignalCode의 대응은 이 표의 verdict_type과 별도 안건이다.

#### 리뷰 결정·검증 사례

BE는 새 현지 서비스명/배지/제외 사유를 언제 어느 층에서 이관할지, DB CHECK·로더·API·기존 데이터 호환, 배지 파생 주체와 AI 입력/출력, 실패 표시 응답, 단수 제외 사유 우선순위를 제안한다. AI는 원값 보존과 정책 매핑·호환 버전·지원하지 않는 입력 거부를 정리한다. 사용자 정책이 달라지는 매핑은 PM 확인 대상으로 분리한다.

검증 사례: regulated 대체 있음/없음, conditional 대체 있음, rewritable 원값 보존, 현지 두 원값의 present/uncertain/absent, 현지 실패와 uncertain 구분, allowed 억제 후 판정 0행의 audit, 복수 제외 사유가 있는 섹션, 되살리기 후 AI 원본 보존, 빈 문자열/공백/템플릿의 대체 표현. 각 사례는 입력·정책 행·배지·bucket·사유·audit 기대 결과를 함께 검토한다. 실제 테스트나 코드 변경은 아직 하지 않았다.

다음 작업은 사전 공급·판정 저장의 필드별 매핑표(필수/NULL·출처·스냅샷·API 노출)와 audit JSON 구조 초안이다. 현재 판정값 매핑은 공동 리뷰 대기이며 enum을 먼저 구현하지 않는다.

각 snapshot_key·match_key·evidence_key는 이 audit 문서 안의 연결키 제안이다. 사전 external_id나 DB PK를 대체하는 전역 식별자가 아니다. 원본 ID와 실행 묶음의 대응을 유지하며 연결 대상 부재를 NULL/다른 행으로 고쳐 성공 처리하지 않는다. 사전 항목 삭제 후에도 스냅샷은 남아야 하므로 현재 FK 제약과 삭제 정책은 BE가 별도 검토한다.

저장 검증·트랜잭션 추천:

1. 고정 묶음에서 지원값·필수값·사용 ID·스냅샷·검사 범위를 검증한다. 최신 사전 내용과 비교해 결과를 거절하지 않는다.
2. 이번 실행의 블록 참조, finding 식별 범위, 문자 구간 및 `matched_text == source_ko[start:end]`, 모든 배열 참조의 존재를 검사한다. 화면의 UTF-16 인덱스와 혼용하지 않는다.
3. 현재 채택 대상 실행인지 확인하고 교체 전 내용, 새 finding/판정 및 연결 audit, 현재 실행 연결·완료 반영을 하나의 DB 트랜잭션으로 처리한다. ID 배정 이후 audit의 판정 ID도 같은 트랜잭션 안에서 확정한다.
4. 취소/오래된 실행은 현재 결과를 교체하지 않는다. audit 저장 실패도 전체 결과 저장 실패로 보고 일부 결과만 완료 처리하지 않는다. C1의 부분 실패 저장은 이 무결성 예외가 아니다.
5. 사전을 사용했지만 판정이 0행인 allowed/억제 사례도 검사 범위·사용 스냅샷·정책 버전과 대응을 남긴다. 감사 이력과 작업 실패 이력의 역할을 구분한다.

리뷰 사례: 한 finding의 복수 사전, 사전 없는 이미지 근거, 동일 사전의 여러 판단 범위, allowed로 판정 0행, 억제된 매칭 보존, 사전 재적재/삭제 후 결과 저장, 근거 확인일 누락, 대체 표현 안의 구분자, 재분석 실패/늦은 성공, 블록 수정/삭제 후 과거 매칭 해석, 보조 평면 문자·결합문자 구간, audit 쓰기 실패의 전체 롤백. 현재는 사례 정의이며 테스트 실행 결과가 아니다.

BE 결정 요청은 공급처가 없는 필드의 보완 방식, 단수 대표 컬럼 선택, audit 키·크기·보존 및 조회/API 범위, 삭제 후 식별 관계, 동시성/트랜잭션이다. AI는 통합 입력형의 필수/선택과 사용 근거·검사 범위 출력을 정리한다. 다음 초안은 하류의 text_block.style·auto_adjust·overflow 경계이며, 이 초안의 미결은 공동 PR 리뷰에 남긴다.

### 5.13 auto_adjust의 사용자 배치와 자동 결과 분리（추천안·미확정）

| 층 | 확인한 의미 | 차이 |
|---|---|---|
| AI 계약 6.1 | schema_version·layout_bbox·updated_by=user | 사용자 배치 입력. 원본 bbox 보존, 섹션 로컬, 미리보기/최종 렌더 공통 |
| OpenAPI AutoAdjust | 저장 font_scale·line_break_applied → 응답 fontScale·lineBreakApplied | 자동 조판 결과. 사용자 layout_bbox를 표현하지 않음 |

| 현재 CFM 조회/수정 | 조회는 auto_adjust를 그대로 autoAdjust에 넣음. BlockPatch는 trans1·revision | OpenAPI의 내부 키 변환과 실제 조회 차이 존재. 사용자 영역 변경 요청 형식도 현재 명세에 없음 |

**추천: 사용자 배치 입력과 자동 조판 결과를 서로 다른 의미로 인계한다.** 기존 AI 계약의 layout_bbox는 유지하는 방향으로 검토하고, font_scale·line_break_applied 같은 자동 결과는 해당 렌더 산출물에 연결한다. 최종 저장 위치는 기존 JSON 안의 명확한 하위 구조와 별도 저장 위치를 BE가 비교 결정한다. 이번 초안만으로 컬럼·엔드포인트·JSON 키를 추가하지 않는다.

- 배치가 없으면 원본 bbox, 있으면 layout_bbox를 사용한다는 기존 계약은 유지한다. 원본 bbox에 사용자 변경을 덮어쓰지 않는다.
- 사용자 배치도 섹션 로컬 정수 px로 받는 안을 추천하되, 원본 bbox의 정수 규칙이 사용자 편집 정밀도까지 자동 확정한 것으로 보지 않는다. 화면 배율 역변환·반올림 주체, x/y≥0·w/h>0·섹션 내부 조건, 잘못된 영역의 거절 방식은 BE/FE 명세에 남긴다. 조용히 잘라서 저장하지 않는 안을 추천한다.
- 배치 초기화의 의미는 원본 bbox로 돌아가기다. 요청에서 키 누락/NULL/초기화를 어떻게 구분할지, 담당하지 않는 JSON 키를 보존하는 갱신 방식은 BE가 정한다.
- 번역문·배치 변경은 기존 계약대로 revision을 증가시키고 재렌더한다. 자동 렌더 결과 저장 때문에 입력 revision이 반복 증가하는 구조는 피한다. 실행 취소/현재 시도 검사도 revision 검사와 함께 적용한다.
- fontScale의 기준 크기·허용 범위·실제 적용값, lineBreakApplied가 자연 줄바꿈인지 강제 개행 삽입인지 아직 정하지 않았다. 자동 폰트 축소의 허용 자체와 최소 크기도 API 필드 존재만으로 승인하지 않는다. 렌더 결과가 원문/번역문을 임의 축약하지 않도록 한다.
- BE가 최종 저장/응답을 정한 뒤 OpenAPI 소유 브랜치 feature/api-tracking에서 요청·응답·호환 계획을 반영한다. 현재 클라이언트에 새 의미를 기존 필드로 조용히 내리지 않는다.

### 5.14 overflow·최신 렌더 유효성（추천안·미확정）

기존 계약은 완료된 최신 렌더의 현재 배치 영역에서 폭 또는 높이가 초과하면 true이며, 초기 false는 완료 증거가 아니다. 반면 현재 run_render는 charLimit이 있을 때 글자 수 비교로 overflow를 갱신한다. 글자 수 제한 검증과 실제 조판 초과는 다른 검사이며 분리하는 안을 추천한다.

| 상황 | 표시·저장 추천 | 확인할 경계 |
|---|---|---|
| 이번 입력의 렌더 미완료/실패 | 초기 false·이전 overflow를 현재 측정으로 표시하지 않음 | API boolean 외 완료/유효성을 식별할 정보가 필요. 새 필드/NULL 변경은 BE 결정 |
| 최신 렌더 성공, 폭·높이 이내 | overflow=false | 실제 사용 폰트·크기·행간·배치로 측정했는지 확인 |
| 최신 렌더 성공, 폭 또는 높이 초과 | overflow=true, 문장 보존 | 실행 실패와 구분. C4 및 검수/최종 출력 조건에 연결 |
| 글자 수 초과이나 실제 영역 이내 | 글자 수 제한 검사 결과와 overflow를 분리 | char_limit으로 자동 축약하거나 overflow를 대체하지 않음 |
| 글자 수 이내이나 긴 단어/높이 초과 | 실제 렌더 기준 true | 문자 수만으로 놓치는 사례 |
| 편집/배치 변경 후 옛 렌더 도착 | 현재 revision과 다르면 반영하지 않음 | 이미지 참조와 overflow를 같은 유효 입력 결과로 반영 |
| 배경·스타일·폰트 매핑 변경 | 같은 텍스트 revision이어도 결과 입력 유효성 재검사 | revision만으로 모든 렌더 입력을 대표하지 않음 |
| 대상 없음·원본 대체 | 측정 생략/대체를 실제 렌더 성공과 구분 | C4의 예외와 표시 계약 필요 |

BE 측정 명세에는 실제 폰트 로드 완료 시점, 줄바꿈·행간·padding·border, 측정할 텍스트 영역, 소수 px 허용 오차·정확히 경계와 같은 경우, 원본 px와 CSS/캡처 배율 대응을 포함한다. 프리뷰 배율 때문에 초과 결과가 달라지지 않게 원본 기준으로 판정하는 안을 추천한다. DOM 속성 하나를 지금 계약으로 고정하지 않는다.

렌더 입력에는 현재 번역문/배치 revision, 스타일 결과, 배경, 역할 폰트 매핑과 렌더 설정의 유효한 버전/식별을 묶는 안을 추천한다. 캐시 키·저장 필드는 BE와 정한다. 이미지 업로드만 성공했다고 DB 완료 처리하지 않고, 현재 실행/시도·입력을 검증한 결과 참조와 overflow를 함께 채택한다. 실패 시 옛 미리보기를 보존할 수 있어도 최신 완료로 표시하지 않는다.

리뷰 검증 사례: 색만 NULL·정렬만 NULL·단일 줄 기본 left, 대상 없는 블록, bg_color가 있는 사진 배경, 소수 글자 크기와 프리뷰 배율, 배치 초기화·경계 밖 입력, 폰트 지연/대체, 긴 단어의 폭 초과·여러 줄 높이 초과·정확히 경계, 글자 수 제한과 실제 초과 불일치, 편집 중 옛 렌더 도착, 같은 revision에서 스타일/배경 변경, 원본 대체와 렌더 성공의 구분. 테스트 실행이 아닌 공동 리뷰용 사례다.

결정 순서는 (1) AI 측정값/사유와 BE 조판값 경계 (2) 사용자 배치 요청 및 자동 결과 저장/API (3) 렌더 입력 유효성과 초과 측정 (4) C4·N5 집계 연결이다. 다음 문서 작업은 compliance_flags·API 신호 코드와 RG-021/RG-022 상품별 검증 정보의 공급/저장/인계를 정리하는 것이다. 이 초안의 미결도 전체 PR 리뷰에 포함한다.
