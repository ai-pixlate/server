# pipeline.md — AI 파이프라인 실행 순서·채택 기술·제약

> 근거: 개발계획 v3.6 · 스키마 계약 문서 v3.5 · PoC 검증 결과 요약 2026-09-17 (별도 PoC 레포, 이 레포 밖)
> 범위: MVP — 원본 규격 유지 · 미국 · 영어. 12월 범위(규격 변경 경로·썸네일·정밀 누끼)는 이 문서에 없다.
> 우선순위: 서비스 흐름은 이 문서 → 산출 값·함수 경계는 `contract.md` → 컬럼 타입·제약은 BE 정본 ERD.
> 표기: `확정` 그대로 구현 / `미정` `open-questions.md` 참조 / `BE 확인 필요` BE와 합의 후 구현.
> 파라미터 값의 정본은 `pipeline/config/default.toml`이고, 이 문서의 값은 기본값 기록이다. 실험 중 값 변경은 문서에 반영하지 않는다. config 파일 경로·프롬프트 디렉터리(`pipeline/prompts/`)는 세 정본에 없는 레포 구조 결정이며 `dev.md` 2절이 소유한다.

## 1. 실행 순서

```text
① 섹션 분해
→ ② 텍스트 추출
→ ③ 줄·문단 병합 및 역할 분류
→ ③-1 AI 섹션 판정 → 정책 적용
→ [섹션 확인 — 사용자 개입 1]
→ ④ 제품 라벨 판정
→ ⑤ 브랜드 로고 제외
→ ⑥ 인페인팅 / ⑦ 스타일 추출 / ⑧ 로컬라이징 번역 (병렬 가능)
→ ⑨ 조판·렌더
→ [검수 및 레이아웃 조정 — 사용자 개입 2]
→ 저장
```
[계약 1.1] [개발계획 4.3]

- ①~③은 `analyze()` 한 함수가 수행한다. 스타일 추출·섹션 판정·정책 적용·라벨·로고는 별도 단계다. [계약 1.2]
- ④ 이후는 **포함으로 확정된 섹션**에만 수행한다. 제외 섹션에는 ④부터 하류 작업을 생성하지 않는다. [계약 1.1, 1.4]
- ⑥⑦⑧은 두 제외 판정(④⑤)이 끝난 뒤 남은 대상에 대해서만, 입력이 준비되면 병렬 실행할 수 있다. [개발계획 2.1] [계약 1.1]
- 앞 단계 산출물이 다음 단계 입력이다. [PoC 0장]

## 5. 하류 처리 제외 규칙

- **라벨·로고 제외**: `is_product_label` 또는 `is_brand_logo`가 `true`인 블록/영역은 판정 이후 **번역·인페인팅·스타일 추출·번역 규제 검증·텍스트 레이어 생성을 모두 수행하지 않는다.** 이미 수행한 OCR·병합·섹션 판정 결과와 제외 사유는 보존하고, 최종 이미지에는 원본 영역이 그대로 남는다. 공통 번역도 만들지 않는다. [개발계획 2.1]
- **하류 작업 생성 조건 3개**: 섹션 확인 완료 ∧ `section.bucket = 'include'` ∧ `is_excluded IS FALSE`. `bucket` 기본값만으로 확인 완료를 판단하지 않는다. [계약 2.4]
- **섹션 제외**: 확인 단계에서 상태로만 기록하고 실제 제거·재배치는 렌더에서 수행. 원본 좌표는 바꾸지 않는다. [개발계획 3장] [계약 3.3]
- **되살린 섹션**: 유효한 결과는 재사용, 미실행 하류 단계는 최초 실행. 최초 판정은 `original_verdict`에 보존. [계약 4.2, 9장]
- **로고 처리 범위**: `block_exact`만. 로고 파일 입력·이미지 매칭·매칭 실패 신호·심볼형 로고는 MVP 이후. 불일치를 실패 경고로 다루지 않는다. [개발계획 2.1] [계약 2.3]
- **제품명**: 별도 `role`을 두지 않는다. 제품명/효능 주장 구분은 **미정**. [개발계획 2.1] [계약 2.1]

## 6. 코드에 닿는 설계 원칙

- **좌표는 섹션 로컬**로 관리하고 원본 위치는 `top_offset + y`로 복원. 편집 후 레이아웃 좌표(`auto_adjust.layout_bbox`)는 원본 `bbox`와 구분해 저장. [개발계획 3장] [계약 3.1, 6.1]
- **의미 단위 ≠ 처리 단위**: OCR용 임시 분할은 의미 섹션으로 저장하지 않고, 중복 정리 후 원래 섹션 좌표로 통합. 임시 분할선은 출력 절단선이 아니다. [개발계획 3장, 3.1] [계약 3.2]
- **AI 판정과 정책 적용 분리**: AI는 항목 해당 여부·근거만, 정책 적용은 별도 로직. 판정 항목이 같으면 정책 변경으로 AI를 다시 부르지 않는다. [개발계획 3장] [계약 1.3]
- **보존 대상은 가공 전에 제외**: 지운 뒤 원복이 아니라 처음부터 마스크에서 보호. [개발계획 3장]
- **무거운 처리는 캐시**: 단계별 입력·실행 설정을 캐시 키로. 입력·모델·프롬프트·용어집·판정 항목 정의가 바뀌면 관련 단계 캐시 유효성 재판단. 라벨·로고 판정이 바뀌면 처리 대상을 재계산하고 영향받는 ⑥⑦⑧⑨ 결과 갱신. [개발계획 3장] [계약 9장]
- **길이 초과는 정상 상태**: 조판 단독 흡수 불가(골든 초과율 97%). 자동 축약·재번역 없이 사용자가 영역을 확장. 문구 수정 시에만 규제 재검증. [개발계획 2.2, 3장] [계약 5.1, 6.2]
- **확장은 데이터 추가로**: 국가·규제 분류·판정 항목은 코드 수정 없이 데이터로 늘어나는 구조. 규제 사전 조회 키는 (타겟 국가, 규제 분류). [개발계획 2.1, 3장]

## 7. 구현 시 유의

- 인페인팅 **마스크를 넓혀 다시 지우지 말 것** — 팽창 50%에서 얼룩이 늘고 좋은 섹션이 가장 크게 나빠짐. 잔존율 측정·재시도는 MVP 이후. [PoC 0장] [개발계획 4.1]
- **빈 텍스트·저신뢰 영역을 "글자 아님"으로 읽지 말 것** — 빈 텍스트 40개 중 28개가 실제 글자였음. `score_min`에서 제외된 영역은 원문을 보존한다. **제외된 저신뢰 글자를 번역·렌더에서 어떻게 다룰지는 미정** — 정합성 확인이 필요하다는 방향만 정본에 있음. [PoC 1장] [개발계획 6장]
- 인페인팅 대상 판정은 블록 `ocr_confidence`가 아니라 **원시 영역별 `score`**. [계약 2.5]
- **섹션 판정은 텍스트만으로 안 됨** — 비포·애프터 절반이 라벨 없는 사진 짝·그래프. 섹션 이미지를 항상 동봉. [PoC 0장, 11장]
- VLM은 **항목별 해당·애매·근거만** 낸다. 정책 데이터를 항목 on/off로 구조화하는 것은 PoC 실험 방식이며 **미정**. [계약 1.3] [PoC 0장]
- 심볼형 로고는 텍스트 대조로 못 잡음 — 미검증, MVP 이후. [PoC 0장]
- 주의문구 미탐 위험 — 시험 조건 각주는 캡션으로, 경고 문장은 본문으로 가는 경향. 범위는 **미정**. [PoC 5장] [개발계획 4.1]
- 가격 `role`은 표본 부족으로 사실상 미검증. [PoC 5장]
- 실패 처리: `AnalyzeError(code, retryable, message, source_image_id)`. `IMAGE_OPEN_FAILED` 재시도 불가, `OCR_FAILED` 허용 횟수 내 재시도, 텍스트 0개는 오류 아님(빈 `text_blocks`). [계약 8장]
