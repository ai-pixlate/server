- 확인하지 못한 것: `requirements-gpu.txt` 설치, GPU 서버 접속, Linux에서 `requirements-ocr.txt` 설치·oneDNN 동작.
- `test_sample_generator_is_reproducible`(샘플 생성기 재현성)는 이 브랜치 이전부터 있던 환경 의존성이다. `make_synthetic._font()`가 DejaVuSans를 못 찾으면 Pillow 기본 폰트(Aileron)로 대체돼 글자 bbox가 달라진다. Windows 등 DejaVu가 없는 PC에서 실패하며, 기대 좌표를 그 PC 기준으로 덮어쓰지 않는다. 해결은 폰트 파일을 레포에 동봉하거나 테스트를 DejaVu 있을 때만 돌리는 것 중 택일 — 미결정.
- `synthetic_01`은 영문 합성 이미지다. 한국어 OCR·역할 판정의 실제 검증은 `samples/local/` 표본으로 한다.
- ① 섹션 분해의 실측 기록(1~4차 보고서 · 정답 목록 `truth.json` · 드라이버·분석 스크립트)은 레포 밖(PoC 레포 · 로컬 스크래치패드)에 있다. `pipeline/out/`은 git 제외. 실측을 이어 가려면 `samples/local/` 34장과 `truth.json`이 필요하다.
- **OCR 고정 입력 v1 보관 방식**(5차 실측 후 결정, 레포 밖): `pipeline/out/r5/full/`과 GS-02_014의 세 실행(`_run1`·`_run2`·`_run3`)은 보고서가 참조하므로 그대로 보존하고 덮어쓰지 않는다. 별도 폴더(v1)에 33장은 r5/full, GS-02_014는 **run3**(3회 중 정답 2891을 유지한 실행)을 복사하고, 출처(실행 디렉터리 · 회차 · 선택 기준 · 실행 커밋 `6d09dfb`)를 v1 안에 기록한다. 생성은 `freeze-input`으로 한다(2026-09-23): r5/full과 run3의 `split.json`은 버전 1이므로 `--base <레포 루트>`를 주고, 출처는 `--meta`로 남긴다. 이미지 복사·경로 재지정·검증(입력본 내부 참조 · 해시 · 연속성 · 레포 밖 사본 검증 · 원본 불변)은 도구가 한다. 이 선택은 OCR 개발용이며 ① 성능의 근거로 쓰지 않는다. 규칙은 `dev.md` 5절.
- **② 기준선 측정 환경(2026-09-25)**: 이 PC의 GPU 가상환경(`paddlepaddle-gpu` 3.3.1 · CUDA 11.8)에서 잰다. CPU 환경 결과와는 프로브 4개 섹션에서 거의 같았지만(`dev.md` 6절) 기준선끼리 비교할 때는 같은 환경의 결과만 쓴다.
- **OCR 고정 입력 v1 현황(2026-09-23)**: 실측 PC에서 생성(`--meta`로 출처 기록, GS-02_014는 run3) 후 zip으로 옮겨 `pipeline/out/ocr_input/v1/`(git 제외)에 풀었다. 34장 · 섹션 112 · 높이 201~3,470px · 폭 800/830/1000. **4,000px 초과 섹션이 없어** 임시 분할은 v1로 실측 검증할 수 없다.
- **v1 경계 선별의 범위 한정**: 내부 경계 78개를 경계 위아래 행의 균일도로 자동 선별하고 표시된 2곳(GS-01_002 29174 그라데이션 · GS-02_014 9200 #29 줄 간격)을 육안 확인한 범위에서 ①의 글자 획 절단 0건. 전체 경계를 사람이 전수 확인한 결과가 아니다. 원본 이미지 경계에서 잘린 글자 1건(GS-03_016 끝 ↔ GS-03_017 시작 "TO USE") — ① 기인이 아니라 입력 기인이며 고정 입력은 바꾸지 않는다(채점 명세 v2 `source_cut`).
- **품질 표본 12개(2026-09-23 확정)**: GS-02_014/09 · GS-01_002/16 · GS-01_002/17 · GS-03_002/04 · GS-02_001/04 · GS-03_018/11 · GS-01_002/15 · GS-02_007/02 · GS-02_001/03 · GS-01_002/05 · GS-02_002/01 · GS-03_016/01 (유형·선정 이유는 1a 보고서 3절). 4,000px 초과 유형은 해당 섹션 없음. 1a 프로브 섹션(GS-02_003/01 · GS-03_005/01 · GS-02_014/04 · GS-02_009/06)과 겹치지 않는다.
- **OCR 정답 도구(2026-09-23)**: `docs/ai-experiments/tools/ocr_truth/` — `truth.py`(`init` · `draft` Gemini 전사 초안 · `serve` 브라우저 작성·검수 화면 · `check` 자동 검사 · `status` · `freeze`)와 `annotator.html`. 정답은 `docs/ai-experiments/ocr_truth/v1/<표본>__<섹션>.json`(이미지 SHA-256 · 줄 ID · 텍스트 · bbox · 태그 · 검수 상태 · 변경 이력). Gemini 결과는 `verified: false` 초안이고 사람이 이미지와 전수 대조해야 `reviewed`가 된다. `freeze`는 12개 모두 검수 완료 · 자동 검사 통과 · 채점 명세 v3에 미커밋 수정 없음일 때만 명세 커밋 해시와 `MANIFEST.json`을 남긴다. **초안 현황(2026-09-25)**: 12개 모두 Gemini(`gemini-3.8-flash`) 초안 369줄, 검수 0. 명백한 초안 오류 예: GS-02_002/01 L005 · L006은 좌표 숫자를 텍스트로 지어낸 것 — 전수 대조 필수. 앱이 사용자 환경변수를 물려받지 못하면 실행 명령 안에서만 사용자 범위 `GEMINI_API_KEY`를 읽어 넘긴다(값 출력·기록 금지).
- **1a 프로브 형식 관찰(품질 판단 아님)**: 검출 단위가 섹션마다 어절·줄로 섞인다 · 인식 텍스트에서 띄어쓰기가 자주 빠진다 · 비문자(로션 모양 · 손가락 그림)를 글자로 검출한 영역 2건(score 0.388 · 0.628). CPU 속도는 oneDNN을 끈 상태에서 섹션당 9~28초.
- ① 5차 검증의 범위 한정: "글자 획 절단 0건 · 회귀 없음"은 34장 표본, 4차 저장 응답 재생, 균일 행 선별 검사 + 육안 확인 범위의 결과다. 다른 표본·실제 VLM 호출에서의 보장이 아니다. 보정은 후보 1,207건 중 1,033건에서 발동하므로 실행 간 비교는 `accepted` 집합으로 한다(`dev.md` 5절).
- ①의 VLM 실패 처리(#25)는 BE 합의 전이라 `VlmError`가 그대로 전파된다(CLI 종료 코드 4). 워커 연결 시 이 정책을 먼저 정해야 한다.
- 워커(`app/tasks.py`)는 아직 스텁이며 `pipeline`을 부르지 않는다. 연결 시 큐 라우팅(`app/celery_app.py`)은 BE 소유다(루트 `README.md`).
