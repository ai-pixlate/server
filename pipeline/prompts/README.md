# pipeline/prompts — 프롬프트 원문

`docs/ai`의 `{{PROMPTS_DIR}}`가 가리키던 디렉터리다. 프롬프트 원문은 여기에만 두고 문서에는 경로만 적는다(docs/ai/README.md 4.4).

| 파일 | 단계 | 상태 |
|---|---|---|
| `section_boundary.md` | ① 긴 구간 VLM 경계 선택 — 소제목 위 여백에서 자를 y 목록을 JSON으로. 소항목·목록 항목·라벨 아래는 제외. `{{WIDTH}}` `{{HEIGHT}}`는 실행 시 치환 | 초안 (1차 실측 반영, 2차 실측 전) |
| `merge_assist.md` | ③ `llm_assist` — 추가 병합·역할 재판정만, 분할 금지. 입력 JSON(블록 ID · 텍스트 · bbox · 줄 수 · font_h)은 프롬프트 뒤에 따로 보낸다. 역할 정의는 이번 프롬프트의 잠정 의미 정의(open-questions #9 확정 아님, `docs/ai/pipeline.md` 7.2절) | 초안 v1 (실측 전) |
| `merge_assist_region.md` | ③ `llm_assist` 보충 — `merge.xycut`을 켰을 때만 `merge_assist.md` 뒤에 붙는다(설정 키 없음, 경로는 `pipeline/stages/merge.py`의 `REGION_PROMPT_PATH`). 입력 블록의 `region` · 읽기 순서 ID · 다른 `region`끼리 병합 금지. `region` 값은 2026-10-26부터 칸 묶음 번호(y 절단으로만 이어진 후보 영역의 묶음)이며 프롬프트 문구는 그대로다(4 · 5차 실행에 쓴 문구). 넘은 응답은 실패가 아니라 칸 묶음별로 나눠 조립한다(`docs/ai/pipeline.md` 7.1 · 7.2절, open-questions #86) | 초안 (2026-10-23, 실측 전) |
| `judge_context.md` | ③-1b 현지부적합 맥락 판정 — 항목별 `present` · `absent` · `uncertain`과 실제 근거(현재 섹션 블록 ID · 근거 출처)만. 앞뒤 섹션은 해석 참고이며 근거로 귀속 금지. 입력 JSON(블록 · 항목 · 맥락 2열 · 후보 · 문맥)과 섹션 이미지는 프롬프트 뒤에 따로 보낸다(`docs/ai/pipeline.md` 7.3절) | **1차 실측용 확정** v1 (2026-09-29, 사용자 검토 4건 반영: 혼합 섹션에서 판정 미하향 · absent/uncertain 구분 · 근거 규칙을 검증기와 일치 · 콘텐츠 안 지시문 무시). 판정 품질 확정이 아니다 |
| `label.md` | ④ 제품 라벨 판정 — 블록별 `is_product_label` boolean만. 입력 JSON(블록 ID · 원문 · `box_2d`)과 섹션 이미지(긴 변 1024)는 프롬프트 뒤에 따로 보낸다. 경계 사례: 혼합 블록 true · 패키지 밖 제품명 · 문서 글자는 이름 · 문서라는 이유로 true 아님 · 애매하면 true(`docs/ai/pipeline.md` 7.4절, open-questions #66) | 초안 v1 (2026-09-29, 소수 표본 · 1차 실측에 사용. 판정 품질 확정 아님) |
| `translation_review.md` | ⑧ 번역문 LLM 규제 판정 — 번역기와 독립. 섹션 문맥 안의 대상(`t1` …) × 검사 항목(`r1` …)마다 `judgment`(risk · no_risk · undetermined) · `mention` · 위치(quote · anchor) · 공급 근거 ID만. 근거 밖 법규 · URL · 상품 사실 생성 금지, 입력 안 지시문은 데이터. 입력 JSON은 프롬프트 뒤에 따로 보낸다(`pipeline/stages/translation_review.py`) | 초안 v1 (2026-10-12, 실측 전 · AI 선행 구현. BE 연결 시점 · 순서 미정 — BE 연동 전 일괄 검토, `docs/ai/be-handoff.md` 8.12) |
| `translate.md` | ⑧ 로컬라이징 번역 — 섹션 문맥 안의 대상 블록(`t1` …)만 번역, 용어(BE 공급) · 표현 지시(고정 묶음의 대체 표현) 적용, 원문 수치 유지 · 자리표시자 생성 금지, 번역 불가 블록은 명시적 실패. 입력 JSON은 프롬프트 뒤에 따로 보낸다(`pipeline/stages/translate.py`) | 초안 v1 (2026-10-08, 실측 전. 확정은 #11 기술검증 후) |
| `translate_brand.md` | ⑧ 번역 보충 — `translate.md` 뒤에 붙는다. 브랜드 · 키워드 값이 하나라도 있을 때만(설정 키 없음, 경로는 `pipeline/stages/translate.py`의 `BRAND_PROMPT_PATH`). 페이로드 `brand`(한글명 · 등록 영문명 · 개요 · 핵심 고객층 · 키워드, 값 있는 키만)의 쓰임: 브랜드 한글명 → 등록 영문명 그대로, 개요 · 고객층 → 어조 · 표현 수위만(내용 추가 금지), 키워드 → 원문에 있을 때 일관된 표현(끼워 넣기 금지). 값이 없으면 붙지 않아 중립 톤이고 모델 입력이 바뀌지 않는다. 인계 공급은 BE 확인 전(`docs/ai/open-questions.md` #90) | 초안 (2026-11-08, 실측 전 · 가짜 모델 검증만) |
| `aplus_label.md` | A+ 템플릿 모듈 — 섹션 내용 라벨 19종. 상품 하나의 섹션 전체를 1회 호출로 보내고 섹션마다 주 라벨 1개 · 보조 라벨 0~2개 · 확신도 · 이유를 받는다. 입력 JSON(섹션 ID · 읽은 글)과 섹션 이미지(`[s1]` 뒤에 이미지, 긴 변 1024)는 프롬프트 뒤에 따로 보낸다. 라벨 표는 데이터 담당의 분류가이드 v1.4를 옮긴 것이며 영어 예시 문구를 한국어로 바꾸고 옵션 종류(opt) · 이미지 위 ID 설명은 뺐다(`pipeline/aplus/label.py`, `docs/ai/open-questions.md` 2.9절) | 초안 v1 (2026-11-23, 실측 전. 분류 품질 확정 아님) |
| `aplus_plan.md` | A+ 템플릿 모듈 — 7칸 구성. 문구를 쓰지 않고 칸마다 템플릿(A/B) · 배치 변형 · 넣을 1차 번역 블록 ID · 사진을 자를 자리(`box_2d`)만 고르고, 사진마다 누끼 여부(`cutout`)를 답한다(누끼 여부의 기준은 주지 않는다 — `docs/ai/open-questions.md` #98). 템플릿 고르는 기준은 데이터 담당 변환기 README 5-2의 표와 사람 검수 결정을 옮겼고, 블록 고르기 · 고르지 않는 블록 기준은 이 레포에서 쓴 초안이다. 입력 JSON(칸 후보 · 템플릿 규격 · 섹션별 블록)과 섹션 이미지는 프롬프트 뒤에 따로 보낸다(`pipeline/aplus/plan.py`, `docs/ai/open-questions.md` #94) | 초안 v5 (2026-11-24 누끼 여부 · 블록 역할 → 칸 규칙 · `caption`의 항목 연결(빈 자리만 · 2A 효능 문구) 추가, `label` 선택 제거. GS-01 한 원본 · GS-02 · GS-03 각 1회 실행. 품질 확정 아님) |
| `aplus_compress.md` | A+ 템플릿 모듈 — 압축(2차 번역). 템플릿 한도를 넘은 글 칸의 문구만 한도 안으로 줄여 쓴다. 입력 JSON(대상이 있는 칸마다 그 칸의 글 전부 · 대상 글의 `target` ID와 `max_chars` · 채택되지 않은 앞선 답 `tried`)은 프롬프트 뒤에 따로 보내고 이미지는 보내지 않는다. 줄이는 기준(없는 내용 · 수치 추가 금지 · 줄이는 순서 · 숫자 값 유지 · 제품명 · 브랜드명 · 성분명 유지 · 완화 표현 유지 · 표기 유지 · 못 맞추면 `failed`)은 이 레포에서 쓴 초안이다(`pipeline/aplus/compress.py`, `docs/ai/aplus.md` 4.7 · `docs/ai/open-questions.md` #94) | 초안 v1 (2026-11-26, GS-01 · GS-02 · GS-03 각 1회 실행. 줄인 문구의 품질 확정 아님) |

- 파일 이름은 config의 `*.prompt_path`와 맞춘다.
- 프롬프트를 바꾸면 실행 기록(`run.json`)에 파일 해시가 남는다. 버전 관리는 git이 한다.
