# pixlate baseline 평가 지시

평가 자료에 포함된 `protocol/evaluation.md`, `dataset.md`, `aggregation.md`를 읽고 해당 버전의 기준을 적용한다. 평가할 원본 식별자·지표·범위와 평가자 역할은 요청에서 받는다. 원본 파일과 산출물, 사람이 확인한 기준 자료, 기록된 표시·확대 조건을 사용한다.

- 최종 이미지는 직접 평가한다. 중간 단계 판정을 최종 등급으로 전파하지 않는다.
- 전체 맥락과 작은 글씨·문제 영역의 세부를 모두 확인한다. 볼 수 없거나 자료가 부족하면 그 한계를 기록한다.
- A/B/C와 판단 불가·해당 없음·산출물 없음을 구분한다. 산출물 부재를 A 또는 자동 C로 처리하지 않는다.
- B/C는 원본 좌표의 결함 위치, 관찰 내용, 기대 조건, 영향과 이유를 구체적으로 남긴다. 동일 결함을 여러 박스로 표시했다고 결함 수를 늘리지 않는다.
- 사전 핵심 영역 K01~K09를 명시적으로 확인한다. 영역 확인으로 원본 전체를 검수했다고 표시하지 않는다.
- 제외된 영역도 원본과 판정 근거·처리 기대값으로 평가한다. 모델이 낸 판단을 기대값으로 사용하지 않는다. 섹션 제외와 포함 텍스트의 대체·완충 지시를 나누어 확인한다.
- 기존 원본 자체의 결함과 새로 발생한 오류를 구분한다. 근거 없는 복원을 요구하지 않는다.
- 독립 재검토 역할이면 1차 판정·설명 파일을 읽지 않는다. 생성·개발 세션과 분리된 세션에서 판정한다. 평가 ID, 역할, 모델 식별자·설정, 세션 식별자를 기록한다.
- 사람 검수가 필요한 항목을 AI 동의만으로 완료 처리하지 않는다. 불일치·C·불확실 사례는 근거와 함께 사람 검수 대상으로 남긴다.
- baseline 실행 지표는 O1 대시보드 지표와 구분해 보고한다. 원본 이미지 기술 처리 완료 비율과 원본당 실행 비용을 O1 완료율·건당 원가로 부르지 않는다.
- 지표 7의 혼동행렬은 고정한 사전·정책의 기대 처리에 대한 대조 건수다. 규제 검출 재현율로 보고하거나 NFR-14 충족 근거로 사용하지 않는다.
- 비용·시간·호출 수는 추정해 채우지 않는다. 해당 값은 실행 기록에서 집계한다.
- 후속 비교에서 결함 대응은 원본·내용 또는 대상·결함 유형을 확인한다. 애매한 대응은 사람 확인으로 넘긴다. 신규 결함과 뒤늦게 발견한 기존 결함, 해결 후 재발을 구분한다.

결과는 도구 README의 평가 JSON 형식으로 작성한다. 원본 전체 판정과 영역·결함 판정을 분리하며, 각 판정이 참조한 이미지·DB 증거 파일과 범위를 남긴다. 도구의 `record` 명령은 판정을 검증·보존할 뿐, 평가의 진실성이나 사람 검수 완료를 보증하지 않는다.
